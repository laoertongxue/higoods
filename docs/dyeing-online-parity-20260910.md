## 3. 条码管理

关联单号、卷码范围、创建时间范围、查询/重置；选择、总卷数/长度/重量、分页及每页条数；ID、条码、关联单、SKU 与图片、状态、入库状态、卷号、长度、重量、克重、幅宽、仓库/库位、入库时间、打印人/时间和操作。

新增、编辑、复制新增、批量修改采用上层表单，保留底层列表。支持长度、米数、重量按幅宽/克重即时换算，负数/非有限值/空必填阻断。批量修改空值保持原值，不把不同卷强制覆盖为第一卷数据。支持补充条码、批量打印、批量删除、细码导入、批量下架；导入先校验预览再确认，删除/下架二次确认；被交出单占用的卷仍执行现有防错。打印预览不等于实际打印，不等于入库或加工完成。条码字段、打印和下架标记保存后重新打开、刷新仍可读取同一记录。预设生产单和交出事件沿用原型的会话演示方式，刷新后重置；条码不保存失去交出单来源的占用锁。动态正式单继续使用既有持久化机制。

## 4. 流程卡

采用纵向六列连续表格、大二维码、序号、中印标题和双语字段。基础信息、色样/卡号、供应商/批号、原料、色号、数量、重量、成分/幅宽/克重与列表同源。重量按长度×幅宽×克重换算并标注理论值。备料松布/装袋/卷支/络筒和复样/染色/脱水/开幅/烘干/定型/包装/出货保留手写空白格。补料单显示红色横条与斜章，普通单不显示；批量一单一页、连续编号，打印/另存 PDF 隐藏工具栏。图片保持同块、比例、大图与失败提示。

## 5. 实施顺序

1. DATA：预设资料与可维护卷记录 → `dye-work-order-demo-details.ts`、`dyeing-task-domain.ts`、`dye-work-order-online-view.ts` → 补齐同源展示资料 → 资料完整性/数量未被展示资料覆盖的专项检查。
2. LIST：工厂 Tab 和信息块 → `process-factory/dyeing/work-orders.ts` → 本地查询/分页/图片/选择验证。
3. BAR：条码管理 → `process-factory/dyeing/output-documents.ts` 及独立条码视图 → 保存/重开/导入/换算/打印/占用防错专项检查。
4. PRINT：专用连续表格 → `dye-work-order-flow-card-template.ts` → 普通/补料/批量打印与低分辨率浏览器验收。
5. VERIFY：最终 diff、相关测试、治理、CodeGraph 同步、任务收据。只根据实际证据更新矩阵；产品确认由用户完成。

## 6. 场景验收

正常：选择工厂 → 查看完整单 → 打开条码 → 填写长度自动得出米数/重量 → 保存重开 → 预览标签 → 打开普通与补料流程卡。

边界：切厂清选择；空选择批量操作提示；非法范围/负数/非法导入不写入；被交出占用卷禁止修改删除；仅预览不记打印、不增加完成数量；批量卡不漏单、不跨单混用资料。

需求登记和交付证据见 `dyeing-online-parity-matrix-20260910.md`。
