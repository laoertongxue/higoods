# 追踪与验收操作细节

触发条件、验证范围、规模、性能门槛、证据复用及完成状态执行根 `AGENTS.md`；本节只补充实际操作，不重复定义流程。记录格式只读 `docs/prototype-review-record-template.md`。

## TRACE-01 触发后的追踪

- 需求核查源码、页面、上下游和已有现场事实，至少覆盖正常及边界场景；说明目标 / 非目标、对象来源 / 唯一性、岗位责任 / 操作条件、状态 / 时序、数量 / 单位、异常恢复及验收。用户只要业务语言时，不写实现细节。
- 计划按依赖写“业务目标 → 文件 / 符号 → 修改 → 验证 → 完成条件”，包含 Mock、旧逻辑处置、风险及阶段，不预填实施结果。
- 每个原子结果只写一次，用稳定编号；字段可合并为：编号 / 需求来源、独立结果、工作包 / 文件符号、验证 / 证据及适用端、状态、确认人 / 版本。不同完成条件不合并，相同规则合并时保留来源；Web / PDA / 打印、图片 / 性能、数量精度、时间、返工及删除保留按实际需求覆盖。
- 状态为 `待实施`、`实施中`、`已实现待验证`、`已验证`、`已阻塞`、`不适用`。开工及关闭时双向核对需求和结果；任务 / 提交 / PR 引用负责编号，完成后绑定实际位置。需求变更同步追踪记录，阶段按负责条目的约定状态关闭，未完成 / 阻塞如实列出。T0 全面审查用“对象 → 问题 → 证据 → 建议”覆盖表。

## 正式性能与环境记录

按根 MOCK-01、PERF-01 选规模和样本，每个性能家族含首次及适用边界；成功 / 失败、保存 / 取消、冷 / 热不混采，视口成本不等价时分验。校准记录、选择器、弹窗终点及图片 / 字体就绪，预检与正式冷态隔离，不预热冷态。

固定服务 / 工作树、源码 / 资产、浏览器 / 设备 / 视口 / 时区、网络、数据 / 附件 / 图片来源及缓存，记录路由和计时起止点。区分冷启动、首次访问、数据初始化及开发 / 本地生产 / 线上环境；不事后挑最快环境，清缓存 / 重置只用隔离验收环境。发布另记构建命令、Node 主版本、包管理器 / 锁文件及环境差异。

## 治理命令范围

治理入口与记录模式按根 REVIEW-01；显式 scope 不带 `--paths` 表示完整范围，不能冒称只验本任务。旧 `--all` 仅是工作区别名。

公共列表运行契约变化或本次确需验证运行能力时用 `npm run check:standard-list-page-template`；纯文案 / 样式不自动触发。只核规则文件可用该脚本的 `--policy-only`，不冒称产品验收；这两种模式均读工作区，不能当作暂存版本证据。空范围不证明产品通过。

## 需要收据时

使用根 RECEIPT-01 命令。其 `--paths <逗号分隔文件>` 核对完整差异清单，不能当过滤器；部分专项仍扫描工作区。有无关差异时隔离到独立工作树，无法隔离如实记未运行，不吸收他人改动。日志 / 收据放独立临时位置，避免自身绑定循环。

工具按路径选检查，合并同范围列表聚合已覆盖的产品治理，其余仅按相同命令去重，嵌套检查仍可能重复；不按 T2 / T4 标签缩减或导入旧成功结果。收据绑定 HEAD、差异、根及声明的专项规则、检查退出值和 CodeGraph；需重新生成时会重跑所选检查，不改写旧收据，原始产品证据仍按根 EVIDENCE-01 判断。远端交付 / 接受命令只支持 GitHub 证据，其他环境按根 RELEASE-01 记录。
