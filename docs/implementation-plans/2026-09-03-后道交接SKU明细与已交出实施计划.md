# 后道交接 SKU 明细与已交出实施计划

## 1. 完成标准

待接收与历史可逐 SKU 核对；后道交接只有“待接收／已交出”且“已交出”与 Web 后道出货单同源；加工与复检可返回执行工作台。最后一次修改后必须通过专项测试、旧交接回归、双视口页面验收、3×5×5 跨端链路、构建、治理检查和任务收据。

## 2. 工作包

### WP-SKU 接收明细

- 业务目标：当前确认对象和历史记录可逐 SKU 核对。
- 文件／符号：`pda-handover-detail.ts:resolvePickupSkuDisplay`、`renderPickupSkuDetail`、`renderPickupCurrentPanel`、`renderPickupRecordItem`。
- 修改：从交接记录反查 SPU/SKU 产品事实和图片，仅对后道接收增加明细，不改通用工厂紧凑记录。
- 验证：当前 SKU、历史 SKU、图片大图及通用接收回归。

### WP-SHIPPED 已交出页签

- 业务目标：后道交接不重复发起出货，只查看 Web 已建立的后道出货单。
- 文件／符号：`pda-handover.ts:getTabConfig`、`renderPostFinishingOutboundCard`、`renderPostFinishingOutboundLine`。
- 修改：后道工厂使用“待接收／已交出”专用页签；“已交出”读取 `listPostFinishingOutboundOrders()` 并逐 SKU 展开。
- 验证：页签边界、单号／数量／状态同源、实图、旧 `tab=handout` 不可达。

### WP-BACK 操作页返回

- 业务目标：现场人员无需依赖浏览器返回键。
- 文件／符号：`pda-post-finishing-flow.ts:shell`、`renderPdaPostFinishingExecutionPage`、`renderPdaPostFinishingRecheckPage`。
- 修改：为后道加工和复检标题栏注入返回 `/fcs/pda/exec` 的明确动作。
- 验证：两个路由的按钮可见、点击后路由正确。

### WP-VERIFY 交付闭环

- 更新专项 Playwright 契约和原型审查记录。
- 两轮追踪：正向从方案到实现和证据；反向从页签、页面、Mock、测试回到需求。
- 最后一次实质修改后重跑所有适用证据。

## 3. 实施顺序

`WP-SKU → WP-SHIPPED → WP-BACK → WP-VERIFY`。共享出货单是已交出的事实源，不在 PDA 内新建第二套出货数据。
