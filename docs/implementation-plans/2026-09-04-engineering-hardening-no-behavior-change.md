# 工程加固实施计划（不改变业务逻辑与原型展示）

## 1. 目标与完成标准

本轮按用户确认的顺序完成五项工程加固：修复库位 T1/T2 专项失败、收口裁剪主链路类型错误、扩大渐进类型检查、建立 lint/format 基线，并对模块加载器、路由分发、存储封装和巨型文件实施第一批可验证的低风险治理。

完成必须同时满足：

- 不改变业务对象、状态含义、数量公式、权限、路由、Mock 数据、页面 HTML、文案、样式和交互结果。
- 每项修改都有“需求编号 → 实现位置 → 专项检查”的直接证据。
- 不通过删除断言、降低类型严格度、关闭 lint 规则或跳过现有门禁制造绿灯。
- 全量 TypeScript 既有错误可继续分批存在，但本轮负责范围必须从基线中明确减少，且不得新增范围外错误。
- 最后一次实质修改后重新运行受影响专项检查、构建/治理检查及 CodeGraph 同步。

## 4. 工作包与顺序

### WP1：T1/T2 失败诊断与最小修复

- 业务目标：完整交出 T1 后，占用投影只保留仍有数量的 T2；T1 部分回仓后按现有顺序恢复。
- 文件/符号：`scripts/check-cutting-warehouse-location-map.ts`、`buildWaitHandoverLocationOccupancyStates`、特殊工艺完整事件解析器。
- 修改：先确认失败事件是否满足当前完整事件契约；若测试夹具缺字段，仅补齐事件事实；只有确认生产投影存在缺陷时才修改投影。
- 验证证据：T1/T2 断言、部分回仓断言、同时间事件顺序断言和完整库位专项检查通过。
- 完成条件：不得删除或放宽完整事件门禁，不得改期望值掩盖失败。

### WP2：裁剪主链路类型收口

- 业务目标：类型定义准确反映当前运行数据，不改变运行时取值和分支。
- 文件/符号：裁剪主事件账、`production-material-prep.ts`、`sewing-dispatch.ts` 及其直接类型定义。
- 修改：补齐缺失字段声明、缩窄状态联合、修正可空值/字段名称的静态表达；不添加运行时默认值来改变业务结果。
- 验证证据：负责文件定向 TypeScript 检查无错误；相关裁剪专项检查通过；全量错误总数不增加。
- 完成条件：本轮列出的裁剪错误归零或逐项记录无法安全修复的既有业务歧义。

### WP3：扩大渐进类型检查

- 业务目标：让 `domain`、`components/ui`、`state` 成为持续可检查的工程边界。
- 文件/符号：`tsconfig.engineering.json`、必要的分层 tsconfig 或入口清单、`package.json`。
- 修改：扩大 include/引用范围；如目标目录自身仍有既有错误，建立按目录可独立执行且不隐藏错误的阶段配置，先修到对应命令通过。
- 验证证据：各分层类型命令和聚合 `typecheck:engineering` 通过。
- 完成条件：三个目录均被真实编译，不使用 `strict: false`、`skipDefaultLibCheck` 或排除错误文件绕过。

### WP4：lint/format 基线

- 业务目标：提供稳定、低噪声、可自动执行的静态规范入口。
- 文件/符号：`package.json`、锁文件、lint/format 配置及忽略清单。
- 修改：选择与当前 Vanilla TypeScript/Vite 兼容的最小工具；新增检查与写入命令；首次仅修本轮触达文件或明确的安全规则，不批量改写全仓。
- 验证证据：lint 检查和 format check 可重复通过；配置不关闭核心正确性规则来掩盖新增问题。
- 完成条件：命令、配置、忽略范围和后续收敛方式均可审计。

### WP5：第一批基础设施与巨型文件治理

- 业务目标：减少重复和入口文件体积，同时保持懒加载时机、路由命中、存储 key/序列化/异常处理及页面结果不变。
- 文件/符号：`src/main.ts`、`src/main-handlers/fcs-handlers.ts`、`src/router/`、`src/data/browser-storage.ts` 和选定高集中度存储调用文件。
- 修改：提取类型安全懒加载器；建立边界安全的路径匹配帮助函数并替换脆弱的 `includes`；扩展现有浏览器存储封装并迁移第一批直接调用；将这些纯基础设施代码从巨型入口抽出。
- 验证证据：构建、菜单/路由契约、相关页面专项检查、存储契约测试、关键渲染快照或源码契约前后一致。
- 完成条件：不改变模块导出、路径、存储 key、JSON 形态、异常回退、HTML 与事件行为；未治理的后续批次明确登记。

## 5. 风险与控制

- 旧测试夹具可能不符合更新后的完整事件契约：优先补齐夹具，禁止降低生产门禁。
- TypeScript 修复可能诱发运行时“顺手兜底”：限定为类型层修复，任何运行时代码变化必须有前后等价证明。
- lint/format 首次启用可能造成超大 diff：不做全仓写入，只建立基线并处理本轮文件。
- 路由与存储重构风险高：每批只迁移具有相同输入输出的基础模式，保留原 key、顺序和失败语义。
- 既有工作区差异较大：验证以本轮边界和命名检查为准，最终报告单列前置差异与本轮差异。
