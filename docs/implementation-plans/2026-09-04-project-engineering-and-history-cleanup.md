# 项目工程与历史文件清理实施计划

## 1. 目标与完成标准

本计划落实 2026-09-04 项目审查建议，在不改变现行业务页面和 Mock 事实的前提下：

1. 清理可重新生成的本地产物。
2. 修复已确认的数量解析 Bug 和 UI 组件同名导出冲突。
3. 恢复可执行的 TypeScript 检查入口和默认测试入口，但不在本任务越界清理全部既有类型债务。
4. 建立文档现行状态索引，移除已经禁用的 Superpowers 历史资料及其脚本依赖。
5. 移出不应进入源码仓的运行状态、历史输出和确认无调用的孤立脚本。
6. 以专项测试、构建、治理检查、完整 diff 和 CodeGraph 状态作为完成证据。

完成时必须满足：工作区只剩本任务声明的受控差异；数量解析专项通过；UI 组件出口不再产生同名导出错误；默认 `npm test` 能运行明确测试；历史文档删除不破坏现行检查脚本；构建与适用治理检查通过。

## 4. 工作包

### WP-01 本地生成物清理

- **业务目标**：去除不参与源码交付且可重建的本地产物。
- **位置**：`output/`、`playwright-report/`、`.playwright-cli/`、`.playwright-mcp/`、`dist/`、`test-results/`、`.superpowers/`、忽略的 `.DS_Store` 与快照。
- **验证证据**：目标路径不存在；`git status` 不产生受控差异。

### WP-02 工程正确性和入口

- **业务目标**：修复已证实 Bug，并让开发者拥有明确可执行的检查命令。
- **位置**：数量解析函数、UI 骨架卡片导出、TypeScript 配置、`package.json`、新增专项测试。
- **验证证据**：数量解析测试；渐进类型检查；默认测试；生产构建。

### WP-03 文档权威源收口

- **业务目标**：现行检查不再依赖已禁用历史目录，文档能区分现行与历史证据。
- **位置**：`docs/INDEX.md`、现行需求/计划、两个检查脚本、`docs/superpowers/`。
- **验证证据**：全仓无现行代码读取 `docs/superpowers/`；相关检查脚本通过；目录删除。

### WP-04 仓库文件清理

- **业务目标**：从源码仓移除运行状态、历史输出和确认无调用的旧工具。
- **位置**：`data/state_store.db/`、`outputs/`、`.trae/` 的禁用内容、候选孤立脚本和旧 HTML。
- **验证证据**：逐项引用核查；package 脚本路径完整性检查；构建通过。

### WP-05 最终验证

- **业务目标**：证明清理未破坏现行工程入口。
- **验证证据**：专项测试、相关脚本、构建、治理检查、CodeGraph 同步/状态、完整 diff 审查。

## 5. 风险与恢复

- 删除受控文件均可从 Git 历史恢复；本地生成物只能重新生成。
- 删除旧脚本前必须确认没有 package、脚本、测试和文档引用；“文件名未引用”只作为候选证据。
- 历史文档若仍承载现行规则，先迁移规则再删除原文件。
- 若默认全量 Playwright 测试成本过高，默认 `test` 应指向稳定的治理与专项单元测试，浏览器全量测试保留独立命令。
