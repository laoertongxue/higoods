# 盘扣及新增辅助工艺实施计划

## 1. 目标与完成标准

在不改变既有原型技术栈和运营菜单命名的前提下，把盘扣、花朵、打褶、烫钻接入字典、技术包、任务、工厂、厂内仓、Web、PDA、打印和中央辅料仓。完成以追踪矩阵全部原子需求具有当前代码位置、专项契约和适用的真实页面／打印证据为准。

## 2. 依赖顺序

`字典与工厂事实 → 技术包对象与快照 → 加工单生成与数量状态 → 仓储投影 → Web/PDA → 菲票打印 → 中央辅料仓 → 双遍验收`

## 3. 工作包

### WP-01 字典、工艺定义与工厂事实

- 业务目标：建立四个独立辅助工艺、三类专属工厂和稳定的工厂分配规则。
- 文件／符号：`process-craft-dict.ts`、`special-craft-operations.ts`、`special-craft-dedicated-factories.ts`、`factory-master-store.ts`、`store-domain-pda.ts`。
- 修改：增加工艺编码、加工对象、双口径元数据、FLOWER/APF/SPF 工厂档案和旧 ID 迁移；菜单领域名称与工厂名称分离。
- 验证证据：`check:button-loop-auxiliary-crafts`、工艺分类和菜单专项检查。
- 完成条件：四工艺可查、盘扣对象仅捆条、其他三项仅裁片、分配规则和运营菜单命名同时正确。

### WP-02 技术包多捆条与逐条盘扣选择

- 业务目标：纸样包可同时维护普通捆条和盘扣捆条。
- 文件／符号：`pcs-technical-data-version-types.ts`、`tech-packs.ts`、`tech-pack/context.ts`、`pattern-domain.ts`、`events.ts`。
- 修改：为每条捆条保留 `specialCrafts`；增加添加、删除、编辑和盘扣切换；路线未确认时阻断；纸样池演示层继承真实捆条而不丢失。
- 验证证据：技术包对象／版本专项契约、纸样详情专项契约、浏览器纸样池截图。
- 完成条件：同一纸样包可见两条捆条，且仅前襟盘扣捆条显示“盘扣 · 黄色菲票”。

### WP-03 版本、评审差异与生产快照

- 业务目标：盘扣选择在技术包克隆、差异比较和生产冻结后仍可追溯。
- 文件／符号：`pcs-technical-data-version-repository.ts`、`pcs-tech-pack-review-diff.ts`、`production-tech-pack-snapshot-types.ts`、`production-tech-pack-snapshot-builder.ts`。
- 修改：深拷贝捆条工艺数组，纳入版本差异和快照字段。
- 验证证据：技术包目标对象／版本专项检查和按钮盘扣综合契约。
- 完成条件：运行加工单只读取生产快照中的逐条选择，不读取可变当前页面状态。

### WP-04 盘扣加工单领域模型

- 业务目标：一生产单一盘扣单、多张捆条菲票明细、张／米／个三种口径不混用。
- 文件／符号：`button-loop-craft-flow.ts`、`special-craft-task-orders.ts`。
- 修改：新增聚合生成、投入明细、事件和四动作门禁；排除通用盘扣重复任务。
- 验证证据：`check:button-loop-auxiliary-crafts` 正常、重复扫描、非整数、未交完阻断场景。
- 完成条件：单据唯一、仅选中捆条入单、产出按个累计且无需衣服用量公式。

### WP-05 统一动作写回和重复投影防护

- 业务目标：Web/PDA 共用同一盘扣动作结果，且仓储只生成一套事实。
- 文件／符号：`process-action-writeback-service.ts`、`process-warehouse-linkage-service.ts`、`runtime-process-tasks.ts`。
- 修改：双口径任务走盘扣动作分支；通用裁片仓储投影遇到捆条盘扣时退出；分次交出时保留待交出仓剩余数量，全部交出后再归零并完成状态。
- 验证证据：综合契约、真实 Web 确认接收和 PDA 全流程。
- 完成条件：同一动作不重复入仓、数量与状态跨端一致。

### WP-06 专属厂内仓与工艺库区

- 业务目标：FLOWER/APF/SPF 默认有待加工和待交出仓，每个工艺落入自己的工艺-对象库区。
- 文件／符号：`factory-internal-warehouse-locations.ts`、`special-craft-task-orders.ts`。
- 修改：建立默认库区／货架／库位；仓储位置优先按工艺和对象精确匹配；盘扣入库张、出库个；FLOWER 同时保留烫画／直喷的成衣和裁片四组对象库区。
- 验证证据：厂内仓模型检查、综合契约中的 `盘扣-捆条库区` 精确断言。
- 完成条件：盘扣不落通用 A/B 区或其他工艺库区，其他新增工艺均有独立默认区域。

### WP-07 工艺菜单和 Web 加工单

- 业务目标：四个工艺各有独立菜单和加工单页面，运营菜单名保持不变。
- 文件／符号：`app-shell-config.ts` 的动态工艺菜单来源、`task-orders.ts`、`task-detail.ts`、`shared.ts`。
- 修改：通过工艺定义自动生成独立入口；盘扣列表和详情展示双口径；四动作使用盘扣专用弹窗。
- 验证证据：菜单专项检查、综合契约、浏览器 Web 加工单截图。
- 完成条件：盘扣、花朵、打褶、烫钻独立入口存在，Web 能逐张接收并显示后续动作。

### WP-08 PDA 交接与执行

- 业务目标：一线按页面职责完成盘扣，避免张和个混淆。
- 文件／符号：`special-craft-pda-scope.ts`、`pda-exec-detail.ts`、PDA 工厂用户数据。
- 修改：识别四工艺和捆条对象；交接只显示接收／交出，执行只显示填报／完成；盘扣产出输入只接受正整数；隐藏不适用于盘扣的通用逐菲票完工统计。
- 验证证据：真实 APF PDA 会话从接收到完成的浏览器用例和截图。
- 完成条件：四动作全部完成且任何页面不出现职责外动作或单位错误。

### WP-09 捆条菲票和黄白分纸打印

- 业务目标：盘扣捆条黄票明显可识别，普通捆条白票不受影响。
- 文件／符号：`binding-strip-orders.ts`、`fei-tickets.ts`、`label-print-template.ts`。
- 修改：捆条明细携带盘扣标记；列表按纸色分批；混色拒绝；两者固定 100mm × 100mm；黄票接入现有黄色菲票模板注册；白票和黄票都保留标题、SPU、生产单、裁片单和既有切割追溯字段。
- 验证证据：综合契约、浏览器真实打印预览、物理像素范围检查和截图。
- 完成条件：黄票显示盘扣/APF/中央辅料仓，白票保持普通捆条，混色无法生成任务。

### WP-10 中央辅料仓收货

- 业务目标：盘扣交出后由中央辅料仓按个接收。
- 文件／符号：`button-loop-accessory-receipts.ts`、`wls-accessory-receipts.ts`。
- 修改：从已交出盘扣任务生成待收货行；同一加工单累计已收数量，后续分批交出只增加新增待收数量；确认收货后保留收货人、时间、数量、单位和去向。
- 验证证据：综合契约和 PDA→WLS 同一 SPA 状态的真实浏览器验收，覆盖 10 个与 14 个两次交出、两次收货。
- 完成条件：24 个盘扣先收 10 个，再显示已收 10／待收 14，最终累计已收 24 个，不出现米或张且不覆盖前次收货。

### WP-11 历史兼容与旧事实清理

- 业务目标：旧工厂 ID、旧目标对象检查和伪工艺禁用规则不阻塞新业务。
- 文件／符号：工厂/PDA 迁移、`special-craft-banlist.ts` 及相关专项脚本。
- 修改：过滤旧档案；允许捆条作为盘扣对象；旧捆条明细缺少 `specialCrafts` 时按空数组兼容；保留合法“印花工艺／染色工艺”业务文案，不将其误作已删除伪工艺全局禁词。
- 验证证据：工厂、字典、技术包、仓储回归检查。
- 完成条件：旧档案不再生成，新工艺不被旧检查误杀，既有烫画／直喷／特种工艺归属不变。

### WP-12 双遍验收、治理与收据

- 业务目标：正向逐需求验收一次，反向从代码、路由、Mock、打印和测试查漏一次。
- 文件／符号：综合检查脚本、Playwright 用例、总体设计、矩阵、完整原型审查记录。
- 修改：建立直接契约、真实页面证据和追踪闭环；修正验收中发现的纸样池丢捆条、打印模板未注册、PDA 错误通用进度、FLOWER 对象库区缺项、分次交出剩余量被清零、分批收货覆盖前次已收数量、旧捆条明细缺字段报错、单张捆条菲票丢标题／SPU 八项缺口。
- 验证证据：追踪矩阵中的两遍结果、治理检查、CodeGraph 状态和任务收据。
- 完成条件：矩阵无无说明的待实施／阻塞项，最后一次实质修改后所有受影响检查重新执行。

## 4. 风险与控制

- 双单位混用：以盘扣专用领域模型和 UI 文案隔离张、米、个。
- 重复任务／库存：任务生成排除通用盘扣，仓储通用分支对捆条盘扣短路。
- 演示层覆盖真实数据：纸样池 demo 包必须继承来源捆条。
- 打印装错纸：黄白入口分开，混色任务直接阻断，预览再次提示纸色。
- 页面重载丢原型内存：验收跨模块流转使用同一 SPA 导航；领域契约另行验证持久记录口径。
