## 1. 完成标准与顺序

把用户确认后的领取、Web 执行、1:1 单据链、两仓和出货打印规则落入现有原型，同时保持线上仓库/出货页结构。只有矩阵全部适用项“已验证”、两轮 3×5×5 UI-only 验收一致、构建/治理/CodeGraph/任务收据通过，才算实现完成。

依赖顺序：`共享事实与编号 → 质检 → 后道 → 复检/出货 → 两仓/追溯 → PDA → 打印 → 两轮证据 → 双向核查`。

## 2. 工作包

### WP-1：共享事实、编号、授权与日志

- 业务目标：一次回货形成唯一 1:1 下游链，锁定两段差异规则。
- 文件/符号：`post-finishing-full-flow.ts`、`post-finishing-document-numbering.ts`、授权和操作日志事实源。
- 修改：确认回货自动建质检单；质检号按生产单最大序号递增且幂等；全部下游唯一生成；补充领取/退领、草稿清空、全链守恒和授权消费日志。
- 验证：核心 3×5×5、编号、差异/授权和追踪专项。
- 完成：15条链各只有一张质检/后道/复检/出货，5%与零容差断言通过。

### WP-2：质检列表、领取与执行

- 业务目标：完整单号领取、一单一质检员、本人退领、Web 完成并强制进入后道。
- 文件/符号：`qc-orders.ts`、`qc-workbench.ts`、`events.ts`、`shared.ts`。
- 修改：顶部领取弹窗；“质检台”改“质检员”；所有者门禁；退领清空；加工项目必选；买手/QC资料冻结。
- 验证：领取冲突、退领重领、结果录入、资料和通用打印 Playwright。
- 完成：非领取人阻断，退领无残留，完成只生成一张后道加工单。

### WP-3：后道加工单 Web 执行

- 业务目标：Web 为正式执行入口，并与 PDA 共享同一任务。
- 文件/符号：`work-orders.ts`、`work-order-detail.ts`、Web/PDA后道处理。
- 修改：顶部完整单号“开始后道”及识别详情；统一执行标题/返回；移除优先级横幅；Web逐SKU完成/瑕疵/返厂/授权；PDA中断可由Web接管。
- 验证：详情动作、Web-PDA草稿一致、浏览器接管场景。
- 完成：Web正常完成和接管均生成同一唯一复检单。

### WP-4：复检、错码和出货

- 业务目标：Web完整复检，错码阻断，唯一生成出货单。
- 文件/符号：`recheck-orders.ts`、`outbound-orders.ts`、共享事实源。
- 修改：精确领取/退领；合格/瑕疵/条码；错码→重贴→复扫；差异授权；出货列表/详情对齐线上；移除逐SKU出货接收区。
- 验证：复检Playwright、错码恢复、幂等、出货字段检查。
- 完成：一复检一出货，错码未恢复绝不出货。

### WP-5：总任务、两仓、日志与授权码

- 业务目标：总任务聚合多次回货/质检，两仓沿用线上布局承接库存和单据链。
- 文件/符号：`tasks.ts`、`warehouse.ts`、`audit-records.ts`、`statistics.ts`、`authorization-code.ts`。
- 修改：总任务关联弹窗；待加工仓 Web 回货确认/送检；待交出仓入仓/交出/收货回查；日志主从结构；独立动态码；全部页面通用质检打印。
- 验证：管理列表对齐、命名截图、库存/流水回查。
- 完成：总任务显示5次回货和5张质检单，两仓数量一致，任一单号可回溯。

### WP-6：PDA

- 业务目标：现场入口与Web同事实、少输入、强防错。
- 文件/符号：`pda-post-finishing-flow.ts`、公共回货和PDA仓库页/处理器。
- 修改：0数量阻断；完整码；超5%复点授权；逐SKU后道；收货差异授权；清理直达复检旧文案。
- 验证：360×800、412×915视口和全链Playwright。
- 完成：关键动作无溢出，PDA写入可在Web回查。

### WP-7：八类打印

- 业务目标：任意后道管理页精确打印质检单/详情，出货可整单、批量条码和吊牌。
- 文件/符号：`full-flow-print.ts`、在线质检模板、共享打印入口。
- 修改：无上下文完整号弹窗；出货整单线上字段；按SKU数量展开条码/吊牌；错码SKU贴标。
- 验证：具体单号、A4、40×30、批量数量、图片失败态。
- 完成：所有打印读取目标链，标签张数等于出货量。

### WP-8：Mock与两轮UI证据

- 业务目标：用页面操作证明15条独立链走通。
- 文件/符号：验收Mock、专项脚本、`post-finishing-full-flow*.spec.ts`。
- 修改：固定3×5×5和15类场景；禁止测试直接写领域状态；输出JSON、逐链截图、关键页面截图和trace。
- 验证：`2026-09-03-auto-qc-final-pass-1`、`pass-2`、最终命名UI目录。
- 完成：两轮链路结构、最终状态和数量一致。

### WP-9：双向核查与项目门禁

- 业务目标：无遗漏、无旧旁路、无越界能力。
- 文件/符号：设计、计划、矩阵、源代码、路由、Mock、测试、审查记录。
- 修改：第一遍从需求到实现/证据；第二遍从代码/页面/测试回到需求；清理旧文案和冲突入口；生成收据。
- 验证：表面/追踪、构建、列表/原型治理、CodeGraph sync/status、任务收据。
- 完成：矩阵无无说明的待实施、实施中、已阻塞或已实现待验证。

## 3. 旧逻辑处理与风险

从命名页面删除或阻断“质检直达复检”“无需后道”“PDA优先”“Web应急”“复检Web只读”“逐SKU出货与接收”。历史模型若仍服务非本次页面，不以隐藏菜单冒充删除；反向检查保证本流程不可触达旧旁路。旧文档保留但标注由2026-09-03方案取代。

原型使用浏览器状态；自动化 PDA 不是实体设备。真实扫码速度、扫码枪换行、打印纸张偏移、线上权限和库存须现场复验，不能纳入本地“已验证”。
