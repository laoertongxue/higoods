# 后道生产任务、后道加工单与关联记录实施计划

## 1. 目标与完成标准

本轮把后道业务对象收口为两层，并在现有后道管理页面基础上补齐关联查询，不重做线上仓库页面结构：

- `后道生产任务`：以生产单为粒度的全流程总任务，承接登记、回货、质检、后道加工、复检、出货的汇总关系。
- `后道加工单`：某次回货对应的质检完成后，确认需要执行实际工序时生成的执行单。
- 一个后道生产任务允许多次回货；一次回货最多生成一张质检单。
- 质检单号只能由系统按 `生产单号-序号` 生成，序号取该生产单已有质检单最大序号加一，不允许人工指定或修改。
- 后道生产任务列表可直接查看该任务全部回货记录和全部质检单；弹窗是列表页局部交互，不整页重绘。
- Web、PDA、打印、生产单详情、仓库、复检、出货和追溯页面使用同一对象名称和关联事实。

完成必须同时具备：实现位置、专项契约、命名页面 UI 证据、3 个生产单 × 每单 5 个 SKU × 每单 5 次回货的数据证据，以及两遍正向／反向追踪结果。

## 2. 事实依据

- 用户确认：后道生产任务是生产单级总任务；后道加工单是一次质检后需要实际执行的加工单。
- 用户确认：同一生产单可多次送货，每次确认回货后形成一张唯一质检单。
- 用户确认：质检单号严格使用 `生产单号-序号`，按最大序号递增且不可人工修改。
- 当前原型事实：默认 Mock 为 3 个生产单、每单 5 个 SKU、每单 5 次回货；最终确认的回货均已有质检单，未送检的质检单显示“待送检”，尚未最终确认的回货才没有质检单。
- 当前页面基线：后道待加工仓、后道待交出仓继续保持现有统计卡、Tab、筛选、表格／卡片和操作布局；本轮仅补对象名称、关系入口和链路内容。

## 3. 范围与非范围

### 3.1 范围

- 后道工厂管理菜单、路由跳转提示、页面标题、统计名称、字段、按钮、空状态。
- 后道生产任务列表的回货记录弹窗和质检单弹窗。
- 质检单统一编号服务、回货最终确认自动建单入口、待加工仓送检激活入口、已有单据最大序号恢复与幂等。
- Web 质检、后道加工、复检、出货、追溯、生产单详情、PDA 执行、打印标题与字段。
- Mock、专项脚本、Playwright 命名页面证据和治理文档。

### 3.2 非范围

- 不实现真实后端、数据库锁、分布式编号服务或生产环境迁移。
- 不改变用户已确认的回货 5% 授权规则、后续任意差异授权规则、质检领取／退领、复检和出货状态机。
- 不重构后道待加工仓和后道待交出仓的线上基线布局。
- 不把本地 Mock／浏览器验证表述为线上数据、真实 PDA、扫码枪或实体打印机验收。

## 4. 工作包

### WP-1：对象命名与导航收口

- 业务目标：所有相关入口清楚区分生产单级总任务和质检后的实际加工单。
- 实现位置：`src/data/app-shell-config.ts`、`src/router/routes-fcs.ts`、后道 Web 页面、生产单详情、PDA 页面、打印模板和相关领域展示。
- 修改：菜单和聚合页统一为“后道生产任务”；实际执行对象统一为“后道加工单”；内部兼容标识如 `POST_FINISHING_WORK_ORDER` 保持不变。
- 验证：源码旧用户可见词审计；Web、PDA、打印命名页面；相关专项脚本。
- 完成条件：`src` 中不存在用户可见的孤立“后道任务”或“后道单”，且上下游页面不混用两个对象。

### WP-2：后道生产任务关联记录弹窗

- 业务目标：管理人员从一条生产任务即可看到该生产单的所有回货和所有质检单。
- 实现位置：`src/pages/process-factory/post-finishing/tasks.ts`。
- 修改：操作列增加带数量的“回货记录（N）”“质检单（N）”；弹窗分别展示回货批次、送货单、工厂、登记／确认／差异、状态、确认时间，以及质检单号、关联送货单、质检数量、质检人、状态、生成时间和查看／打印入口。
- 验证：默认 Mock 第一条任务打开两个弹窗；回货 5 行、质检 4 行（另 1 次回货尚未最终确认）；关闭后仍停留在原列表；1366×768 无页面级横向溢出。
- 完成条件：数据只按当前后道生产任务筛选，不混入其他生产单；弹窗打开／关闭不触发列表整页重绘。

### WP-3：质检单严格编号

- 业务目标：每个生产单的质检单独立连续编号，不依赖回货批次号，不允许调用方越过系统指定序号。
- 实现位置：`src/data/fcs/post-finishing-document-numbering.ts`、`src/data/fcs/post-finishing-full-flow.ts`。
- 修改：仅识别完整的 `<生产单号>-<正整数>`；下一个序号取编号账和已持久化质检单中的最大值加一；调用方传入的 `sequence` 对 QC 无效；同一幂等键重复请求返回同一编号。
- 验证：常规 1～5、非连续已有 1／4 后生成 5、编号账丢失后仍从已有质检单恢复、重复确认或重复送检都不产生第二张质检单；确认后送检前不可领取，送检后沿用原号进入待质检。
- 完成条件：3 个生产单各自生成 `-1` 至 `-5`，不存在跨生产单串号、复用、人工改号或把第 5 次回货直接当作 `-5` 的错误。

### WP-4：跨端链式关系与打印

- 业务目标：登记 → 回货 → 质检 → 可选后道加工 → 复检 → 出货始终保留生产任务和本次回货身份。
- 实现位置：后道待加工仓、质检单、后道加工单、复检单、待交出仓、后道出货单、差异日志、生产单详情、PDA 执行页及打印模板。
- 修改：展示上游生产单／后道生产任务、当前送货单／质检单、可选后道加工单、复检单和出货单；加工单打印路由使用独立打印壳。
- 验证：Web 列表与详情、PDA 精确扫描、打印预览、旧打印兼容路由。
- 完成条件：任一后道加工单、复检单或出货单均可回溯到生产单和对应回货；打印预览不显示管理端顶部及侧栏。

### WP-5：验证、双向追踪与治理

- 业务目标：证明需求没有漏项，也没有把旧概念或越界能力带回页面。
- 实现位置：专项检查、Playwright 用例、需求追踪矩阵和原型审查记录。
- 修改：更新旧术语断言；补回货／质检弹窗、严格编号、PDA、独立打印壳和 3×5×5 契约。
- 验证：专项脚本、命名页面、构建、列表治理、原型治理、CodeGraph 状态。
- 完成条件：正向和反向追踪各执行两遍；全部适用条目有一组当前版本证据，无无说明的待实施项。

## 5. 依赖顺序

1. 先固定对象定义与编号规则。
2. 再把关联记录投影到后道生产任务列表。
3. 再收口 Web、PDA、打印和上下游文案。
4. 最后执行 3×5×5 数据验证、命名页面 UI 验收和双向追踪。

## 6. 风险与恢复

- 编号账被清空：从已有质检单号重新计算最大序号，避免从 1 重启。
- 历史非法编号：不参与严格序号计算，不覆盖合法单号；原型不承担生产数据清洗。
- 两个点击处理器同时响应：关联弹窗按钮和弹窗容器标记为局部交互，阻止页面级处理器立即重绘移除弹窗。
- 打印壳残留：后道专用打印路由纳入独立打印路径判断，保留旧统一打印路由兼容。
- 默认数据并非每次回货都已最终确认：回货数量和质检单数量分别展示；最终确认的 4 次回货已有质检单，其中待送检记录尚不可领取，另 1 次未确认回货尚无质检单。

## 7. 实际执行与验证结果

### 7.1 实施结果

- WP-1～WP-5 均已实施；用户可见对象统一为“后道生产任务”“质检单”“后道加工单”。
- 后道生产任务首行默认 Mock 展示 5 次回货和 4 张已生成质检单，两个操作入口均以局部弹窗打开并可关闭回到原列表；其中 1 张处于“待送检”，另 1 次回货尚未最终确认。
- 质检单编号由统一服务生成；调用方传入的序号对质检单无效，合法已有单号最大序号与编号账共同决定下一号。
- 回货最终确认与质检单创建是同一业务动作；待加工仓“确认送检出库”只完成库存交接，并把同一质检单从“待送检”激活为“待质检”。
- 两仓保留线上统计卡、Tab、筛选、库存列表和流水布局，只增加一单到底的生产任务、回货、质检、加工、复检与出货关系。
