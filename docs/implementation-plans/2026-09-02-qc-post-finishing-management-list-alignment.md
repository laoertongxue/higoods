# QC 后道管理列表线上基线对齐实施计划

> 历史计划：领取、Web执行、强制后道链和出货打印以 `2026-09-03-QC后道领取Web执行与出货打印实施计划.md` 为准。

> 日期：2026-09-02  
> 需求来源：`docs/product-design/2026-09-02-QC后道管理列表线上基线对齐方案.md`

## 1. 目标与完成标准

在保留线上列表骨架与既有数量口径的前提下，把后道生产任务、质检单、后道加工单、复检单对齐用户提供的线上页面，并补齐查看、打印和 SKU 重量操作；同时明确回货最终确认自动建质检单、待加工仓仅执行送检出库。完成必须同时具备代码、专项契约、命名浏览器、治理、构建和 CodeGraph 证据。

## 2. 范围与依赖

- 共享事实依赖：`src/data/fcs/post-finishing-full-flow.ts`。
- 列表公共能力依赖：`src/components/ui/standard-list-page.ts` 等既有标准列表组件。
- 路由继续使用现有 `/fcs/craft/post-finishing/*`；“查看任务”复用现有 `/fcs/dispatch/workbench` 并携带任务号查询，不新增状态入口。
- PDA 后道和复检逻辑保持当前实现，不在本计划重复改造。

## 3. 工作包

### WP-1 后道生产任务线上基线

- 业务目标：恢复线上统计、筛选、字段和操作，不丢失 SKU 重量及质检查看/打印。
- 文件 / 符号：`src/pages/process-factory/post-finishing/tasks.ts`、`src/pages/unified-dispatch-workbench.ts`、`renderPostFinishingTasksPage`、`renderUnifiedDispatchWorkbenchPage`、`handlePostFinishingTasksEvent`。
- 修改：标准列表、五张统计卡、六类筛选、线上字段、重量弹窗和本地保存；删除“生成质检单”列表操作；“查看来源任务”携带当前后道生产任务号进入任务分配工作台并加载对应来源任务；压缩 SPU、任务、数量和操作列。
- 验证证据：专项脚本、浏览器确认任务号精确定位及无“生成质检单”、保存重量后 `0/5 → 1/5`、1366×768 首屏至少 5 个数据列和固定操作列。
- 完成条件：TASK-001～TASK-007 均达到已验证。

### WP-2 质检单命名与列表

- 业务目标：用户可见名称统一为质检单，恢复线上筛选、字段和打印，同时保留精确领取流程。
- 文件 / 符号：`qc-orders.ts`、`qc-workbench.ts`、`app-shell-config.ts`、相关仓库/审计/PDA文案。
- 修改：标准列表、领取区、统计、全字段、查看与两类打印、主管释放；删除用户可见“质检任务”旧名；压缩单号、工厂、质检台、SKU、数量和操作列。
- 验证证据：专项脚本、质检单和质检详情单浏览器快照、1366×768 首屏至少 5 个数据列和固定操作列。
- 完成条件：QC-001～QC-006 均达到已验证。

### WP-3 后道加工单线上基线

- 业务目标：恢复线上筛选、字段、详情和任务流转卡，并明确 PDA 优先 / Web 兜底。
- 文件 / 符号：`work-orders.ts`、既有 `work-order-detail.ts`、`full-flow-print.ts`。
- 修改：标准列表、状态统计、线上字段、详情/PDA/打印/追溯动作；打印名称收口为后道加工单流转卡；压缩单据、工厂、SKU、项目、时间和操作列。
- 验证证据：专项脚本、后道加工单与流转卡浏览器快照、1366×768 首屏至少 5 个数据列和固定操作列。
- 完成条件：POST-001～POST-005 均达到已验证。

### WP-4 复检单线上基线

- 业务目标：恢复线上筛选、字段和详情，不替代 PDA 现场复检。
- 文件 / 符号：`recheck-orders.ts`、`renderPostFinishingRecheckOrdersPage`。
- 修改：标准列表、统计、线上字段、详情动作；保留主管释放和 PDA 入口；压缩关联单号、款式、SKU、时间和操作列。
- 验证证据：专项脚本、复检列表及具体单据详情浏览器快照、1366×768 首屏至少 6 个数据列和固定操作列。
- 完成条件：RECHECK-001～RECHECK-004 均达到已验证。

### WP-5 打印、契约与治理

- 业务目标：补齐三类打印并证明流程未变、页面符合标准列表和原型治理。
- 文件 / 符号：`full-flow-print.ts`、`src/pages/print/templates/post-finishing-qc-print-template.ts`、`src/data/fcs/post-finishing-full-flow.ts`、`src/components/ui/list-page.ts`、`scripts/check-post-finishing-management-list-alignment.ts`、`package.json`、相关既有检查。
- 修改：让 `QC_ORDER`、`QC_DETAIL` 采用线上主质检单 / 质检详情单版式和真实对象图片，并由后道生产任务与质检单列表共用；收口 `POST_ORDER` 标题；标准列表在无二级标题和列表动作时收起重复标题栏；增加四页字段、动作、跳转、打印和密度静态契约；同步旧测试文案。
- 验证证据：专项检查、相关既有检查、构建、浏览器、CodeGraph、治理和任务收据。
- 完成条件：PRINT-001～PRINT-002、GOV-001～GOV-002 均达到约定状态。

## 4. 依赖顺序

1. 先锁定线上页面字段及当前领域流转。
2. 再按同一事实源实现四张列表。
3. 补齐打印与用户可见命名。
4. 建立专项契约和需求追踪矩阵。
5. 在最后一次实质修改后重新运行专项检查、浏览器验收、治理、构建、CodeGraph 同步和任务收据。

## 5. 风险与控制

- 风险：保留“生成质检单”会与回货最终确认自动建单重复。控制：从后道生产任务操作列删除该入口；专项同时锁定“确认建待送检单、送检只激活同一单”。
- 风险：“查看来源任务”只打开通用工作台而没有定位当前任务。控制：携带后道生产任务号和来源参数，并在工作台按该任务号加载唯一目标任务。
- 风险：标准宽表造成页面整体横向溢出。控制：复用标准列表的内部滚动容器并以 1366×768 验收。
- 风险：压缩列宽后长单号或动作被遮挡。控制：长编号允许单元格内断行，操作使用双列网格和不换行动作文字，并逐页核对可见性与最大行数。
- 风险：列表数据与当前 Mock 状态不一致。控制：所有聚合从共享事实源实时计算。
- 风险：打印入口虽然可打开，但版式与线上不同或两个列表入口产生两套内容。控制：两类入口共用同一在线版式渲染器，并用具体质检单/后道加工单 ID 打开三类命名打印路由。
- 风险：旧“质检任务”文案残留。控制：相关受管页面全文检查并增加菜单静态断言。
