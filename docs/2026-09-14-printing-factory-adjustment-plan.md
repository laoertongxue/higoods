## 3. 范围、角色与业务对象

### 3.1 范围

本次调整印花厂管理内的待接收、加工单及详情、待加工仓、待交出仓、待交出列表、交出单据、统计、大屏，及直接关联的扫码、图片、打印、导出和原型状态保存。

继续使用 Vite、TypeScript、Tailwind 和现有字符串模板，不建设真实后端、权限系统、数据库、离线队列、复杂工艺引擎或新框架。只扩展印花所需的既有共享能力，不重做染色、水溶、毛织或裁床业务。

本模块处理 BOM 中需要印花的物料；不把裁片、菲票、成衣件数引入本次物料加工流程。线上筛选存在纱线、辅料等物料类型，但是否适用某种印花工艺必须依据实际任务和工艺能力，不能据筛选选项推断所有组合有效。

### 3.2 角色与动作

| 角色 | 主要工作 | 责任边界 |
|---|---|---|
| 管理/计划/跟单 | 查需求、分配工厂、维护交期、查看进度与超期、导出 | 工厂视图切换不改变当前操作身份 |
| 印花厂收货/仓管 | 扫来源单、登记实收、入库位、备料、出库扫卷 | 对本厂收到和实际交出的物料负责 |
| 印花主管/操作员 | 核对花型和版本、开始实际工序、分批报工、登记实际产出卷 | 收到物料不代表已开工，打印标签不代表加工完成 |
| 运输交接人员 | 接收已核对的物料，形成实际交出事实 | 司机等待与实际交接分开；具体身份字段需按既有运输入口核对 |
| 下游仓库/加工厂收货人 | 对实际收到的每卷/每批确认入仓 | 本厂不能以“交出”动作代替下游实收 |

### 3.3 加工单粒度与来源

建议一个印花加工单对应：一条物料加工任务、一个投入物料 SKU、一个确定的输出要求/花型版本、一个加工厂、一个上游供料组织。同一生产单需要多个物料或不同输出 SKU 时，形成多个加工单。

- “一个上游组织”允许该组织多次调拨/交出、分批到货；列表组织信息只展示一次，下面展示来源单据及批次数。
- 一个送货单可以装载多个来源单据/多个加工单的物料，收货仍逐来源明细登记，不能按一个总数任意分摊。
- 如已存在多个真实上游，应先核对并拆分对应任务或明确业务例外，不能只截取第一条来源隐藏历史。
- 备货收货允许没有生产单、没有加工单；后续关联既有库存，不再生成第二次入库。
- 改投入保留原计划和实际替换记录；不能将多个无关联物料长期塞进同一单。

三类信息必须分开：

| 信息 | 回答的问题 | 表达 |
|---|---|---|
| 需求来源 | 为什么要做、业务需求来自哪里 | 生产需求/生产单、备货、相关采购需求、补料需求及真实编号 |
| 创建方式 | 这张加工单通过哪个业务动作生成 | 线上已有生产单创建、备货创建、深圳改款、万隆改款；仅采用实际有依据的值 |
| 是否补料 | 是否承担补充物料需求 | 独立标识；同时保留原需求、生产单和本次补料编号 |

例如“生产需求 + 生产单创建 + 补料”可以同时成立，不能强制三者互斥。线上接收人、下游组织、目标仓库、成衣生产工厂与印花加工厂也分别保存和展示，不能用一个名称代替所有角色。

## 5. 印花加工单列表的具体布局

### 5.1 顶部工厂、筛选和摘要

增加工厂页签：全部加工厂、常用印花厂、其他工厂、待分配。工厂名称/编号来自主数据；线上 FLOWER、ANJANI、BAGUS、Clint 等作为对照，不照搬染厂 GTG/MJS。页签数字采用同一范围的加工单去重数，不能取交出单数。

基础筛选：综合查询、接收状态、加工状态、交出状态、加工厂。

更多筛选按业务排列：需求来源、创建方式、是否补料、售卖类型、物料类型、印花工艺、单双面、当前生产环节、花型资料是否齐备、打印机/设备、上游组织、下游组织/目标仓库、接收人、投入是否调整、存在未处理差异、超期、时间类型和区间。使用当前资料中已确认的字典，不生成空选项。

综合查询覆盖加工单、任务单、需求单、生产单、备货/采购/补料编号、商品 SPU、投入和产出物料 SPU/SKU、正反面花型编号、卷码、来源单和交出单。每个查询命中显示真实对应字段。

全部筛选条件下方单独放操作行：查询、重置、导出、更多筛选/收起更多。按用户最新反馈，仅保留线上已有普通导出，取消此前额外建议的两项专项导出。批量打印印花确认单保留，按所选加工单打印。

摘要保持六项：加工单数、计划投入、本厂已接收、实际使用、合格完成数量、下游待接收。数量按单位分组，缺失历史另示“X 单接收记录不完整”，不能用不完整总和冒充可比较全量。

## 6. 新增待接收与接收入仓

### 6.1 来源与页面

复用当前染厂已确认的工厂接收流程：仓库审核通过的调拨/出库来源、上游工厂已实际交出的来源，生成对应接收工厂的待接收事项。来源上游加工单只是关联信息，实际应收由具体单据和明细决定。仓库已批准但尚无实际出库时分别展示状态与数量，不能伪造发出时间。

页面提供工厂页签、操作身份、默认收货库位、扫码接收、送货单查询、来源单查询、备料关联。筛选含关键词、来源类型、物料类型、登记状态、关联状态、上游、时间；操作行在全部条件之后。

列表列：待接收单/来源、物料及真实图、关联需求/加工单、应收与实收、登记状态、收货仓/库位、操作。待接收事项必须能定位到本厂、来源单、来源明细和一次交接，不按物料 SKU 全局混在一起。

### 6.2 收货步骤与防错

1. 扫描来源单或送货单，展示发货方、接收厂、来源单据、物料图/编码和本次应收。
2. 按来源明细核对物料，逐卷扫码或按该物料的包装和业务单位登记实收。
3. 选择实际收货仓与库位，显示每条“少/多多少”和本次合计。
4. 确认接收并入仓，回显已保存记录、库位与下一动作。

面料：卷码、每卷实际长度、卷数、适用重量。纱线：按既有纱线登记能力记录件/筒及毛净重等适用信息；辅料、包装等按各自业务单位。不能对所有物料强制“正整数卷数”。染厂特定运输重量上限是否适用于印花，另行确认。

正常多批、短收、超收、显式零收均需如实记录：空白不等于 0；零收不生成正库存；短/超收不自动结束来源、不自动换到异常库位。后续可继续登记实际到货，保留每次差异。当前印花以来源剩余量作为收货硬上限的规则需与上述事实登记分开处理。

禁止错厂、错物料、非有效来源、同一交接重复入仓、提交中重复点击；保存失败应说明未成功并允许安全重试。卷码防重按本次交接及当前位置判断，不能永久禁止同一卷之后再次合法流转。

### 6.3 与加工单和库存的关系

- 实收增加本厂对应仓位库存，不再次扣减上游已经出库的库存。
- 接收记录可关联指定印花加工单；多单共用来源时必须人工明确各明细归属，分配合计等于实际物料数量。
- 无加工单的备货先入库，后续关联只分配已有库存；不得重复计入本厂累计实收。
- 加工单展示“已收齐/部分接收”等收货进度，同时单列“计划投入还缺多少”，两者不互相替代。
- 接收后加工仍可为“未开始”；只有实际工序开工才记开工时间。

## 7. 印花生产过程与状态

### 7.1 三段总状态与印花细分环节

| 维度 | 建议含义 |
|---|---|
| 接收 | 待来源、待接收、部分接收、已收齐；超收附独立差异提示；历史不完整明确显示 |
| 加工 | 待分配、未开始、加工中、加工完成、已取消；其下显示当前适用工序 |
| 交出 | 未到交出、待建单/待交出、部分交出、全部交出；下游接收进度另外表达 |

线上现有“等待花型、测试花型样品、等花型米样、等打印、等转印”等应保留为印花细分进度。工厂已分配且等花型，应显示“加工未开始 · 等待花型”，不能显示待分配。生产环节建议如下，由实际工艺决定是否需要：

`花型资料准备 → 样品/米样确认（适用时）→ 待打印 → 打印中/完成 → 待转印 → 转印中/完成 → 产出整理 → 加工完成`

不需要转印的工艺不生成转印数量与时间。不能通过一次“填报加工完成”同时补齐从未发生的打印和转印事件。正反面进度可分开核对，同一物料不重复生成两份最终库存。

### 7.2 生产操作

- 开始加工：核对工厂、物料、需求、已确认花型版本、本次可用备料，再记录实际开工人和时间。
- 工序填报：记录当前环节、本次加工物料/批次、实际使用、实际完成、适用设备、时间与备注。累计值由记录汇总；重复提交不得叠加。
- 分批完成：允许某批已有可交出产出、剩余仍在生产；整单只有剩余计划已处理且必要工序完成后才完成，不能仅凭存在一个 `completedAt` 推断。
- 产出卷：登记实际每卷数量、单位、输出 SKU、花型/批次和库位。可以提供草稿行辅助录入，但按总数平均拆卷只能是草稿，不能自动成为实际每卷长度。
- 不良、损耗和在制分别表达；未完工的投入减产出不自动全算损耗。只做必要的原因、责任人和数量登记，不新增大型异常系统。

线上“待审核、部分入库、已完成”含义涉及不同环节，不能直接塞进加工状态；应根据真实审核/接收记录分别表达。其精确审核对象见第 17 节待确认项。

## 8. 两类仓库与库存数量

### 8.1 待加工仓

保留当前来源单、任务、物料、数量、库位和关联动作，改成统一标准列表。新增或明确工厂、收货批次、物料类型、可用/已备料/实际已用数量、实际单位、需求及加工单归属。

物料真图与名称/编码在同一列，面料展开卷码与每卷长度，其他物料按相应包装明细展示。备料占用不等于消耗；实际领用进入在制时扣减待加工可用库存，后续报工不再重复扣减同一份物料。

### 8.2 待交出仓

按真实产出卷/批次展示加工单、物料和花型、实际完成数量、所在库位、已占用交出单、可用数量和操作。已建单的物料仍在本厂但已占用，不能从实物库存直接消失。

待交出仓解决“物在哪里、有多少”；待交出列表解决“哪些产出具备建单条件”。二者读取相同卷和库存记录，不各自保存一份完成数。

### 8.3 统一记账时点与公式

| 真实动作 | 本厂原料库存 | 本厂产出库存 | 下游 |
|---|---|---|---|
| 来源单待接收生成 | 不增加 | 不变化 | 不变化 |
| 本厂接收并入仓 | 按实收增加 | 不变化 | 不变化 |
| 备料关联/占用 | 实物总量不变，可用量减少 | 不变化 | 不变化 |
| 实际投入/领用 | 对同一物料只扣一次，进入在制 | 不变化 | 不变化 |
| 实际产出入仓 | 不重复扣已投入数量 | 按实际合格产出增加 | 不变化 |
| 建交出单/工厂扫卷 | 不变化 | 只占用，不扣实物 | 不增加库存 |
| 实际交出 | 不变化 | 按实际卷/批扣减 | 生成对应待接收 |
| 下游实收 | 不变化 | 不重复扣减 | 按下游实际收到增加 |

对同一可比单位、同一范围，分别定义：

- 原料实物库存 = 累计实收入仓 − 累计实际投入 − 其他有据出库 + 有据退回；可用原料 = 实物库存 − 有效备料占用。
- 在制数量 = 实际投入中尚未形成已确认产出/损耗/其他处置的部分；不同维度不可直接相减。
- 在厂产出 = 已入仓合格产出 − 实际交出 − 其他有据出库 + 有据退回。
- 可新建单数量 = 在厂产出 − 有效交出草稿占用；已在当前草稿中的卷由本草稿管理，不被第二次选择。
- 下游待接收 = 各有效实际交出明细尚未登记的应收量之和；草稿与作废单不参与。超收单列，不能使待接收变负数。已有历史差异终结事实的记录继续尊重其结论，不重新算成待收。
- 已核算损耗只汇总明确归属的完工批次/处置记录，不使用整单“计划−完成”计算。

输入/输出业务单位不一致时，必须先确定可比基准；长度可按精确换算关系展示，重量不能仅凭幅宽/克重转换成“实测长度”。按物料形态保留独立数量，避免跨单位库存守恒假象。

筛选：工厂、关键词、下游组织/仓库、接收人、单据状态、是否可创建、卷码准备状态。默认看待处理；可切换已建单记录并打开对应交出单，不能只把它们从视野删除。

### 9.2 交出单据列表与详情

保留线上交出单编号、关联加工单/任务单、总卷数、总数量、SKU 数、交出时间、状态、打印/详情；增加创建时间、下游去向、扫卷进度、下游实收/待收。

### 9.3 建单、扫卷与交出的状态边界

| 环节 | 发生条件 | 是否扣减产出库存 | 能否记下游实收 |
|---|---|---|---|
| 已建单/待扫卷 | 选择有效产出并生成草稿 | 否，仅占用 | 否 |
| 扫卷中 | 工厂实际核对部分卷码 | 否 | 否 |
| 工厂扫齐待交接 | 本单卷码核对齐备；有司机流程时显示“厂已扫卷待司机” | 否 | 否 |

### 9.4 删除、作废与修改边界

线上存在“单个单据删除”“整单删除”按钮，本次未执行，不能确定前者的实际删除粒度。原型建议明确表达为“移除本单加工单/卷明细”和“作废整张交出单”，确认框列出释放的卷/数量与影响，保留记录。

- 未实际交出：允许按身份和当前准备状态修改草稿，释放相应占用；已扫卷记录不能静默抹去。
- 已实际交出：不允许删除事实、改为草稿或直接修改已交出数量。发现错误显示责任处理入口，沿用现有纠正机制，不在本次创造复杂退货/逆向物流系统。
- 下游短收/超收：显示应收、实收与差异，不自动把物料退回本厂库存，不以“整单完成”补齐数量。

## 10. 详情、编辑、打印与导出的一致性

### 10.1 详情

沿用现有详情能力，按以下顺序整理：基础信息与醒目需求来源 → 投入及上游 → 印花要求与花型 → 接收与备料记录 → 生产工序/批次 → 产出与下游交出 → 四段时间完整记录 → 备注、变更与日志。

接收记录可打开来源单；产出可打开实际卷；交出可打开实际单据；下游实收可定位本次记录。缺少对应单据时显示“尚未生成”或“历史关联未补齐”，不能仅凭一个旧字符串编号伪装成可追溯单据。

### 10.2 编辑权限和冻结内容

| 内容 | 编辑规则建议 |
|---|---|
| 需求来源、需求单、生产单、任务、创建方式 | 顶部完整展示，默认只读，纠正来源须通过对应来源业务动作 |
| 加工厂 | 从既有任务分配/改派入口办理，不能在普通信息编辑中静默换厂；有实物在旧厂时保留归属与转移事实 |
| 工艺、面别、花型图/编号/版本 | 未开工可修改；已开工需记录变更原因、影响批次和新版本；已经完成的批次保持原快照 |
| 原计划投入/实际替换 | 使用现有“调整投入”入口；校验规格、数量、库存归属与实际未用范围，不覆盖已接收/已加工历史 |
| 深浅、温度、设备、交期、备注 | 仅编辑适用字段；重要参数变更保留前后值、人员、时间 |
| 实收、实际用料、产出、交出、下游实收及实际时间 | 普通编辑只读，由对应作业记录产生，不能直接填写累计汇总值 |
| 取消加工单 | 未执行时确认取消；有收货、在制、产出、有效交出单时先处理既有责任与物料，不复制线上任何状态都可直接取消的表象 |

备注支持列表快速查看、详情完整查看和编辑留痕。执行端错误说明缺什么、在哪里补、何时找主管；不能显示英文内部状态。

| 打印物 | 用途 | 必须携带的信息 |
|---|---|---|
| 印花信息单 | 按线上五行基础信息表打印 | 单号/创建时间、商品SPU、计划Yard/Meter、Fabric、PO、Fabric SKU、实际用量/卷数、图片、二维码。详细版式以§21为准 |

| 产出条码 | 标识一卷/一个实际包装单元 | 卷/包装唯一编号、加工单、物料 SKU、花型/批次、实际数量和单位、适用重量/规格；重打保持同一物理标识 |

| 信息 | 列表 | 详情 | 编辑 | 信息/确认单 | 导出 |

| 计划、本厂实收、使用、完成、交出、下游实收 | 同口径摘要 | 明细可追溯 | 汇总只读 | 按用途显示并标注单位 | 数值、单位、完整性分列 |

普通导出保留完整单据、物料、数量、时间字段。此前两项专项导出及处理入口删除。值为 0 必须导出为 0；未知留明确原因，不能混成空值。

## 11. 统计与大屏

### 11.1 统一统计口径

| 指标 | 定义与范围 |
|---|---|
| 加工单数 | 当前筛选范围内不同印花加工单数量 |
| 生产单数/需求单数 | 分别按真实关联编号去重，不能叫“采购单数量”却统计加工单 |
| 计划投入/本厂实收/实际使用 | 分别来自计划、收货、实际用料记录；同单位汇总 |
| 合格完成 | 最终可交接实物产出；不把打印和转印各加一次 |
| 实际交出/下游实收/下游待收 | 分别来自实际交出、下游接收、未收明细；排除草稿及作废 |
| 今日计划应完成 | 当地业务日期内到期、尚需完成的计划工作量；字段有计划产出则使用计划产出，否则标注计划投入口径 |
| 今日实际完成 | 当地业务日期实际形成的最终合格产出增量，不按整单最后更新时间整单重算 |
| 超期加工单 | 已过有效计划完成时间且尚未加工全部完成；无交期单独列示，不能算作未超期 |
| 未处理接收差异 | 按明确责任范围统计差异明细数和数量，不直接与加工损耗混算 |
| 完工批次损耗率 | 对可比单位且已核算批次计算损耗/实际投入；零分母与历史缺失显示不可计算 |

长度与重量分组，规范化“公斤/kg”“米/m”“yard/Yard”等同义单位；Yard 与米可选择统一口径，使用 `1 Yard = 0.9144 米`，保存原值并在最终展示时舍入，不逐行舍入后反复累加。不同维度不能合计成一个数字。

印尼工厂“今日”建议按工厂配置时区计算，例如对应工厂适用 `Asia/Jakarta`，管理端注明业务日期；不能直接取查看者电脑的日期。跨时区边界需专项验证，此项为目标建议。

原型目前已有按单位汇总和本地保存，不需要另建统计存储。存在历史缺失时给出已知数量及缺失单数，暂停无效比较；严禁为了让合计好看补造实收。

### 11.2 统计页和大屏分工

统计页支持工厂、日期、工艺、需求来源和物料类型筛选，展示趋势与按工厂/工艺汇总，点击进入同条件加工单、接收或交出明细。汇总使用标准分页表。

大屏聚焦本厂今日待收、缺花型/待确认、待开工、打印/转印在制、待产出整理、待建单、扫齐待交接、下游未收与超期。每项可以回到实际待办，卡片显示对象图片、编号、数量单位和当前动作；不把所有历史订单长期列成待办，不铺满无分页无限长列表。

## 12. 图片、Mock 与历史资料

每个商品、每种投入与输出物料、每个适用正反面花型必须有对应正式素材。列表同列放图与名称/编号；详情、编辑、条码维护、交出详情和打印同样处理。缩略图可打开大图，支持按钮、遮罩、Esc 关闭；保持比例，低分辨率不溢出。加载中、加载失败必须可见且可恢复。

“正式素材待核验”“参考图待核验”不能无条件显示在每张正常单上，必须来源于实际资料状态。资料完整的演示单走完整闭环；历史确实缺失的单保留事实提示和补齐入口，不用无关占位图冒充完成。正常能力交付不得依赖缺图场景。

拟补充的演示场景至少包括：

1. 单面乱印：一个仓库来源、两次到货、未开始加工。
2. 双面印花：正反花型分别完整且版本可识别，生产中。
3. 定位印：分批完成，一部分已有实际产出，一部分仍在制。
4. 需要转印的有效工艺：打印完成但尚未转印，最终可交出数量不能提前增加。
5. 无需转印的有效工艺：不显示虚假转印记录。
6. 同一上游厂多批交出：来源单据可追溯，物料和上游组织不重复堆砌。
7. 备货先收后关联：没有生产单，库存只增加一次。
8. 补料或改款来源：原需求与本次来源同时清楚，变更不覆盖历史。
9. 已建交出单未扫齐、已扫齐待交接、部分交出、全部交出待实收。
10. 下游分批实收、短收、超收、显式零收，不自动补齐或结案。
11. 按业务单位管理的非面料物料；只使用确认适用的工艺和下游关系。
12. 历史记录不完整：明确缺项，不影响已有真实事实，不能与正常完整样例混淆。

当前 PH-006 的纱线、热转印、裁床去向组合应首先核对真实业务依据，不能机械保留，也不能未经确认断言纱线不能印花。工厂与仓库来自现有主数据，禁止通过 PO 拼接虚构去向。

## 13. 正常与边界验收场景

### 13.1 正常闭环示例（拟造的演示数据，不是真实业务）

一张双面印花加工单计划投入 100 Yard，由同一仓库分两批供应 60/40 Yard。本厂实收两批后累计 100 Yard，库存 100 Yard，加工状态仍为未开始。

实际投入 100 Yard，按适用路线分别记录打印、转印。最终形成三卷 32/33/33 Yard，共 98 Yard，确认加工损耗 2 Yard；双面不将 98 翻倍。

先选择两卷 32/33 创建交出单，占用 65 Yard，在厂产出仍 98，可另建单 33。扫齐两卷后仍未出库；实际交接后在厂产出剩 33，下游待收 65。下游收到两卷后本厂不再扣库存，下游实收 65。剩余一卷另单交出并实收，最终实收 98。

每一步需在加工单、两类仓、交出单、下游待接收和统计中读到同一份数量，刷新页面仍保留相同记录。

### 13.2 边界结果

| 场景 | 预期 |
|---|---|
| 来源应收 60、实收 58 | 入库 58，显示少 2，不自动关闭，后续补到 2 可继续登记 |
| 来源应收 60、实收 61 | 如实记录 61 与多 1，保留来源和责任，不伪造另一来源；后续投入仍受本厂真实可用库存约束 |
| 显式实收 0 | 有登记人/时间与原因，不生成正库存；留空则阻止提交 |
| 同一送货单关联多个来源 | 各明细分别核对，合计等于明细和；不得任意分摊到多个订单 |
| 工厂已分配，花型未齐 | 显示未开始/等待花型，不回到待分配，不允许开工使用缺失版本 |
| 打印完成 100，转印尚未开始 | 只显示打印工序完成；需要转印的订单不能直接增加最终产出 |
| 尝试把 98 的产出建成 99 的交出单 | 阻止；保留已选内容并说明超量 1 |
| 同一卷重复加入两个草稿 | 第二单阻止，显示已占用单据 |
| 草稿更换卷、已有扫齐记录 | 重新核对变更明细，旧日志保留，不能保持错误的扫齐结论 |
| 已交出后再次点击交出/刷新重试 | 不重复扣减或生成第二份下游待接收 |
| 下游只收到部分或短收 | 实收按现场记录，未收/差异明确；不强行标记收齐 |
| 历史损耗确为 0 | 页面、打印、导出都显示 0；未知历史不能显示成 0 |
| 热转印不适用的物料/路线 | 不允许因通用表单自动生成转印记录，显示所缺的业务配置或转交主管核对 |
| 切换加工厂页签 | 只改变查看范围，不改变提交动作的当前身份 |
| 图片失败、输入连续键入、弹窗展开 | 有失败提示；输入不中断，页面不整页闪烁，滚动位置保持 |

## 17. 需确认的业务含义及建议处理

这些问题不妨碍确定页面结构和已发现的错误，但涉及的业务动作应在实施前明确，不能由工程实现偷偷决定。

| 待确认项 | 已知事实 | 建议处理 |
|---|---|---|
| “待审核”审核什么、谁审核 | 线上已交出记录仍可显示待审核；当前原型也有审核入口 | 保留审核信息，与加工、交出、下游实收分别表达；核对是数量、工艺、结算还是其他审核后再绑定动作 |
| 定位印/定向印/乱印与打印/转印的适用关系 | 线上有这三种工艺，原型有另一组加工方式；不是已证实的一一对应 | 按现有工艺主数据确认路线；不将三种工艺都强制设为热转印 |
| 打印机字段的实际设备含义 | 线上编辑资料及原型均有相关设备信息 | 区分生产打印设备与标签打印设备，不能把打印标签动作记为生产工序完成 |
| 非面料印花与纱线规则 | 线上筛选含多种物料，原型存在纱线样例 | 以真实 BOM/工艺能力确认可执行组合；染厂特定重量限制不自动推广 |
| 司机等待与实际交接责任 | 线上可见扫卷 3/3 但仍待司机、无交出时间 | 保留等待环节；继续核对已有运输/司机入口后确定确认人和必填字段，不新建运输系统 |
| 来源确实多组织/产出多去向的例外 | 染色已确认单物料单上游；打印存在多订单合成一张交出单 | 本方案默认单加工单单物料单上游；真实多组织/多去向需明确任务拆分与批次分配，不隐去历史 |
| 已开工后的工艺变更、取消与差异终结权限 | 线上有编辑/取消按钮，但本次未执行验证其约束 | 采用保留事实、确认影响、主管处理的边界；不新增未经确认的强制结案能力 |

建议确认后的实施顺序：先修接收/库存/工序事实，再调整加工单和待接收，随后补独立交出页面，最后统一打印、导出、统计、大屏与演示数据验收。这样每个新页面展示的数量和状态都有可靠的业务依据。
