# 现有五类需求的业务视图补齐与验收

用户反馈：当前七入口仍主要使用通用表，未承接之前提出的现有业务需求。本轮按新子域架构补齐业务视图，保留既有计算/版本能力，不将旧页面逐页迁移作为目标。

| 来源 | 子域业务视图 | 本轮必交付 |
|---|---|---|
| P1 | 决策总览 → 库存健康 | 消耗贡献6:3:1、三分类矩阵、六动作组、TOP10、日期及明细 |
| P2 | 风险与决策 → 库存预警 | 覆盖/在途/ETA筛选、库存日均覆盖、到货批次、逾期、口径说明 |
| P3 | 消耗与经营分析 → 物料日报 | 截止日、重点/突变、分仓、采购/订单日需求、已BOM/未BOM分列 |
| P4 | 消耗与经营分析 → 关联商品 | 品牌渠道、商品销量趋势、BOM单耗与物料需求、预选关联区别 |
| P5 | 供需计划 → 生产备料 | SKU监控新增/编辑、固定量/天数触发和目标、原料库存/工序、建议计算、生成记录和执行回执演示 |

业务页使用明确的Mock场景，页面各自汇总与明细读取同一组样例。历史P1/P2/P3口径以明确名称展示，不能暗中视为同一指标。未接入源系统、缺实物图不阻断继续补齐业务交互，但不宣称生产或图片验收通过。

原子验收：HLT-01三矩阵/六组可筛；HLT-02贡献比例不混库存比例；WARN-01筛选/分页；WARN-02未来最早及全部逾期批次；DAY-01日需求与采购分列；DAY-02无BOM未知及突变；GOODS-01商品过滤趋势及需求；GOODS-02关联销量不跨料相加；PREP-01增改监控规则；PREP-02建议零原因；PREP-03原料可用及工序约束；PREP-04生成去重与分段回执；LINK-01五视图可从主导航到达且跨视图带上下文。最终命名页面测试和报告逐条回填。


## 本轮结果与证据

五个独立业务视图已接入统一导航，默认决策总览展示库存健康；原物料全景、供需日历、风险处理、包材分析和配置发布继续保留。页面数量不能等同于完整方案已验收。

| 验收项 | 结果 | 直接证据与限制 |
|---|---|---|
| HLT-01 / HLT-02 | 原型通过 | 6项健康计算/渲染测试；浏览器动作组与查询；三矩阵、六动作组、贡献及TOP10从12个SPU同源计算。真实14标签及生产阈值未核实 |
| WARN-01 / WARN-02 | 原型通过 | 7项预警测试；浏览器展开批次/切换对照；标准分页、覆盖/在途/ETA筛选；未来最早与全逾期最近批次 |
| DAY-01 / DAY-02 | 原型通过 | 日报与商品8项专项测试；浏览器09-13突变筛选；采购需求、BOM推算与未映射件数分开，不伪造完整需求 |
| GOODS-01 / GOODS-02 | 原型通过 | 品牌渠道筛选、7日趋势、BOM与预选分开；商品SPU去重；真实爆款口径未知 |
| PREP-01 / PREP-02 | 原型通过 | 浏览器新增/编辑、目标小于触发线阻断、未映射阻断、只读限制；已在途覆盖目标时建议为0并解释原因 |
| PREP-03 / PREP-04 | 原型通过 | 5项备料单测；浏览器生成去重、加工产出、3000+5000分批实收、刷新持久化；同原料共享占用、单位和实际SKU限制 |
| LINK-01 | 部分通过 | 五视图均能通过导航到达；日报内商品用料关联可展开，预警两条对应目录可打开详情。所有视图共享SKU/日期/供给池上下文、统一数据源尚未完成 |

专项单测66项通过；浏览器13组通过，含1366×768和1280×720布局。对应 `tests/unit/material-decision*.test.ts` 与 `tests/material-decision.spec.ts`，日志在 `output/material-decision-evidence/`。布局图片按 `output/material-decision-{health,warnings,daily,goods,preparation}-{1366,1280}.png` 保存。

## 后续仍需完成的统一能力

1. 独立业务演示集统一到同一SKU、供给池和时间快照，并保持跨页筛选与钻取上下文；当前明确隔离演示集，禁止混加。
2. 历史参考口径与全局策略、健康阈值和备料规则的统一版本发布、审批和生效日期。当前健康阈值仅临时试算，备料规则本机保存，未伪装正式发布。
3. 真实数据与实物图片、源单据回执、工厂/仓库映射、服务端权限；完整方案其余条款仍以原子矩阵为准。

未修改线上业务数据，未创建线上采购/加工/收货单。本轮完成的是五类既有需求的可操作原型补齐，不是全量生产验收。
