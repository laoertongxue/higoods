# 后道回货与质检调整需求

版本：2026-10-10；依据：用户四项要求及同日确认的串联编号规则。当前原型基线 HEAD 99e25a0b。

## 1. 目标与范围
回货按生产单分批识别；质检员每次只执行一张任务。覆盖后道回货、质检、加工、复检、出货、相关 Web/PDA/打印及同浏览器保存链路。不增加真实登录或后端，不修改其他业务模块。既有 SKU 重量设置未参与本次编号/质检动作，其旧 localStorage 保存入口保持原状并登记为未迁移范围；全站生产来源保护与其他模块存储不在本次迁移范围。

## 2. 编号
回货=生产单-回货次数；质检=回货-ZJ；后道加工=质检-HD；复检=后道加工-FJ；加工后出货=复检-CH；质检直达出货=质检-CH。单据显示第 N 次回货。重复动作复用单据，编号生成后固定。质检合格总量为 0 时不建立空后道任务、复检或出货单；有合格可交数量时才生成相应下游。依赖实际来源单，不伪造中间环节。

## 3. 执行质检与清单
PDA 前往 Web 的质检入口进入执行质检。菜单拆为执行质检和质检清单，复用现有 qc-workbench/qc-orders 路由。执行页先按当前人员唯一标识读取未完成的质检单；有任务直接显示操作详情，没有任务才输入完整质检单号领取。领单动作同时限制一单一人、一人一张未完成任务。待送检、已完成、他人持有和不完整单号均阻断。未完成时移除取消、切换任务和自行退领入口；原有主管释放保留二次确认及操作记录。清单用于查询/只读详情/打印，领单入口转为执行质检。查询使用当前单号；没有匹配记录显示明确空态；重置清空查询条件。只读详情不允许领取、编辑或提交；执行入口即使携带其他单号，仍续做本人未完成单据。

## 4. 图片
后道不再维护独立 SPU 技术参数，移除页面、事件、状态提示、存储写入和旧专项契约。质检详情按 SPU、颜色显示已有款式图片，同一颜色多尺码不重复显示；标明颜色，支持关闭按钮/遮罩/Esc 大图。失败态明确。商品及技术包的原有尺寸资料不删除。

## 5. 保存与旧资料
复用现有轻量记录事务和 Blob 引擎，以独立后道命名空间按记录保存本次动作涉及的主单、明细、编号、上下游、授权和日志。首次访问读取静态示例，不复制种子。最近登记按登记时间展示，刷新保持顺序。事务 complete 后才发布成功，失败保留数据与输入；版本核对阻止跨标签覆盖。图片保存 Blob 和引用。
旧后道资料由页面明确触发转换，停止旧写入；分批转换、读回校验后删除对应旧源，源变化/冲突/失败保留旧资料。旧独立参数和无法作为当前业务来源的旧出货资料仅存档。提供本浏览器后道资料导出/导入入口；不清空全站存储。

未保存凭证在替换、重新扫码和管理员退出时释放临时图片；管理员退出清空本次送货人、联系方式和凭证，避免下一次登记带入前次输入。已保存附件保持既有引用。

## 6. 场景与验收
正常：同一生产单二次回货，生成 -2、-2-ZJ；人员领取后刷新仍进入原任务；完成生成 -HD，复检后生成 -FJ-CH。直达：没有加工项目时生成 -ZJ-CH。
边界：已持有任务不能领取另一张；多标签同时领取只能一张成功；保存失败输入保留；没有合格数量不建空出货单；旧资料转换中断可重试且不覆盖目标冲突。
仓库弹层跟随关联单据时关闭当前弹层，返回列表后仍可继续操作。
Web 按 1366×768、1280×720、1024×768；PDA 按 390×844。加载与受影响交互均保留至少五次原始耗时，<=1000ms。静态契约、存储与浏览器证据分别登记。

## 7. main 发布整合（2026-10-11）
用户已明确授权本地合并 main 并推送 GitHub main。先接入当前 main，再按相同数据、动作、路由和设备保留已确认原型；仓库列表接入当前标准骨架门禁，以实际表格、分页渲染和页面对比证明行为不变，不修改检查器或全站生产来源保护。发布证据与原 final35 分开绑定版本；远端发布及 Production 状态按相同提交核对。
