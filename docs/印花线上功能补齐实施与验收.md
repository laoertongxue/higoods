# 印花线上功能补齐实施与验收

## 目标与边界
以用户提供的线上印花单、待加工仓、待交出列表、交出单据和条码弹窗为现场依据，在当前原型上增量补齐。保留加工单的标题、筛选、六项摘要、选择表头、七类业务列、直接展示的行操作和详情六区结构。新功能通过原有按钮和附加弹窗进入；不改造菜单和全局布局。

原型模拟操作，不修改线上业务数据。接收、加工、交出保持独立；生成交出草稿不等于实物交出，更不代表下游已接收。已有素材和历史记录缺口继续明确显示。

## 功能核查与实施顺序
1. 条码：已有单卷编辑、批量修改、补充、单卷及批量打印；补齐列表维护入口、筛选分页、全选、复制新增、删除和细码导入，保护已交出/入库卷。打印不改变交接状态。
2. 交出单据：已有单张加工单交出和下游接收；新增基于实际产出卷的待建列表、批量建单、合入草稿、单据明细、确认交出、作废草稿和打印。多单合并要求同工厂、同接收方、同接收仓、同单位。数量从卷明细计算，不手填总数。
3. 待加工仓：已有库存、接收记录、加工用料记录、库区库位及流水入口。保留现有布局，核查可操作范围；不把库存均值自动拆成真实卷，也不绕开来源接收新造库存。
4. 验证：领域守恒与原子回滚、草稿卷防错、重复建单、跨厂/接收方阻断、实际页面及打印，1366×768与1280×720；在同一工作树5188服务验收。

## 范围与限制

线上功能依据为用户提供的详细页面快照；本次连接Chrome读取线上标签页超时，未把快照内容表述为最新线上复验，未执行线上写入。
预置12张演示加工单继续使用原来的内存演示方式，刷新会恢复初始数据；正式生成加工单沿用现有保存机制。本次未新增后端或扩充持久化范围。
手工库存调整尚未获业务范围选择，未用等待时间代替用户答复。其余条码/交出/查询功能独立完成。正式图片及历史资料缺口继续影响完整验收。
