## 1. 主要结论

1. 取消复检不是删除一个菜单。当前菜单、两套 Web 路由表、懒加载包装、事件链、专用 PDA、通用 PDA 工厂入口、加工列表/详情、仓库流水、业务链、统计、两套打印体系和旧专项断言均直接消费复检。必须同步退役活跃入口与旧写入，历史已完成事实另保留只读身份。
2. 无加工 QC 已有实际 `outboundOrder` 对象，但表面仍称“直接成衣仓待接收”、跳过待交出区；目标要求统一经过后道出货单与实际出货。应复用真实出货对象、补齐出货责任与时序，不能把展示文字改完就认定流程完成，也不能再建一张重复出货。
3. 管理中心需要真实注册的配置/只读页面。仅加菜单会被 `routes.ts` 的菜单兜底渲染成占位页。领取、检查、稽查决定继续在原业务执行页。
4. 当前“已质检”“通过数量”和多处纸面数量仍按整批/旧投影使用。抽检后必须分别表达实检三类、未检放行、正常物流量，不能继续把整批放行量当实检合格或把合理未抽检当短少。
5. 原测试框架可复用，但旧测试包含与新需求相反的断言，且部分依赖旧人工验收输出文件。必须先更新受影响契约与夹具，再运行；旧套件通过不证明新业务通过。
