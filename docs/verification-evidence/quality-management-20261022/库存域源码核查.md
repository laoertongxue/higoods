## 1. 本期继承边界

- 一仓一款一申请，包含所选仓库该款所有合资格正常品，可有多 SKU 和来源库位；不能任意填写部分送检量。
- 排除订单占用、已拣货、待出库及原瑕疵/破损。申请后直接整批下架出库，原仓内数量减少；不新增冻结、在检占用、释放、取消和中止流程。
- 整批交出、整批实收；差异保留。本申请就是库存 QC 批次，实收为应检基数；实收 0 先处理差异，不能用 0 应检自动完成。
- 库存共用成衣基本及附加标准和分轮升检，但不套四条生产回货初始全检条件；升检只本申请。
- QC 完成前不部分交货；完成后，正常放行量=实检合格+获准未检放行，瑕疵和返工单独分流。
- 正常货回原成衣仓，允许选择新库位，上架后恢复可售；瑕疵进瑕疵品仓；返工交 `goto_global`，不再 QC。无某类货不生成空交接。
- QC 完成和申请完成分别判断。申请须等相应仓库接收/适用上架、goto_global 实收和数量差异处理完毕；不等待 goto_global 返工完成。
- 不扩展辅料、客户退货质检、功能角色、质检结果更正、接替、额外纸签、费用扣款或新执行端。后道复检整个节点已在最新需求中取消，库存不能新建数量复检节点绕回旧流程。

一项动作中仅调用一次共同 `commitPcsRecords`；后道模块对库存来源需提供“准备本次改动”的纯函数或窄数据接口，由协调调用共同提交，再发布内存结果。不能先运行有独立 persist 的后道函数再保存库存申请，也不能将一库成功另一库失败解释成“稍后同步”。

上架直接进 `pre-inbound.ts` / `putaway.ts` 的库存来源分支，保留原页面入口与新来源链接。销售出库页也按 sourceKind 展示本期送检出库，不要求新增销售面单事实；库存业务不强制走预出库波次拣货。

## 5. 演示源切换与用户资料保护

1. 开发时先列旧源。上述库存页普通业务没有发现库存本地持久化；localStorage 仅列表偏好。旧页内存操作不是可以恢复的历史资料，不伪称迁移成功。独立销售库确有用户覆盖/版本/操作记录；PCS 共库亦有其他业务，均不能清空。
2. 先建立有明确版本的同一静态成衣库存事实，让相关四个库存视图、申请预览及直接渠道可售投影读同一身份/数量。对旧演示不同仓名/款号，只可在核对后明确配置映射；不能凭相似命名自动加总。独立瑕疵仓和 goto_global 目标必须是真实字典身份。
3. 静态源只读，用户动作只存受影响余额覆盖/申请/流水；保留 seed version 和删除标记。刷新/首次读取不写整批 seed；发版不能复活已送出库存或覆盖用户变化。
4. 若本期涉及的订单排除源落在 `higood-finished-outbound-v1` 用户记录中，先以稳定仓+SKU 的精确交集确定最小迁移记录，不迁整个销售仓域。该参与记录如取消/出库会改变排除事实，必须把相应动作切到共库同事务；不能读旧库变化再顺序复制一份占用。本期不参与的销售单/面单仍留原库。
5. 当前销售示例使用 FADSS/ASYSA/CHCKL 实际款码，库存示例为 SKU-GC，仓名也不同。当前源码无法证明它们属于同一库存，不能默认相等。实施先用明确关联的 Mock 校准，真实保存资料若缺对应应保留原记录并说明来源缺口，不改业务要求、不补造生产来源。
6. 如需迁移，严格停止该范围旧写入→分批转换并保留稳定源映射/进度→目标读回核对→只清已验证且有权的旧范围→完成。迁移不藏在库存普通读取里；旧多标签页不能继续写旧源；中断可续，不能删库重建。
7. 不处理辅料仓库及其迁移，不变更客户退货质检。新同库 collection 只按本期对象读写，维护/全库备份能力的存在不是新增库存技术维护门槛的理由。

## 8. 仍需核实的事实，非待用户重新决定的业务

1. 稳定成衣仓/瑕疵仓/库位字典对应关系。当前多个静态仓名不证明同一仓；独立瑕疵仓还没有本期可用的权威映射。
2. 可用、订单占用、已拣、待出库的唯一记录及重叠身份。当前页面/数据拆散，不可直接用于真实排除；实施者应先修来源，再写规则。
3. 实际保存的销售覆盖是否与本次库存有稳定精确交集，决定最小同库迁移清单和原销售动作切换范围；不能假定浏览器没资料。
4. 本期统一后的成衣静态数据须保证真实图片、款色码、单位、库存及库位能相互核对；目前多个旧 seed 尚不满足这些条件。
5. 主代理后道 `post-finishing-records` 命令怎样接收库存来源、准备同次提交的记录和处理不同去向，须双方按最终实际符号绑定，不从旧只认生产回货的接口硬塞空生产号。
6. 每次差异处理应记录真实处置去向，不能只为“整体完成”写 done。已确认的差异规则不是授权修改原实收、补造库存或关闭未完任务。

这些缺口都能通过本地源码/一致 Mock/实施契约继续核实。本轮未发现需要重新讨论一仓一款、默认抽检、去向、无冻结、无中止等已确认业务的理由。
