# 技术包正式样本与列表调整：本次业务基线

日期：2026-10-06。来源：用户本轮技术包截图与明确要求。此文只登记本次技术包范围，不代替此前 PCS R1 整体业务验收。

1. 默认展示 26 条技术包；其中 20 条为正式已发布版本，资料完整度必须由真实内容计算为 100%，且没有待补齐项目。纸样原文件、BOM、花型、颜色用料、尺码和确认工艺路线均需存在。
2. 其余 6 条为草稿：3 条未提交审核，3 条在审核流程中。技术包资料齐备与是否发布是不同事实，草稿可以拥有完整资料。
3. 正式样本准备阶段包含 3 款面料，每款为染色 → 印花 → 洗水。投入与产出均关联实际存在的物料 SKU；洗水不改变物料身份，保留该阶段及前序关系。
4. 正式样本生产阶段包含 5 个需要额外加工的裁片，每个为绣花 → 压褶。准备阶段不展示无准备加工对象；裁片路线不展示没有额外工序的裁片。基本裁剪和车缝仍作为生产节点。
5. 技术包业务 ID 使用稳定递增纯数字；新建按全局已有数字最大值加一。隐藏的稳定关联 ID 保持，防止破坏原有生产单、款式和审核引用。
6. 列表允许维护跟单、版师，买手从款式档案读取并只读展示。关联生产单使用已有生产需求及精确版本引用，不能凭空编造。
7. 操作增加日志弹窗，展示时间、操作类型、说明、操作人。人员维护追加持久操作日志；查看日志不写入业务数据。时间列展示创建时间与最后更新时间。
8. 已存在的历史制版/改款来源可以准确读取，不能冒充生产准备来源；新建仍只允许生产准备单的技术包确认任务。确认未编辑的旧演示快照使用版本化只读投影。旧原始快照要求记录与内容同时精确匹配；本轮已经保存的早期演示资料版本按精确内容指纹补正路线、预览和演示物料引用，人员、时间和操作日志保持原样。真实技术资料编辑不匹配时保持用户内容。
9. 普通读取不落盘种子，不删除旧记录或清库。修改一个投影技术包仅保存实际修改的记录及一致内容，不能把其他演示修正批量写入浏览器。

正常场景：打开已有旧演示数据的浏览器，看到 26 / 20 正式 / 3 未提交 / 3 审核中；打开正式版本工艺 Tab，查看三条连续面料路线与五条裁片路线；维护跟单后刷新，人员与日志一致。

边界场景：已保存内容与识别到的旧静态基准不完全一致时，保留该用户记录和内容；错误角色候选禁止保存。资料缺少原文件时，完整度下降，不能只修改显示数字。创建来自历史制版来源的新版本被阻止。

原型资料范围：复用随应用发布的真实静态 DXF / RUL 文件样本，并明确其是共享原型样本、并非当前款式生产文件；新增原型印花 SVG 和染色标准说明有单独执行资料用途。全部是产品原型示例，不代表真实采购、加工或审核已经发生。

## 当前事实与交付边界

本轮现场证据已出现 26 行，其中 20 行为已发布且 100%，6 行为草稿；独立审核筛选分别得到 3 条未提交和 3 条第一阶段并行审核。正式技术包 1 的详情已从“资料待补齐”修复为七个关键项全部完成，确认工艺图关联的三款面料投入、产出均可解析，五个裁片各展示绣花和压褶。全 20 个正式样本的内容与路线一致性另由专项契约覆盖。详情现场样本为技术包 1，不能把这张截图描述为逐页打开全部 20 个详情的证据。

性能统一按 1 秒验收，不允许例外。最终同源码构建的列表、详情、工艺Tab、人员持久保存、日志与筛选各五次均通过，原始结果、版本与缓存条件见 [最终回执](../2026-10-05-pcs-prototype-adjustment-plan/evidence/closure/final-verification.md)。原浏览器也重新核对26条，没有清空已有资料。整体PCS R1的158项验收仍单独追踪，不将技术包本轮关闭等同于全部产品接受。
