## 2. 档案与基础配置

五类物料采用分类属性模板：面料、辅料、纱线、耗材、设备配件。服装用纽扣/拉链等属于辅料。SPU/SKU、包装和批次分层沿用已确认的 A/B 项；已有织带、绳子半成品宽度/直径、截断长度等特例继续保留。

- 空差从目标字段、表单、导入模板和计算范围中排除；原始核查证据保留。
- 幅宽只保留一个字段，语义就是有效幅宽，不设全幅/净幅双字段，不增加有效幅宽计算。
- 染色物料必须关联 Pantone 体系和色号。实物样和图片可提供辅助识别，不能代替 Pantone。
- 服装使用一套内部尺码字典，支持现有字母、数字、均码。平台可有展示别名映射，但不按市场或品类建立新的内部尺码体系。
- 品类、风格、品类编号是三个独立属性。用户附图实例分别为“套装”“休闲”“89-Printed Set-35-55印花套装”。原型“风格编号”与目标“品类编号”的来源映射由代码/字典核查确定，不能把实际风格值当品类编号。
- 成分、组织、幅宽、克重、纱支等使用适用模板和单位；标准技术要求与批次实测结果分开。
- 基础配置维护独立属性定义、取值、分类模板、编码参数、单位和平台映射；保存属性的稳定身份，显示名称变化不改 SKU 身份。
- 新值停用后不供新建选择；历史记录保存当时含义和必要快照。被使用的实质规格变化按新规格/版本处理。

### 2.1 物料 SKU 的计量单位视图

SKU 详情设置“计量单位”Tab，五类物料统一适用；列表可显示主单位，但完整换算关系集中在此视图。

| 部分 | 内容 | 规则 |
|---|---|---|
| 主单位 | 单位、名称、数量精度 | 每个 SKU 必须且只能有一个；主单位不随页面切换变化。 |
| 辅助单位 | 单位、用途、对应主单位数量、换算依据 | 可有多个；每条清楚显示“1 辅助单位 = X 主单位”。 |
| 依据 | 固定关系、确认的规格换算或包装含量、依据版本 | 米/码为固定关系；KG/长度须有对应规格依据；包/箱等须有明确含量。 |
| 适用动作 | 采购、计价、发料等 | 业务单据选取适用单位，并保存当时换算依据。 |
| 维护 | 新增/编辑/停用辅助关系、变更说明 | 不能用当前换算覆盖历史单据；批次实测由对应业务域保存。 |

示意：主单位 M，辅助单位 Yard，则显示“1 Yard = 0.9144 M”。KG 与 M 不使用全品类统一系数。此 Tab 没有库存数值、供方报价或库位字段。详见 [字段细化第 3 节](field-contract-candidates.md#3-计量单位-tab)。

## 3. 加工对象、工艺与物料身份

### 3.1 必须区分作用对象

| 业务动作 | 作用对象与产出 | 档案规则 |
|---|---|---|
| 染色、印花、绣花、物料烫画 | 面料/辅料等物料到加工后物料 | 形成对应加工 SKU，保留投入与产出关系。 |
| 已印花面料裁成片后，再对裁片印花 | 先物料、后裁片 | 工艺名称可以再次出现；裁片加工归其生产对象，不能只根据工艺名称全链禁重。 |
| 裁片压褶、裁片打揽 | 裁片 | 本期不产生新的物料 SKU，结果由生产工艺及裁片事实表达。 |
| 多色纱线横机成片、再缝盘 | 多投入生产，产出为片、半成品或毛衣 | 通过生产 BOM、工艺路线和产出身份描述；不任选一种纱线充当唯一前驱根码。 |
| 同一既定目标的返工 | 执行中的对应对象 | 留在执行/返工记录，不能将每次返工自动变成新永久物料。 |

同一种工艺在同一物料对象的普通加工链中一般不重复；对象变为裁片等后，要在新对象范围解释工艺。不得按名称全局禁止，也不得据此建设任意复染/复印的通用循环流程。

多色纱线场景已确认；下面的领域分工是据此进行的设计细化：物料提供纱线 SKU 身份，生产技术提供多投入及数量关系，执行记录成片/缝盘事实，最终成衣引用成品 SKU。需要独立管理的半成品接入既有对应对象，普通生产片不因为出现一条记录就新建物料 SKU。具体与现有毛织对象的字段映射仍需核查。

## 4. 编码与花型

### 4.1 已确认结构

- PT 紧随 Pantone 色号；XH 表示绣花加工段；YH 表示印花加工段。
- 花型编号可用于印花与绣花；pl001197 就是花型编号。
- 单面用 A，双面用 AB；取消早期 DM/SM 建议。
- 渗透印必须入码；物料烫画形成新 SKU，因此编码规则也要表达该加工段。
- 后加工保留前驱完整编码，通过显式对象 ID 识别投入，不能仅凭含 X 判定。
- 单独印花在唯一基础规格时可从 SPU 根码生成；多基础规格时以实际前驱 SKU 完整码生成。
- 多投入成片/毛衣生产不沿用“任选一条投入纱线逐段追加”的编码方法。

~~~text
染后：CNIDML160-black-19-4003PT
染后再绣花：CNIDML160-black-19-4003PT-pl001197XH
染后单面印花示意：CNIDML160-black-19-4003PT-pl001197-AYH
染后同花双面印花示意：CNIDML160-black-19-4003PT-pl001197-ABYH
~~~

前两条来自已确认方案；后两条是用已确认 A/AB/YH 组成的模板示意，不是已迁移的线上编号。不同花双面需要两个有正反顺序的花型引用。

### 4.2 仍需在编码规格中落实的参数

渗透印具体字符串、烫画后缀、不同花双面的精确拼接、来源值规范化、码长和条码兼容尚需完成规格设计。可提出 ST（渗透）/TH（烫画）作为设计候选，但这两个字符尚未被用户点名确认，也尚未成为实现值。不能把“渗透印是否入码”继续列为问题，它已经明确入码。

旧码保留可追溯映射；本轮没有修改任何线上或本地业务记录。历史重复等异常治理按 U31 排除，不另建迁移修复工作台。

## 5. 标准成本

### 5.1 公式与范围

在相同计算币种、换算到对应产出计价单位后：

~~~text
基础综合标准成本 C0 = 人工维护的标准采购成本 P + 基础标准运输成本 T
第 n 阶段综合标准成本 Cn = 承接上道标准成本 + 本道按产出计的含税标准加工费 Fn
~~~

| 项目 | 本期口径 |
|---|---|
| 采购、运输、加工价 | 全部含税。 |
| 基础运输 | 在基础层计入一次；含运报价须识别，不能再重复相加。 |
| 后续加工新增运输 | 不计入本次综合标准成本；若实际发生由物流/实际业务保存。 |
| 损耗、缩率 | 不进入本次公式。 |
| 染化料、绣花线等辅助用料 | 已包含在加工费中，不另加一份标准辅材成本。 |
| 开版、制网、打样费 | 本期不考虑，不建设摊销功能。 |
| Asaya 与其他品牌 | 印花、染色使用一致价格，不设两组品牌费用列。 |
| 计价基准 | 档案加工单价按对应加工产出计。 |
| 原始精度 | 保留来源有效精度；计算至少 6 位，默认单价显示 4 位可展开，按已确认四舍五入规则汇总。 |
| 缺失与零值 | 不混用；缺价不能视作完整的核价依据。 |

示意 P=5、T=1、染色=0.8、印花=1.2 元/码：基础 6、染后 6.8、再印后 8。采购标准改为 6 后自动为 7、7.8、9；新增后段运费、标准损耗、一次性费用都不加入此例。数字仅为设计示例。

多色纱线到毛衣的成衣/半成品 BOM 核价不由上述单前驱物料加法直接替代，也不在本轮擅自定义完整成衣实际成本公式。

### 5.2 自动传递与历史

标准采购成本人工维护。采购、纳入公式的基础运输及加工标准费用变更，按显式依赖关系自动更新受影响各阶段及分支，无下游人工复核门槛。保留变更原因、版本和影响对象；物料身份与编码保持不变。

已发布 BOM、已确认核价、已发生单据保留采用时的快照；未发布草稿重算当前参考标准并体现变动，正式保存遵循其业务动作。普通查询不为了显示新参考值反复写回业务记录。

### 5.3 多币种展示

默认显示 RMB/CNY，可依据展示汇率查看 IDR、USD。显示金额必须带币种、单位和所采用的汇率/方向。

切换展示币种不改变费用原值、物料编码、标准版本或历史单据。来源原币金额与归一计算依据按覆盖要求保留；展示换算与成本重新生效分开。本期不建设“正式生效的成本汇率调整触发全链重算”流程，也不把一个标准成本复制成三份独立维护的币种成本。

## 6. 渠道店铺商品

### 6.1 关系与约束

~~~mermaid
flowchart LR
    S[款式 SPU] --> K1[内部 SKU 1]
    S --> K2[内部 SKU 2]
    L[店铺内一个 PID] --> E1[平台规格 ID 1]
    L --> E2[平台规格 ID 2]
    L --> E3[平台规格 ID 3]
    E1 --> K1
    E2 --> K1
    E3 --> K2
    L -->|唯一款式归属| S
~~~

该 PID 的所有规格必须映射到同一 SPU 下的 SKU；同内部 SKU 对应多个外部规格仍保留多条实例。正式历史渠道商品也必须映射完整。编辑过程可暂未选完，但不能将其保存成正式未匹配商品；原型示例和正式导入样本按完整关系准备。

父容器维护共同标题/详情/类目/图片；各外部规格维护外部 ID、显示属性、内部 SKU 关联和售价。两者是渠道内部数据分工，不新增第四个内部商品档案层级。

- 店铺/PID/平台规格均用稳定身份；不能以“内部 SKU+店铺”或再加 PID 作为唯一约束。
- 同内部 SKU 的多个外部规格默认引用一致价格，可以显式独立覆盖；覆盖差价不能被后续默认值同步抹平。
- 固定实物套装和虚拟搭售按已确认 A06 区分；虚拟搭售保留组件及数量定义，其承接结构继续细化，仍须满足一个 PID 同款式、每个平台规格明确匹配内部 SKU。不能用组件多对多关系绕开这些约束，也不据此新增第四层商品档案。

### 6.2 经营范围与测款

当前经营渠道：Shopify、TikTok、独立站；市场：ID、MY。默认一店一个市场，销售币种和结算币种分别表达。独立站按单独经营渠道保留；其具体技术站点/外部映射需核实，不能自动当作 Shopify 的别名。

渠道商品可关联测款单；测款单的“渠道上架”动作选择店铺、款式及已匹配规格，创建或关联渠道售卖记录，发布结果返回该测款动作。无“开发项目”业务对象、项目字段、项目必填或按项目节点锁定渠道记录的规则。

历史其他渠道/市场来源保留必要查询和追溯，不列为当前新刊登经营范围。测款上架可以先于测款结论，测款通过仍按既有规则作用于生产准备等后续流程。

### 6.3 双向同步与共享可售额度

正常业务字段变化需要在 PCS 与平台之间双向同步到一致；平台变化只记录差异、等待人工选择是否采纳，不再是正常操作流程。平台可写业务内容、平台原生只读状态和内部 SKU 身份的归属需要分别列入字段同步表。双向同步不允许平台覆盖内部物料、供应商、标准成本或 WMS 库存主事实。

~~~mermaid
sequenceDiagram
    participant T as 测款
    participant C as 渠道商品
    participant P as 平台
    participant W as WMS可售事实
    T->>C: 渠道上架动作与可选测款关联
    C->>P: 发布或同步本侧变更
    P-->>C: 返回外部身份及实际状态
    P->>C: 同步平台侧业务变更
    C-->>T: 返回对应上架动作结果
    W-->>C: 提供同一内部SKU的共享可售口径
    C->>P: 同步共享可售表现
~~~

共享的含义：WMS 某 SKU 可售 100，关联多个链接也只有同一池 100；订单占用/释放由对应库存业务负责，再向各销售关联同步。不得把 100 按渠道重复累计，也不引入按店铺先切份额的默认方案。

双向同步的版本、回执、避免自循环、同时修改、部分成功等属于后续接口设计和验证事项，不新增正常人工审批。旧回执不能覆盖新版本，真实失败不能显示两边已经一致。平台回传数量只作为外部观察值，不能直接覆盖 WMS 库存主事实。当前尚未证明各平台适配能力，更未实现真实同步。

## 7. 审核、历史与排除项

同一人可以维护并审核。职责保持区分用于动作留痕，具体人员配置不作为本轮设计冻结的前置要求。SPU 与首批 SKU 可合并审核，后增 SKU/加工产出单独审核；停用限制新业务，不自动终止在途单据或自动下架平台链接。

本期明确排除：空差、额外有效幅宽计算、多套内部尺码、开发项目、品牌拆分的印染价格、后段运费/损耗/缩率/辅助材料重复费用/一次性费用计入综合标准成本、成本汇率重新生效流程、历史异常治理、未匹配渠道商品、按店铺分配额度，以及 PCS 本地资料维护工具。

U31 是本次设计场景的边界，不是线上数据质量已经被证实正常。已有测试库异常结果保留在原始证据中，但不再作为本期“先建设修复流程才可设计”的门槛。正式记录仍执行必填、身份引用及唯一性等基本校验。

## 8. 设计场景校验

| 场景 | 预期结果 | 防止的错误 |
|---|---|---|
| 染色新料未填写 Pantone | 无法通过该染色规格必填校验 | 用同图色/色样替代色号。 |
| 输入幅宽 150 cm | 就是有效幅宽 150 cm | 再扣空差或从全幅另算。 |
| SKU 主 M、辅 Yard/KG | 分别显示固定关系或有依据的规格换算 | 全部物料共用 KG↔M 系数。 |
| 面料印花后裁片、裁片再印花 | 在不同作用对象记录同名工艺 | 全链按工艺名禁重或为每片新增物料 SKU。 |
| 多色纱线到横机成片/缝盘 | 保留多投入、数量与产出关系 | 随意选一根纱线作唯一编码前驱。 |
| 创建加工单时没有库存 | 加工业务条件齐全时仍可建单 | 强依赖 WMS 数量或接口成功。 |
| 标准采购成本由 5 到 6 | 示例成本链 6→6.8→8 自动变为 7→7.8→9 | 加入本期排除费用或改历史成本快照。 |
| RMB 切换 IDR/USD | 按展示汇率显示同一标准 | 重建成本版本或改变原值。 |
| 同 PID 两外部规格映射同内部 SKU | 两条独立记录，默认同价，可独立覆盖 | 按内部 SKU 去重。 |
| 给同 PID 选择其他 SPU 的 SKU | 阻止保存该不一致关联 | 允许跨款式 PID。 |
| 保存未关联内部 SKU 的正式渠道规格 | 必填引用校验失败 | 生成待匹配正式记录或虚构内部 SKU。 |
| 平台改单与 PCS 改单 | 正常变更按各自方向同步达到一致 | 只留差异不采纳，或无限回传循环。 |
| 多销售关联共享可售 100 | 仍为同一个库存池，后续占用统一扣减 | 算成多个 100 的内部库存。 |
| 同一维护人执行审核 | 权限允许时正常完成并分别留动作 | 因两角色为同一人而阻断。 |

这是对设计一致性的逐项推演，不是代码、自动化、浏览器或性能验收。剩余来源核查和字段实现参数列于 [设计门槛](decisions-and-gates.md)。
