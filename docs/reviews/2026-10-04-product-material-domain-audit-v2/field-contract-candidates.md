# 字段归属与页面契约细化稿

更新：2026-10-05。业务口径以 [业务基线](confirmed-rules-and-refinements.md)与[64 项确认登记](decision-register-2026-10-05.md)为准。本文件落实字段层级、必填、来源、单位、变更与页面；实现命名、现有代码映射和少量编码参数尚需完成，不代表已经实现或迁移。

## 1. 领域边界与唯一维护责任

| 领域 | 负责维护 | 对其他领域的引用 | 页面边界 |
|---|---|---|---|
| 基础配置 | 分类、独立属性、取值、分类模板、统一尺码、Pantone、单位定义、编码参数 | 被引用对象及来源映射 | 配置入口可集中；各字典语义独立。 |
| 商品档案 | 款式衣服 SPU、内部商品 SKU、基础内容与身份规格 | 技术资料、测款、渠道关联 | 无供应商/库存事实，不增加开发项目。 |
| 物料档案 | 五类物料主档、SKU/阶段、标准规格、单位关系、识别码与资料 | 工艺、花型、标准成本 | 无供应商页签、库存摘要、空差。 |
| 物料标准成本 | 人工标准采购、基础运输、逐道按产出的加工费及生效版本 | SKU/阶段、单位换算、前驱成本 | 不区分 Asaya/其他品牌印染费用；展示币种切换不改费用原值。 |
| 技术资料/生产工艺 | BOM 多投入及数量、工艺定义、作用对象、产出要求与版本 | 成品/物料 SKU、花型、裁片/半成品身份 | 物料派生和裁片加工分开；毛织多投入不伪装成单前驱物料。 |
| 采购/供应管理 | 供方、报价、采购方式/地区/收货策略、实际采购条件 | 商品/物料 SKU | 实际采购选择供应商，档案建档不依赖供方。 |
| 生产执行 | 加工单、成片/缝盘、裁片加工、返工及交接事实 | 技术资料和投入/产出身份 | 创建加工单不依赖库存有无或库存接口成功。 |
| WMS/订单履约 | 实物及可售库存、占用释放、收发批次 | 相同 SKU 的所有销售关联 | 共用可售池；平台观测量不反写成库存主事实。 |
| 渠道经营 | 店铺、PID 容器、平台规格映射、价格、发布及双向同步 | 同一款式 SKU、基础资料、测款单、共享可售口径 | 正式历史记录全部匹配；无开发项目、无未匹配队列、无预切店铺库存。 |

本轮是原型设计。DDD 用于事实归属和动作边界，不引入微服务、真实后端、完整离线队列或通用领域框架。真实平台连接能力与原型演示分开验收。

## 2. 基础配置与物料身份字段

### 2.1 基础配置的目标清单

| 配置 | 核心内容 | 使用规则/确认来源 |
|---|---|---|
| 品类 | 独立属性值及业务名称 | “套装”等；独立于正式分类树、风格和品类编号（U05）。 |
| 风格 | 独立属性值及名称 | “休闲”等，不以品类编号代替（U05）。 |
| 品类编号 | 正式业务编号、中文/外文名称、状态和排序 | 如 89-Printed Set-35-55印花套装；编码不从数组位置生成（U05）。 |
| 品牌 | 稳定引用、名称、外部品牌映射 | 单选，平台品牌 ID 独立（A05/B10）。 |
| 商品定位 | 基础款、设计款等完整已用选项 | 单选；保留线上各已用业务选项（B10）。 |
| 风格/流行元素/特殊工艺等营销属性 | 独立属性及可多选值 | 标签不直接生成生产任务（B10/C01）。 |
| 人群/年龄/人群定位 | 各自的独立多选值 | 保存字段语义，不用一个总备注字段替代（B10）。 |
| 服装尺码 | 一套字母/数字/均码及顺序/展示别名 | 无品类/市场体系 ID；平台名称映射不制造第二套内部尺码（U04）。 |
| 颜色/Pantone | 标准颜色、Pantone 体系和编号、名称、别名 | 染色要求 Pantone；样图为资料而非替代必填值（U03）。 |
| 物料分类/属性模板 | 五类及子类、字段类型/单位/身份层级/必填条件 | 主档、SKU、包装、批次和工艺参数分开（B01—B05）。 |
| 单位 | 单位编码、名称、量纲、精度、固定换算 | SKU 自有主辅关系和包装/规格换算，不用全局任意系数覆盖（U06）。 |
| 花型/工艺/编码参数 | 花型引用、工艺作用对象、A/AB/PT/XH/YH、渗透印参数 | 花型资料继续由其资料对象维护，配置保存引用和规则（U07—U10）。 |
| 价格展示参数 | 支持币种、展示汇率及方向/时间、费用类型和精度 | 默认 RMB，支持 IDR/USD；不设计成本汇率重新生效流程（U14/U21）。 |
| 平台/店铺属性映射 | 当前三渠道、两市场及必要外部属性 | Shopify、TikTok、独立站；ID/MY，默认一店一市场（U22/U23）。 |

原型原有“风格编号”面板的全部读写和数据来源需要映射为正确的目标属性，不能仅修改显示标签而让商品仍读数组序号。原始“面料”营销选项中纤维/组织/面料名称的差异保留来源，按目标成分/组织/营销属性分别映射。

### 2.2 档案字段层级

| 字段组 | 字段及类型方向 | 层级/必填 | 来源与修改规则 |
|---|---|---|---|
| 主档身份 | 稳定 ID、业务编码、名称、多语名、类别/子类引用 | 主档；身份和主名称必填 | 编码默认生成；迁入原码保留；审核后不随改名或供方变化修改（A03）。 |
| 根技术规格 | 成分明细、组织、幅宽、克重；纱线纱支/股数/捻度；分类适用参数 | 主档或按子类模板；适用身份字段审核前必填 | 幅宽只有一个值，语义有效幅宽；cm。克重明确 g/m²，不把 KG 直接迁入（U02）。 |
| SKU 身份 | 稳定 SKU ID、父档案、规格值、SKU 编码、识别码、状态 | SKU；必填 | 默认服装颜色/尺码；物料按分类色花/规格/加工阶段，变更实质规格使用新身份（A04/F04）。 |
| 加工关系 | 直接投入物料 SKU、产出 SKU、根物料、工艺定义/版本、作用对象 | 物料加工阶段；加工 SKU 必填 | 与生产多投入 BOM、裁片加工记录分开，不随工艺名称相同而折叠。 |
| 色花 | 标准颜色、Pantone 体系、Pantone 编号、花型/版本、正反花型引用 | SKU/加工定义；染色 Pantone 必填；印绣花型必填 | pl001197 为花型编号；A/AB 与渗透印独立参数进入编码（U03/U10）。 |
| 设备适配 | 设备类型/型号引用和适配说明 | 配件关联，多值 | 不写入颜色字段，适配关系不因重命名设备丢失（B05）。 |
| 主辅单位 | 主单位、多个辅助单位、换算数量和依据 | SKU；主单位必填 | 见第 3 节，单位不能混作颜色/服装尺码。 |
| 包装 | 包装种类、含量、含量单位、版本 | SKU 关联包装规格 | 单纯含量变化不自动新建永久 SKU（B14）。 |
| 物流测量 | 净重/毛重、长宽高/体积、测量基准和单位 | SKU/包装适用字段 | 标准资料可维护，实测批次结果在对应业务域（B15）。 |
| 素材 | 文件引用、用途、名称、类型、版本 | 主档/SKU/花型/技术资料 | 主图、实物样、花型、销售图等角色明确；新审核需可识别资料（F03）。 |
| 责任与审计 | 维护/审核角色、操作人、时间、变更原因、版本 | 相应对象 | 同一人可维护及审核；Vendor 旧值身份继续技术核对，不自动转供方（U30）。 |
| 来源 | 来源系统/原 ID/原码及必要原值 | 来源映射 | 本期不设坏数据修复工作台；原始调查保留供追溯（U31）。 |

空差、全幅/净幅派生计算、库存、供方联系方式/供货链接不进入物料目标主档表单。移出的采购字段由采购侧承接，空差按用户要求排除；不以此抹掉原始核查证据。

## 3. 计量单位 Tab

### 3.1 展示与字段

SKU 详情的“计量单位”Tab 上方显示唯一主单位，下方列出辅助单位。主档未选择具体 SKU 时，展示规格列表及各自主单位，并进入所选 SKU 的单位视图；不假设整个 SPU 必须只有一种主单位。

| 字段 | 类型/约束 | 必填与说明 |
|---|---|---|
| SKU 引用 | 稳定 ID | 每条关系必填。 |
| 主单位引用 | 单位 ID；每 SKU 唯一 | SKU 必填；主单位在此集中展示。 |
| 主单位数量精度 | 配置引用/正数精度规则 | 按业务单位配置，不在库存字段另造口径。 |
| 辅助单位引用 | 单位 ID；同 SKU 不重复有效关系 | 每条辅助关系必填；支持多行。 |
| 对应主单位数量 | 正十进制数 | 表达“1 辅助单位 = X 主单位”，显示明确方向。 |
| 换算依据 | 固定/规格标准/包装含量的明确依据 | 跨量纲和包装换算需要可解释依据；不能默填 1。 |
| 依据版本 | 稳定关系版本或来源版本 | 使用过的关系变更留痕；下游单据保存采用时的关系。 |
| 适用用途 | 采购/计价/发料等 | 选择相应动作允许使用的单位。 |
| 状态/变更说明 | 有效/停用及文本 | 停用限制新增选择，历史仍可追溯。 |

关系唯一性、正数和缺依据校验属于方案基本防错；此处具体字段命名仍为设计。不会新增库存数量、库存换算按钮或供应商页签。

### 3.2 示例及边界

- 主 M、辅助 Yard：1 Yard = 0.9144 M，关系固定。
- 主 PCS、辅助包：按具体包装定义，例如 1 包 = 100 PCS；另一包装含量独立版本管理。
- 主 M、辅助 KG：只有确认了相应规格换算依据后可维护；标准理论换算与批次实测换算分开。
- 改当前关系不得重算历史单据保存的数量；不因打开 Tab 或切显示单位写回一批业务记录。

## 4. 标准成本字段与界面

| 字段 | 必填/范围 | 计算与变更 |
|---|---|---|
| 成本对象 | 物料 SKU/加工阶段 ID | 每个阶段可追溯到上道标准。 |
| 人工标准采购单价 | 基础料核价时必填，缺失与 0 分开 | 含税；人工维护，不跟最近一笔采购自动走。 |
| 基础标准运输单价 | 明确金额或真实 0，核对是否已含运 | 只在基础层计一次。 |
| 上道标准引用 | 派生物料核价必填 | 显式前驱及成本版本，不用字符串解析。 |
| 本道标准加工单价 | 加工核价必填 | 按产出计，含税且已含染化料/绣花线等辅助费用。 |
| 计价单位 | 费用及累计值均明确 | 对应产出单位；输入/输出单位不同先按有依据的标准关系归一。 |
| 来源币种/金额及计算依据 | 原始来源需要时保留 | 不能丢弃旧采购币种；展示换算不修改这些原值。 |
| 累计成本 | 计算字段 | 上道标准加本道加工费；基础为采购加基础运输。 |
| 展示币种 | RMB 默认，IDR/USD 可选 | 同一个成本的换算结果，不是三份独立维护价。 |
| 展示汇率 | 汇率方向、数值、来源/时间 | 仅用于币种展示，变化不创建标准成本生效版本。 |
| 成本版本/原因/操作人时 | 标准金额变化时留痕 | 自动传递到依赖阶段；历史单据快照保持。 |
| 完整性 | 完整/缺价等可解释状态 | 不把未维护金额显示成真实 0。 |

界面按“基础采购、基础运输、承接上道、本道加工、累计标准”展开。印花/染色只保留共同价格，不做 Asaya/其他品牌两套表。后段运输、损耗、缩率、一次性费用及额外辅材成本均不增加输入行或计算分支。

本轮保留标准成本版本用于追溯，不引入成本汇率调整发布/审批流程，也不因用户允许同人审核而增加不必要的岗位分离限制。

## 5. 渠道店铺商品字段与动作

| 对象/字段组 | 核心字段 | 约束与来源 |
|---|---|---|
| 店铺 | 内部店铺 ID、经营渠道、外部店铺 ID、名称、市场、销售币种、结算币种、时区、经营状态 | 当前 Shopify/TikTok/独立站，ID/MY；默认一店一市场。 |
| PID 容器 | 内部记录 ID、店铺、外部 PID、内部款式 SPU、来源、建立时间 | 正式记录必须明确所属款式；外部 PID 在对应渠道/店铺命名空间识别。 |
| 共同内容 | 标题、详情、平台类目/属性及版本、图片/视频及顺序、销售尺码图、语言 | 内容可初始化继承；店铺覆盖值独立；技术尺寸引用正式来源。 |
| 平台规格 | 内部记录 ID、父 PID、外部 SKU ID、sellerSku、平台属性/显示名、图片 | 按外部实例保留，不按内部 SKU 在 PID 内去重。 |
| 内部映射 | 内部 SKU ID、映射版本/来源/生效时间 | 正式历史和新记录都必填；内部 SKU 的 SPU 必须等于父 PID 款式。 |
| 价格 | 默认价格来源、按外部规格的显式覆盖、价格类型、币种、生效范围 | 同内部 SKU 默认相同，覆盖后可不同；同步不抹掉覆盖价。 |
| 测款关联 | 可选测款单 ID、渠道上架动作关联、发布结果引用 | 无开发项目、项目 ID、项目节点或其必填限制。 |
| 发布 | 指定发布内容版本、动作、任务 ID、提交/回执时间、结果、外部身份 | 新刊登和更新区分；重试不创建重复外部实例。 |
| 双向同步 | 方向、对象/字段范围、变更版本、来源标识、最近成功状态、必要回执/失败原因 | 正常两向变更自动同步；失败不能伪称一致；不以每次人工采纳作为正常步骤。 |
| 平台状态 | 平台原状态、对照展示状态、更新时间 | 平台审核/风控等只读事实按平台权威回传；本地发布意图与实际结果分开。 |
| 可售关联 | 内部 SKU 及 WMS 共享口径引用 | PCS 不自建数量事实；平台观察数量若保留，只用于同步记录。 |
| 历史 | 变更、价格/内容/映射版本及操作事实 | 映射纠错不自动改已完成订单；停用不自动下架。 |

### 5.1 双向同步的字段责任

- 渠道标题、描述、媒体、可写平台规格显示信息和售价：PCS 与平台均可成为变更发起方，正常路径应传播到对侧。
- 内部 SKU/款式身份、技术尺寸与标准成本：由内部所属领域维护，平台规格仍通过映射引用；不会把平台改名当作内部实物规格变更。
- 平台原生状态：平台为实际结果来源，PCS 的发布/下架等请求不冒充结果已经生效。
- WMS 库存：WMS 唯一权威，订单占用/释放经相关领域处理；平台数量回传不能直接替代 WMS 主事实。
- 同时改同字段、延迟回执等的技术处理需设计；最小原则是有版本/来源、避免循环、错误留痕，不能用“最后收到的一条必然最新”代替业务一致性。

### 5.2 可售共享与套装

同一个内部 SKU 的多个外部实例共用可售池，不能因三个链接都显示 100 就把内部库存算为 300。默认方案不设店铺分配额度。不同外部售价并不产生不同库存池。

固定实物套装按套收发时有明确成品 SKU；虚拟搭售维护组件和数量定义。虚拟搭售在单 PID 同款式、每个平台规格匹配一个内部 SKU 这两个约束下的承接结构继续细化，不据此新增第四层商品档案或默认允许跨 SPU PID。组合可售计算属于库存/履约职责，本轮没有给出新的套装库存算法。

## 6. 状态、权限和页面组织

- 档案状态、审核状态、平台在售/审核状态、同步结果分别表达；不沿用同一旧 status 数字的混合语义。
- SPU/初始 SKU 可一并审核，后增 SKU/加工结果单独审核；同一人可维护与审核，两动作留痕。
- 物料详情采用基本资料、SKU/加工关系、计量单位、标准成本、资料/操作记录等分工；无供方/库存/本地资料维护页签。
- 渠道以店铺 PID 列表进入详情，展示规格映射、价格、内容、测款关联与发布/同步事实；不按开发项目或上传批次充当商品主身份。
- 基础配置各属性独立；商品尺码一套。品类、风格、品类编号分开展示和维护。
- 历史异常治理和待匹配队列不在本期范围。新建/保存依然校验必填、正确父子引用和编码唯一，防止产生与已确认约束冲突的新记录。
- 历史来源、编码别名、旧附件证据保留；没有清空本地资料、写数据库或自动迁移的授权。

## 7. 尚需完成的设计工作
