# PCS 原型调整：实施工作包与验收计划 R1

计划日期：2026-10-05；状态更新：2026-10-06。**用户已授权执行 R1，各工作包已有本地实现，仍在逐项验收，尚未关闭。** 执行依据为 [方案正文](prototype-adjustment-proposal.md)、[字段字典](field-dictionary.csv)、[原子需求矩阵](requirement-traceability.csv)。本文件没有授权数据库写入、浏览器资料删除、提交或发布。实际结果以 [实施进度](implementation-progress.md) 和 [当前证据索引](current-requirement-evidence.json) 为准。

## 1. 完成标准与依赖顺序

原型完成需要同时满足：业务对象仅一处维护；五类物料和渠道商品能连续走通主要场景；线上信息有明确承接位置；应退役入口和重复事实已收口；记录/附件保存可靠；实际页面、设备和性能证据已生成。构建、Mock 数量和文档条数不能替代这些结果。

建议次序：WP01 定身份与变更范围 → WP02 基础配置 → WP03 商品档案与 WP04 物料档案 → WP05 单位 → WP06 成本 → WP07 渠道商品/店铺 → WP08 发布同步 → WP09 上下游桥接 → WP10 全链收口。WP10 的存储与通用校验从 WP01 起随各工作包实施，不能最后才补持久化。WP03/WP04 可以在契约稳定后独立排期，本计划不要求多代理并行。

各包开始前重读当前 HEAD、工作树与实际服务；本轮现状基线为 `main / 88324f65506f47c678b17d1b51879f8fd7c2488a`，验收不得沿用本次旧截图或另一工作树的页面。主文件名是当前定位，不要求按表新建大量通用模块；需要的新结构落在直接相关的现有模块，新增文件须绑定负责需求。

## 3. 每个业务对象的读写与关联登记

下表是目标记录边界，括号中的英文名是逻辑对象名，不要求新建同名 IndexedDB 对象仓库。优先复用 `pcs-record-db.ts` 已有记录组织；物理存储名称在 WP01 绑定。固定演示源保持静态，用户变化按记录保存。

| 对象 | 唯一保存责任 / 原子动作 | 全部必须覆盖的读入口与关联 |
|---|---|---|
| 配置项及模板版本 | 保存值、版本、审计；不把13个字典整包重写 | 配置列表/编辑、建档选择器、批量建 SKU、导入、已停用值历史显示 |
| SPU＋首批 SKU | 一次建档/合并审核原子保存主档、首批规格、资料引用、日志 | 款式/规格列表、详情、直达、新增规格、复制、测试上架、技术包、渠道选择 |
| 物料根＋基础 SKU | 建档保存根、规格、单位、识别素材、日志 | 五类列表、SKU 视图、主档/SKU 详情、技术引用、采购/加工选料 |
| 加工产出 SKU＋加工定义 | 一次保存输出 SKU、唯一前驱边、工艺资料和日志 | 加工树、成本依赖、设计改款、技术BOM、加工单、条码、PDA消费 |
| SKU 单位/包装 | 主单位及关系版本与包装含量一致保存；当前依赖成本的必要变更同动作处理 | 单位 Tab、核价、采购计价、发料、用量、打印、历史采用系数 |
| 标准成本版本 | 单价及依赖关系、受影响当前版本一致提交；不可一半已新一半旧 | 成本树、SKU列表摘要、未发布 BOM参考、冻结的历史核价/业务单据 |
| 店铺 | 统一 storeId；业务身份与销售/结算配置一处保存 | 店铺列表/详情、渠道新建、同步、测款上架选择器；无第二份项目店铺 |

| 附件实体与引用 | Blob 元数据/实体/对象引用一致提交；复制复用文件 | 原图、主图、花型图、执行稿、尺码图、导入导出、复制、替换、历史资料 |

物料旧整包项 `higood-pcs-material-archive-store-v2` 已由代码确认。其他旧项按现有仓库登记，不猜键名。转换前记录旧键/对象仓库/附件与归属，关闭受影响旧写入；转换后读回核对实体、关系、数量、单位、引用，再按既有规则处理已验证来源。不做整站清空，不把转换按钮塞回 PCS，不把旧表包裹为一条新快照继续写。

若同动作对象在现有存储中分库，先收口本动作的存储边界再宣称原子性；不能把两个成功提示视为一个事务。保存成功以事务 complete 为准，失败保留原记录和本页输入。当前已完成的事务、失败保护和转换验证见 [实施记录](implementation-progress.md) 与 [证据说明](evidence/README.md)，未闭环入口继续按矩阵登记。

## 5. 原型演示数据设计

所有样例明确为演示，不自动导入真实数据库。已有可用图片优先复用；不能只用名称、色块或不可加载的URL通过验收。用户附件与静态示例分来源。

| 场景组 | 最少准备 | 目的 |
|---|---|---|
| 商品 | 6个款式：普通款、多色多码、同款异品牌、固定套装、虚拟组合、无渠道款；每个至少2个合理SKU（固定套装可1个） | 覆盖身份、状态与组合关系；包含独立品类/风格/编号 |

| 加工链 | 基础→染色→印花，另有绣花/烫画分支；A、AB同花、AB不同花、渗透；旧xPT别名 | 真实前驱、阶段规格、花型资料和加工单传参 |
| 单位 | M/Yard、KG跨量纲有依据、PCS/包100/包600、纱线KG/筒 | 不同SKU默认单位不同；缺依据仅做未提交失败用例 |

| 平台商品 | 至少8个PID；其中同PID3个外部规格映射2个内部SKU；同店铺同款2个PID；至少1个外部独立价格 | 证明父容器、外部实例、内部SKU不能互代 |

## 7. 证据与关闭规则

每项原子需求记录实际文件/符号、自动化结果、相关S场景、截图/录屏/打印结果、完整耗时、Git HEAD、服务工作树、设备和确认版本。适用页面时间以数据读写/计算/渲染均完成且可用为终点；出现 Loading、骨架或 Toast 不算完成。每场景至少保留首次与重复操作样本、最大值和环境；不以平均值掩盖超时。真实平台网络耗时不冒充本地原型性能结果。

必须正向核对“64决策→正文→原子需求→代码→证据”，再反向核对“页面/字段/按钮/Mock/测试→原子需求”。旧项目对象、独立变种、库存/供方维护、品牌价分栏、假平台ID和旧维度名称分别核查菜单、路由、类型、处理器、保存、导入导出、测试；只隐藏按钮不算删除完成。

无命名页面、图片或性能证据的需求最多标“已实现待验证”。只有负责需求全部到达约定状态才能关闭工作包。源码本地实现、远端提交、公开部署、产品接受分别记录；本计划不提前合并这些状态。
