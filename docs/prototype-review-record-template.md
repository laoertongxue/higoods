# 原型变更记录模板

依据 `AGENTS.md` REVIEW-01、PERF-01、EVIDENCE-01。只复制本任务适用的一种格式到 `docs/prototype-review-records/`，不为小任务复制完整审查表。同一事实只写一次，可引用已有有效证据；旧完整 / 轻量格式继续可读。

## T2 简要记录

文案 / 纯样式用“轻量可见变更”；行为确实不变的内部整理用“无用户可见影响声明”。简要格式不得承载动作、业务、数据、存储、路由或公共接口契约变化。

```markdown
# 本次变更
## 简要记录
- 记录模式：轻量可见变更
- 对象 / 路由：待填写
- 改动与边界：待填写改动、未变化的契约及核验方法
- 契约变化：无
- 版本：待填写日期、分支 / HEAD、文件哈希、实际服务 / 设备等适用信息
- 验证人：待填写
- 证据：待填写实际操作、观察结果与截图 / 日志或已有证据位置
- 性能：不适用（待填写未影响加载、布局成本或事件链的具体依据）
- 结果：通过
## 受管文件
- `src/实际文件.ts`
```

可见变化须有真实页面证据；性能实际受影响时将“性能”改为“通过：原始样本位置及版本”，按 PERF-01 验证。失败不能写通过。无可见影响模式可省性能字段，但须在记录中增加下列实际已通过的直接技术命令；不能只靠格式 / 治理检查证明行为不变。有效历史证据可按 EVIDENCE-01 复用。

```markdown
## 验证命令
- `实际直接技术验证命令`：通过
```

轻量可见模式不为了凑字段额外运行格式命令；实际运行的命令可同样登记。若保留历史列表结构，仍追加“历史列表局部修正”表，逐文件记录 `文件 | 基准 SHA256 | 当前 SHA256 | 依据`，并满足 LIST-01 的结构比较与页面证据要求。

## 行为 / 业务变化的完整记录

只为实际适用结果列自查项；复杂需求矩阵已有结果时按编号引用证据，不重复抄表。仅复制下面块，并用真实值替换全部示例。

```markdown
# 本次产品审查
依据 `AGENTS.md` REVIEW-01。
## 基本信息
- 日期：YYYY-MM-DD
- 任务 / 需求编号：实际任务或编号
- 验证人：实际执行者
## 影响判定
- 记录模式：完整产品审查
- 用户可见影响：有
- 判定依据：本次改变的业务行为
## 自查结论
| 检查项 | 结论 | 证据 / 问题及处理 |
| --- | --- | --- |
| 实际独立结果 | 通过 | 对应证据位置或矩阵编号 |
## 最终结论
结论：通过
## 受管文件
- `src/实际文件.ts`
## 页面证据
- 版本：日期、分支 / HEAD、差异哈希、服务 / 工作树、设备和实际资产
- 证据：命名路由、动作、结果及证据位置
## 性能结论
- 结论：通过
- 依据：两页默认 Mock 的原始样本、起止点、版本；不适用时写具体原因
## 验证命令
- `本记录承担且实际执行的专项命令`：通过
## 例外
- 无
```

单项结论为通过 / 不通过 / 不适用（附理由），最终结论只有通过 / 不通过；失败记录可保存，不能作为交付通过证据。命令结果使用严格的“通过”或“不适用（具体原因）”，失败 / 未运行不能作为本次交付证据，不在“通过”后追加计数或说明。

记录只声明已完成的产品验收和收据外检查；需要收据时，收据内命令及结果另存，禁止预填或执行后回填绑定报告。最终任务完成须合并全部适用产品证据和技术检查，产品记录通过不替代尚未执行的检查或用户接受。

列表用 `npm run check:list-page-governance`（已包含产品治理），其余产品改动用 `npm run check:prototype-design-governance`；版本与路径范围按根规则。常规 Mock / 性能按 MOCK-01 默认两页，场景有业务依据，不自动继承历史大库规模。
