## 顺序与边界

1. 在独立工作树修正测款单创建、持久化、第⑧步渠道商品及价格阻断，核对 TO-0007 跨页与刷新结果；原有同名实拍图改走仓库本地资源，在干净 origin 用品名与图片相符的 TO-0006 复核建档。
2. 将有明确物料 SKU 的草稿 BOM 映射到基础态变种，保留已发布技术包快照。无 SKU 身份的历史行不能自动猜测物料身份，留待补充业务映射依据。
3. 修复生产对象编号入口和与现行数据相符的专项断言，保留对“裁片完成”展示的检查。
4. 最后运行关联 spec、TypeScript、构建、列表治理及命名路由；在原型审查记录中登记原始性能样本和用户授权例外。
5. 后道 QC 主线补齐：将既有 3 组后道验收生产来源抽成无运行态依赖的共享 Mock；生产需求、生产单与后道来源都读取该组身份、SKU 数量及工厂。保留既有 QC / 回货编号；按现有 Mock 初始化补入款式/SKU 档案、发布态演示技术包 Mock V1.0 和冻结快照，并通过标准上游校验。页面和审计记录明确其为原型样本，不代表真实技术文件发布。新增 QC 专用款和生产单不参与原有设计改款、通用字典工艺样本轮换。专项核对每条 QC 的生产单与需求、15 个 SKU 数量和主工厂，浏览器从 QC 与生产编号打开总览后可继续追到需求。
