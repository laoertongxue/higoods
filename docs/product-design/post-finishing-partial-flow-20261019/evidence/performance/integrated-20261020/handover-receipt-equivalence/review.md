# 后道出货实收摘要等价审查

日期：2026-10-20。独立静态审查 + 公开 Node 业务命令契约。未启动浏览器、构建或读取真实数据库；本结果不代表性能达标或现场业务执行。

## 基线身份与运行方式

`before-handover-head.ts.txt` 是 HEAD 原实现。该文件当前任务 diff 只包含本次摘要优化，因此作为真实 pre-summary 基线。Node registerHooks 仅拦截该规范文件 URL 的模块加载，向整个依赖图提供旧原文，其余依赖仍读当前工作树。这样不产生旧模块/新模块混用的循环依赖，也没有替换产品磁盘源码。基线和当前分别在独立 Node 进程执行同一脚本、固定时间、相同公开入口生成的事实。

先前捕获的 `intermediate-first-patch-capture.ts.txt` 已含第一版摘要实现，其身份已纠正，保留作过程证据，不用它冒充修改前源码。它与最终版的差异是 Map 保持首个匹配以及快照建立时机。

## 静态结论

新 getter 每次遍历当前 outboundOrders，返回出货 ID、单号、状态、实收时间及各行实收之和。字段均为 primitive，每次创建新数组/对象，不引用原行、无缓存、无写入。旧逐张读取为 `.find(id || no)` 后 clone，再对各行 `receivedQty || 0` 求和；新摘要保留同一口径。

同步 bulk read 内只建立一张临时 Map，同时登记 ID 与单号且只在 key 不存在时写入，保留旧 `.find` 的首个匹配优先顺序。快照在 pickup 构建之后建立；同一次同步刷新中无异步写入。普通和专用后道目录各自创建当次快照，不跨读取复用。单张既有调用仍走旧完整 getter。数量、差异、完成状态、实收时间和 hydrate 逻辑未改变。

## 实际等价契约

七阶段：静态染色初始化前/后；公开回货→实收确认→送检→QC选择两项→逐项1000→明确100/100/800三次复检→扫码→完成生成三张出货；首张100实收；第一张100及第三张授权799实收、第二张待收；第二张100实收（各张不同时间）；QC无加工项直接出货。

比较每阶段全部 public head 对象、顺序与所有 metadata；包括 all/non-wool/task过滤、类型/工厂/生产单过滤、所有 ID 与不存在 ID、普通及专用后道领用/待交出/完成列表、工厂/全局统计。七阶段共351个 all-head 对象，以及上述派生读取全部 deepEqual。摘要每次逐字段比对完整出货 getter 的投影，断言 primitive-only，并修改返回对象验证源与下次读取不受影响。

基线与当前均 exit0；JSON assert.deepEqual exit0。完整输出保存于 before/after-snapshot.json，命令与阶段摘要见 report.json。输入来源计划仅在隔离 Node fixture 临时调整，结束恢复；下游事实全部由公开业务入口生成。
