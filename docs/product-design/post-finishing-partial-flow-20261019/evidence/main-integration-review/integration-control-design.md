# 混合旧资料及新辅料入口最小集成控制设计

阶段：2026-10-20 main整合后、修复前设计；尚未运行，不预填通过。拟新增独立 `tests/post-finishing-accessory-integration.spec.ts`，不改既有本期三套新测试或产品源码，主代理负责实现与最终窗口。

输入边界：加工/QC/复检由本期公开回货→实收→送检→领取QC等命令创建，再仅编码为明确旧schema2表示；辅料使用main已冻结post/postLegacy隔离验收来源，明确是历史初始夹具，不冒称本次上游实操。混合包中的加工和受管辅料可属于两张不同真实fixture生产单，保留各自SKU与来源，禁止把AW物料强塞给加工SKU。两库快照按实际记录/附件内容比较，不靠DOM隐藏证明无写入。

## I1 混合旧flow迁移及来源切换

两个明确子场景：先R加工迁移再辅料归档；先辅料归档再R加工迁移。输入同一LS旧flow含公开来源生成的H/N加工/旧Rc，以及受管材料调拨/库存（入10、余7）和关联Blob；保留现有PCS原材料行作重复来源控制。

真实后道work-orders入口点击转换。注入一次本次PCS事务失败，断言旧LS、原材料及附件、现有WLS记录不变，提示真实未保存；恢复后同入口成功。R只迁非辅料活跃事实与完整只读archive，不新建受管材料活跃行、不删除/重写已有PCS材料。H/N、旧Rc、附件可回读；LS仅在R读回校验成功后清理。

辅料从LS切换到R只读archive后，其稳定来源身份和原始版本仍可辨认。显式辅料归档成功后库存为7、历史入库10，无二次库存。刷新、再次prepare/归档/迁移均无重复；若已在R前归档，切换后不产生假冲突或第二批canonical库存。相同LS+archive去重；真实内容不一致单独断言阻断且原源保留。

在完成H/N承接后追加一次实际加工登记和明确交复检，证明新桥baseline不会误伤正常非辅料写入；前后WLS数量及来源不变。保留真实页面截图和两库记录/附件JSON。

## I2 后道备份恢复与辅料事实隔离

目标已有新Accessory正式入库事实；从公开D1来源导出R备份，作为合法旧格式备份加入明确旧managed材料行与Blob。使用真实审计页file input导入，不以直接import返回代替UI终点；等事务完成、当前F及DOM读回再断言。

首次恢复：非辅料事实准确恢复，受管材料只读archive存在，无新PCS活跃材料副本，已有WLS调拨/库存/收货/附件逐条不变。再登记加工、提交复检成功，WLS仍不变。同备份重试幂等；同来源ID不同内容冲突拒绝，数据库不变且输入保留。错误格式→同input合法重试验证本期preserveInput修复未回退。恢复后R再备份/新上下文回读应保留只读材料archive和原Blob；不冒称R范围备份包含全部Accessory活跃事实。

## I3 新managed PDA正式单与角色边界

从main冻结post在途初始夹具进入实际 `/fcs/pda/handover?tab=pickup&materialOrderNo=<正式新号>`。不能只mount导出模板。

ROLE_OPERATOR：实收与库位不可编辑，无确认动作；原F/receivePostFinishingMaterialTransfer对managed单拒绝，两库不变。ROLE_ADMIN、ROLE_HANDOVER、ROLE_DISPATCH分别使用独立上下文验证有确认权限；其他工厂账号拒绝，不能由URL越过工厂边界。使用prototype正式身份夹具，非真实工厂鉴权证明。

选一个授权角色完整走：逐行实收和DLN库位；错误量/缺库位阻断，输入保留。注入事务失败、两库无半套保存、恢复同意图重试成功；新Accessory库存、调拨和齐套一致，PCS无材料副本。刷新及Web正式辅料页回读一致、重复提交不重复库存。该辅料职责不改变本期成衣仓收货角色。

## 原子与保留边界

R迁移的非辅料业务行+只读archive+其Blob须在PCS既有事务边界内保存并读回；清LS在读回之后。WLS显式归档是下一独立动作，保持其自身canonical事实+文件+batch同库同事务，失败保留PCS原档案，不串行双写冒充跨库原子。此设计不要求把两个独立动作合成分布式事务。

需主代理明确的兼容条件：main旧“纯材料整包R转换始终拒绝”是否保留。可继续要求纯材料包走辅料专页，同时允许混合包仅迁非辅料；若改为R可只读归档纯材料，原main契约须相应改验无活跃退休事实/无重复库存/原档案可核读，不能静默忽略旧检查。

实施绑定：主代理随后指定实际新增文件为 `tests/post-finishing-main-integration.spec.ts`，包含4个唯一用例（I1两种顺序分别计例、I2恢复、I3角色组合）。原计划文件名未创建。纯材料guard按原main契约保留。
