## 1. 背景、依据与目标

### 1.1 背景

一个生产单可以拆分成多个车缝任务，由不同三方工厂承接。不同任务的成衣 SKU 可能共用同一种面料。裁床交出裁片时，需要把用于换片的布料一并交给相应任务，并有独立菲票识别这份布料。

仅在生产单上保存“换片布已打印”不能证明某个车缝任务已经取得所需换片布；把同一个票号重复打印给多个工厂，也无法区分实物去向。本方案围绕“生产单—面料—独立换片布菲票—中转袋／直接随交—车缝任务交出”建立一致的业务关系。

### 1.3 本方案目标

1. 自动形成准确、无重复的生产单换片布打印待办。
2. 为每份 5 Yard 换片布建立独立身份，支持新增和补打。
3. 在中转袋中准确表达三类货物及各自单位。
4. 对每个车缝任务按其 SKU 实际需用面料校验，缺失阻断，历史已交不重复要求。
5. 在同次交出中保存裁片与换片布去向，支持 Web、PDA、打印及历史回查。

## 4. 进入、退出与改派处理

### 4.1 自动进入和初始建票

生产单当前有效裁剪分配进入本裁床适用范围时，自动形成打印行。三方自行裁剪的合并任务不进入。不能等接单、铺布或裁剪完成后才出现。

资料完整时，每种合格面料一次性生成 1 张待打印票；资料不完整时保留生产单行并显示“面料资料待核对”，阻断对应建票／打印，不悄悄漏掉该单。核对完成后补齐缺失的初始票。

初始建票是分配进入后的业务结果，打开页面仅展示该结果。刷新或重复读取不重复建票；已有同生产单同面料票时不再创建第二张“初始票”。后续新增必须来自明确的新增动作。

### 4.2 改派移出

用户确认“改派后去掉”落实为原裁床当前列表及可操作范围移除。退出后，即使旧页面、旧预览仍开着，也不能继续新增票、确认首次打印、装袋或交出。

本方案建议的历史处理如下，不表示用户已明确要求物理删除历史：

| 改派时状态 | 当前操作范围 | 历史与实物处理 |
| --- | --- | --- |
| 未打印、未装袋 | 从原裁床待办移除，票不再可用 | 保留失效原因，序号不重用 |
| 已打印、未装袋 | 原票不得继续扫码使用 | 保留打印记录；提示旧标签不再适用 |
| 已装袋、未交出 | 不得随旧分配继续交出 | 保留袋内真实内容并标记“分配已变更”，按现有移出／拆袋方式处理，不在系统中凭空消失 |
| 已交出 | 不回滚已经发生的交出 | 保留原任务、原工厂、票号和时间；不自动转移到新工厂 |

改派到另一个适用裁床，由新分配形成新操作范围；若旧未交票失效后需重建，使用新唯一票号并继续序号。重新回到原裁床也不能把已失效旧票自动恢复成可交票。具体旧票失效／重建采用第 15 节 D02 的方案选择。

若一个生产单存在多个裁剪任务，某个任务改派但本裁床仍保留有效适用任务，不能仅因出现一次改派就删除整单行；须根据改派后的实际剩余归属重算。多裁床并行的面料范围归属按第 15 节 D05 评审，不靠默认选第一条分配。

## 5. 面料识别与 SKU 需求计算

### 5.1 面料来源和去重

生产单清单读取生产单对应的正式技术资料及明确有效的生产执行用料关系。页面同时保留来源版本，避免后续产品档案变化无声覆盖已出票／已交出的历史事实。

任务检查从任务分配的成衣 SKU 出发，结合颜色和适用 SKU 范围，取得实际需用面料并去重。不能只从本次拿到的裁片票倒推全部需用面料，因为某种面料的裁片本次可能尚未交出。

去重时同编码、同实际变体／颜色规格且身份一致的面料共用一个面料对象；同名不同编码、同类不同颜色不能合并。纸样不同、部位不同不应使同一实际面料重复要求初始换片布票。没有可靠身份时阻断对应操作并显示资料缺项，不能用名称猜一个物料编号。

### 5.2 朴的名称识别

用户确认依据物料名称判断。方案默认候选规则为：去除名称首尾空白后，名称包含“朴”的物料排除；不把“衬”“里布”“辅料”自动纳入同义范围，不使用备注代替物料名称。该具体匹配方式列为 D01，需用实际物料名称样本校验后定稿。

示例测试名称“纸朴”“有纺朴”用于验证包含匹配，均为构造测试数据，不表示仓库实际存在这些物料。名称为空时不能判断为普通面料，显示待核对。

### 5.3 需求集合

- 整单打印面料集合：本生产单范围内全部合格面料。
- 某车缝任务需求集合：该任务有效 SKU 需用的合格面料并集。
- 相同面料用于该任务多个尺码，需求集合中只计一次。
- 无合格面料且资料完整：显示“无需换片布”，不伪造空票；资料缺失不等于无需换片布。
- 某任务新增需用面料时只对新增缺项提出随交要求；已有面料不重复交。
- 换料／加工导致物料编码变化时，只认可当前正式资料或明确执行关系给出的映射；不得凭同名、相似图片自动互认。

## 6. 换片布菲票规则

### 6.1 固定规格和初始数量

每张换片布票固定 5 Yard。展示只读文本，不提供长度输入、单位切换或批量修改。每种合格面料初始一张；后续允许新增多张，无需先存在车缝任务才出票。

票可以先属于生产单和面料，交出时再确定具体任务。不得为了打印强制先创建任务分配。是否在装袋时预关联任务，沿用当前装袋入口有无任务上下文；交出前必须明确归属。

### 6.2 新增独立票

在生产单打印详情点击“新增换片布菲票”：选择本单合格面料、输入新增张数（正整数，默认 1），显示“每张 5 Yard，新增 N 张，共 5×N Yard”，确认后建票。可继续选择其他面料；本次不允许自由输入另一生产单面料。

取消不建票；重复点击或同一请求重试不重复建票。不同明确新增动作分别生成新票。张数输入的技术上限用于防止误操作，不得擅自设定业务终身票数上限。

### 6.3 唯一编号

建议专用可读前缀 HPB，结构示意：HPB-生产单稳定号-面料稳定短码-序号。此格式是方案，不是现有代码。完整票号和内部 ID 均须唯一；短码发生碰撞时不能继续出票。

按生产单＋面料连续编号，至少三位，不截断、不回绕；超过 999 后继续 1000。作废、失效票的编号不回收，补打不推进序号。页面排序、筛选、改名均不改变票身份。

扫码内容包含明确的换片布类型及稳定票据身份。不能仅编码生产单号，也不能沿用部位／捆条的同一业务票号。识别类型与票据存在性、有效性共同核验，不能只看前缀放行。

### 6.4 新增、首次打印与补打

| 动作 | 票据身份 | 实物份数 | 状态和记录 |
| --- | --- | --- | --- |
| 新增独立票 | 新身份、新序号 | 增加一份／张 | 待打印 |
| 首次打印 | 使用已建票身份 | 不再增加 | 确认出纸后记首次打印 |
| 补打 | 原身份、原序号、原长度 | 不增加 | 增加补打记录，不重置交出状态 |
| 打开／取消预览 | 不变化 | 不增加 | 不标记已打印 |

补打要求选择原因，如“标签破损、打印不清、打印失败、其他”；其他时填写简短说明。已交出票允许补打用于历史核对，但界面提示“该票已交出，补打不会形成新的可交出换片布”。不新增独立换片布撤销交出流程。

## 7. Web 打印页面设计

### 7.1 标准列表

拟新增路由：/fcs/craft/cutting/replacement-fabric-fei-tickets。该路由尚未实现，不作为现有访问地址。

结构：页面标题与主操作 → 查询卡片 → 统计卡片 → 数据列表卡片 → 分页。使用项目现有标准列表能力，页面主体不横向溢出。

### 7.2 打印详情

明细字段：勾选、面料、序号、票号、5 Yard、打印状态、当前装袋位置、交出状态、对应任务／工厂、最近打印时间、操作。

动作：新增换片布菲票、整单打印、打印已选、补打已选、查看打印记录。跨页选择保留并明确显示已选总数；“全选当前页”与“选择整单”文案分开。

“整单打印”默认选择本单当前有效的全部票，不受明细分页限制。包含已打印票时明确提示“首次打印 A 张、补打 B 张”，已打印部分记录补打原因；不能悄悄跳过已打印票，也不能把补打产生为新票。已失效票不进入当前整单打印，历史查看时说明失效原因。

新增票后列表汇总立即更新，原先全部已打印的生产单变为部分已打印。打开详情、勾选、翻页、展开和关闭使用局部更新，保留滚动与输入。

## 8. 打印票面及打印结果

### 8.1 必填票面

| 信息 | 表达要求 |
| --- | --- |
| 标题 | 最大醒目文字“换片布菲票”，黑白也能辨认 |
| 生产单 | 完整生产单号，长号换行不得截断 |
| 款式 | 款号／SPU，辅助识别来源 |
| 面料 | 名称、完整编码、颜色／规格；真实面料图与标识同一信息区 |
| 序号 | “本单本面料第 002 张”，不使用第 2 次打印 |
| 长度 | 固定“5 Yard”，独立醒目位置 |
| 唯一票号 | 人可读完整票号 |
| 扫码 | 二维码及可读码值；如沿用条码则与二维码指向同一票身份 |
| 打印信息 | 本次打印时间；补打增加“补打”标识，身份不变 |

未确定任务时不印猜测的任务／工厂。实际交出归属保存在交出记录中。黑白热敏纸也必须通过标题、前缀、结构区分，不借用已有白票／盘扣黄票的颜色含义。

拟优先复用现有标签规格，最终纸张尺寸待现场打印机／耗材确认（D04）。不在评审前把某一尺寸写成已获授权的现场标准。预览必须按真实物理比例检查，一票一完整标签；不能裁掉编码、5 Yard 或二维码。

### 8.2 打印完成口径

浏览器无法可靠证明设备实际出纸，原型不声称有设备成功回执。本方案建议采用：预览就绪 → 发起打印 → 返回页面确认“已完成打印”或“未完成，重新打印”。只在用户确认已完成后标记已打印；取消、失败、仅下载／打开预览不自动改变状态。该最小确认交互列为 D03。

整批默认确认全部成功；发生部分出纸时可选择本次已成功票号，未成功票保持原状态。首次未成功票重试仍使用原身份；已成功票再输出记补打，不新建票。

图片和扫码图形未就绪时不允许确认打印就绪。图片缺失显示对象和原因；不得用无关占位图冒充。预览支持点击大图、关闭按钮、遮罩及 Esc，图片保持比例。

## 9. 中转袋混装及全链展示

### 9.1 装袋识别

扫码先识别是部位菲票、捆条菲票还是换片布菲票，再读取各自真实来源。换片布可在现有装袋流程加入，不新增一套平行袋号或单独换片布袋管理。

换片布首次有效扫码条件：票存在且有效、已完成首次打印、生产单仍在当前处理范围、未交出、未被其他有效袋占用。与袋内其他票遵守原有同生产单等约束，本次不放开跨生产单混装。

连续扫描同票提示“已在当前袋内”，不增加份数；在其他袋时显示袋号并引导按现有拆袋／移出流程处理。扫描普通物料码、生产单码不能代替独立换片布票。

### 9.2 三类明细和汇总

| 类型 | 专属展示字段 | 业务数量 |
| --- | --- | --- |
| 部位裁片 | 部位、颜色、尺码、编号范围、票号 | 片 |
| 捆条 | 捆条名称、规格、原票号、来源加工单 | 沿用捆条真实数量及单位，不强行改成片 |
| 换片布 | 面料名称／编码、颜色规格、本面料序号、票号 | 份／张及 Yard，每份固定 5 Yard |

共同展示生产单、真实图片、当前所在袋、任务／接收工厂（已确定时）。不适用的尺码、部位留空或显示“—”，不能填“换片布部位”伪造部位关系。

袋汇总示例：“部位裁片 3 张／300 片；捆条 2 张／按原单位汇总；换片布 2 张／10 Yard；共 7 张菲票”。同单位也只在业务类型相同且含义一致时合计。

### 9.3 拆袋、重装、回收和历史

移出未交出票只解除装袋关系，不删除票、不新增长度。拆袋重装保持票号、面料和 5 Yard 不变，一张换片布票不可拆成两张或拆成 2 Yard＋3 Yard。

来源袋保留内容和结果袋内容必须守恒；换片布分别按票数和 Yard 核对，部位裁片继续按片核对。不能因换片布没有正片数而拒绝整个袋，也不能为通过旧校验填造 5 片。

物理空袋回收、下一次使用不解除旧票“已交出”的事实。袋报废不自动推导袋内换片布损耗或再次可用；沿用既有实物清空／处理前提，不新增损耗流程。

### 9.4 受影响展示面

Web 中转袋列表／详情、PDA 袋详情、待交出仓候选、装袋／重装确认、交出确认、交出记录详情以及相关导出必须读到同一组带类型的明细。

中转袋身份标签仍只识别物理袋，不随本次货物改变。货物标识和装袋清单新增捆条／换片布区域；原颜色尺码矩阵只统计部位裁片。无裁片但有其他类型时，不显示“空袋”。内容超出时分页，续页重复袋号、使用周期和页码，禁止截断。

现有货物标识代码要求每条明细具有正整数片数、颜色和尺码。扩展时按对象类型分别检查：换片布检查面料身份、固定长度和票号，不要求成衣尺码；不能为了通过原检查而伪填尺码或片数。捆条同样使用其原业务必需字段。

历史货物标识补打绑定原使用周期和当时快照，不读取物理袋下一周期的内容。原黑白热敏货物标识的既有图片例外不擅自扩大；新换片布菲票、Web/PDA 识别区仍按真实图片要求执行。

## 10. 车缝任务交出门槛

### 10.1 计算规则

设任务 T 的所需合格面料集合为 R；该任务、该接收工厂历史有效已交换片布面料集合为 H；本次一起确认且明确归属于该任务的换片布面料集合为 C。

缺少集合 M = R − (H ∪ C)。仅当 M 为空，换片布条件通过。通过后仍须满足原有任务有效性、袋状态、部位票合法性、实际可交量等检查。

H 只来自有效成功交出记录；已取消／失败操作、仅打印、仅装袋、不完整历史记录、其他任务和其他接收工厂均不计入。C 只来自本次确认范围的真实票，不能由“我已准备好”勾选框代替。

一张票只能对应一个实际车缝任务的交出。两个任务属于同一工厂，也不能共用同一张票满足两次责任交接。同一任务多个 SKU 共用一种面料，只需至少一份该面料；允许额外随交已新增的独立票，但不要求每批再交。

### 10.2 单袋与多袋

- 单袋操作：C 来自该袋本次交出的换片布。
- 同一任务多袋同次确认：C 来自所有直接袋、拆袋结果袋及本次明确随交对象的并集；同一票去重，并核对只在一个有效位置。
- 不在本次选择范围的袋不参与 C。
- 先对整个确认范围核对，再形成各袋交出记录；不能处理第一只袋时因另一只尚未写入而误判缺料。
- 任一必要校验或保存失败，本次裁片和换片布不得出现一部分已完成、一部分未完成。沿用现有业务预检规则，受影响持久化按第 11.4 节改为同一 IndexedDB 事务；现有整包 localStorage 回滚不能作为目标实现，不宣称已有真实后端事务。
- 重试同一确认返回原结果，不新增交出次数；任务自动接收／开始等关联结果不得在预检或失败时提前发生。

### 10.3 不经中转袋的简易交出

“也可以装袋”不解释为强制装袋。简易裁片交出沿用读取任务单后核对、确认的主流程，增加“换片布”区域：逐种显示所需面料、此前已交、本次需随交和缺少项；扫描／选择未装袋且可交的换片布票，随本次裁片一起确认。

已在中转袋中的票不能被直接交出重复取用，须走对应袋流程或先按规定移出。没有本次裁片交出时不开放独立换片布确认，以满足“不需要独立交出”的范围。

### 10.4 分批交出与任务变更

同一任务第一次交齐所需面料后，后续批次 C 可以为空。后续仍读取 H，不能依靠页面缓存的“已交过”状态。

任务新增需要面料时，只补新增缺项；已交票不得重复拿来交给另一个任务。改派接收工厂不能自动把旧工厂已收换片布算给新工厂。仅改 PPIC 联系人或显示名称、不改变任务及实际接收工厂时，不自动抹掉已发生的交出。已完成历史任务不因上线本功能被追溯改成未交出。

历史未完成任务若缺少可识别的换片布记录，不能批量伪造已交。下一次交出按当前缺项随交；如确有旧线下已交，是否提供专门历史补录是另行需求，本次不自行开放免检或补录按钮。

### 10.5 确认页和结果

确认页在主按钮前展示任务单、生产单、接收工厂／PPIC、本次裁片和其他货物分项数量，以及如下换片布核对表：

| 面料 | 任务需要 | 此前已交 | 本次随交 | 结果 |
| --- | --- | --- | --- | --- |
| 面料 A | 需换片布 | A-001，5 Yard | 无需重复 | 已满足 |
| 面料 B | 需换片布 | 无 | B-001，5 Yard，袋 BAG-002 | 本次满足 |
| 面料 C | 需换片布 | 无 | 无 | 缺少，不能交出 |

阻断文案：“本任务还缺少［面料名称／编码］的换片布，请扫描对应菲票随本次裁片交出。”能够查看缺项和调整选择，但不提供跳过。

确认后回执同时展示本次各类型货物、换片布票号与长度、接收任务和工厂、交出人／时间、关联袋／使用周期，并可进入交出记录。后续查看明确区分“此前已交”与“本次新交”。

## 11. 状态、数量与历史一致性

### 11.1 状态分开表达

| 维度 | 状态／表达 | 改变它的业务动作 |
| --- | --- | --- |
| 票有效性 | 有效、因分配变更失效等 | 当前分配和票据有效性处理，不等同于打印 |
| 打印 | 待打印、已打印 | 确认首次打印；补打只增加记录 |
| 所在位置 | 未装袋、已装入某袋／周期 | 确认装袋、移出、重装 |
| 交出 | 未交出、已交出 | 与裁片同次确认成功 |
| 订单打印汇总 | 待打印、部分已打印、全部已打印、无需换片布／资料待核对 | 从当前有效票和完整性计算 |
| 任务满足情况 | 缺少某面料、此前已满足、本次可满足 | 从任务需用和交出事实计算，不独立手改 |

装袋不改变交出；补打不改变有效性、所在袋及已交状态；空袋回收不改变已交事实。

### 11.2 数量规则

有效票份数 N → 对应换片布长度 5×N Yard。打印次数不是 N；同一票被补打十次仍是一份。全局合计时按唯一票据去重，不把同一票在打印、袋、交出三个地方出现计三份。

裁片实交、剩余、齐套、车缝接收与自动开始所依赖的裁片事实继续只统计合法裁片。换片布不作为裁片产出，不要求对应铺布单／裁剪完成行，不进入部位打编号和特殊工艺回仓判断。

捆条读取已有完成量和合法性，不因本方案统一混装而被默认为部位裁片。既有毛织片票等其他类型保留原行为，本次不删类型、不改其单位口径。

### 11.3 历史兼容

能由已知旧来源准确确认的历史部位票，按其原类型读取；未知类型或缺来源的历史记录只读提示，不能一律猜成换片布。旧片数继续为片，新类型不回填伪片数。

新记录保存当时面料身份、名称、固定长度、票序号、任务和工厂等交接必需信息，避免后续改名改变历史票义；不复制无关产品档案字段建立第二事实源。

### 11.4 本地保存、旧数据迁移与恢复

本节依据当前工作区 AGENTS.md 第 2.4 节，属于后续实现强制边界。本次只登记方案，不执行迁移或清理用户数据。

产品仍为免登录、单浏览器本地原型。固定 Mock 与演示图片读取静态资源；新增票、打印记录、袋关系、交出记录及本次关联状态按记录保存在 IndexedDB。localStorage 仅保留有界的筛选／列偏好，读取或写入失败时使用默认值，不得作为业务保存后备。

| 对象／范围 | 目标存储（对象仓库名称为拟定） | 受影响入口和动作 | 旧来源登记 | 验证 |
| --- | --- | --- | --- | --- |
| 换片布票和新增动作标识 | replacementFabricTickets／operationRecords | 分配进入、改派、新增、打印读取、扫码、导出 | 新增对象无旧键；静态夹具不批量落盘 | A7、S26 |
| 本次打印记录及状态 | printRecords | 首打确认、部分确认、补打、历史预览 | 关联部位旧来源 cuttingFeiTicketRecords、cuttingFeiTicketPrintJobs；只迁移本次链路依赖范围 | A7、S26、27 |
| 三类袋明细和使用周期 | bagUses／bagContents／operationRecords | 装袋、移出、重装、详情、打印、回收读取 | cuttingRuntimeEventLedger 相关事件；旧手动票来源通过 CUTTING_MANUAL_FEI_TICKET_SOURCES_STORAGE_KEY 继续登记具体键值 | A7、S27 |
| 任务交出及自动接收／任务状态 | handovers／handoverItems／taskStates | 单袋、多袋、简易交出及下游回读 | cuttingRuntimeEventLedger；现有任务存储及其他调用入口在 W0 逐项登记，未盘清不得开始清理 | A7、S26、27 |
| 当前资料及图片引用 | 复用受影响资料存储；静态素材维持静态 URL | 列表、详情、标签、交出历史 | 仅引用现有合法文件 ID；若链路含业务 Base64，纳入转换清单 | A7、S28 |

同一动作涉及的票据、装袋、交出、接收、任务状态和操作记录须在同一数据库的同一事务中保存；等待事务 complete 后才发布新内存状态及成功提示。不能只等一条写请求成功，不能把整包旧账本换个位置存成一个大 JSON。校验和图片准备在事务前完成；事务内核对版本、占用及稳定操作标识，避免多标签页抢同票或重复建票。

普通查询、首次进入和刷新不得写入业务种子。自动初始票由分配业务动作触发；历史已有分配的初始化通过明确一次性迁移处理，不能偷偷在列表读取时重复建票。详情、打印和 PDA 直达链接独立读取持久记录，不依赖先打开 Web 页面。

迁移顺序：登记独占／共用旧键和附件 → 停止相关旧写入 → 按稳定来源 ID 分批转换到 IndexedDB → 读回核对数量、内容、引用 → 删除已验证的源项 → 标记该批完成。共用键保留其他模块记录；中断可继续；无法阻止旧标签页继续写入时不删源数据、不宣称完成。处理 versionchange 关闭连接及 blocked 升级提示，不删库重建、不长期双写。

文件如属于静态演示图不复制进数据库。链路中用户文件使用原始 Blob 和文件 ID 引用，不能业务 JSON 内保存 Base64；复制复用引用，替换和删除先核对全部有效引用，清理无引用附件不能误删历史票或其他任务仍使用的图。

复用或提供轻量数据管理入口，支持本次范围的空间估算、带格式版本的完整备份、校验后导入恢复、无引用附件清理。备份包含业务记录、覆盖／删除标记及实际附件，不能只有文件 ID。错误格式、重复／版本冲突需明确处理，失败不破坏现有记录。重置或清理用户业务数据需单独明确授权，不把清空网站作为故障修复方法。

IndexedDB 不可用时明确“用户数据无法读取／保存”，可展示有标识的静态演示内容，不伪装成正常空列表。换浏览器、设备、域名或主动清除网站数据不会自动恢复，本地备份用于恢复。本次覆盖的是受影响动作完整链路，不宣称全站所有模块已迁移。

## 12. 端、图片与性能要求

### 12.1 Web 与 PDA 分工

### 12.2 图片

所有本次出现的款式、面料、捆条对象使用与其对应的实拍／正式效果图，缩略图与编码／名称同一列或信息块。支持大图、遮罩／关闭／Esc、比例保持、低分辨率不溢出。加载和失败可见，可重试；缺真实素材列明对象并作为验收阻塞，不用色块、图标或无关网图冒充。

### 12.3 弱网与保存失败

原型处理第 11.4 节存储及资源失败的明确反馈，不构建离线基础设施。保存失败显示“未保存”，保留用户选择；重试不重复建票、不重复交出。不能弹成功后刷新丢失。预览资源失败与交出保存失败分别说明原因。

### 12.4 验收尺寸和性能

管理端 1366×768，并检查 1280×720；主管／执行 Web 1024×768；PDA 按现有设备核实尺寸，拟包含 360×800 与 400×806。尺寸为验收计划，不表示本次已运行页面。

本次后续实施涉及的页面：冷启动、刷新、站内切换，以及查询、重置、导出、分页、排序、列设置、输入、勾选、新增、图片、预览、打印准备与确认、扫码、移出、重装、交出等所有适用动作均须严格小于 500ms，每项至少 5 次，含首次与边界样本，保留原始值。不能以平均值或骨架屏替代达标。

计时到目标数据、必要图片及可操作结果就绪；用户读写和系统打印对话框内的人工等待不计，但回到页面确认后的系统保存需重新计时。没有 1 秒例外授权。纯文档交付不运行页面性能验收，不因此宣称功能通过。
