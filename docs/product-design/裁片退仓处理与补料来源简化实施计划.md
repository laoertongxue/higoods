# 裁片退仓处理与补料来源简化实施计划

## 1. 目标与完成标准

本计划把《裁片退仓处理与补料来源简化总体设计》落实到当前 Vanilla TypeScript 原型。完成标准：退仓发起、票据证据、件/片数量、退裁片库存、报废、车缝退仓补料、原裁片单关联、补料来源筛选、大菲票、真实图片和标准列表均存在当前实现，并由专项契约、命名页面和项目治理证据闭环。

## 2. 范围与依赖顺序

执行顺序为：共享补料登记 → 退仓领域事实 → 退仓页面 → 补料和裁片单投影 → 仓区/菜单 → Mock 与迁移 → 自动化和浏览器验收 → 治理与任务收据。

不改普通补料的采购、染色、印花和物料准备推进逻辑；不改既有菲票分类与打印分流；不在退仓模块实现齐套、装袋和交出。

## 3. 工作包

### WP-01 统一补料业务来源

- **业务目标**：人工补料和车缝退仓补料可独立筛选、展示和追溯。
- **文件 / 符号**：`src/data/fcs/cutting/supplement-order-registry.ts` 的 `SupplementOrderLifecycle`、`saveSupplementOrder`；`src/data/fcs/cutting/cut-order-supplement-fixture.ts`。
- **修改**：增加必填业务来源、退仓/交出引用和可复用裁片快照；既有 fixture 显式写入人工来源；克隆、身份与校验覆盖新增字段。
- **验证证据**：退仓专项契约；补料列表与裁片单回归。
- **完成条件**：任何新补料单都具有明确来源，车缝退仓来源缺少引用时不能保存。

### WP-02 重建退仓领域事实

- **业务目标**：责任、接收、票据证据、库存、报废和补料结算使用同一事实源。
- **文件 / 符号**：`src/data/fcs/cutting/cut-piece-return-domain.ts`。
- **修改**：从正式车缝交出生成候选；冻结来源；新增发起、接收、报废、按原裁片单拆分补料、大菲票及迁移；移除当前流程中的补料到齐、重新齐套和退仓内再交出动作。
- **验证证据**：`scripts/check-cut-piece-return-processing-v2.ts`。
- **完成条件**：责任公式和库存守恒成立；重复、超量和错票被阻断；结算不可重复。

### WP-03 重构退仓标准列表与操作台

- **业务目标**：主管在一个命名页面完成发起、接收、报废、补料和快速制票。
- **文件 / 符号**：`src/pages/process-factory/cutting/cut-piece-return-processing.ts`。
- **修改**：接入统一列表页、标准表格、分页控制器；增加新增退仓、三步清点、证据模式、详情、报废、创建补料、100mm 大菲票、真实图片大图和错误恢复；校验失败不重绘表单。
- **验证证据**：`tests/cut-piece-return-processing.spec.ts`；三张当前页面截图。
- **完成条件**：1366×768 和 1280×720 无页面横向溢出；完整主链路可演示；错误后输入保留。

### WP-04 补料管理承接来源与深链

- **业务目标**：退仓创建补料即结算，后续只在统一补料业务中查看状态。
- **文件 / 符号**：`src/pages/process-factory/cutting/supplement-management.ts`。
- **修改**：新增来源筛选/标准列/排序/冻结；人工创建显式写入人工来源；详情展示来源、退仓、交出、原裁片单和可复用快照；支持补料单号深链。
- **验证证据**：`tests/supplement-management-list-template.spec.ts` 和退仓完整链路。
- **完成条件**：人工补料既有入口不变；车缝退仓筛选只返回对应来源。

### WP-05 原裁片单反向联查

- **业务目标**：原裁片单能区分并查看多次人工/退仓补料。
- **文件 / 符号**：`src/pages/process-factory/cutting/cut-orders.ts`。
- **修改**：列表标签区分业务来源；详情展示来源退仓、交出和可复用快照；保留同裁片单多次补料。
- **验证证据**：`tests/cut-order-supplement-linkage.spec.ts` 和退仓完整链路。
- **完成条件**：按原裁片单查询可准确打开本次补料，不覆盖历史补料。

### WP-06 仓区和菜单收口

- **业务目标**：退裁片有独立库区入口，菜单可识别，旧齐套/交出入口不残留。
- **文件 / 符号**：`src/pages/process-factory/cutting/warehouse-hub.ts` 的 `renderCutPieceReturnZoneArea`；`src/icons/shell-icons.ts`；`src/pages/process-factory/cutting/meta.ts`。
- **修改**：仓区仅展示在库、已转补料、已报废；声明不直接形成普通待交出库存；为菜单补 `ArchiveRestore` 图标；更新页面说明。
- **验证证据**：退仓专项契约和命名页面侧栏检查。
- **完成条件**：当前代码无可执行的退仓内重新齐套或正式再交出动作。

### WP-07 兼容、Mock 与失败态

## 4. 风险与控制

| 风险 | 控制 |
|---|---|
| 将部位片数当成退件件数 | 件/片分别保存，只有最终退件件数进入责任公式 |
| 退回、报废、补料重复扣减责任 | 责任只读取正式交出和已确认退件 |
| 扫错或重复使用菲票 | 与冻结票号精确匹配并全局去重 |
| 一张退仓跨多个裁片单只创建部分补料 | 按裁片单预构建并原子登记，失败回滚 |
| 退裁片混入普通待交出仓 | 独立库区和独立投影，不生成中转袋 |
| 新来源字段破坏人工补料 | 人工入口显式写入 `MANUAL`，完整既有回归 |
| 表单报错后现场输入丢失 | 错误只刷新反馈区域，不重绘操作弹层 |
| 历史设计继续误导实现 | 当前总体设计声明替代范围，旧文档增加已替代提示 |
