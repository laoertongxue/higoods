## S01 背景、目标与已确认边界

现场暂未实际使用中转袋。PPIC 需要拿打印任务单，到裁床待交出仓领取分给其承接工厂的裁片；仓管需要按任务识别实际裁片，查看逐张菲票，一次确认本批交出。

本次同时完成三件事：

1. 所有已分配任务具备任务单打印能力，未分配任务保留置灰文字按钮。
2. 生产单管理的生产确认单，按用户给出的线上确认单对齐内容结构、图片和打印效果。
3. 新增 Web、PDA 简易裁片交出，并联动裁床交出单、工厂接收记录、PPIC 交出与欠片及可交数量。

**用户明确确认：仓储确认交出，就等同于 PPIC 和三方工厂确认领取接收。** 新增流程不设置“待工厂确认接收”，也不增加一次 PPIC 确认。

| 任务类别 | 已分配后可打印任务单 | 简易裁片交出 | 任务单必须明确的内容 |
| --- | --- | --- | --- |
| 独立车缝 | 是 | 是 | 承接本任务车缝；到裁床待交出仓领取对应裁片 |
| 车缝 + 烫包 | 是 | 是 | 承接车缝及烫包；到裁床待交出仓领取对应裁片 |
| 裁剪 + 车缝 + 烫包 | 是 | 否 | 承接工厂自行裁剪，接收面辅料，再完成车缝及烫包 |
| 其他任务 | 是 | 否 | 按当前任务定义展示其实际工序、对象、数量与承接工厂 |

保留现有中转袋装袋、入仓、交出、回收等能力。此次不改变任务拆分粒度，不新增按任意数量拆分同一 SKU 的分配能力；不扩展裁片退仓、报损、库存调整、对账结算的新流程。已存在的相关记录要正确读取新交出数量。

这是原型调整：复用现有 TypeScript、字符串模板、轻交互与本地持久化，不建设真实后端、跨设备同步、真实鉴权或离线队列。原型内展示的工厂、操作人和业务记录为 Mock。

## S03 角色、业务对象与任务单身份

### S03.1 角色

| 角色 | 负责动作 | 页面显示的责任 |
| --- | --- | --- |
| 计划/分配人员 | 分配任务、查看并打印任务单 | 实际分配记录及承接范围 |
| PPIC | 持纸质任务单到场领取，为指定三方工厂承接裁片 | 本次领取人、所属工厂和任务 |
| 裁床仓管 | 输入/扫描任务单，核对实物和菲票，确认交出 | 真正点击确认的操作人和交出时间 |
| 三方车缝工厂 | 查看本任务已接收裁片和历史明细 | 仓库确认后已接收，不再点击第二次确认 |

打印不代表交出，识别任务码不代表交出。只有仓管确认成功，才产生本次交出和已接收事实。接收记录明确写“由裁床仓库确认交出后记为已接收”，不能伪造工厂操作人或独立的工厂确认时间。

Web、PDA 都校验当前原型账号属于可操作的裁床仓库角色和仓库范围。PPIC 或三方工厂账号可查看自身记录，不能冒充仓库提交。复用现有角色上下文，不建设新权限平台。

### S03.2 对象关系

生产单 → 运行任务 → 有效分配（工厂、SKU 范围、PPIC）→ 任务单身份。

已裁产出 → 菲票（SKU、部位、编号范围、实际片数）→ 本次简易交出记录。

一条交出记录归属一个有效分配，包含多张菲票；工厂已接收记录和 PPIC 已领数量读取这同一事实。一个任务可有多次交出，后续批次只包含新增可交的有效菲票。

### S03.3 编号和扫码协议

以下为拟采用的技术设计：

- 每次有效分配生成稳定的任务单编号，例如 `RW-260916-00123-V1`，同时显示现有任务编号与生产单号。示例仅说明格式。
- 新增编号字段依附现有分配事实；历史已分配任务从当前运行任务、承接工厂和实际 SKU 范围补齐索引。不能因其缺少后来新增的分配记录而将“打印任务单”错误置灰，也不能把补齐索引当作重新分配。
- Code 128 只编码短任务单号，避免将长 JSON 压缩成难扫描的窄条码。二维码复用统一打印载荷，包含文档类型、分配标识、版本、任务单号及目标路径。
- 手输号码、扫码枪条码、二维码解析最后都调用同一个任务单解析函数。
- 工厂、PPIC、SKU 和数量必须重新读取当前有效事实；不信任二维码里携带的旧数量或工厂名称。
- 同一有效分配、同一业务版本重复打印，号码不变；打印行为不生成领取记录，也不累计交出。
- 工厂或任务范围改变时按现有改派产生新的有效分配，旧任务单失效。若同一分配允许责任 PPIC 调整，任务单业务版本随责任变更失效更新；原交出记录保留当时责任人快照。
- 单纯打印时间变化不使旧纸失效。二维码载荷不能跳过版本和有效分配校验。
- 新简易入口提示输入“任务单号”，以纸上同名号码为准，避免让用户猜生产单号或内部 ID。生产单码、菲票码、中转袋码不按任务单误识别。

## S04 任务分配工作台与任务单打印

### S04.1 操作列

每行均显示“打印任务单”文字按钮，固定在查看详情附近。

| 状态 | 表现 |
| --- | --- |
| 未分配、招标中尚未中标、没有有效承接工厂 | 灰色、disabled；可理解提示“分配任务后可打印” |
| 直接分配成功、自动分配成功、中标形成有效分配 | 立即可点击 |
| 已分配但未接单、未开工、未上传合同、尚未领裁片 | 保持可点击 |
| 分配被取消/被替代且当前无有效分配 | 不允许把失效分配当作当前任务单打印 |
| 同一行代表多个当前有效分配 | 简短选择承接工厂/分配范围后打印对应任务单，不能合并成无法区分工厂的一张纸 |

不额外增加 PPIC 是否到场、是否有可交菲票、是否完成裁剪等打印条件。历史资料缺项在预览中说明，核心演示 Mock 需补齐；缺少领取必要信息时仅阻断领取动作。

### S04.2 打印内容

采用 A4 纵向、白底、黑色细表格线；打印按钮和返回按钮只在预览工具栏，不进入纸张。信息顺序：

1. 标题“任务单”、任务单号、真实条码、二维码。
2. 任务类型与明确的任务内容，字号与层级突出。
3. 生产单号、任务编号、SPU/款号、款名、真实款式图、承接工厂、PPIC、分配日期、任务要求完成日期。
4. 本工厂的 SKU/颜色/尺码/分配数量，显示合计，服装数量单位为件；其他工艺任务另按其真实工作量单位展示，不把米、码、批等统一套成件。
5. 交付对象和领取地点。车缝及车缝+烫包写“裁片；裁床待交出仓”；三合一写“面辅料；承接工厂自行裁剪”。
6. 与本任务相关的部位/面辅料、真实图片、纸样资料、工艺与尺寸信息。仅保留适用于本任务 SKU 和工序的内容。
7. 工艺注意事项及有效任务单识别说明。任务单不预先承诺动态的本次可交菲票或仓库实交量；实际可交清单由仓库识别时生成。

两类合并任务按当前工艺策略明确责任：

- 车缝+烫包：承接车缝至烫包，并展示冻结技术包要求的开扣眼/装扣子；由中台工厂负责的辅助/特殊工艺不能误写为承接工厂责任。
- 裁剪+车缝+烫包：承接完整合并任务中已定义的工艺；明确自行裁剪及面辅料领取，不打印“去裁床领裁片”。
- 独立车缝：只写当前车缝任务承担的内容，不因生产单还有烫包等后续任务而一并打印为本厂责任。

纸上同一物料行将图片与名称/编码放在同一信息块。预览可点击大图；纸上保留图片本身。禁止显示“已关联物料图”代替实际图片。

### S04.3 复用与打印副作用

拟新增任务单文档类型 `DISPATCH_TASK_SHEET`、来源类型 `EFFECTIVE_TASK_ASSIGNMENT` 和独立模板，接入既有统一打印预览与模板注册表。预览链接由 `buildUnifiedPrintPreviewLink` 按分配 ID 构建；复用二维码、Code 128、现有图片大图能力与打印 CSS 的最小公共部分。

不复用旧 `issueSewingPickupSlip` 作为“打印任务单”实现：其打印版本与作废语义不等同于任务身份。重打任务单不作废正常分配、不清空历史交出、不更新库存。生产流转卡、交货卡仍为各自用途，不改名冒充任务单。

## S05 生产确认单与线上版本对齐

参考为用户展示并已核查的 [线上 PO18901 生产确认单](https://manage.higood.ai/fcs/production_order/index.html?action=printOrderBarcode&id=18901)。对齐目标是栏目结构、字段位置、实际图片、表格层级和纸张效果；本地不同生产单必须展示自身数据，不能硬编码 PO18901。

| 布卷数、预计总件数 | 实际布卷来源、生产单数量 | 布卷按唯一卷身份汇总，不能按 BOM 行数计数；预计总数用件，不与码数/米数相加 |

| warna & gambar | 颜色/SKU + 对应款式效果图 | 每个颜色明确对应实际图，不能让无键图片数组随机匹配颜色 |
| 纸样 Pola kertas | patternFiles、纸样 imageUrl、附件资料 | 各部位/面料显示实际纸样图和存在的 DXF/RUL/PRJ 链接；只有文件名没有链接时补充来源绑定，不放不可用假链接 |
| Kain & aksesoris 面料 | BOM + 颜色物料映射 | 对齐名称、SKU、部位、单耗/总耗、单位、实际图片、印染/裁剪等要求和仓库信息 |
| Kain & aksesoris 辅料 | 辅料 BOM | 对齐辅料名/编码、单件用量、总量、图片、备料与仓库信息；各单位独立显示 |
| Daftar SK | 生产单 SKU 明细 | 颜色×尺码矩阵、行列合计；捆条信息按实际长度单位显示 |
| Graf ukura | sizeMeasurements | 尺码为行、成衣测量部位为列，带 cm 等真实单位；按线上顺序组织 |

需要在冻结打印快照中显式补充“线上展示字段”的来源映射，包括吊牌价、部分时间/布卷字段、带颜色身份的图片、附件 URL 等当前未完整暴露的信息。不能由模板临时拼无关字段，也不能为了完成布局编造线上事实。Mock 可以补充有说明的演示值。

数量规则：

- 面料、辅料显示真实使用单位。当前模板把面料硬写为“米”的位置需要修正，支持 Yard、米、PCS、DZ、CNS 等原有单位。
- 现有确认快照的总耗可能含损耗，线上示例为单耗×件数。先使用权威冻结用量，并显式区分净用量与含损耗备料量，不能为贴合截图悄悄更改备料业务。
- 用量保留来源精度，不能沿用通用最多两位小数将 298.484 截成 298.48。件/片为整数，长度、用量按各自精度。
- 不混加不同计量单位，不展示 NaN、undefined 或无意义的 0。

打印验收使用同一参考区块顺序和对应密度：标题首表、颜色/纸样、面辅料、SKU 尺码数量、成衣尺寸。调整现有通用模板额外的大块签字区和技术信息页脚，避免它们挤压线上确认单版式。真实业务仍需保留的操作信息放预览工具栏，不能暴露 PrintDocument 等实现词。

## S06 简易交出的菲票匹配与数量规则

### S06.1 读取步骤

1. 解析任务单号，读取对应有效分配与当前版本。
2. 校验任务为独立车缝或车缝+烫包，承接三方工厂和责任 PPIC 明确。
3. 读取该分配的生产单、实际 SKU 范围、颜色、尺码、分配件数以及冻结部位用量。
4. 从实际裁剪产出生成的有效菲票中匹配；特殊工艺后的裁片必须有可追溯的已回仓事实，仍关联原裁片身份。
5. 以生产单 + 精确 SKU + 部位 + 适用范围/编号范围核对归属；不能只用颜色尺码文本或生产单号。
6. 排除已交出、已失效、被其他任务占用、在外加工未回仓或其他不允许交出的记录。
7. 汇总候选清单；本次确认只交出屏幕上这一批。

不要求提前装袋、不要求中转袋入仓、不要求创建临时袋。菲票打印状态不是裁剪完成事实；已生成有效菲票且有真实已裁数量时，不增加“先打印菲票”门槛。作废票不可交。

### S06.2 归属与共存

- 当前独立车缝按完整 SKU 分配时，按本分配完整 SKU 查找，排除其他工厂的 SKU。
- 如果历史资料出现同 SKU 多个承接范围，必须进一步使用现有分配/部位实例/裁片编号范围确定归属；无法唯一对应的票不进入自动可交清单，并说明需处理的菲票。不能按工厂排序、随机或先进先出猜归属。
- 已被有效中转袋占用的票不从简易通道重复交出，提示其袋号及当前去向；仍可按现有中转袋流程完成。简易交出过的票也不能再次装袋后交出。
- 两条路径需要共享“菲票是否已消耗”的查询，提交时重新校验；不能各管一份交出数量。
- 部分票缺少归属资料时，可交的明确票仍单独列出；未纳入原因可展开查看。存在影响本次候选正确性的冲突时阻断该冲突票，不假装已齐套。

### S06.3 数量和批次

| 名称 | 计算口径 |
| --- | --- |
| 分配件数 | 当前有效分配的 SKU 数量合计，单位件 |
| SKU/部位应交片数 | 分配件数 × 冻结的该部位每件片数；只针对适用 SKU/部位 |
| 累计已交片数 | 同一责任范围内有效已确认交出明细的实际片数，去除重复来源 |
| 本次可交片数 | 本次有效菲票逐行实际片数合计 |
| 本次确认后剩余应交 | 冻结应交片数减去确认后的累计有效已交片数；已有退回/作废修正按现有责任账规则处理 |
| 已齐套件数 | 使用现有各必需部位最小配套量规则；不能用总片数直接当件数或把各部位覆盖件数相加 |

本方案拟采用整张菲票交出，不在简易弹窗新增拆票、改片数或拆分数量流程。单票超出本任务剩余范围、包含混合归属或片数不明确时，不截取一部分数字提交；标明原因并交由已有上游资料/菲票处理动作修正。用户核对后一次确认全部已列出的本次可交票；不增加强制逐张扫描、勾选、签字等步骤。

允许分次领取：本次已裁未齐套也可交出当前有效清单，后续已裁票形成下一次批次。待裁数量不冒充可交库存。本次记录“已接收”并不代表整个任务裁片已经全部接收，更不代表车缝或烫包生产任务已完成。

### S07.3 成功与失败

成功保留结果：交出单/交出记录编号、菲票张数、片数、接收工厂、PPIC、交出人、时间；状态“已交出 · 工厂已接收”。提供“查看交出记录”“继续下一单”。

确认前再次校验有效分配和本次票清单。若页面打开期间其他操作已交出其中某票，显示变化，要求重新核对，不静默提交与屏幕不同的批次。新增已裁票也不在点击瞬间自动混进旧清单。

保存失败保留任务单号和核对内容，明确“未完成交出，请重试”。按钮点击立即显示处理中，阻止重复点击；失败后可重试同一批次。局部刷新弹窗与相关统计，不重绘整页或丢失滚动位置。

页面分为三个轻量状态，而非沿用中转袋五步：

1. **识别任务**：首屏主动作“扫描任务单”，扫码枪回车识别，复用可用的相机扫码能力；有“手动输入任务单号”兜底。支持从任务单二维码直接进入后只读识别，不能打开即自动交出。

3. **交出结果**：固定底部“确认交出”完成一次提交，展示同 Web 的成功信息和“继续扫描”。

Web 与 PDA 使用同一个解析、候选生成和提交函数，不复制两套资格判断、片数计算或接收状态转换。交出来源分别记录 Web/PDA。

## S09 一次确认后的记录、库存与工厂接收

### S09.1 单一持久化事实

复用现有裁床事件账，增加独立的“简易裁片交出”事实类型。不要把旧的整袋交出字段全部改为可空，也不要生成 `NO-BAG` 等假袋号。

最小记录包括：

- 交出记录 ID/编号、业务批次去重标识、发生时间、操作来源。
- 任务单号及版本、有效分配 ID、运行任务 ID/编号、生产单 ID/编号。
- 承接工厂 ID/名称、领取 PPIC ID/姓名、裁床工厂/仓库、实际操作人。
- 当时的任务类型、款式与图片引用、SKU 分配范围，以及冻结技术包/裁片责任快照版本；历史应交量不能在刷新后按新技术包重算。
- 每张菲票 ID/号码、实际产出来源、SKU、颜色/尺码、部位、编号范围、实际片数。
- 合计菲票张数、合计片数、明确的“仓库确认即接收”依据。

先成功保存这一条确认事实，再显示成功并刷新各读取视图。接收状态从此事实得出，不依次另写三套容易失败不一致的记录集合。

复用现有幂等追加校验：相同批次重复提交返回已有结果；不同批次要重新校验菲票未被消耗。稳定批次身份包含分配/版本和本次菲票集合，而非每次点击随机新建。对同一浏览器多标签的同时提交，资格复核和保存须在同一本地提交临界区完成；如现有存储封装不足，只增加提交范围的浏览器互斥，不建设分布式锁或重试基础设施。

### S09.2 各页面的可观察结果

| 读取位置 | 确认后的结果 |
| --- | --- |
| 当前简易弹窗/PDA | 本批成功，原清单不再可交 |
| 裁床待交出仓 | 更新未交裁片数、已交数量及对应任务可交数量；不减少不存在的袋库存 |
| 裁床库存明细 | 有原库存记录的扣减对应记录；无袋未建库位记录的裁片按实际产出可交余量扣减，不伪造库位 |
| 中转袋装袋/交出 | 新已交菲票不可重复进入后续袋交出 |
| 裁床交出单与记录详情 | 增加一条本次交出记录，逐菲票明细完整，方式“简易裁片交出”，工厂接收“已接收” |
| 工厂接收列表、记录和详情 | 同一来源记录直接“已接收”，接收数量等于仓库实交，接收时间等于仓库确认时间 |
| PPIC 交出与欠片 | 按 SKU/部位增加有效实交、减少剩余欠片，保留未齐套情况 |
| 相关历史/回货约束查询 | 从统一交出查询读取实际交出数量，不因没有袋记录而判定尚未交出 |

原型的本地持久化能力保证同一浏览器数据空间下 Web/PDA 视图与刷新一致。不同真实设备的实时互通需要后端，不在本次原型实现范围内；不把本地 Mock 联动描述为已经具备生产级跨设备同步。

### S09.3 接收状态的层级

本次交出记录：已交出。
本次工厂接收记录：已接收。
任务累计接收：可为部分接收/全部接收，按尚余应交片数与既有规则计算。
车缝/烫包任务进度：仍按原生产执行流程，不因领到裁片自动完成。

新记录不产生“待工厂确认”“待回写”按钮或第二次“完成接收单”的强制业务确认。若现有接收单头部需要汇总，系统自动根据记录显示累计状态，不能再让工厂点一次才影响库存或欠片。

## S10 交出单、接收命名与旧入口收口

### S10.1 裁床交出单

使用现有交出单模块和详情路由，不建立第二套“简易交出单台账”。

拟按有效分配聚合任务交出单，每次确认新增一条交出记录；各批次共享任务上下文。业务类别仍是“车缝交出”，增加“交出方式”区分简易裁片/中转袋。

列表提供任务单号/任务号/生产单/工厂的查询及交出方式、时间等直接相关筛选，显示接收工厂、PPIC、菲票张数、片数、状态。新调整的标准列表遵循现有查询卡片→统计→列表→分页和列设置规范，不扩展全站布局治理。

详情增加“任务与接收信息”“本批菲票明细”“操作记录”。袋信息明确“不使用中转袋”，不能显示未装袋警报；不存在的库位不伪造。历史交出记录保持原责任、数量及接收状态，不批量改为已接收。

### S10.2 工厂“接收”

以三方车缝工厂相关接收业务为更名范围，用户看到的入口、页签、标题、按钮、记录名和空态统一使用“接收”。

当前 `pda-handover.ts` 的通用收货页已大量使用“接收”，因此不是把全仓库所有 pickup/领料 字符串全局替换。落实时列明三类：

- 已是接收语义的通用入口：复用，新增已接收记录读取。
- 三方车缝专属、仍名为领料的页面/对象：完整改为接收，包括专属文件/符号、类型、字段、路由、事件命名、Mock、存储键和检查文案；删除旧专属路由注册，不保留兼容跳转。
- 真正的领料申请/领料凭证、三合一面辅料和其他工艺工厂原有流程：按其真实用途保留，不能把“申请领料”误改成仓库已接收。

共享 `PdaPickupRecord` 当前承载多种不同工厂业务。此次新裁片接收采用明确的接收语义投影，通用域本身不因本次两类任务而整体更名或改确认行为；不建立专属新旧对象双写。若实施发现某字段实为本次被更名的专属对象，按完整迁移处理，不能只改标题。

### S10.3 PPIC 与旧裁片领料单

两类领裁片任务在 PPIC 任务页统一提供“打印任务单”“查看接收/交出记录”，复用工作台生成的同一张任务单、同一码。

停止为这两类任务新建旧“裁片领料单”版本，删除其“手工填片数即可交出”的活动入口和提交分支，防止绕过逐菲票扣减。历史旧单和旧交出事实仍可在历史记录查看，不因页面收口删除审计事实；旧码不再允许新增交出，可说明改用当前任务单。通用扫码入口保留，因为它还有面辅料等其他业务，不为旧裁片单新增兼容重定向。

既有辅料、三合一面辅料领取流程不被替换成裁片简易交出。现有补料、退仓、责任移交只接入必要数量/身份变化，不趁机重做业务流程。

新增一组相互关联的演示场景，而非几张互不关联的静态页面。建议在一个场景文件中定义以下数据并接入现有初始化入口：

每个款式、每个物料都绑定与对象匹配的真实照片/正式效果图；同一对象跨工作台、任务单、仓库、接收详情保持同图同码。可优先使用已有 `public/materials/fei-ticket/` 等明确标注对象的正式物料效果图及现有款图，不能因“有图片文件”就把不相干面料套在同一行。

资源清单记录对象、资源路径、来源、颜色/规格对应关系和出现页面。没有对应素材的对象需补齐或换成有完整资料的演示对象；不能用无关随机图、纯色块、首字母或静默占位图通过验收。加载失败显示对象和“图片加载失败”，提供重试；必须演示的正常场景不得带缺图交付。

## S12 防错、恢复与性能

| 场景 | 目标行为 |
| --- | --- |
| 查不到任务单 | 保留输入，提示核对纸上任务单号，允许重新扫描 |
| 输入生产单/袋/菲票码 | 说明当前需要任务单，不错误跳到其他对象 |

| 没有可交菲票 | 展示“暂无可交裁片”；显示已交/待裁/在外加工等有事实的原因 |
| 超出分配剩余、混合归属、片数异常 | 不进入可交集合，显示受影响菲票及原因 |
| 已入有效袋 | 显示袋号，使用中转袋交出路径；不擅自解绑袋 |
| 确认期间数据变化 | 保留任务，刷新差异并要求重新核对；不能静默变更本批清单 |
| 连点/扫码枪重复回车/重试 | 同一事实返回原交出编号，不累计两次 |
| 本地保存失败 | 明确未成功，输入和明细保留；不展示已接收假成功 |
| 权限/仓库范围不匹配 | 可展示允许查看的信息，禁止确认并说明应由哪类仓库人员操作 |
| 历史无菲票交出 | 按现有已确认数量保留；无法确定具体已消费票时不给同范围新票盲目放行，要求先核对来源，不自动二次交出 |
| 图片失败 | 显示对象和重试入口，不用错误图片掩盖缺失 |

防重要求作用于真实菲票来源，不只是按钮 disable。页面逻辑与数据提交各自校验，现有袋交出入口也要读同一已交事实。

本地反馈目标沿用项目 200ms：输入、展开、弹窗、确认点击立即有可见反馈；异步生成打印内容即时显示处理中。列表分页，PDA 分批渲染；输入不整页刷新，图标仅处理新增区域，输入框焦点和滚动位置稳定。

## S13 正常与边界场景推演

以下为设计示例，不是真实工厂记录。

生产单 PO-DEMO-01：工厂 A 的独立车缝任务分到黑色 M 100 件；工厂 B 分到黑色 L 80 件。每件需前片 1、后片 1、左袖 1、右袖 1，因此 A 应交 400 片。

第一次，A 的前片、后片、左袖各已裁 100 片，生成 3 张有效菲票；右袖未裁。PPIC A 持 A 的任务单：

1. Web 输入或 PDA 扫码，同样显示 A/PPIC A、黑色 M 100 件，以及 3 张票共 300 片。
2. B 的黑色 L 菲票不进入清单；右袖未裁数量不进入本次可交。
3. 仓管确认，生成一条含 3 个菲票明细的交出记录。工厂 A 立即看到本批已接收 300 片。
4. PPIC 欠片显示右袖仍缺 100 片；本批已接收不等于已齐套。重复点击仍只有原记录。

第二次右袖已裁并生成有效票，再用同一有效任务单识别，只出现新右袖票 100 片。确认产生第二条记录，累计 400 片、剩余 0；生产任务仍等待实际车缝执行完成。

边界推演：

- 改派后使用旧任务单：在识别/确认阶段阻断，不把原工厂纸单默默指向新工厂。
- 前片票已装入一个在用袋：不进入简易清单，标注袋号；原袋流程仍能按既有规则交出。
- 某票记 120 片而本部位剩余 100 片：整票不自动截成 100；修正上游后再识别。
- 手机按 PDA 页面确认后，在同一原型数据空间切回 Web 重读：只能看到剩余票和已生成记录，没有再次可交的旧票。
- 先有旧手工交出 100 片且缺少票号：保留历史责任数量，该范围不能凭新路径重复领出；实施迁移必须给出可追溯的核对结果或阻断。

## S15 假设、待关闭事项与变更控制

本方案不再把“三合一是否领裁片”“仓库交出后是否另需接收确认”列为待确认：两项用户均已明确，本方案严格采用已确认口径。

技术设计假设：整票交出、系统自动列出全部本次可交票、任务单号依附有效分配、单一事件保存后各端读取。它们是本方案提出的实现选择，并非当前已经存在的能力。

实施前/过程中需用直接证据关闭的资料项：

1. 线上两个含义不明确字段、吊牌价、布卷与时间字段的真实映射；不影响其他已确认功能，但未绑定不能称打印完全对齐。
2. 历史已分配任务与有效分配记录缺口，及旧手工裁片交出缺少菲票关系的数量范围。
3. 每个新增演示款式/物料/纸样的对应图片和可用附件。
4. 实际 PDA/扫码枪/打印机的现场纸张和扫码效果，模拟页面不能代替设备证据。

实施阶段先更新本总体方案，再同步工作包和矩阵。任何增加拆票、改变分配粒度、增加工厂二次确认或要求先装袋的改动，都属于业务口径变化，不能在代码或测试中自行加入。

### 实施补充：实际完裁后的特殊工艺关联（MOCK-005）

核查发现，原型特殊工艺菲票关系原先只在首次读取时建立，后续实际完裁的新菲票无法加入；历史演示关系还固定使用测试裁床。为验证“工艺在外不可交、真实回仓后才可交”，本次补充缺失关系刷新：仅追加由实际完裁菲票、技术包工艺和已有加工任务共同匹配的新关系，不重置原有加工、交出或回仓状态。新关系按对应有效裁剪任务唯一承接工厂确定来源裁床；来源不明确时不生成关系。回仓单及入仓记录回到该来源裁床，历史关系继续沿用原来源，不能将测试裁床事实冒充专用裁床事实。

独立演示订单 `PO-DEMO-SIMPLE-BAG-0916` 使用实际完裁事件和真实装袋命令验证袋占用；`PO-DEMO-SIMPLE-CRAFT-0916` 使用实际完裁菲票、工艺加工任务及真实发料、接收、完工、回仓命令验证工艺在外/回仓。两者显式初始化，不改变主验收 M/L、车缝+烫包和三合一任务号、分配及库存。车缝 M/L 均为人工分配，自动来源样例由独立订单固定裁床任务提供。
