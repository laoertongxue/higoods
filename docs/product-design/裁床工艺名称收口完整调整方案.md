# 裁床工艺名称收口完整调整方案

## 1. 总体设计与需求

### 1.1 背景与权威事实

2026-08-28，产品明确要求收口裁床定位类裁法与重复特种工艺：

- 删除 `legacyValue=64` 对应的重复特种工艺旧项，不再生成特殊工艺加工单、菜单、PDA 识别、打印识别、路线步骤或价格配置。
- 原裁床定位类裁法及旧别名统一为唯一名称 `定位裁（激光切）`。
- 代码、业务文案、Mock、路由模板、脚本、测试、文档和文件名必须同步，不保留遗漏或双重口径。

### 1.2 范围

- 工序工艺字典、遗留值映射、裁床工艺定义、作用对象和可见工厂配置。
- 工厂入驻、工厂主数据、仓库、PDA 分类、任务边界、派单 SLA、PCS 成本与配置维度。
- 生产需求 Mock、路线模板、任务价格、PDA 和打印识别。
- 专项检查、Playwright 契约、历史设计文档和原型审查记录。
- 全仓文件内容及文件名残留门禁。

### 1.3 非范围

- 不新增新的特种工艺加工单。
- 不改变普通裁、定向裁及其他辅助／特种工艺的业务规则。
- 不修改与本任务无关的成衣 SPU/SKU 整色替换工作区改动。

### 1.4 对象与规则

1. `定位裁（激光切）` 属于裁床工序，作用对象为裁片部位。
2. 它使用既有裁床任务与裁床工厂，不进入特种工艺工厂管理。
3. 原 `legacyValue=1` 继续承载该裁法的历史兼容，只更新名称。
4. 原 `legacyValue=64` 及其派生编码全部删除，不兼容为新的特种工艺入口。
5. 含该裁法和绣花的路线模板只保留一个裁床步骤；裁床步骤标明具体裁法，绣花继续作为独立工序。
6. 全仓只允许在完整新名称中出现括号内的能力词；旧名称、旧别名和旧内部编码不得独立残留。

### 1.5 正常与边界场景

- 正常：打开工序工艺字典，只看到 `定位裁（激光切）`、普通裁、定向裁；特种工艺清单不再出现已删除旧项。
- 正常：工厂能力选择、PDA 任务分类、SLA、成本评审和路线模板都把新名称识别为裁床工艺。
- 边界：历史值 1 仍解析为新名称；历史值 64 不再生成活动工艺或特种工艺加工单。
- 边界：全仓扫描剔除完整新名称后，不得再命中旧中文名称、旧别名或旧内部编码；文件名同样不得命中。
