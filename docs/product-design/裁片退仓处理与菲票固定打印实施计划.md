# 裁片退仓处理与菲票固定打印实施计划

## 1. 目标与完成标准

本计划负责把《裁片退仓处理与菲票固定打印完整产品设计方案》落实为可演示、可追踪、可验收的管理端原型。完成标准是所有原子需求均绑定当前实现位置和一组直接证据，相关专项契约、命名页面、打印预览、图片、列表治理、构建和任务收据均有当前版本结果。

## 2. 事实依据

- 线上非特殊工艺菲票的 100mm × 100mm 物理尺寸是本轮统一基准。
- 普通 / 特殊工艺分类、白色 / 黄色热敏纸分流及特殊工艺承接工厂门禁属于既有规则，必须保留。
- 退仓责任按件计算，部位库存按片计算。
- 退回裁片先进入裁床待交出仓内独立退裁片库区，补料后重新齐套装袋，再进入普通待交出仓。
- 只有正式交出改变“后来正式重新交出件数”；进入待交出仓不改变责任。

## 3. 范围

- 部位菲票打印投影、打印文档和预览排版。
- 裁片退仓领域事实、补料关联、库存和责任公式。
- 裁片退仓菜单、路由、标准列表、详情及动作。
- 裁床待交出仓中的退裁片库区和重新齐套批次展示。
- 专项契约、治理记录、需求追踪矩阵和当前版本验收。

## 4. 非范围

- 不改菲票生成、分类、白 / 黄纸规则、补打和特殊工艺判断。
- 不新增真实接口、数据库、打印机驱动或 PDA 页面。
- 不调整用户工作区中的 PCS 专项变更和其它既存改动。

## 5. 工作包

### WP-01 菲票物理规格与字段排版

- **业务目标**：普通和特殊工艺部位菲票统一为 100mm × 100mm，并提高关键信息辨识度。
- **实现位置**：打印投影、标签文档构建、打印样式、菲票页面预览。
- **修改**：固定部位菲票纸型；面料名称 / 身份 / 颜色拆分；唛架编号 / 铺布单号拆分；保留纸色与承接工厂门禁。
- **验证证据**：固定打印布局专项契约；普通和特殊工艺命名打印预览；浏览器尺寸和字段检查。
- **完成条件**：两类部位菲票实测尺寸一致，旧 150mm 分支不再被部位菲票选择，原纸色与门禁专项回归通过。

### WP-02 退仓责任与库存事实

- **业务目标**：冻结来源责任，建立件 / 片分离的接收、库存、报废和应回公式。
- **实现位置**：裁片退仓领域模型及本地原型事实存储。
- **修改**：退仓单、接收记录、部位库存批次、责任事件和操作追溯；超责任阻断、报废核销及幂等保护。
- **验证证据**：裁片退仓专项契约中的 200 → 188 → 188 → 203 数量链和异常断言。
- **完成条件**：所有责任变化只由确认退件和正式重新交出触发，部位报废和差异不改变件数责任。

### WP-03 补料与重新齐套

- **业务目标**：按现场决定手动补裁，关联现有补料事实，并把退回裁片与补料裁片重新组成完整件。
- **实现位置**：裁片退仓领域模型、统一补料单登记、退裁片库存和齐套批次。
- **修改**：手动部位片数、独立最终件数、按原裁片单拆单、补料到齐入退裁片库区、部位可用量校验、新中转袋和正式再交出。
- **验证证据**：专项契约验证 17 片补裁高于 12 片清点值、两张补料单、45 片齐套、14 片剩余和正式交出责任增加。
- **完成条件**：补料、库存、齐套和责任四组数量可逐项追溯且守恒。

### WP-04 退仓管理页面

- **业务目标**：为裁床退仓员、主管、齐套员和交出仓管提供同一业务工作台。
- **实现位置**：菜单配置、页面元数据、路由、事件入口、裁片退仓标准列表页。
- **修改**：菜单、列表、筛选、统计、分页、列设置、排序、冻结、图片、大图、详情及全部业务动作。
- **验证证据**：列表治理检查、命名浏览器验收、低分辨率和局部交互检查。
- **完成条件**：无需离开退仓单即可完成接收、报废、补料、补料到齐、齐套、打大菲票和正式交出。

### WP-05 待交出仓联动

- **业务目标**：区分未齐套退裁片和已经重新齐套的普通待交出中转袋。
- **实现位置**：裁床待交出仓工作台。
- **修改**：新增退裁片库区摘要、重新齐套待交出中转袋和返回处理 / 正式交出入口。
- **验证证据**：待交出仓命名页面验收和退仓专项契约。
- **完成条件**：原退裁片不混入普通库存；齐套袋可见；正式交出前后责任展示一致。

### WP-06 退裁片大菲票

- **业务目标**：旧实物菲票缺失时仍可快速识别部位和重新打票。
- **实现位置**：裁片退仓页面和退仓领域模型。
- **修改**：扫码 / 输入识别、直接选择部位、一键全选、固定 100mm × 100mm 预览、二维码及打印记录。
- **验证证据**：专项契约和命名打印预览。
- **完成条件**：不依赖旧实物票，能够按当前可用部位生成和打印一张可追溯大菲票。

### WP-07 文档、治理与交付证据

- **业务目标**：保证范围无遗漏并能正向、反向追踪。
- **实现位置**：总体设计、实施计划、需求追踪矩阵、原型审查记录和任务收据。
- **修改**：把每条规范拆为稳定编号，绑定实现、自动化和页面 / 打印证据。
- **验证证据**：设计治理、列表治理、构建、CodeGraph 状态和任务收据。
- **完成条件**：矩阵不存在无说明的待实施、实施中、待验证或已阻塞条目。

## 6. 依赖顺序

1. WP-01 可与退仓领域并行，但打印门禁必须先于最终打印验收。
2. WP-02 是 WP-03、WP-04、WP-05 和 WP-06 的事实基础。
3. WP-03 完成后才能验证齐套和正式再交出。
4. WP-04、WP-05 完成后执行浏览器闭环。
5. 所有实质修改完成后再生成 WP-07 的最终证据和任务收据。

## 7. 风险与控制

| 风险 | 控制 |
| --- | --- |
| 把片数差异误作件数责任 | 责任事件仅接受确认退件件数和正式再交出件数 |
| 齐套入仓就提前增加责任 | 待交出仓批次与正式交出记录分离 |
| 补裁片数被退回片数限制 | 补料输入只校验非负整数，不以清点量为上限 |
| 补料来源被合并 | 按原裁片单分组登记补料单 |
| 退裁片混入普通待交出库存 | 独立退裁片库区，齐套后才生成新中转袋 |
| 旧菲票缺失无法识别 | 允许按退仓单已知部位直接选择 |
| 特殊工艺打印逻辑被误改 | 对纸色分流和承接工厂门禁做专项断言与回归 |
| 图片以占位素材冒充 | 逐对象使用正式图片并验收缩略图、大图和失败态 |
| 吸收用户其它工作区变化 | 只修改本计划声明文件，最终按任务差异报告 |

## 8. 最终验证顺序

1. 文件差异与格式检查。
2. 裁片退仓领域专项契约。
3. 菲票固定打印布局专项契约。
4. 既有菲票纸色、打印路由和列表迁移回归。
5. 菜单 / 路由、待交出仓和补料关联检查。
6. 标准列表与原型设计治理。
7. 当前分支构建。
8. 当前分支命名页面、图片、大图、低分辨率、退仓操作闭环和三类打印预览。
9. CodeGraph 同步与状态检查。
10. 任务收据及矩阵证据回填。
