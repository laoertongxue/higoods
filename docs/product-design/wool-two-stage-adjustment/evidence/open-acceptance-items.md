## 2. 交互覆盖缺口

已有两份独立脚本对 89 个命名操作各记录 5 次（共 445 样本全部通过，最大 95.59999999403954ms），包括列表六状态、输入/查询/重置、分页、排序、列显隐/恢复、大图、填报/超量阻断、Web/PDA 纱线和片接收、备料分配，以及 Web/PDA 横机完单二次确认、Web 设备关联和数量更正。最终结果以交互 JSON 为准；即便这些全部通过，仍不能视作“全部交互”通过。

尚缺完整五样本计时的受影响入口：

- 更多筛选的全部条件、所有详情展开、导出完成与空导出、列拖拽/冻结/页大小。
- 数量更正已覆盖正常打开/输入/保存；尚缺下游已消耗等拒绝场景。横机完单已覆盖 Web/PDA 打开/取消/确认；尚缺缝盘完单及无效完单场景。
- 设备选择、关联已覆盖；尚缺更换/释放、不可用设备阻断及设备档案操作。
- 领退料、仓库移动、库存及接收历史各明细入口。
- PDA 扫码、多候选、错厂、交出、事实记录分页、顶部待办/账号及底部导航首次动作。
- 工艺片逐站接收、填报、交出、最终成衣工艺实际批次接收整条路径。
- 打印生成、长内容分页、失败后重试；图片在全部受影响入口的打开/关闭与失败反馈。

这些入口部分已在 31 个真实浏览器功能用例中通过，功能证据不替代性能证据。

## 4. 已定位但未用不安全方式规避的热点

- 毛织片工艺查询先前逐片克隆整份接收账；本次已改为同版本冻结查询快照及一次归集，数量结果保持原契约。
- 共享 PDA 任务、交接、仓储加载仍涉及其他工艺默认数据和重复仓储派生读取。当前工作树的[任务队列 CPU 调用栈](./pda-queue-cpu-diagnostic.json)显示 `getAcceptedTasks → listMobileExecutionTasks → listPdaMobileExecutionTasks` 会进入印花初始化及跨工厂投影；[采集脚本](./pda-queue-cpu-diagnostic.mjs)使用开发服务 5186，只用于定位，不替代上表生产预览 4186 的真实加载耗时。调用栈包含重叠父子时间，不累加为验收值。
- 同一工艺仓事实版本重复读取会反复克隆/重装派生行；仅跳过这一步会让通用写入口对派生库存的临时修改残留。安全优化需要同时证明快照恢复、upsert、库位、交出、盘点等写入口后的失效规则，因此本次未采用不完整缓存。
- 当前已采用更轻的逐字段防御性复制和 PDA 交接冻结查询快照；递归污染、通用仓库快照恢复及实际 PDA 写入后刷新反例通过。每次重装库存仍保留。
- 保留原 PDA 风险/超时同步；未通过删内容、跳初始化、减数据、预热、延迟给 Loading、降低阈值或更改治理基线换取通过。

## 5. 后续关闭顺序

1. 对上述受影响共享路径做最小、可证明等价的性能修复；新增反例必须先证明事实与权限不变。
2. 同一冻结构建重跑全部加载及受影响交互；为第 2 节缺口建立真实完成条件与五次原始样本。
3. 重放相应功能路径和业务契约，复核真实图片/打印/低分辨率。
4. 对最终增量再次做对抗式审查，完成矩阵正反向追踪后才逐项标已验证。
