# 剩余交互性能补测覆盖说明

脚本：`scripts/check-wool-remaining-action-performance.mjs`。本文件说明测量范围和前置，不替代最终原始样本。正式结论以同一冻结构建生成的 `acceptance-500/remaining-action-performance.json` 为准。

## 运行与计时

```sh
WOOL_BASE_URL=http://127.0.0.1:4198 WOOL_SETUP_BASE_URL=http://127.0.0.1:5198 node scripts/check-wool-remaining-action-performance.mjs
```

每条流程使用五个独立浏览器上下文；标准列表按 1366×768 / 1280×720，PDA 按 360×800 / 400×806。记录分支、HEAD、工作树、构建指纹、浏览器、实际尺寸、每次原始值及命名完成条件。`WOOL_ACTION_FLOWS` 与 `WOOL_ACTION_REPEATS` 仅用于保留诊断结果，少于五次不能通过。

开始时间在真正的 click / input / change / dragstart 事件捕获阶段取得。结束条件是对应真实数据结果已经呈现、可见图片解码完成、再经过两次动画帧。筛选输入的测量包含筛选结果局部重绘；CSV 包含下载流全部可读，PDF 包含实际 PDF 字节生成。没有用只变色、Loading、DOM 插入或空下载代替完成。

`裁厂接收详情加载` 独立记录冷进入、刷新、站内切换。先由 Web 真实交出形成实际批次，再把该真实持久化状态复制到全新、无页面缓存的裁厂上下文；冷进入前不加载页面模块。站内切换使用裁厂交接页 `tab=handout` 中实际交出批次卡片（当前接收动作位于该卡详情），缺卡片直接失败，不注入导航按钮。

## 前置与不适用边界

1. 普通流程不导入源模块，不替换业务账、不拦截业务请求。只为隔离验收设置已经存在的原型 PDA 登录身份。
2. `最终成衣工艺批次` 是唯一例外：当前原型没有从页面创建该完整生产单技术包快照的入口，所以使用已存在的 `wool-final-downstream-review.ts` 领域验收前置。前置在开发服务独立上下文运行，持久化后转入新的生产预览上下文；只有之后的真实 UI 接收计时。前置耗时和页面创建能力不被伪称已验收。
3. 无效缝盘完单和维修/停用设备没有可点击的提交入口时，验收结果应是按钮不存在/不可选与对应事实不变，不通过注入 DOM 或移除 disabled 来制造“用户动作”。数量拒绝和工艺无效完单仍通过正常可达入口测量。
4. 物理打印机、操作系统打印目的地选择、用户阅读与手工填写耗时不属于页面系统响应；脚本验证并计时实际 PDF 生成，未把 `window.print` 调用返回当作生成完成。
5. 长内容跨页、图片失败后重试、低分辨率组合、错厂与多候选等功能证据仍由对应专项验收文件记录；本脚本不能替代那些功能证据，也不能将未计时的入口自动认定性能通过。

## 当前状态

脚本语法检查通过。单轮诊断用于纠正选择器和前置身份，诊断结果保存在 `/private/tmp/wool-remaining-diagnostic*.json`，不作为五样本通过证据。最终构建冻结后需完整运行脚本，并由主代理核查所有错误、五样本完整性和 `< 500ms` 判定。

## 裁厂接收详情补充核查

当前原型的毛织最终交出头是 `HANDOUT`，裁厂通过交接页 `tab=handout` 的实际批次卡进入并确认实收。脚本沿用此真实入口；不把 `pickup` 中没有该卡误判为丢单。

详情新增读取对应毛织加工单的真实款图，与款号和本批 SKU 同块呈现，沿用现有大图组件。路由使用原详情渲染器直达，继续执行原工厂权限和接收数量校验。

CPU 诊断发现演示生产单 `PO-MZ-*` 的身份行会调用全局生产对象视图，两次查找最终仍返回原纯文本。详情现仅对明确标记 `demoSource` 且真实生产单数组不存在对应目标的毛织单保留同一纯文本结果；真实生产单继续原解析和链接。此改动没有减少验收数据，也没有延迟展示内容。所有最终性能值仍需在冻结构建重新运行。

实收 CPU 另定位到明确毛织事实仍调用特殊工艺菲票返仓探测，首次生成整套菲票。现仅在 `sourceWoolHandoverId` 存在时跳过这个不匹配的探测；真实特殊工艺返仓仍执行原逻辑，实际毛织接收、数量/工厂校验及仓库联动保持。单轮修复后诊断的详情三种加载和22项动作均低于500ms；这仍不是正式五样本通过证据。

## 1024 主管设备与门禁反例

`WOOL_ACTION_DEVICE=1024 node scripts/check-wool-remaining-action-performance.mjs` 单独运行九组适用主管流程，每组五个独立 1024×768 上下文，输出 `remaining-action-performance-1024.json`：实际纱线/外加工片接收、接收历史/大图、设备更换释放/档案、设备及关联列表控件、两仓列表控件、物理纱线仓库操作、成片/成衣库存调整及转出转回。PDA 流程仍保留原小屏尺寸，不能被该模式误标为主管验收。

新增列表控件等待真实表格替换，包含 180ms 自动筛选延迟；覆盖各筛选选项、重置、每页条数、适用分页、排序、显隐、冻结、列拖拽与恢复。设备/关联/仓库当前源码与标准列表外壳均未提供独立查询或导出按钮，脚本按不存在入口注明，不伪造导出。完整数据不足一页时，实际禁用的翻页按钮记录为不适用；不通过改变样本数制造可点状态。

旧主交互和补充交互脚本都已加入可见图片外层的失败检查：即使 `onerror` 把 `<img>` 隐藏，外层仍可见时也判定失败。负向控制可分别运行：

```sh
WOOL_IMAGE_FAILURE_PROBE=1 WOOL_BASE_URL=http://127.0.0.1:4198 WOOL_PERF_OUTPUT=/private/tmp/wool-main-image-negative.json node scripts/check-wool-action-performance.mjs
WOOL_IMAGE_FAILURE_PROBE=1 WOOL_BASE_URL=http://127.0.0.1:4198 WOOL_PERF_OUTPUT=/private/tmp/wool-extra-image-negative.json node scripts/check-wool-extra-action-performance.mjs
```

负向控制仅在隔离浏览器拦截真实 `/cardigan-sample.jpg`，等待真实失败文案和隐藏图片，再点击不重绘该缩略图的筛选展开。正确结果是每个 `隐藏失败图片门禁反例` 样本 `visibleImageFailures > 0` 且 `pass: false`，进程以 1 退出。它验证门禁有效，不是页面性能验收失败的豁免；有意测试失败反馈/恢复的专项证据独立记录。

两份图片负向控制已各运行五次，十个样本均记录 `visibleImageFailures: 1`、`pass: false`，且没有脚本异常。原始证据为 `acceptance-500/image-gate-negative-main.json` 与 `acceptance-500/image-gate-negative-extra.json`；它们只能证明失败图没有被误判为正常通过，正常五样本交互仍需单独执行。

新增主管控件的单轮诊断已走通：设备档案/关联列表、两仓页签与筛选列配置、实际纱线/片接收，以及待交出仓成片/成衣库存调整→转出→转回。物理库位纱线不提供库存调整入口，脚本没有制造该按钮；调整与转回使用实际可操作的成片/成衣库存。最后两流程的 51 项动作最大 214ms、零脚本异常；诊断仍不替代最终五样本。
