## 1. 调整范围和完成目标

本次需要同时调整标准配置、后道QC、产前版批版、库存送检、后道加工至出货，以及直接使用这些事实的清单、统计、PDA、打印和当前记录读取。质检管理仅配置和查阅分析，实际办理仍在原业务入口。辅料、客户退货质检、质量费用、生产放行审批和新设备不纳入。

最终应形成三条可独立验收的业务链：

1. 生产回货实收→原后道QC领取开检→按固定标准分轮检查及稽查升检→QC完成→可选后道加工→后道出货单→实际交出→成衣仓实收。整个链没有活跃复检节点。
2. PPIC实收一件本厂产前版→领取批版并固定标准→无问题/有问题及具体项目→原反馈登记结束。连续48小时从领取计，不限制大货，不再次批版，不向后道提供参照。
3. 一仓一款全部合资格正常库存→申请并整批下架出库→后道整批实收→按实收开展库存QC→正常货返原仓并上架、瑕疵进独立瑕疵品仓、返工交goto_global→各去向和差异处理完成后结束申请。

## 3. 最小实现组织与事实归属

### 3.1 共用判断，保留各业务唯一结果

共用标准及规则保存到现有 `higood-pcs-records` 的新collection。后道和库存共同成功的记录也使用该库。产前版继续使用现有production-context库；同一批版的标准快照、结论、问题和反馈在原业务记录里共同保存。质检汇集跨这些来源只读适配，不新增可以独立修改的汇总结果。

共用配置是不可变的已生效版本。开检读取适用版本，生成完整检查快照随本次业务结果提交；紧接保存前复核选中版本，已被停用/替代则提示重新读取。跨库配置读取不宣称与产前版写入构成一个事务：以本次开检最后一次成功选取有效版本的时刻作为匹配边界，记录该时刻、有效版本身份和内容，立即随原业务开检保存；这之后才发布的版本不追溯改变本次已选快照。保存失败不算开检，下次重试重新选取。这个边界避免承诺不存在的“两个库同一提交瞬间最新”；不为此添加跨库锁或分布式事务。无需让标准生效与所有在检业务共同写入。

### 4.2 标准编辑及合成算法

每个标准项保留稳定ID、维度、名称、检查内容、判定要求、适用条件、依据引用及单位。维度不替代具体检查项。六维要求以业务正文为准，公差不编数。资料缺失显示缺失，不阻止有有效标准的正常检查。

合成顺序固定：匹配一个适用基本标准→匹配同层唯一类别附加→匹配同层唯一指定款附加。新项追加；覆盖项必须给出原项ID和适用范围，按指定范围替换字段，未覆盖部分保留。不能名称模糊匹配、整维替换、任意优先数值或择严。

“一个基本标准”也须配置生效时保证：同对象、同环节且适用范围相交，只能命中一份有效基本标准。共用一份标准是其适用环节可以多个，不是同一环节现场从两份任选。生效并发同样校验范围版本，不能按发布时间临时择一；发现存量重叠列明冲突，不继续假匹配。

生效前同时校验对象一致、关联原项有效、范围合法及同层同款不重叠。静态/显式集合可直接求交，条件集合按本期支持的款式类别、指定款和适用环节精确比较；无法证明不相交的配置不允许同时生效，须缩小或拆清条件。不能留到QC现场选一份。重叠判定及标准生效记录使用共同范围版本，防两标签同时各生效一份导致冲突。

没有匹配附加标准时用基本标准；有匹配的有效附加必须用。没有适用有效基本标准不能假称已按标准开检；提示配置缺口。项目适用条件在配置时表达，不设置执行免检按钮。应有实物缺失按问题记录，正常约定后道加工尚未完成不自动算第三方漏做。

编辑有效内容时派生新草稿，明确生效后成为新有效版本，旧版供已开检单引用；停用不毁历史，不预约生效。新开检保存最终项目和依据快照，升检轮次不重新匹配。版本更新不自动追检；必要的独立追检只保留明确对象/项目与原记录关系，不提供绕过批版无再批、内部返工无QC及结果不得更正的入口。

## 5. 生产回货初始全检来源

### 5.1 四条判断及覆盖

默认条件配置在“生产回货后道QC”环节。前三条产生款+生产单覆盖，第四条产生款+工厂+生产单覆盖，任一命中全检，所有理由保留。库存/产前版即使在同一后道现场也不调用此判断。

- 正式商品定位为基础款或冷启动基础款即命中，不能读页面展示别名或随机seed类别。
- 正式关联技术包难度A/A+/A++命中；B/C/D继续看其他条件；不新增S/A+++，不从后道`styleGrade`归一化值判断。
- 从生产单绑定的正式版本技术包取BOM，仅解析面料行。优先用`materialSkuId → getMaterialSkuRecordById → materialId → getMaterialArchiveById → 根档案materialCode`；仅编码时使用现有精确SKU身份/别名解析，或经明确根码匹配。任一面料SPU在20项外即命中，不能因为另一面料在名单内抵消；实际替代料不覆盖此正式依据。
- 工厂真实执行前3个唯一车缝任务命中。`recordRuntimeTaskExecution`及`autoStartRuntimeSewingTaskFromCutPieceHandover`所形成的真实执行事件可作为来源，分配、自动接单、演示克隆、非车缝任务不可直接计次。相同实际任务多批只计一次。

物料无法精确解析时，记录“来源未能解析”及原值，不把unknown自动判名单内/名单外，也不宣称正常通过。先完成可靠映射或来源修复，再启用该生产范围判断；不要把资料缺失普遍改为全检。正式数据本身足以命中其他有效条件时，可按已证实条件全检并保留未解析提示，不伪造第四个理由。

### 5.2 真正执行序次的最小补齐

实现专用查询，只接受稳定任务身份、车缝工序、三方厂、可追溯的实际开始/执行事件及来源类型。新记录读取已固化的每厂首次执行序次；同任务重复事件去重。可验证存量第一次建序时才按真实发生时间和既有事件依据核对先后，无法证明时保留缺口；不得按生产单号、任务seq、创建时间或分配排序，也不在每次查询时重排已固化序次。

新执行动作在原任务存储事务内写入稳定的首次真实执行事实；不为序次把全任务域搬到PCS。后道只读该事实并固化命中来源。无真实历史记录时按当前第一次任务进入全检，保持用户确认。已有不完整/矛盾执行时间无法证明先后的集合，先列明事实缺口，不能为凑序次自动改写历史。该缺口是实施前数据核对，不重新设计取消、改派、返工计次。

拟新增`src/data/fcs/sewing-execution-history.ts`保存这个小范围事实，在两个真实开工入口以同一个确保首次事实的函数接入；工厂计数、首次事实、任务/必要生产单变化和命令同原库事务。新记录按首次真实执行提交时分配稳定序次并保留实际发生时间/系统确认顺序；同厂并发由原库revision拒绝冲突后重读，不从回货时间补排。可验证存量按其真实事件依据显式转换，不能把静态预造startedAt批量升级为真历史。

首次形成全检覆盖事实时，对范围内未完QC按100%提高目标，已检抵扣、标准快照不变，已有稽查被更高全检决定承接且完整留痕；尚未开检/后续批次按全检，已完成不重开。覆盖不因工厂后来接更多任务解除，普通升检不写这种跨批覆盖。

不必为一次命中同步重写所有批次：保存稳定覆盖事实及版本后，读取/提交QC时以“本单已升目标”和“有效覆盖要求”取高；完成动作必须校验当前覆盖版本，旧标签不能按过期30%完成。范围内已有待稽查时，以有来源的转全检决定承接并关闭该待办，保留触发和转全检原因，不伪造人工稽查意见或留下无更高档可选的死锁。已完成单读历史固定结果，不套当前覆盖重算旧实检。

## 6. 原后道QC的具体调整

### 6.1 页面和动作

保留`qc-orders.ts`清单和`qc-workbench.ts`完整单号领取入口、普通QC不得挑选全量待检池的既有限制。删除主管退领/清空结果路径及对应命令的可执行能力，不新增接替。

执行页先显示实物图片、款色码、来源及批次数量，再显示固定标准、依据及命中原因；之后显示累计目标/已检/待补检、本轮三类输入、问题项及适用纸单。生产来源有生产单/厂/任务，库存来源有原仓/申请/实收差异，不强行显示空生产号。

新开检一次性保存快照。新轮输入默认未填或0，不默认整批合格。逐SKU实物结果沿用现有明确颜色尺码登记能力以便分流守恒，但系统不按SKU分配样本、不要求每SKU至少一件；本轮未抽SKU可以无实检。物流所需SKU真实类别数量与整批抽样规则分别处理。

“提交本轮检查”保存本轮新增三类、问题、累计量及是否触发稽查。即使触发稽查，本轮已提交事实也已保存，QC状态仍未完成。禁止反复提交同一轮增加数量。提交后不更正该轮；未提交可改，保存失败保留输入和所选文件。

“处理稽查”只能选更高有效档或100%，填写决定；不提供同档结束、降低、绕过放行。稽查办理在原QC页面，中心仅查阅。随后补差额并新增轮次。达到目标、无待稽查、适用资料完整才能“完成QC”；不能把现场检完或打印当完成。

### 6.2 数量和轮次

令N为本批实际实收送检量，p为当前累计比例，m为最低量（未设置为0）：

```text
累计应检T = min(N, max(ceil(N × p), m))
本轮实检 = 本轮合格 + 本轮瑕疵 + 本轮返工
累计实检C = 不重复的已提交各轮实检之和
待补检 = max(0, T - C)
未检U = N - C
不合格B = 累计瑕疵D + 累计返工R
完成后正常放行L = 累计实检合格G + U = N - D - R
```

整数件数且非负，C不能超过N。满足当前目标不代表允许随意重复追加旧实物；每轮只新增。N=0不能自动QC完成。T=N即全量检查，无论由全检条件、100%档还是最低量/取整导致，均不触发抽检稽查。

SKU用于实物和去向守恒：每个SKU累计实检Cᵢ≤该SKU实收Nᵢ，三类互斥，未检Uᵢ=Nᵢ−Cᵢ，正常可交Lᵢ=实检合格Gᵢ+Uᵢ=Nᵢ−瑕疵Dᵢ−返工Rᵢ。各SKU汇总必须等于整批对应量，不能从其他SKU借数量填结果。此校验不分配SKU样本：A只有1件、B有99件，整批目标30时，A填实检30不合法，A不抽、B实检30合法，不要求A至少检查1件。

本期整批方式固定，p、m、档位和各轮阈值按环节配置；默认30%、档30/50/100、第1/2轮阈值各2。无阈值的轮次不凭空加默认规则。每轮用当轮D+R判断，不累计旧坏件再次触发。100→30坏3→升50只补20坏2→再升100只补50，累计已检50时坏件5，不能算80或再触发首轮。

**已确认的参数版本时序Q01：**同一QC开检后，即使后台修改比例、最低量、各轮阈值或档位，该单仍继续沿用开检所选规则版本直到结束，新开检用新版本；有效初始全检覆盖仍单独取高，可把在检单提高到100%。轮次提交、稽查可选档位、补检数量和打印均读取本单固定规则参数，不再读取后台当前可变配置。用户已于本轮明确确认此规则。

同件多问题用问题项目集合表达，不用原因件数相加反算瑕疵，不强制逐件ID。抽样未检不走现有“实检小于送检”的数量差异授权；原回货点数、真实交出/实收差异仍沿原有效规则，不顺手删掉。

### 6.3 纸单、依据与结果

后道生产回货QC必须有适用纸面双签单上传。纸单记录本次标准快照ID、当前要求版本、轮次、应检/实检、三类、问题及双签位置。升检生成新的纸单要求版本，重新打印并上传；旧纸单/文件保留，不能覆盖前轮或拿旧30%纸单完成50%。问题照片选填，不由图片门禁变成问题照必填。

资料在本次开检固定：保留已有色差图、尺寸和实际封版样衣引用内容/版本/文件ID；新上传可成为后续检查候选，不能偷偷替换在检依据。缺资料按已有资料检查，冲突按项目澄清并记录实际采用依据；不得引用产前版补缺。
