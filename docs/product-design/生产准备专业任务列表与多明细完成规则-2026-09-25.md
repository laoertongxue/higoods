# 生产准备专业任务列表与多明细完成规则

## 已确认范围

2026-09-25 用户明确：生产准备单、制版任务、花型任务、调色任务、辅料下单任务、首单样衣任务、销售展示样衣任务、技术包确认任务均需有足以推进业务的列表信息；筛选、统计、表格和交互参照染色加工单。

一张准备单可有多个花型、多个调色物料和多个辅料下单明细。同一准备项的全部有效明细完成，才可视为该项完成。不能用一条完成、上传一份成果、绑定一张采购单替代整项完成。

## 当前事实与来源

- 花型和调色已有逐物料行成果及买手审核，返工行保留、已通过行锁定；当前服务要求所有有效行通过。
- 辅料下单已有多采购单绑定及全部辅料 SKU 覆盖核对；不把采购到货作为下单任务完成条件。
- 同一 SKU 不同成衣颜色、BOM 行及成果要求保持独立行；花型按当前 BOM 印花要求行展示，不虚构独立花型编码。
- 销售展示样衣来源是设计改款；保留来源关系，不强制归入准备单。
- 未启用、因需求变更结束是明确的非执行范围，不计入待完成分母；零条有效需求不能表达为全部完成。

## 目标页面

统一：查询卡片（关键词、状态、当前责任团队、来源；更多筛选含执行人和计划日期）、查询/重置/导出、同范围统计、标准表格、分页、列设置、款图大图。

每行包括任务及来源款式、业务要求及明细进度、责任与计划、当前阻断/下一步、成果与时间。多明细先展示摘要，展开查看逐项状态；专业详情仍为执行入口。

| 页面 | 必须可判断的业务信息 |
| --- | --- |
| 制版 | 基码/齐码、梭织/毛织、尺码范围、当前成果版本、版师、计划时间 |
| 花型 | 所需印花明细、适用颜色/工艺、各项通过/待审核/返工，已通过/总数 |
| 调色 | 各物料与目标色、色号、染厂、要求确认、审核及返工，已通过/总数 |
| 辅料 | 应下单辅料、已覆盖/未覆盖、绑定采购单及实际下单时间 |
| 首单样衣 | 各颜色尺码应做/实做件数、制作人、成果与差异 |
| 销售展示样衣 | 设计改款来源、颜色尺码要求、实际结果、制作团队、当前动作 |
| 技术包 | 前置项完成/总数、未完成项及明细进度、当前确认责任与结果 |
| 准备单 | 专业准备项完成进度与内部明细完成进度并列，不混淆分母 |

## 实施顺序与存储范围

1. 核对现有服务门禁，建立多明细正常/部分完成/返工/结束场景验证。
2. 复用现有标准列表组件，补齐七类专业列表的只读业务信息、查询统计和导出。
3. 在准备单摘要复用同一明细进度，核对跳转和来源。
4. 当前工作树执行单测、构建、命名路由、图片和性能验证，记录未通过项。

本次不新增保存业务数据的动作。列表读取现有准备单、BOM、采购事实、成果和设计改款；查询条件在内存，列偏好按路由使用有界 localStorage。现有业务仓储中的 localStorage/自动演示初始化属于已存在问题，本次不得以列表调整宣称完成业务存储迁移。
