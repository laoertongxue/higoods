# 工序工艺字典默认顺序删除总体设计

## 1. 背景与目标

工序工艺字典用于说明有哪些阶段、工序、工艺和任务边界，不应替所有款式定义一条共同的生产顺序。原页面把活跃工序汇总成一条“基础工序顺序”，技术包路线在缺少顺序时也会读取这套字典排序，容易让生产计划、跟单和工艺人员误以为所有款式都必须经过同一条路线。

本次目标是完整删除这条跨款式默认顺序，使每个款的生产先后与并行关系只来自该款技术包已经录入并确认的路线。

## 2. 范围与非范围

### 2.1 本次范围

- 删除工序工艺字典页的“查看基础工序顺序”入口、弹窗、状态和事件。
- 删除工序定义中的逐工序排序值，以及生成、查询默认路线顺序的数据能力。
- 技术包路线不再按字典工序顺序或工序编码进行兜底重排。
- 空技术包不再自动补入一条硬编码的印花、裁片、车缝、烫包路线。
- 技术包中的“字典基础路线”来源改为“工序字典引用”，只说明工序资料来自字典，不表达先后顺序。
- 任务清单明确展示“生产准备工序不进入任务清单”，避免把 BOM 推导的准备工序误认为可分配生产任务。

### 2.2 保留边界

- 保留准备、生产、后道三个阶段及其展示分组；阶段是业务分类，不是每款完整路线。
- 保留各款技术包已经录入的步骤号、并行线、并行组、确认人和确认时间。
- 保留同一 BOM 物料必须满足的工艺约束，例如水溶必须先于染色、染色必须先于印花。
- 保留工序工艺字典的筛选、详情和任务边界说明。
- 不修改任务合并、工厂分配、生产单冻结和下游执行规则。
- 保留 `main` 已生效的 KOL-GOTO 整单任务和合并任务边界说明，不因本次页面文案调整而覆盖。

## 3. 业务对象与事实来源

| 对象 | 本次后的职责 | 顺序事实来源 |
| --- | --- | --- |
| 工序工艺字典 | 说明工序、工艺、阶段、作用对象和任务边界 | 不提供款式生产顺序 |
| 款式技术包 | 保存该款实际工序及串行、并行关系 | 该技术包的步骤号、并行线和确认记录 |
| BOM 物料要求 | 触发与具体物料相关的准备工序 | 只形成该物料必要的依赖约束 |
| 生产单技术包快照 | 冻结投产时采用的款式路线 | 已发布且已确认的技术包路线 |

## 4. 目标流程

1. 工艺人员在某款技术包中选择该款需要的工序。
2. 工艺人员按实际做法调整串行或并行关系并确认路线。
3. 如果 BOM 触发水溶、染色或印花，系统只补入真实要求并执行同物料依赖校验。
4. 技术包未维护生产工序时，页面显示没有该款生产路线，不再用字典顺序或硬编码路线填充。
5. 投产时继续读取并冻结该款已确认路线，字典只用于解释工序资料。

## 5. 场景校验

### 5.1 正常场景

款 A 的技术包明确为“裁片 → 绣花 → 车缝 → 烫包”，款 B 明确为“毛织与辅料处理并行 → 车缝”。两款分别按自己的确认路线展示和冻结，不因字典中工序的展示位置而被改成同一顺序。

### 5.2 边界场景

某款没有录入生产工序，但 BOM 存在同一物料的水溶和染色要求。系统可以生成这两个真实准备工序，并保证水溶在染色前；不得顺带补入裁片、车缝或烫包，也不得把其他未确认工序拼成默认路线。

## 6. 验收口径

- `ORDER-001`：字典页无默认顺序入口、弹窗、编号和相关事件。
- `ORDER-002`：工序定义无逐工序路线排序值，无默认顺序查询能力。
- `ORDER-003`：同阶段且无明确步骤的技术包条目保持该款原始录入顺序。
- `ORDER-004`：明确步骤、并行关系和同 BOM 工艺依赖保持有效。
- `ORDER-005`：空技术包不生成硬编码生产路线。
- `ORDER-006`：来源只显示“工序字典引用”，不再显示“字典基础路线”。
- `ORDER-007`：字典筛选和工艺详情继续可用。
- `ORDER-008`：任务清单可见地说明生产准备工序不进入任务清单，并保留 KOL-GOTO 整单任务和合并任务边界。

## 7. 假设与确认

- 本仓库为原型数据，不承担生产数据库迁移；本次删除当前代码与 Mock 中的旧来源值。
- 用户已于 2026-08-19 确认“无跨款式默认顺序”的业务口径，并授权将本次调整直接合并发布到 GitHub `main`。
