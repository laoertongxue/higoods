# 裁床接收管理紧凑分组卡片与 Web 接收实施计划

## 1. 目标与完成标准

在分支 `codex/cutting-receive-grouped-cards` 和工作树 `/private/tmp/higoods-cutting-receive-grouped-cards` 内完成三个命名页面的紧凑卡片改造与 Web 接收闭环。完成以需求矩阵全部有当前代码、专项契约和适用页面证据为准，不以构建通过或旧截图代替。

## 2. 范围与非范围

- 范围：三页结果区、卡片骨架、物料列、Web 接收弹窗、明确仓库 / 库位选择、Web/PDA 共用确认、差异阻断、接收记录、图片大图、分页、专项测试和审查记录。
- 非范围：上方筛选 / 统计、菜单 / 路由、接收节点生成、数量公式、部分接收、真实后端、鉴权、数据库、打印及离线队列。

## 3. 工作包

### WP-1 需求与证据控制

- 业务目标：把用户确认的保留、删除、动作和异常口径拆成可独立验收条目。
- 文件：总体设计、实施计划、需求追踪矩阵、原型审查记录。
- 修改：修正初版“只改展示、继续跳 PDA”的旧边界；追踪紧凑度、删列、Web 接收、PDA 回归和异常恢复。
- 验证：正向逐条映射设计→矩阵→实现→证据；反向检查代码 / 文案 / Mock / 测试无越界。
- 完成：矩阵无无说明的待实施、实施中、待验证或阻塞项。

### WP-2 明确仓库与库位投影

- 业务目标：Web 接收必须明确选择真实可用的裁床待加工仓库位，不能依赖 PDA 当前工厂或默认第一个仓库。
- 文件 / 符号：`warehouse-location-map.ts`、现有库位图模型与 SELECT 组件。
- 修改：导出可用裁床仓列表；支持按明确仓库 ID 构建 WAIT_PROCESS 库位投影；纳入现有库存和运行时占用；复用既有空闲 / 停用 / 范围校验。
- 验证：多仓不默认、错误仓库、空选择、停用、已占用及有效选择专项契约。
- 完成：提交只能取得当前选定仓库中仍为空闲的稳定库位引用。

### WP-3 Web/PDA 共用接收事务

- 业务目标：两端以同一节点、数量、库位、幂等和原子事务规则完成接收。
- 文件 / 符号：`pickup-management-runtime.ts` 的共用确认与仓库事实写入；`pda-warehouse-wait-process.ts` 的确认处理。
- 修改：抽取接收会话→待加工仓事件写入；参数化 `WEB` / `PDA` 来源与操作角色；使用跨端一致幂等键；Web 与 PDA 均调用共用协调入口；保留旧异常会话重试兼容。
- 验证：一会话、N 明细、N 入仓事件、多单位、重复确认、节点版本过期、差异阻断、事务回滚及 PDA 回归。
- 完成：同一节点只能成功确认一次，任一端重试不重复入账。

### WP-4 紧凑共用卡片与删列

- 业务目标：首屏聚焦生产单、款式、位置、数量和接收动作。
- 文件 / 符号：`pickup-management-list.ts` 的列定义、卡头、款式摘要、页面摘要、需求段和卡片渲染。
- 修改：卡头改为紧凑行；移除重复文案和嵌套操作卡；款式图缩为 64px；物料图保持 48px；删除加工状态、加工可供、已到仓、超配异常；位置列改为 180px 紧凑文本；来源列简写；卡片间距收为 12px。
- 验证：三页 DOM / 可见文案 / 列设置 / 旧偏好契约；1366×768 与 1280×720 截图和尺寸测量。
- 完成：卡头与摘要不超过目标密度，页面主体不横向溢出，首条物料进入首屏。

### WP-5 Web 接收弹窗与局部交互

- 业务目标：主管无需离开 Web 即可核对整节点物料、选择库位并确认接收。
- 文件 / 符号：`pickup-management-list.ts` 的弹窗状态、渲染、事件处理和局部刷新；FCS 全局 Esc 关闭入口。
- 修改：活动节点复核、只读物料、接收人、明确仓库、库位图、差异折叠区、确认反馈；成功清空三页快照并局部刷新；接收弹窗优先于记录和大图响应 Esc。
- 验证：打开、取消、仓库切换、库位选择、差异上报、阻断、成功、失败保留选择、跨页记录及无整页闪烁。
- 完成：Web 主按钮直接打开弹窗且可完成当前节点全部物料接收，不存在仅跳 PDA 的主流程。

### WP-6 分页、图片与三页一致性

- 业务目标：紧凑卡片仍保留分页、排序、列偏好和图片识别能力。
- 文件 / 符号：卡片分页、列偏好、大图浮层、接收记录抽屉。
- 修改：三页共用骨架和底部分页；旧列偏好归一；款式 / 物料缩略图可点大图并有加载 / 失败 / 关闭状态。
- 验证：10 / 20 / 50、空态、翻页、排序、筛选局部更新、大图按钮 / 遮罩 / Esc、图片失败态。
- 完成：同一生产单不跨页拆分，三页行为一致。

### WP-7 专项验证与交付证据

- 业务目标：以最终改动后的直接证据逐项证明无遗漏。
- 文件：相关静态检查、Playwright、完整原型审查记录、需求矩阵和任务收据。
- 修改：移除旧“Web 只能跳 PDA”契约，新增 Web 接收、删列、紧凑度和跨端一致性断言。
- 验证：相关 pickup 专项、构建、列表治理、原型治理、CodeGraph sync/status、三路由双视口浏览器验收、局域网 200 和任务收据。
- 完成：矩阵全部标记“已验证”，证据均生成于最后一次实质修改之后。

## 4. 依赖顺序

1. WP-1 固定原子需求。
2. WP-2 提供明确目的仓与可选库位。
3. WP-3 建立两端共用确认事务。
4. WP-4 与 WP-5 接入共用 UI 和 Web 主流程。
5. WP-6 补齐分页、偏好和图片交互。
6. WP-7 在最后一次修改后统一验证并回填证据。

## 5. 主要风险与控制

- 多仓误收：Web 不静默选择第一仓；必须显式选仓。
- 节点并发变化：打开与提交都核对 ID / 版本，过期立即阻断。
- 重复入账：会话和每条事件使用稳定幂等键，Web/PDA 共用。
- 半成功：接收事实与仓库流水受同一原子日志保护，失败回滚。
- 库位争用：提交前重建投影并二次校验，保留仍有效选择。
- 差异绕过：共用事务入口强制检查待处理差异。
- 视觉回退：尺寸测量与双视口截图在最终代码后执行。
- 旧列偏好：列归一化自动剔除已删除键，不修改全局偏好机制。
