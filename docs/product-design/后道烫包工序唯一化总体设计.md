# 后道烫包工序唯一化总体设计

## 1. 背景与目标

当前后道业务已在部分页面使用“烫包”，但代码中仍残留两项旧后道工序的编码、数值工艺码、双布尔字段、兼容归一、Mock 及历史说明。本次将后道阶段收口为三个实际工序：开扣眼、装扣子、烫包。

完成后，烫包的业务名、业务码、系统工序码、工艺码和质检需求字段必须全链路唯一。

## 2. 范围与非范围

### 2.1 本次范围

- 工序工艺字典、工厂能力和工序类型。
- 后道质检单、实际工序单、任务、台账与统计。
- 任务合并、履约时效、生产合同和综合评估。
- 技术包 BOM 使用工序、里程碑配置和生产确认单。
- PDA 任务、待办、交接识别和 Mock 数据。
- 旧字段、旧编码、旧数值工艺码、旧文案、旧文档和文件名残留。

### 2.2 明确不删除

- 包材档案、包装材料、包装袋和包材仓。
- 送货、装箱、包数、包装说明、包装照片和产品出货信息。
- 染色加工单在打卷后的独立成卷封装节点。该节点属于染色内部执行，不是后道成衣工序。

## 3. 权威业务对象

| 对象 | 唯一值 | 用途 |
| --- | --- | --- |
| 后道阶段 | `POST` / 后道 | 阶段分组，不生成独立工序 |
| 业务工序 | `IRON_PACK` / 烫包 | 工厂能力、任务和执行识别 |
| 系统工序 | `PROC_IRON_PACK` | 技术包和里程碑关联 |
| 工艺 | `CRAFT_2000010` / 烫包 | 工序工艺字典唯一活跃行 |
| 质检需求 | `needIronPack` | 质检结果、实际工序单和动作投影 |
| 加工对象 | 成衣 | 字典、任务、质检和交接统一识别的后道对象 |

## 4. 业务规则

1. 后道阶段只有开扣眼、装扣子、烫包三个实际工序。
2. 开扣眼或装扣子被判定需要时，烫包自动勾选并锁定；只需烫包时可单独勾选。
3. 质检单、SKU 质检明细、动作记录和实际工序单只保留一个烫包需求事实。
4. 车缝+烫包和裁剪+车缝+烫包按当前合并任务类型、履约时效和合同类型运行。
5. 新数据不做旧编码归一，不保留停用行、双写字段或旧 Mock 入口。
6. 烫包是会生成独立任务的外部工序，必须进入任务分配与生产确认；开扣眼、装扣子仍是后道内部产能节点。
7. 独立烫包按整个生产任务分配，不允许勾选 SKU 拆分任务；成衣 SKU 需求明细仍可查看。

## 5. 正常场景

后道质检员对多 SKU 成衣完成质检，勾选装扣子后，系统自动勾选并锁定烫包。提交后，加工单内保留装扣子与烫包两类明细，不生成重复的烫包事实。

## 6. 边界场景

- 仅勾选烫包：允许提交并生成烫包明细。
- 不需要任何实际后道工序：不生成实际工序单，仍经过收货、质检、复检和交接流程。
- 遇到未知后道编码：不做兼容映射，不误生成烫包任务。

## 7. 验收口径

- 工序工艺字典中后道只有三个当前工序，烫包只有一条活跃工艺。
- 独立烫包的字典数据定义为按生产单，同时保留成衣 SKU 需求明细。
- 后道质检页只展示开扣眼、装扣子、烫包。
- Web、PDA、合同、时效、技术包、Mock 和历史文档使用同一烫包口径。
- 两次核查均无旧后道工序实体、字段、映射、文案或文件名残留。
