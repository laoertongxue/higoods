## 5. 统一业务事实和计算

### 5.1 采购与整单

生产单关联一个或多个商品采购单；一张商品采购单不拆到多个生产单。取最早下单的准确时刻，加 28 个自然日得全量入成衣仓截止；合单、数组排序、生产建单日期不重置时钟。应完成量使用关联商品采购原始下单明细，消费者取消不调减。

有效成衣仓入库数量达到全部应完成数量即已全部入库。最终全量入库时间可核实时独立判按期或逾期；仅数量明确而时间缺少时，显示“已全部入库／按期结果待核实”。上游资料冲突另列核实，不把已入库整单重新标成生产未完成。未取得入库量则未知，不能当 0。

整单结果、局部工作时效、资料完整性为三个独立维度。“无当前合同逾期”不承诺整单必按期；单项历史逾期也不能自动认定整单逾期。没有可靠预计结束依据时保留整单按期把握待核实。

### 5.2 数量

成衣数量在未下发／工厂／后道／已交出待收／仓库／位置待核实之间互斥归属，批次及 SKU 去重并可追到源单。已实收但后道位置缺少的残余数量保留在“位置待核实”；任务归属缺少单列，不能替其他工厂承担。

物料需求＝本单库存采用＋本单补采；采购、原料仓入库、调拨交出、下游实收、加工产出各自表达事实。同一物料的库存批可按实际批次先行，不强制等待采购批。实际采用全量加工单才在图中汇合。

米、粒、个、片、件不相加。辅助工艺的 600 袖片不能自动变成 600 件成衣。工厂合同回货分母为该任务工厂实领量，分子为归属该任务的后道实收量；同厂不同任务不能互相抵扣欠量。

### 5.3 准备、工艺和交接

准备整体由最早采购下单计时，无定位印 4 天、有定位印 5 天；多支线不累加阶段要求。准备单、BOM、前期输入、调色／花型／样衣／纸样／辅料下单／技术包确认及发布读取明确适用与复用关系，按当前 PCS 方案展开。翻单复用显示原成果与版本，不虚构本次制作时间；未启用及需求变更结束项不是当前欠项。

每笔物料采购从自己的下单时间到面辅料仓实际入库，要求 8 自然日。每道适用辅助工艺要求 3 自然日。大货染色／印花／水洗等其他标准和交接标准未确认时只展示真实历时及“标准待配置”，不能套辅助工艺 3 天。

制作／加工用明确实际开始至完成；交接用上游实际交出／调拨出至下游实际接收；未发生事件不启动其时钟。每项至少执行人和接收确认责任，质检交接事实保留已有结果、数量及差异，不增加审批等待计时。

中转仓收货、人工配料与裁床领料必须读取明确的单据事实，不能从“裁床接收”简写倒推。原 19 场景无这些具体源记录的入口展示“待核实”，不补假完成。独立 SCENE-20 的 A01 纽扣 9,000 粒补有三张单据：09-20 15:30 辅料仓周婷交出、16:00 中转仓林芳接收；16:20 至 16:40 林芳人工配料；16:50 交出、17:00 裁床刘军实领 9,000 粒，差异 0。对应 WLS `/wls/transit/receive-manage`、`/wls/transit/allocation-manage`、`/wls/transit/outbound-manage`，依次关联并回链原调拨单。仅此补充场景补单，原 19 场景事实不改；标准未确认则不判逾期，不增加齐套或审批闸门（SUPPLY-005）。

裁片部位可分别裁出并开展无需／单道／多道工艺。裁片放行和辅料配料按来源人工事实显示，监控系统不自动判齐套、自动放行或自动下发车缝任务。

### 5.4 合同与工厂产前样衣

合同从业务分配日期起算，分配日为第 1 天，全部自然日含星期日。独立车缝 30%／70%／100% 为第 4／8／9 天；车缝＋烫包为第 5／9／10 天；裁剪＋车缝＋烫包为第 6／9／12 天。读取原分配及适用合同，不在 DDS 保存第二套规则。缺业务分配日期不回退到接单日期，旧快照保留原记录并显示“业务分配日期待核实，回货时效暂不能判定”。PDA 与进度看板不能因为无可判节点而显示全部节点完成；相关消费者为 `src/pages/pda-exec-detail.ts` 与 `src/pages/progress-board/task-domain.ts`，已有专项和当前原生PDA/看板85完整样本，缺日期不假完成、已知日期仍正常；CONTRACT-005已验证。原生补充任务只用于该边界，不增加V7图示场景。

## 7. 来源单据、存储与失败边界

来源要有显式关系：商品采购 → 生产单；生产单 → 生产准备及所用正式技术包版本；BOM物料 → 供给需求 → 采购／原料入库／库存调拨 → 加工及逐次交接 → 中转配料／裁床领料；裁剪部位 → 工艺加工及交接 → 人工放行；车缝任务分配及合同 → 工厂实领 → 后道实收 → 后道加工／交出 → 成衣仓入库。不能按同款或同厂猜归属。

静态 Mock 由 `src/data/production-timing/fixtures.json` 和 `source.ts` 的共享只读登记提供；DDS 图示与 `source-document-detail.ts` 原模块详情适配读取同一张登记记录，不另存摘要副本。仅精确匹配已登记 native 单据 ID 的路径进入适配页，其余记录仍由原模块处理。此接入不等于所有原模块列表已包含这些记录，不新增真实办理能力。单据存在和动作完成分开，未来计划不可当实际完成。

本轮排除来源绑定与规则修改保存能力，当前入口停止调用旧写入；原浏览器资料保留，不删除、不迁移、不清空。继续跟进由 `timing-followups.ts` 调用既有 `followup-storage.ts` 的按记录 IndexedDB 事务，生产单 ID 为明确归属。未保存输入留在内存；跟进人、对应工作／整单、原因、动作、业务人员预计时间与历史记录同窗展示，预计时间只作反馈不覆盖源事实。事务 complete 后才显示成功，操作 ID 稳定并检查版本；保存失败保留输入。登记实际时间与固定演示核实时点分开。普通保存 5 次已读回确认，刷新和独立新标签可读历史；草稿和连续保存另有修复后 5 次记录。浏览器故障注入此前被自动审批拒绝（user declined），用户现已授权临时验收注入，失败、配额与冲突的实际浏览器场景再次重放仍被权限设置拒绝，现时已阻塞（STORE-005），单元契约不能替代该门禁。旧需求跟进无法证明唯一生产单归属时保留原记录，不猜映射、不复制到多单。静态演示记录不首次写入业务库，读取不回写；偏好仅可使用有界 localStorage。IDB失败不能冒充空记录或正常0值。

款式、物料、部位对象使用明确对应素材；图内识别块、摘要与源详情同步，支持大图、加载和失败态。当前素材由 `src/data/production-timing/material-images.ts` 明确映射：款式为 `/images/production-timing/shirt-086.jpg`；F01 为 PCS 白坯原料示意 `/materials/fei-ticket/white-poplin.png`，不能将蓝底／花型目标当已取得原料；F02、A01、A02、A03 为静态原型物料效果图，来源、SHA256 与 Mock 标记登记在 `public/images/production-timing/material-effect-sources.json`。这些素材用于原型识别，不证明真实物料规格或采购实物。源详情款式／物料缩略图和大图已实测，未知采购明确缺图；加载失败态已落代码，F02摘要与原详情图片加载失败各5次已验证（UI-012，见最终矩阵）。图示与 V7 的同有效宽度像素一致尚无通过证据（UI-011）。不能把V7款式图片冒充物料图，不以原型或基线未提供素材为由豁免图片门禁。
