# V2.0 页面信息结构修订与审阅安排

依据：用户2026-09-17指出页面从上到下平铺、主次不清，并要求逐行审阅产品方案。此次改动先修正任务与信息的对应关系，再重新核对业务覆盖。V1.0旧验收的浏览器通过不能证明信息结构合适；本次受影响条目重新验证。

## 页面层级

|层级|入口|回答的问题|下一步|
|---|---|---|---|
|一级：时效总览|运行概况 / 分布分析 / 数据待补，互斥Tab|整体是否异常；哪些事项值得进入查看|点击状态、日期、阶段，带当前筛选进入生产任务列表|
|二级：生产任务|标准列表，可返回总览|具体是哪几笔、先跟哪一笔|进入某任务详情|
|三级：任务详情|全程时效 / 工作明细 / 数量批次 / 实发订单 / 计算与版本 / 跟进记录|本任务为什么晚、卡在哪个工作|工作抽屉进一步查看证据|
|四级：工作项抽屉|时效与数量 / 前后依赖 / 来源证据|这个工作谁做、何时完成、事实是什么|在原位置登记跟进或查看前后工作|
|一级：团队与工厂|组织列表|哪个团队需要关注|进入团队工作台|
|二级：团队工作台|可执行工作 / 需要协调 / 交付记录，互斥Tab|现在先做什么、催谁、历史表现如何|进入工作项或任务|
|独立二级：规则验证示例|从规则配置和任务公式进入|某个边界怎么算|按示例选择查看，不混入真实任务正文或任务统计|

## 内容分配

- 总览默认只保留紧凑摘要、到期压力和最多3笔重点入口。完整宽表放生产任务页；阶段和责任归入分布分析；数据事项独立页签。一级页面不拼接全部下级列表。
- 全部业务查询页默认显示四项高频条件，更多条件在同一等列网格展开；查询、重置、导出、更多/收起固定在全部条件之后的底行。统计统一48px。Tab切换保留已应用筛选，草稿仅查询后生效。
- 任务页首屏采用48px时效摘要，风险条只放一句原因和工作入口；默认展开正在执行及风险阶段，已完成阶段折叠。所有阶段始终可见，可展开全部。
- 数量批次分数量进度、数量与放行两个子页签。计算与版本分整体公式、逐项倒排、版本记录，以及有未定路线时的路线判断；每次仅渲染当前内容。
- 独立BOM/返工/缺关联等演算移到规则验证示例，不再放在某一生产任务的公式后面。数据来源、计算上下文和返回入口须明确。
- 工作抽屉按时效数量、依赖、来源证据分Tab；跟进动作放固定底栏。内容不足时明确未知，不补零。
