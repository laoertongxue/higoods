## 1. 当前来源快照与范围

本轮已核对的接入范围是 **33 条 FCS 生产需求、30 条明确技术包路线映射、14 条需求对应的 76 个既有执行任务**。这些记录来自当前仓库的原型业务库，不是线上业务数据。数字是本轮快照，不是固定模板、目标完成数或正式时效结论，后续应随来源记录计算。当前任务的读取时点使用本次实际读取时间，各任务 asOf 驱动已用时间、逾期判定与甘特当前线；旧固定演示时钟只在独立规则示例保留。

|来源对象|已经具备的依据|尚未具备或不得推断的依据|
|---|---|---|
|FCS 生产需求|原需求 ID、来源采购编号、需求数量、跟单和现有时间字段|来源字段不能证明采购精确下单时刻时，不能自行补出 T0 的时分秒|
|技术包路线|30 条明确映射；节点、直接前置、投入／产出 SKU 与关联版本|没有明确映射的不按同款默认选择；没有显式前置不按阶段顺序补边|
|既有执行任务|14 条需求、76 个任务及已有实际工厂、状态和起止字段|执行数量可能是多需求共用的生产单总量，不能当本需求份额；未匹配不伪造，同工艺不同节点不合并|
|PCS 生产准备|现有专业任务类型、适用/复用规则；DDS 可保留显式同款关联|默认本地准备库为空；准备主单没有需求 ID 关系，不能编造默认准备单或准备完成|
|合格产出和发货|当前没有接通完整可核算的事实|来源执行状态/计划量不能充当合格量；未接实发不能推定 0、不能造客户订单|
|正式 SLA 和发货承诺|当前没有接通可用于任务考核的完整标准|需求生产交期不等于全部发货截止；旧 Mock 预算不自动套入当前任务|

V1/V2 的 10 笔独立任务、31 项/24 天主例、5 个订单、7000/400/6600 件和 3/5 等指标只保留为历史规则示例；当前主列表、总览、跟单、团队、工作项、订单统计都不能读取这些数值作为实际来源。示例可以在“规则验证示例”中说明计算方法，必须与当前业务任务分开。

## 2. 生产任务、准备与工艺工作

1. 商品采购与 1:1 生产需求是同一生产任务起点。主列表读取现有 FCS 需求；同款不同需求各自保留来源标识、数量和起点，生产单合并不能重置时钟。
2. 当前 PCS 准备主单没有需求关联字段。DDS 允许选择并显式关联同款的已有准备单和技术包，保存本地关联；不凭同款自动认定归属，不在 DDS 创建或完成准备业务。错误款式关联须阻断。
3. 默认本地准备库为空时，显示暂无可关联准备单及来源入口；这属于当前初始现场状态，不能为了填满时效图造一张准备单。显式关联仅改变 DDS 的来源关系，不改变 PCS 业务事实。
4. 关联后，准备工作读取原专业任务、类型适用规则、前期成果复用和已存在完成事件。产前样、尺码纸样、花型、调色、辅料下单、技术资料确认按来源展开，不压成固定三天“技术准备”。无需执行、已复用、尚未确定分别显示依据；复用不虚构本次制作耗时。
5. 工艺工作读取技术包明确节点和直接前置；并行分支保留，同工艺不同节点分别计时。节点投入／产出 SKU、既有任务、实际工厂和可用起止依来源显示。阶段只是浏览分类，不能生成固定串行路线。已实际开工的工作不能仅因无 SLA 被归为不可执行；执行可行性与时效可判定性分开。
6. 缺路线、缺明确前置、缺执行任务、缺时刻各自显示具体缺项。前置不完整、预算缺失或其他必要条件未知时，整体要求和预测传播为待判定，不能补 0 或强算 24 天。

## 3. 时效与数量的当前边界

- 统一自然日持续计时；页面、筛选和导出固定北京时间，不提供时间/时区选择，也不另加顶部时区提示。绝对时刻和来源精度保留。
- 生产需求交期保留其生产交付含义。未取得明确的全程实际发货承诺，不能将该日期显示为“全部客户订单发货截止”，也不能据它认定整体已发货逾期。
- 正式单项预算、阶段上限或全程规则未接通时显示待配置；要求数量是否已知与实际合格数量是否已知分别表示。来源可以已知要求量、未知合格量，此时只显示前者，不能将未知合格量显示为 0；工作状态不等于质量放行数量。
- 来源执行任务数量可能是覆盖多笔需求的生产单总量，显示“来源生产单总量；本需求份额待确认”。例如总执行量 2500 件而本需求 20 件，不能把 2500 件当该需求的要求量、产出量或进度分母；缺分配仍是业务缺口。
- 尚无实际发货及生产来源归属事实时，已发、剩余应发、发货进度和订单履约结果不能借旧 Mock 补全。需求量可显示，但应与尚不可核算的发货字段分开。只有实际发货后才知道对应客户订单。
- 来源没有 SLA 时仍可登记责任人有依据的手工预计日期，但只作为该工作人工预计，必须明确方法；不改变实际起止、合格数量或标准要求，也不能据此自动补齐全程预测。
- 旧规则示例的发布和试算不能隐式写入当前来源任务的正式 SLA。原始基线、当前路线标准、生效截止、预测和实际结果仍保持分离，缺少的结果明确未知。

## 4. 界面与信息结构

1. 移除业务页面顶部 Mock 标签、查看角色、时区选择；说明来源性质放在来源说明和文档，不继续占据首屏。删除标签不改变原型与线上事实的边界。
2. 当前管理入口使用既定身份；责任筛选不会更改授权身份或制造真实权限服务。我的跟单依据既定身份与来源负责人，不再使用旧 Mock 跟单甲的固定两笔结果。
3. 默认筛选固定四列：检索、跟单、责任团队、责任工厂。团队与工厂独立；工厂候选仅来自实际来源工厂并保留“未指定”，不能将准备团队、不适用等文本当作工厂。更多条件继续同列宽网格，不因第二行字段少而拉伸。查询、重置、导出、更多/收起按钮必须位于全部条件之后。
4. 查询后列表、统计、图形和导出使用同一范围；重置清全部条件；导出包含当前条件全部匹配记录。固定北京时间同样适用于日期边界。
5. 保留 V2 的总览互斥 Tab、任务顶部 Tab、团队可执行/协调分层和单独规则示例页。来源缺口集中在可定位的二级区域，不恢复纵向平铺大量说明和长表。
6. 任务“工作明细”内部使用嵌入表，不重复页面大标题、不叠多层卡片内边距；左沿对齐，紧凑工具区保留列设置和分页。独立列表仍按标准查询、摘要、列表、分页结构。

后续须保留最终同分支、HEAD、工作树、服务、浏览器、尺寸、数据量、缓存条件的原始证据。首次进入、冷启动、刷新、站内切换和每个交互入口各至少 5 次，包含首次，终点为必要内容和图片完整可用；所有样本严格小于 200ms 后才可能关闭对应性能需求。来源正确性、图形/数量/时效语义和图片也须独立验证，性能通过不代替业务正确。
