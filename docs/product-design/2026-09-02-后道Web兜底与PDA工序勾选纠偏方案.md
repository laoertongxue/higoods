## 1. 本轮确认的业务结论

1. 后道现场动作仍以 PDA 为首选，但 PDA 不是唯一入口。待加工仓收货、后道开始、完成数量填报、瑕疵调整和完成后道必须在 Web 保留同一业务事实上的应急兜底能力。
2. 后道待加工仓必须明确提供“扫码收货（Web 兜底）”。扫码枪输入优先，同时允许手工输入完整送货单号；二者只能定位同一张待确认送货单，不能形成第二套收货记录。
3. 后道要做哪些加工项目已经在质检阶段确认。后道执行页只读展示这些项目，不允许后道操作员再次勾选、增加或减少项目。
4. PDA 后道加工的主任务是逐 SKU 填写本次完成数量。瑕疵与返厂属于完成数量内的结果调整，不得把原因、责任和证据字段平铺在 SKU 卡片首屏。
5. 每个 SKU 的瑕疵调整进入独立聚焦页面，先选择“增加瑕疵”或“减少瑕疵”，再逐项填写每种瑕疵原因对应的数量。总瑕疵数量只能由原因明细求和，不能输入一个总数后全部归到单一原因。
6. 责任方和现场证据图片不属于本轮后道执行事实，PDA 与 Web 后道调整页、提交参数和完成结果均不再提供这两个板块。
7. 返厂数量仍属于结果调整。返厂数量大于 0 时必须填写返厂原因，并从可搜索的接收对象列表中选择接收责任；PDA 使用适合小屏的大触控候选列表。
8. 后道单只有在每个 SKU 已填写合法完成数量后，才允许完成后道并生成复检单。是否可以完成不以是否交出或交出多少为依据。
9. “差异与操作日志”详情不得把链路、差异、瑕疵和全部操作记录同时纵向平铺。详情采用“链路概览 / 差异与瑕疵 / 操作记录”分层导航；操作记录再按业务阶段分组。

## 2. 角色与端侧分工

| 角色与端 | 首选动作 | 兜底与限制 |
|---|---|---|
| 后道仓管 PDA | 扫描送货单，逐 SKU 确认收货 | 与 Web 读取同一待确认记录 |
| 后道仓管 Web | PDA 故障时扫描或输入完整送货单号，完成相同确认 | 页面明确标注“Web 兜底”，不得模糊查询后代选 |
| 后道操作员 PDA | 扫描后道单，逐 SKU 填写完成数量，必要时进入瑕疵调整页 | 小屏首屏只突出当前 SKU、已确认项目、完成数量和主动作 |
| 后道操作员 Web | PDA 故障时从后道单详情开始、继续、调整和完成 | 操作人与应急来源写入日志；不建立独立状态机 |
| 后道管理人员 Web | 查看列表、打印、追溯、必要时应急接管 | 接管必须有明确原因和操作事实 |
| 追溯人员 Web | 先看链路概览，再按需切换差异或操作记录 | 默认不同时展开所有明细 |

## 3. 共享业务事实

### 3.1 待加工仓扫码收货

- 输入对象只能是完整送货单号。
- 扫码枪回车和点击“识别送货单”调用同一定位逻辑。
- PDA 与 Web 使用同一回货确认记录、逐 SKU 点数、5% 阈值、授权、操作人和库存流水。
- Web 入口只是在设备故障时提供另一种界面，不复制数据，不绕过差异授权。

### 3.2 后道加工进度

每张后道单按 SKU 保存一条加工草稿，至少包含：

- SKU 标识和应加工数量。
- 本次完成数量。
- 各瑕疵原因当前数量明细及其合计。
- 返厂数量、返厂原因和接收责任方。
- 最近操作人和时间。

加工项目继续读取质检阶段已经确认的项目，只读展示，不进入后道草稿。开始后道时初始化数量草稿；PDA 与 Web 更新同一草稿，一端填写的完成数量或瑕疵调整必须在另一端可见。

### 3.3 完成门禁

完成后道前依次校验：

1. 当前操作人有权继续该任务；若 Web 应急接管，必须先记录接管原因。
2. 每个 SKU 已填写大于 0 且不超过应加工数量的完成数量，或者瑕疵与返厂已经覆盖该 SKU 的全部应加工数量。
3. 每种瑕疵原因数量和返厂数量均为非负整数；未填写完成数量时，原因明细合计加返厂数量不得超过应加工数量；已填写完成数量后不得超过该完成数量。
4. 增加瑕疵时，每个填写数量都绑定明确原因；减少瑕疵时，每种原因减少量不得超过该原因当前数量。
5. 返厂数量大于 0 时已填写返厂原因，并从候选列表选择接收责任。
6. 后道合格数量由“完成数量 - 各原因瑕疵合计 - 返厂数量”计算；整批均为瑕疵或返厂时，系统以应加工数量作为本批已处理总数并得出合格 0 件，不要求先填写完成数量。
7. 本环节与全链数量差异按既有授权规则处理。

全部通过后，后道单状态变为“后道完成”，并幂等生成唯一复检单。

## 4. 页面结构

### 4.1 后道待加工仓 Web

- 页面主按钮：`扫码收货（Web 兜底）`。
- 弹层首行说明：`PDA 扫码优先；PDA 不可用时在这里扫描或输入完整送货单号。`
- 单一输入框同时接收扫码枪和手工输入。
- 识别后进入现有逐 SKU 回货确认页，不新增第二张收货单。

### 4.2 后道单 Web

- 列表同时保留 `PDA 执行（优先）`、`Web 应急处理`、打印和追溯入口。
- Web 详情展示任务摘要、质检已确认的只读加工项目、每个 SKU 的完成数量输入和紧凑瑕疵摘要。
- `调整瑕疵`进入当前 SKU 的聚焦调整区。
- `完成后道`在每个 SKU 已填写合法完成数量，或整批已全部归入瑕疵/返厂后可用。

### 4.3 PDA 后道加工

- 任务识别页仍为精确扫码/输入。
- 任务详情按 SKU 卡片展示真实图片、SKU、颜色、尺码、应加工数量、质检已确认的只读加工项目和完成数量输入框。
- 每张卡片始终显示一个次级入口：`调整瑕疵数量`；无论是否已填写完成数量都可直接进入并登记瑕疵。
- 卡片只展示紧凑摘要，不平铺原因、图片、责任方、返厂等输入。
- 页面底部持续显示每个 SKU 的数量归类进度；完成数量已填或整批已全部归入瑕疵/返厂，均视为该 SKU 已处理。

### 4.4 PDA SKU 调整页

- 顶部显示返回后道单、SKU 图片与标识。
- 瑕疵区先选择增加或减少，再按原因字典逐行填写数量；总数由系统求和，不提供独立总数输入框。
- 页面不显示责任方、现场证据图片或图片地址。
- 返厂区独立展示数量、原因和接收责任；接收责任通过可搜索候选列表选择，不允许自由文本冒充已选对象。
- 保存后返回后道单，主页面只显示结果摘要。
- 整批均为瑕疵时可直接按具体原因登记全部应加工数量，返回后显示合格 0 件并允许完成后道。

### 4.5 差异与操作日志详情

- 顶部固定展示生产单、回货序号、送货单、当前阶段和状态。
- 一级导航：`链路概览`、`差异与瑕疵`、`操作记录`。
- 链路概览按上游接收、质量、后道、交出分组展示节点，不展示完整日志。
- 差异与瑕疵只展示有差异的 SKU 和统一瑕疵记录。
- 操作记录按业务阶段分组，每组内部按时间排序。

## 5. 正常与边界场景

### 5.1 正常场景

1. 仓管在 Web 扫描完整送货单号，进入同一回货确认记录并完成收货。
2. 操作员在 PDA 开始后道，逐 SKU 填写完成数量；加工项目只读核对，无瑕疵时直接完成。
3. 某 SKU 发现两类瑕疵，进入独立调整页，在“增加瑕疵”下分别填写两种原因数量，返回后继续填报并完成。
4. 已有瑕疵需要更正时，选择“减少瑕疵”，分别填写各原因减少量；系统逐原因校验余额。
5. PDA 故障后，Web 打开同一后道单，读取已保存进度并继续完成。
6. 某 SKU 整批均为瑕疵时，不先填写完成数量，直接按具体原因登记全部应加工数量；系统显示合格 0 件并允许完成。

### 5.2 阻断与恢复场景

1. 输入部分送货单号：不定位、不展示候选、不代选。
2. 任一 SKU 既未填写完成数量、瑕疵与返厂也未覆盖全部应加工数量：完成按钮不可用；完成数量超过应加工数量时领域提交阻断。
3. 增加/减少瑕疵没有任何原因数量：不形成调整；减少某原因超过现有数量：保存阻断并指出具体原因。
4. 未填写完成数量时，各原因瑕疵合计加返厂超过应加工数量则保存阻断；已填写完成数量时超过完成数量则保存阻断。
5. Web 操作人与当前任务操作人不一致：要求明确应急接管原因并记录接管事实。
6. PDA/Web 重复保存同一完成数量：覆盖同一 SKU 草稿，不重复累计；瑕疵调整按明确的增加/减少动作累计并留痕。
7. 日志详情切换标签：只展示当前层级，URL 保留业务链和当前标签，刷新后不丢失。

## 6. 验收口径

- 代码验证：共享事实、完成门禁、原因必填、Web/PDA 同步和日志分组契约通过。
- Web 验收：待加工仓扫码收货、后道单 Web 应急开始、完成数量填报、逐原因瑕疵增减和完成全部可操作。
- PDA 验收：小屏下完成数量为主动作，加工项目只读；独立 SKU 调整页可完成逐原因增减和返厂接收对象搜索选择。
- 追溯验收：三个详情标签互斥展示，操作记录按阶段分组。
- 图片验收：SKU 图片、加载中、失败态和大图能力保持有效。
- 原型边界：以上是当前分支 Mock/LocalStorage 原型能力；不等同于真实后端、现场 PDA 或生产数据已经验收。
