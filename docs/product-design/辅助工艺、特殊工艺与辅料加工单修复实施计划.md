# 辅助工艺、特殊工艺与辅料加工单修复实施计划

> 计划日期：2026-08-28
> 事实来源：《辅助工艺、特殊工艺与辅料加工单全链核查报告》
> 当前状态：逐标签／逐菲票扫码改造已完成本地双轮验证；现实 iData 两轮与实体打印扫码仍阻塞
> 当前版本：基线 HEAD `0d371d62663aa7dd1825288f23459844f7c9b844` + 当前未提交工作树差异
> 实施边界：业务源码、Mock、路由、测试和本地页面已实施；未部署远端环境，不以浏览器小屏代替现实 PDA
> 更新依据：接单以任务为核心；接单后全链以具体加工单为主线；Web 员工主流程收口为四动作；PDA 以少填、多扫码完成同一业务事实
> 范围澄清：辅助工艺、特殊工艺和辅料加工单不使用开工、开工凭证、关键节点上报、补报关键节点、查看开工和节点；任务不手工完成，由其全部加工单完成后自动完成。三方小缝纫工厂及印花、染色专用加工单链不在本计划改造范围
> 详化修订：每个辅助工艺、特殊工艺、捆条加工单和花边辅料加工单均建立独立的全流程测试包；共享测试能力可以复用，但测试数据、用例名称、执行结果和证据不得由其他工艺代表。当前 167 张加工单必须逐单执行完整领域动作，两轮结果和业务记录均需留存

## 1. 目标与完成标准

本计划修复 13 种辅助工艺、4 种特殊工艺、独立捆条加工单和花边辅料加工单之间的对象身份、分批数量、交出、仓库、质检、结算、打印和 Web/PDA 不一致问题。

完成后必须同时满足：

1. `taskId` 只表示报价、竞价、接单、分配、价格、时效和聚合任务；生成具体加工单后，`workOrderId` 是接收、加工填报、分批交出、完成、仓库、质检、结算、打印和审计的唯一业务主线。
2. 一任务多加工单时，用户选择哪张加工单，URL、详情、动作、仓库、交出、打印和日志就始终指向哪张，不允许取第一张兜底。
3. 裁片、成衣、盘扣、捆条、橡筋辅料和花边辅料分别保留正确的加工前对象、加工后对象、数量单位和去向。
4. Web 与 PDA 共用已确认的四动作：确认接收、加工填报、发起交出、完成加工单；两端可采用不同布局和输入方式，但必须执行同一张加工单、同一数量规则和同一状态门禁。
5. 本范围的 Web、PDA、权限、配置、处理器、数据、日志、文案和测试均不提供或生成开工、开工凭证、关键节点上报、补报关键节点、查看开工和节点。
6. 对具有来源任务的链路，任务下至少存在一张加工单且所有加工单都完成后，任务由系统自动完成；不存在手工“完成任务”入口、动作载荷或写回处理器。
7. PDA 以扫加工单、菲票、SKU、物料或规格码为主，系统自动带出可确定信息；实际收到、本次完工、本次交出和差异等现场事实仍必须输入或明确确认。
8. 修复后的 19 行矩阵均有自动化、命名页面和适用的现实 PDA/打印证据；不存在冲突的旧 Mock、旧入口、旧二维码和旧文案。
9. “全部测试通过”是最终整体结论，不是本地自动化结论。只有 167 张加工单本地两轮逐单全流程、162 张 PDA 适用加工单现实 iData 两轮逐单全流程及实体打印扫码全部通过，并且每次动作都有可反查的业务记录，才允许使用该表述。

## 2. 已确定的设计决策

### 2.1 任务与加工单身份

- `taskId/sourceTaskId`：只是报价、竞价、接单、分配、工厂责任、价格、交期和聚合进度的身份。任务只在“接单”模块是用户主操作对象。
- `workOrderId/taskOrderId/bindingOrderId`：接单后的唯一业务主线，承载执行、分批数量、交出、仓库、质检、结算、打印和审计。
- PDA 候选、URL 和动作载荷以 `sourceType + workOrderId` 唯一定位。客户端不再把 `taskId` 作为执行定位参数，避免用户端传入一对不一致的 ID。
- 领域服务通过具体加工单反查当前有效 `sourceTaskId`，再校验任务已接单、工厂归属、任务/加工单状态和时效。审计记录同时固化 `workOrderId` 和当时有效的 `sourceTaskId`。
- 允许扫任务码或生产单码列出候选加工单；候选只是导航，禁止按 `taskId` 直接 `.find()` 一张加工单作为执行对象。
- 缺 `workOrderId`、扫码对应多张加工单但未选定、加工单无有效来源任务、工厂不匹配或状态不允许时，必须阻断并给出明确恢复动作，不得静默兜底。

### 2.2 PDA URL 与候选契约

接单任务保留现有任务路由：

```text
/fcs/pda/task-receive/:taskId
```

接单后的加工单执行路由统一使用：

```text
/fcs/pda/exec/:sourceType/:workOrderId
```

从交接进入时，依然以具体加工单定位：

```text
/fcs/pda/handover/:sourceType/:workOrderId?action=receive|handout&returnTo=...
```

捆条加工单使用 `sourceType=BINDING_PROCESS_ORDER`；辅助/特殊工艺使用 `sourceType=SPECIAL_CRAFT`。如后续为花边增加 PDA，也必须直接使用花边 `workOrderId`，但本阶段不实施。

### 2.3 动作、状态与任务自动完成边界

- 辅助工艺、特殊工艺、捆条和适用的辅料加工单只保留“确认接收、加工填报、发起交出、完成加工单”四个员工主动作。
- 本范围不显示、不校验、不保存、不打印也不追溯开工、开工凭证、关键节点上报、补报关键节点、查看开工和节点；不得把第一次加工填报转换成自动开工事件。
- 确认接收只推进加工单自身的接收/加工状态，不产生独立开工记录。
- “完成加工单”仍是对当前具体加工单的员工操作；一次只能完成当前 `workOrderId`，不得顺带完成来源任务或同任务其他加工单。
- 加工单完成写回后，领域服务重新读取来源任务下的全部加工单。只有任务下至少有一张加工单，且每一张加工单均为已完成，任务才自动完成。
- 任一加工单仍未完成时任务不得完成；取消、作废或零加工单不得被静默视为“全部完成”。这些关闭规则如需扩展，必须另行确认。
- Web 和 PDA 均删除本范围的手工“完成任务”入口；任务自动完成必须由加工单完成写回触发，并保证重复提交幂等。
- 三方小缝纫工厂原有开工、开工凭证和关键节点能力保持原链，不在本计划删除或迁移。
- 印花、染色专用加工单链状态和节点另行设计，本计划不复用四动作结论修改其代码。

候选对象必须显式包含：

```ts
{
  sourceType: 'SPECIAL_CRAFT' | 'BINDING_PROCESS_ORDER'
  workOrderId: string
  workOrderNo: string
  sourceTaskNo?: string
}
```

按钮 DOM 和扫码结果只使用 `data-source-type` 和 `data-work-order-id` 定位执行对象。`sourceTaskNo` 只在加工单基本信息中弱化展示，不参与详情解析。

### 2.3 交出、仓库、质检与结算的加工单主线

交出单、收货记录、库存记录、质检记录和结算明细保留各自的记录 ID，但都是加工单的分批子事实。以下结构统一新增并持久化 `workOrderId/workOrderNo`，必要时同时保存本次产出批次、交出批次或收货批次 ID；`taskId/taskNo` 只作来源快照：

- `PdaHandoverHead` 和交出明细/记录
- `FactoryWarehouseInboundRecord`
- `FactoryWaitProcessStockItem`
- `FactoryWaitHandoverStockItem`
- `FactoryWarehouseOutboundRecord`
- 库存项、差异记录和操作日志
- 质检批次、质检记录及质量扣款依据
- 收入流水、结算明细和对账明细

加工单必须汇总计划、累计完成、累计交出、累计实收、累计质检、合格/不合格、累计结算及各阶段剩余量。查看来源、数量写回、差异、扣款、结算和审计全部以 `workOrderId` 为主线。

旧记录兼容只允许两种结果：

1. 能从结构化来源或嵌入 ID 唯一映射到一张现存加工单，则补齐 `workOrderId/workOrderNo`。
2. 无法唯一映射，则从可操作仓库列表隔离，并记录迁移失败；不允许取第一张或把 `taskId` 当加工单 ID。

价格可以来自任务合同，但结算明细必须保存实际执行的 `workOrderId`、可结算数量、单位、价格快照和价格来源 `sourceTaskId`。已确认的 KOL 整单固定总价等“任务本身就是结算对象”的特例必须单独列出，不得污染本计划范围内的普通加工单链。

### 2.4 打印身份

- FCS 二维码类型新增 `WORK_ORDER`，格式为 `FCS:WORK_ORDER:v1:<workOrderId>`。
- 特殊/辅助工艺流转卡分别显示“任务号”和“加工单号”，不能再用加工单号冒充任务号。
- 扫码后按 `sourceType + workOrderId` 找具体加工单，再由系统取得来源任务和工厂并校验，进入只以加工单定位的 PDA URL。
- 打印数量字段按对象显示：裁片“计划裁片数量”、成衣“计划成衣数量”、盘扣“投入捆条菲票/计划盘扣产出”、橡筋“计划辅料投入/计划定长产出”。

### 2.5 数量与提交

- 裁片：按菲票和裁片部位确认，单位片。
- 成衣：按 SKU 确认，单位件。
- 盘扣：接收按捆条菲票张数；捆条长度只追溯；加工产出和交出按个。
- 捆条：按具体捆条加工单和规格记录裁剪长度，单位米；菲票对应具体规格。
- 橡筋定长切割：加工前对象是 BOM 辅料，投入单位直接继承 BOM 物料单位；加工后对象是定长橡筋，产出单位来自技术包定长需求，通常为条。上游缺定长、产出数量或单位时阻断生成，禁止回退为裁片/片。
- 花边：加工前是采购需求定义的投入行，加工后是采购 SKU，数量单位继承采购 SKU。
- 同一加工单允许多次加工填报和多次发起交出；每批记录本次数量、单位、对象明细、操作人和时间。
- `可交出 = 累计完工产出 - 累计已交出`；仓库实收、质检和结算分别按自己的上游可用量限制，不得超量或跨加工单抵扣。
- 加工填报可按业务对象显示系统建议量，但确认接收和发起交出不得用整单剩余量自动代替实物识别。必须先逐张扫描本批面料／辅料标签、裁片菲票或加工后标签／菲票，再允许修改该标签的本次数量并明确确认。
- 完成加工单不再填数量，而是汇总显示计划、完工、已交、差异和未处理事项；门禁通过后一次确认完成。
- 每次提交生成 `confirmationKey`。相同 `sourceType + workOrderId + actionCode + confirmationKey` 返回同一结果，不重复累计。

### 2.6 范围决策

- 花边继续 Web-only，本阶段不新增 PDA 和打印，不建立第二套状态账。
- 捆条加工单必须补 PDA，因为当前现场执行对象不能继续停留在裁床任务层。
- PDA 删除长篇业务备注和说明，只保留加工单号、对象、关键图片、数量、输入/选择项、主动作、阻断原因和主管兜底；不能为了“简单”删除防错身份与数量。
- 撤销完成、取消、恢复、差异核准等主管纠错动作可按已确认权限保留在 Web，但不计入员工四个主动作，本阶段不为此增加 PDA 按钮。
- 本范围不得继承通用任务执行页的“开工、开工凭证、关键节点上报、补报关键节点、查看开工和节点、完成任务”按钮或处理器。
- 三方小缝纫工厂的开工/关键节点体系明确保留；印花、染色专用加工单链明确隔离，均不得因本计划产生行为回归。

### 2.7 PDA 导航与交互决策

- “接单”只以任务为核心，展示待接单、待报价、已报价和已中标；不在该模块执行加工单数量动作。
- “执行”只展示可执行的具体加工单，提供扫码、加工填报和完成加工单。
- “交接”以具体加工单为入口，提供扫码、确认接收和发起交出。
- “仓管”以加工单产出为主线展示待收、实收、差异、库位和库存记录；操作记录虽有独立 ID，但不得脱离 `workOrderId`。
- “质检”以加工单的具体产出/收货批次建单；“结算”以加工单的可结算结果生成明细。
- 普通首屏只显示加工单号、工艺、对象图片、状态、计划/累计/剩余数量和当前唯一主动作；任务号放在可展开的基本信息中。
- PDA 使用两级识别：第一步扫具体加工单码定位加工单；第二步在确认接收／发起交出动作内逐张扫描真实交接对象。扫加工单只负责定位，不能直接生成整单数量记录。
- 接收面料／辅料逐一扫面料或辅料标签；接收裁片逐一扫裁片菲票；盘扣接收逐一扫投入捆条菲票。交出裁片逐一扫加工后菲票，其他产出逐一扫对应加工后标签。
- 扫码输入默认聚焦并作为主入口；“无法扫码？手动输入”折叠为次要入口。手工码与扫码必须经过完全相同的精确匹配、工厂、加工单、重复、状态、单位和数量校验，不能模糊匹配或绕过门禁。
- 扫码失败、多候选、数量不一致或状态不允许时，页面用短句说明“哪里不对、怎么改、何时叫主管”，不展示内部状态码或系统原理。

### 2.8 防止实施自行推断的明确默认口径

以下事项在当前证据中存在漂移或链路差异。为保证研发不自行选择，本计划先固定默认口径；如产品后续改变，必须先改报告、计划和矩阵，再改代码：

| 事项 | 当前默认口径 | 禁止的自行处理 |
|---|---|---|
| AUX-04 直喷对象 | 按当前加工单事实收口为成衣 SKU/件；如未来确有裁片直喷，新增明确工艺定义或对象分支并另行评审 | 运行时根据是否有菲票猜裁片/成衣 |
| AUX-11 花朵对象 | 按当前加工单事实保留裁片/菲票/片 | 因名称像辅料而改成个或 SKU |
| 通用加工单完成门禁 | 分批加工、分批交出；完成加工单时所有可交出合法产出必须按既定门禁处理完 | 用“已加工一部分”直接完成整张加工单 |
| 任务下取消/作废加工单 | 不等同完成，阻断任务自动完成并提示主管；后续关闭规则另行确认 | 把过滤掉取消单后的 `every()` 当全部完成 |
| 捆条质检/结算 | 先按加工单身份预留并验证；如业务确认不适用，必须在矩阵中由产品签字后改为不适用 | 测试人员或研发直接跳过下游 |
| 花边完成与交出顺序 | 保留当前“完成加工单后仍可交出剩余合法完工量”的独立链 | 强行套用普通特殊工艺的完成前全部交出门禁 |
| 花边任务关系 | 采购驱动，无来源任务，不参与任务自动完成 | 为统一模型虚构 `taskId` |
| SPC-03 特种车缝 | 作为特殊工艺加工单执行四动作，无开工/节点 | 因“车缝”名称进入三方小缝纫任务流 |

## 7. 必测场景

### 7.1 身份与隔离

1. 一任务两张加工单，选择第二张，详情、动作、仓库、交出、打印均保持第二张。
2. 一生产单多张加工单，扫码返回完整候选，不自动选第一张。
3. 一加工单多明细/多菲票，逐行数量归属正确。
4. 加工单来源任务不存在、未接单、已改派或已取消时，系统反查后阻断，不接受客户端伪造任务 ID 绕过。
5. 加工单属于另一工厂，Web 和 PDA 均阻断。
6. 只提供任务 ID 且任务下多加工单，阻断并要求选择。
7. 错误、空白、大小写变化和精确不存在的扫码值，不误匹配其他单。

### 7.2 状态与数量

1. 待接收 → 加工中 → 有完工待交出 → 已交出 → 已完结完整链。
2. 接收超过计划、完工超过实收未完工、交出超过已完工未交出，全部阻断。
3. 未加工不能完成，仍有完工未交出不能完成。
4. 相同 confirmation key 重复提交只产生一条数量和操作记录。
5. 不同 confirmation key 的合法分批操作分别累计。
6. 裁片逐菲票、成衣逐 SKU 的行合计必须等于本次总量。
7. 同一加工单完工 40、交出 30、实收 29、质检合格 28 后，加工单显示的各阶段累计和剩余量正确，结算不超过可结算量。
8. 任一子加工单完成不会直接完成来源任务；任务状态由任务下全部加工单聚合。
9. 一任务两张加工单：第一张完成后任务仍未完成；第二张完成后任务自动完成；Web/PDA 无手工完成任务操作。
10. 本范围所有页面和动作均无开工、开工凭证、关键节点上报、补报关键节点、查看开工和节点；第一次加工填报也不生成开工记录。
11. 三方小缝纫工厂的开工/关键节点原流程保持不变；印花、染色专用加工单链不受影响。

### 7.3 对象专项

1. 盘扣 2 张菲票投入，产出 100 个，交出 80 个；仓库/WLS 不混用张与个。
2. 一任务两张捆条加工单，分别记录米数和结束，互不影响；每个规格菲票指向具体加工单。
3. 橡筋从 BOM 辅料进入，投入单位保留原单位，按技术包定长需求输出；全链不出现裁片/片/裁片菲票。
4. 成衣烫画缺正式成衣 BOM 时不生成；有 BOM 时按 SKU 完整执行。
5. 要求菲票的裁片工艺缺菲票时不允许生成或接收。
6. 花边同采购 SKU 只生成一张生产单；WLS 实收差异写回 PMS，交出量不冒充实收量。

### 7.4 PDA 现场操作

1. 接单 Tab 只有任务、竞价和接单动作；执行/交接 Tab 不以任务卡作为执行对象。
2. 扫具体加工单码只完成加工单定位；进入确认接收／发起交出后，必须逐张扫描本批标签或菲票，不能直接按整单确认。
3. 扫生产单码或任务码遇到多张加工单时，显示候选并要求人工选定，不默认第一张。
4. 工厂、操作人、时间、对象、单位、计划/累计/剩余量由系统带出，不要求员工重复填写。
5. 确认接收／发起交出以已扫对象的数量为默认值，允许对单张标签做部分数量修改；不得出现脱离标签／菲票的自由整单数量输入。
6. 确认接收/发起交出只出现在交接；加工填报/完成加工单只出现在执行。
7. 实体 PDA 软键盘弹出时，当前输入、数量单位和确认按钮仍可见可操作。
8. 辅助工艺、特殊工艺和适用辅料加工单的 PDA 不出现开工、开工凭证、关键节点上报、补报关键节点、查看开工和节点、完成任务。
9. 现实 iData 必须覆盖当前每张 PDA 适用加工单，不允许每种工艺只抽一张代表单。每张加工单每轮固定留存 8 项：扫码定位、确认接收第 1/2 批、加工填报第 1/2 批、发起交出第 1/2 批、完成加工单。
10. 每个非扫码动作必须记录对应业务记录 ID；所有证据同时记录加工单 ID/号、来源任务 ID、操作人、时间、数量单位、状态前后和现场照片。缺任一字段，该动作和该加工单均不通过。
11. 扫码框进入页面即获得焦点；手动输入默认折叠。手动输入合法码可完成同一动作，但必须记录 `MANUAL` 输入方式，错单、重复、模糊、歧义和超量的结果与扫码完全一致。
12. 直接打开旧通用交接详情或旧卡片入口不得提交辅助／特殊工艺整单接收或交出；页面守卫和提交处理器必须同时阻断。

### 8.3 四个动作的输入、写回和门禁

| 动作 | 可进入状态 | 员工最少输入 | 服务端写回 | 数量门禁 | 状态结果 |

### 8.4 任务自动完成算法

任务状态不是员工操作结果，而是加工单集合的派生结果。每次完成、撤销完成、恢复、取消或重新生成加工单后都必须重算：

1. 以服务端反查得到的 `sourceTaskId` 查询该任务下全部本范围加工单，不使用当前页面缓存。
2. 查询结果为 0 张时，不自动完成任务。
3. 任一加工单不是“已完结/已完成”的规范完成状态时，任务不得为完成。
4. 每一张加工单均完成时，任务幂等地自动变为完成，并生成一条系统聚合日志；不得生成员工“完成任务”日志。
5. 如业务允许撤销某张加工单完成，则任务必须重新聚合为进行中；历史自动完成日志保留，不覆盖原记录。
6. 取消、作废不自动等同完成。本轮没有明确关闭规则时必须阻断任务自动完成并提示主管处理。
7. 同一完成动作重复提交，不得产生第二条任务完成日志。
8. 花边生产单没有来源任务，本算法对 `ACC-LACE-01` 明确不适用。

### 8.5 “无开工/无关键节点”落实范围

不得只隐藏按钮，必须逐层处理：

- PDA 列表、详情、交接、扫码结果不出现待开工、开工时限、开工条件、开工凭证、关键节点标签、查看节点或完成任务。
- Web 列表、详情、动作菜单、日志和打印不出现上述概念。
- 本范围不得调用 `TASK_START`、`TASK_MILESTONE_REPORT`、通用 `finish-task` 或对应写回函数。
- `LaceProductionOrder.startedAt` 当前实际承载确认接收时间，迁移为 `receivedAt`；动作键 `start-production` 改为接收语义键，页面仍显示“确认接收”。
- `BindingProcessOrder.startedAt` 不再由首条裁剪记录推导；改为确认接收时间字段，或在没有接收事实时保持空值，不伪造历史开工。
- 特殊工艺任务中已有的通用任务 `startedAt/milestone` 字段不得作为加工单执行门禁，也不得显示；三方小缝纫任务仍保留原字段和页面。
- 印花、染色代码中的节点开始/完成时间属于其专用工艺节点，本计划不删除、不改名。

## 10. 逐工艺全流程专项测试要求

每个专项用例都必须叠加第 9 节适用的通用场景。下列用例是最低要求，不是可选示例。

### 10.1 AUX-01 打揽

全链对象：技术包打揽需求 → 来源任务 → 具体加工单 → 裁片菲票接收 → 打揽完工 → 分批交出 → 仓库实收 → 质检 → 结算 → 加工单打印；单位始终为片。

- `AUX-01-S01`：同一加工单准备前片/后片两个菲票，分两次确认接收和加工填报；断言每张菲票累计独立，总量等于加工单汇总。
- `AUX-01-S02`：缺少必需菲票时阻断生成或确认接收，不得创建“无菲票”组；补齐菲票后可从原需求恢复生成。
- `AUX-01-S03`：某菲票填报合格、损耗和次品，断言可交出只使用合格完成量，损耗/次品不进入另一菲票。
- `AUX-01-S04`：同一任务两张打揽加工单分别执行，第一张完成后任务不完成，第二张完成后自动完成；不得出现任务完成按钮。
- `AUX-01-S05`：打印和 PDA 均显示“打揽”、裁片图、部位、菲票和片，不得显示打条或任务级开工信息。

### 10.2 AUX-02 打条

全链对象：技术包打条需求 → 任务 → 打条加工单 → 裁片菲票 → 分批加工/交出 → 仓库/QC/结算/打印；单位为片。

- `AUX-02-S01`：同一生产单同时存在打揽和打条加工单，扫生产单后必须显示两个明确候选；选择打条后全链保持 AUX-02 的 `workOrderId`。
- `AUX-02-S02`：两个打条菲票分别部分接收、部分完工和部分交出；断言累计、剩余和完成门禁逐菲票守恒。
- `AUX-02-S03`：缺菲票、重复菲票和属于另一加工单的菲票分别阻断，且不改变当前加工单数量。
- `AUX-02-S04`：一任务两张打条加工单按相反顺序完成，任务只在最后一张完成后自动完成。
- `AUX-02-S05`：列表、详情、仓库、结算和打印均使用“打条”代码/名称，不得复用打揽文案或记录。

### 10.3 AUX-03 烫画

全链对象：成衣工艺需求 → 正式成衣 BOM → 成衣 SKU → 烫画加工单 → SKU 接收/加工/交出 → 成衣下游仓库/QC/结算/打印；单位为件。

- `AUX-03-S01`：缺正式成衣 BOM 或 BOM 未关联当前生产单时不生成加工单；补齐正式关联后唯一生成，不重复。
- `AUX-03-S02`：同一加工单包含两个颜色、两个尺码 SKU，按 SKU 分批接收/完工/交出；汇总与各 SKU 合计一致。
- `AUX-03-S03`：扫码使用成衣 SKU/加工单定位，不允许要求裁片菲票，也不得生成“已裁部位/片”记录。
- `AUX-03-S04`：成衣实拍图、颜色、尺码和款号在 PDA/Web 同一信息块展示，缩略图可放大；扫错颜色 SKU 阻断。
- `AUX-03-S05`：同任务两张烫画单独立完成并触发任务聚合；全链无开工、关键节点或任务完成操作。
- `AUX-03-S06`：烫画打印使用件和成衣 SKU，不得落入烫钻或印花加工单模板。

### 10.4 AUX-04 直喷

全链对象：当前确认的成衣直喷需求 → 成衣 SKU → 直喷加工单 → 接收/加工/交出 → 成衣仓库/QC/结算/打印；单位为件。

- `AUX-04-S01`：生成结果的对象必须为成衣/SKU/件；若配置仍返回裁片，专项检查必须失败而不是页面层改文案。
- `AUX-04-S02`：同一生产单同时存在直喷辅助工艺和独立印花加工单时，两套候选、路由、动作服务和状态完全隔离。
- `AUX-04-S03`：多颜色/尺码分批接收、完工和交出，任一 SKU 超量不影响其他合法 SKU。
- `AUX-04-S04`：错扫菲票时提示应扫加工单或成衣 SKU；不得把菲票自动转换为成衣数量。
- `AUX-04-S05`：一任务两张直喷加工单验证身份和任务自动完成；无通用开工/关键节点。
- `AUX-04-S06`：Web/PDA/仓库/打印均显示“直喷”，不显示印花专用节点或裁片单位。

### 10.5 AUX-05 绣花

全链对象：技术包绣花需求 → 裁片部位/菲票 → 绣花加工单 → 分批接收/加工/交出 → 仓库/QC/结算/打印；单位为片。

- `AUX-05-S01`：同款前片、袖片两个绣花部位分别绑定菲票，逐部位数量和图样不可串写。
- `AUX-05-S02`：同一生产单并存绣花、贝壳绣、曲牙绣和一字贝绣花，候选必须显示完整工艺名并保持所选代码。
- `AUX-05-S03`：缺菲票阻断；补齐后从同一需求恢复，不生成重复加工单。
- `AUX-05-S04`：分批完工含损耗/次品，交出量只取合格产出，QC/结算仍归属当前绣花单。
- `AUX-05-S05`：一任务两单、二维码回单和现实 PDA 四动作完整通过，页面无开工/节点。

### 10.6 AUX-06 压褶

全链对象：技术包压褶需求 → 裁片/菲票 → 压褶加工单 → 四动作 → 仓库/QC/结算/打印；单位为片。

- `AUX-06-S01`：同一生产单同时生成压褶和打褶，任务、加工单、列表筛选、候选和打印不得合并。
- `AUX-06-S02`：两个裁片部位分批执行，逐菲票数量与加工单总量守恒。
- `AUX-06-S03`：用打褶菲票扫压褶单必须阻断；不得根据名称相似度模糊匹配。
- `AUX-06-S04`：少产、超量和仍有未交出量的完成请求分别按门禁处理，失败无副作用。
- `AUX-06-S05`：两张压褶加工单验证自动完成任务和下游 `workOrderId` 唯一性。

### 10.7 AUX-07 贝壳绣

全链对象：贝壳绣需求 → 裁片菲票 → 贝壳绣加工单 → 四动作 → 仓库/QC/结算/打印；单位为片。

- `AUX-07-S01`：与一字贝绣花同生产单并存，生成键、加工单号、候选、筛选和打印分别唯一。
- `AUX-07-S02`：多部位、多菲票分批接收/加工/交出，明细合计与总量一致。
- `AUX-07-S03`：错扫一字贝绣花或普通绣花菲票阻断，页面保留当前贝壳绣上下文。
- `AUX-07-S04`：加工单两批交出、一批差异实收后，库存/QC/结算仍能回到贝壳绣加工单。
- `AUX-07-S05`：一任务两单和实机 PDA 验证无开工/节点/手工完成任务。

### 10.8 AUX-08 曲牙绣

全链对象：曲牙绣需求 → 裁片部位/菲票 → 曲牙绣加工单 → 四动作和下游；单位为片。

- `AUX-08-S01`：与普通绣花同生产单时独立生成，工艺名、代码和图片不被“绣花”通用名称覆盖。
- `AUX-08-S02`：多个曲牙部位分别扫码、分批填报，交出批次保留部位和菲票身份。
- `AUX-08-S03`：另一加工单菲票、另一工厂账号和模糊加工单号分别阻断。
- `AUX-08-S04`：同 key 连点与不同 key 分批均按幂等规则执行，累计量准确。
- `AUX-08-S05`：两单任务聚合、仓库/QC/结算/打印和现实 PDA 全链通过。

### 10.9 AUX-09 一字贝绣花

全链对象：一字贝绣花需求 → 裁片菲票 → 独立加工单 → 四动作和下游；单位为片。

- `AUX-09-S01`：同生产单并存贝壳绣、曲牙绣和普通绣花，候选、标题、日志、打印均显示完整“一字贝绣花”。
- `AUX-09-S02`：多菲票分批链，缺一个必需菲票时不能创建“无菲票”明细继续接收。
- `AUX-09-S03`：交出后制造短收差异，库存、质检和结算只使用实际可用量。
- `AUX-09-S04`：一任务两加工单完成顺序反转，任务聚合不受数组顺序影响。
- `AUX-09-S05`：PDA 不显示任务级开工/节点，二维码唯一恢复当前加工单。

### 10.10 AUX-10 盘扣

全链对象：具体捆条加工单/规格菲票 → 盘扣加工单 → 确认接收菲票 → 按个填报产出/交出 → 中央辅料仓实收 → QC/结算/打印。

- `AUX-10-S01`：接收两张捆条菲票，输入单位为张；同时展示每张捆条长度仅供追溯，严禁把长度或张数作为盘扣产出数量。
- `AUX-10-S02`：计划产出 100 个，分两次完成 40/60 个，再分两次交出 30/70 个；所有汇总单位为个。
- `AUX-10-S03`：同一捆条菲票重复接收、属于另一盘扣单的菲票、已作废菲票分别阻断且不增加投入。
- `AUX-10-S04`：盘扣单只引用其真实上游 `bindingOrderId + feiTicketId`；清除当前加工单自身冒充来源任务或孤儿仓库记录的路径。
- `AUX-10-S05`：中央辅料仓分批实收并产生差异，库存、QC和结算仍以盘扣 `workOrderId`/个累计。
- `AUX-10-S06`：一任务两张盘扣单独立执行并自动完成任务；打印同时显示上游捆条菲票和当前盘扣加工单码。

### 10.11 AUX-11 花朵

全链对象：技术包花朵需求 → 当前确认的裁片部位/菲票 → 花朵加工单 → 四动作和下游；单位为片。

- `AUX-11-S01`：花朵辅助工艺与花边采购生产单同时存在时，菜单、路由、对象、单位和状态源完全隔离。
- `AUX-11-S02`：多部位菲票分批接收/完工/交出，任一菲票数量不得写入另一部位。
- `AUX-11-S03`：错扫花边 SKU、盘扣菲票或其他裁片工艺菲票均明确阻断。
- `AUX-11-S04`：短收差异经过仓库、QC和结算后，全链保留花朵加工单 `workOrderId`。
- `AUX-11-S05`：一任务两单、打印二维码和现实 PDA 四动作完整通过，无开工/节点。

### 10.12 AUX-12 打褶

全链对象：技术包打褶需求 → 裁片/菲票 → 打褶加工单 → 四动作和下游；单位为片。

- `AUX-12-S01`：与压褶在同生产单并存，分别生成、筛选、扫码、打印和结算；禁止工艺名称归一化为同一项。
- `AUX-12-S02`：多部位分批链及缺菲票恢复场景逐项通过。
- `AUX-12-S03`：用压褶加工单码/菲票操作打褶时阻断，不得因共享页面而接受。
- `AUX-12-S04`：一批含损耗/次品，交出与结算只使用合法产出；完成门禁正确。
- `AUX-12-S05`：一任务两打褶单和现实 PDA 验证任务自动完成、无通用任务动作。

### 10.13 AUX-13 烫钻

全链对象：技术包烫钻需求 → 裁片部位/菲票 → 烫钻加工单 → 四动作和下游；单位为片。

- `AUX-13-S01`：同生产单存在成衣烫画时，烫钻仍使用裁片/菲票/片，烫画使用成衣/SKU/件，任何层级不得混用。
- `AUX-13-S02`：多烫钻部位和多菲票分批执行，图片、部位和数量对应真实对象。
- `AUX-13-S03`：扫成衣 SKU 或烫画加工单码操作烫钻必须阻断。
- `AUX-13-S04`：仓库实收差异、质检不合格和结算扣减都回到当前烫钻加工单。
- `AUX-13-S05`：两单任务聚合、打印二维码、PDA 小屏和图片大图完整通过。

### 10.14 SPC-01 模板工序

全链对象：技术包模板工序需求 → 模板版本 + 裁片部位/菲票 → 模板加工单 → 四动作和下游；单位为片。

- `SPC-01-S01`：同一裁片部位存在模板 V1/V2 时，只允许正式有效版本生成，详情和打印固化版本快照。
- `SPC-01-S02`：模板版本失效或缺模板文件时阻断生成/接收；补齐后恢复且不重复。
- `SPC-01-S03`：多个裁片菲票分批执行，模板版本不能在中途被另一版本静默替换。
- `SPC-01-S04`：错误工厂、错误模板单和其他特殊工艺菲票分别阻断。
- `SPC-01-S05`：一任务两模板加工单、仓库/QC/结算/打印/PDA 全链通过，无开工/节点。

### 10.15 SPC-02 激光开袋

全链对象：激光开袋需求 → 袋位裁片/菲票 → 激光开袋加工单 → 四动作和下游；单位为片。

- `SPC-02-S01`：前袋/后袋两个袋位分别绑定裁片菲票，数量和图片不可串位。
- `SPC-02-S02`：全项目当前范围的工艺选择、加工单、PDA和打印只出现“激光开袋”，不得恢复已删除的独立旧特种工艺；“定位裁（激光切）”属于其既定名称时按当前字典检查，不与本单混淆。
- `SPC-02-S03`：错扫模板工序或特种车缝菲票阻断，且保持当前激光开袋上下文。
- `SPC-02-S04`：分批加工、分批交出和仓库差异全链按袋位/菲票守恒。
- `SPC-02-S05`：两单任务聚合、打印扫码和现实 PDA 通过，无开工/节点。

### 10.16 SPC-03 特种车缝（花样机）

全链对象：花样机特殊工艺需求 → 裁片部位/菲票 → 特种车缝加工单 → 四动作和下游；单位为片。

- `SPC-03-S01`：打开列表和详情时必须进入特殊工艺加工单路由，不得进入三方小缝纫任务详情。
- `SPC-03-S02`：PDA 列表、详情、权限和动作载荷均无开工、开工凭证、关键节点、补报、节点查看或完成任务；只有四个加工单动作。
- `SPC-03-S03`：同时准备一条三方小缝纫任务，证明其原开工/关键节点能力仍存在，且两条记录互不识别为对方。
- `SPC-03-S04`：多裁片菲票、分批加工/交出、错误工厂和幂等场景全部归属当前特种车缝加工单。
- `SPC-03-S05`：一任务两特种车缝加工单最后一张完成后自动完成任务；不调用通用 `finish-task`。
- `SPC-03-S06`：仓库/QC/结算/打印显示“特种车缝（花样机）”，不简写成车缝。

### 10.17 SPC-04 橡筋定长切割

全链对象：BOM 橡筋辅料 + 技术包定长要求 → 橡筋定长加工单 → 辅料投入接收 → 按定长产出填报/交出 → 辅料仓/QC/结算/打印。

- `SPC-04-S01`：BOM 缺橡筋 SKU、缺单位、缺定长或缺计划产出任一项均阻断生成，并指出需要补哪项。
- `SPC-04-S02`：投入单位继承 BOM（例如米/卷），产出单位按技术包为条；两种单位分别累计，禁止强转为片。
- `SPC-04-S03`：允许合法的小数辅料投入，但定长产出按配置精度；负数、零、超投入/超产出阻断。
- `SPC-04-S04`：Web/PDA/仓库/交出/打印全链不得出现裁片、已裁部位、裁片菲票或片。
- `SPC-04-S05`：多物料批次/规格明细分别接收和产出；错扫裁片菲票或另一橡筋 SKU 阻断。
- `SPC-04-S06`：一任务两定长加工单、辅料仓实收差异、QC/结算和任务自动完成完整通过。

### 10.18 BIND-01 捆条加工单

全链对象：裁剪任务/裁剪单 → 面料 + 纸样版本 + 捆条规格 → 具体捆条加工单 → 按规格记录米数 → 每规格捆条菲票 → 分批交出/入仓 → 盘扣引用。

- `BIND-01-S01`：补齐真实 `sourceTaskId/sourceTaskNo`，同一任务生成两张捆条加工单；选择第二张时详情、记录、菲票和打印始终为第二张。
- `BIND-01-S02`：同单至少两个规格，分别记录直切/横切/斜切米数；各规格计划、实际、损耗和总米数守恒。
- `BIND-01-S03`：两次加工填报追加记录而非覆盖；刷新后持久；重复 key 不重复米数。
- `BIND-01-S04`：短裁、超裁和手动差异分别生成差异事实；完成加工单时明确显示差异和原因，不伪造“开工时间”。
- `BIND-01-S05`：每个规格只生成指向当前 `bindingOrderId/detailId` 的菲票；非法加工单 ID 返回不存在，不回第一单。
- `BIND-01-S06`：分批交出和入仓按米；盘扣接收引用菲票张数，既能追溯米数又不把米数作为盘扣产出。
- `BIND-01-S07`：第一张捆条单完成后任务未完成，最后一张完成后自动完成；无任务完成按钮。
- `BIND-01-S08`：现实 PDA 扫加工单/菲票完成四动作，打印版式和二维码唯一回单；软键盘不遮挡米数和确认按钮。

### 10.19 ACC-LACE-01 花边辅料生产单

全链对象：PMS 采购单 SKU → 唯一采购需求 → 正式加工投入行 → 花边生产单 → PFOS 确认接收/加工填报/交出/完成 → WLS 实收/差异 → PMS 采购实收回写。

- `LACE-01-S01`：同一 `purchaseOrderId::skuId` 多来源行只生成一张生产单；重复同步不重复；不同 SKU 分单。
- `LACE-01-S02`：缺正式投入、投入 SKU、单位用量或图片时记录明确生成失败；补齐后唯一生成。采购单 `338520` 的失败场景必须转为通过。
- `LACE-01-S03`：确认接收只记录 `receivedAt` 和接收日志；删除/迁移 `startedAt` 与内部 `start-production` 语义，不产生开工事实。
- `LACE-01-S04`：至少三次加工填报，包含少产、等量、普通超产和超过计划 1.5 倍二次确认；修改填报必须保留修改前后值和原因。
- `LACE-01-S05`：少产、等量、超产均按既定规则完成加工单；撤销完成后可继续填报并保留历史；完成与撤销不涉及任务状态。
- `LACE-01-S06`：分两批交出，完成加工单后仍按当前规则允许交出剩余合法完工量；每批有交出单、包装和接收责任。
- `LACE-01-S07`：WLS 第一批短收、第二批等量或经授权超收；累计实收、差异、库位和证据正确，交出量不冒充实收量。
- `LACE-01-S08`：PMS 采购实收只回写 WLS 实收累计；采购版本变化显示待查看，确认查看后记录版本和日志。
- `LACE-01-S09`：待接收、加工中、已完结各自取消/恢复权限和二次确认按既定策略；已有下游实收时禁止不安全取消。
- `LACE-01-S10`：花边厂业务员、主管、平台主管、WLS 仓管和 PMS 采购员分别验证权限；越权动作阻断并留日志。
- `LACE-01-S11`：Web 列表/详情展示真实物料和款式图片及大图；输入/产出/采购来源分区清晰。
- `LACE-01-S12`：明确验证没有花边 PDA 路由、PDA 候选、打印入口、任务开工、关键节点或任务自动完成；这些项在证据矩阵写“不适用”。

## 12. 测试执行、证据与签收规则

### 12.1 自动化组织

- 新增一个只编排测试数据和调用真实领域函数的全链检查，不得在测试内复制数量或状态实现。
- 每个工艺至少有独立 `describe/test` 名称，格式包含 `AUX-01`、`SPC-01`、`BIND-01` 或 `ACC-LACE-01`。

- 一个工艺失败时，其余工艺仍输出各自结果；最终命令以非零退出。
- 每个场景断言动作前状态、动作载荷、动作后状态、数量、子事实 ID 和来源 `workOrderId`。

### 12.2 页面和现实设备证据包

花边使用 `web-*`、`wls-*`、`pms-*` 证据，`pda` 和 `print` 在 `manifest.json` 中标记“不适用：本阶段 Web-only”。

### 12.3 签收门禁

- 单个工艺只有通用场景、专项场景、适用页面/设备和下游证据全部齐全后，才能把对应 `TAUX/TSPC/TBIND/TLACE` 标为已验证。
- 前置缺陷阻断后续链时，该工艺标记已阻塞并保存阻断证据；不得拿另一工艺结果替代。
- 共享组件通过不等于所有工艺通过；必须逐项打开命名页面并核对对象、图片、单位和工艺名。
- 最后一次实质修改后，所有受影响工艺的自动化、页面、PDA 和打印证据失效并重跑。
- 产品确认版本必须写入矩阵；没有确认人和版本不得标记 accepted。

### 12.4 最低覆盖数量核对

为防止实现阶段删减场景，最低覆盖按“工艺 × 场景”计数，而不是按共享测试函数计数：

| 范围 | 通用场景执行数 | 专项场景数 | 最低合计 |
|---|---:|---:|---:|
| AUX-01～13 | `13 × 18 = 234` | 68 | 302 |
| SPC-01～04 | `4 × 18 = 72` | 22 | 94 |
| BIND-01 | 18 | 8 | 26 |
| ACC-LACE-01 | 16 个适用通用场景 | 12 | 28 |
| **总计** | **340** | **110** | **450 个最低场景执行结果** |

450 是最低结果数，不代表必须写 450 份重复代码；允许参数化复用测试结构，但最终报告必须能按“编号 + 场景”展开 450 个独立结果。新增风险只能增加覆盖，不能用新增场景抵消表内场景。

## 14. 风险与禁止项

- 禁止仅给 PDA URL 增加 `workOrderId`，却让详情、动作、仓库或打印继续按任务取第一单。
- 禁止把 `taskId` 重命名成 `workOrderId` 作为表面修复；加工单必须保留真实来源任务，但客户端不得用任务 ID 选定执行对象。
- 禁止在接单以外的 PDA 模块继续以任务卡作为辅助/特殊/辅料加工的执行入口。
- 禁止交出、仓库、质检或结算记录只关联 `taskId`；记录自身 ID 不能代替具体 `workOrderId`。
- 禁止将“少填”实现成不显示本次数量、无确认提交或每次默认提交全部剩余量。
- 禁止为了与 Web “完全同布局”在 PDA 堆叠长备注、多层 Tab 和可由系统自动带出的字段。
- 禁止为兼容旧 Mock 保留“查不到就取第一条”。
- 禁止把捆条加工单和盘扣加工单合并为一种对象。
- 禁止把橡筋继续塞进裁片对象，只修改页面文字。
