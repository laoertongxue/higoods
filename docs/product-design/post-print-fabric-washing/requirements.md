面料真实完成印花后，由现场人员触摸实物判断是否需要水洗。需要时只选择目标手感即可创建水洗加工单，由染厂承接。工艺路线和生产单初始拆解不提前安排水洗。助剂、配比和投料由染厂在线下处理。

配套文件：[实施计划](implementation-plan.md)、[原子需求矩阵](atomic-requirements.md)、[直接上下游影响核查](upstream-downstream-review.md)。

## R1 范围与需求来源

### R1.1 有效来源

本会话依次明确了以下规则：

1. 水洗对象是面料，印花完成后现场决定是否需要，由染厂加工。
2. 需要时明确手感即可建单，助剂及百分比不进入系统。
3. 只有真实印花完成、现场人员实际触摸后才能知道是否需要；工艺路线不能提前知道。
4. 用户要求覆盖现场判断、手感建单、染厂执行、技术包路线与生产单拆解，先出方案。
5. 用户先采纳六项建议，要求补齐完整需求、计划、矩阵和上下游核查，当时尚未授权代码改动。
6. 用户随后明确授权按四份文档实施全部 205 项，并要求直接上下游、Mock、Web/PDA、打印、持久化、1 秒性能验证及两轮对抗审查；本轮不提交和发布。

第 5 项将粒度、一单一种手感、人员职责、下游控制、数量口径和来源覆盖纳入本方案。下文给出可实施的具体处理，不再将这六项列为待用户选项。角色名称表示业务职责，账号映射沿用现有原型上下文。

### R1.2 六项决策

| 决策 | 本版执行口径 |
| --- | --- |
| D1 判断与建单粒度 | 使用实际印花产出批次，批次内按整卷选择；默认带入本批全部符合条件的卷。允许部分卷先判断、先建单；不在本功能拆开一卷或凭空拆出长度。 |
| D2 手感与单据 | 一张水洗单对应一种目标手感、同一印花单的同一产出批次及同一面料 SKU。不同手感或不同批次分别建单；同批可按不同整卷分组。 |
| D3 人员职责 | 现场判断人员登记本人实际触摸结果；计划或跟单负责派厂；染厂人员登记本厂执行；交出与接收各由责任方确认。纠错按 R8 的阶段处理。 |
| D4 下游控制 | 所选卷向正常后续加工交出、被后续实际领用或开工前必须有判断结果。需要水洗的卷先完成水洗及对应实物接收。未判断只拦截相关卷的上述动作，不拦截技术包发布、初始拆解、排程、其他卷、内部存放和必要资料维护。本期不新增风险放行。 |
| D5 数量与差异 | 继承面料实际记录的单位与精度，卷数为整数，数量来自所选整卷实测值。登记真实收发和加工产出变化，不设固定缩水率，不将 kg、米、Yard、卷数直接混算。 |
| D6 来源覆盖 | 覆盖现有面料印花的正式生产、生产需求提前加工、采购、备货、补料和设计改款六种展示来源；保留实际底层来源与接收去向，不虚造生产单。 |

### R1.3 继承与非范围

本版替代 2026-10-06 特定技术包演示样本中的固定“染色 → 印花 → 洗水”安排。旧需求和审查证据保留原版本；不据本版改写已发生的生产、交接、库存或人员时间。

继续沿用现有面料身份与追溯规则：本次水洗不自动新增物料 SKU，不自动修改面料规格和克重。水溶与水洗为不同加工，不能合用身份或以水溶代替水洗。

本期不建设线上助剂、配方、比例、投料、助剂库存扣减、配方推荐或审批。不新增真实后端、鉴权服务、云存储、离线队列或自动重试。非面料印花、成衣洗涤和复洗返工新流程不在本次新增范围；现有非面料印花保留并回归验证。

## R2 对象关系与来源

### R2.1 对象

| 对象 | 关系与含义 |
| --- | --- |
| 印花加工单 | 沿用原身份及来源，提供实际完成的面料产出。 |
| 实际产出批次与卷 | 判断的实物范围。每卷须属于明确批次、面料 SKU 和来源印花单；不能以计划用量代替。 |
| 触摸判断 | 记录范围、是否需要、目标手感（需要时）、判断人员和时间。尚未判断不等于不需要。 |
| 水洗加工单 | 由“需要水洗”的判断产生，承接原印花单、批次、卷、手感、数量和原需求去向。 |
| 染厂执行记录 | 记录承接、实收、开工、产出及实际完成，不记录线下助剂。 |
| 交出和接收记录 | 各方对同一实物交接分别确认，保留应交、实交、实收、差异和责任人。 |

每卷在同一有效判断版本下最多关联一张有效水洗单。作废和纠错历史保留，但不重复占用可用卷。不同批次不自动合单，不把整张印花单统一改成需要水洗。

### R2.2 六类来源的承接

| 展示来源 | 水洗单保留的关联 | 完成后的原去向 |
| --- | --- | --- |
| 正式生产 | 原印花单、生产单、实际技术资料版本、面料批次与卷 | 该生产单已明确的后续加工或裁床配套中转位置 |
| 生产需求提前加工 | 原印花单、生产需求、当前匹配状态；无生产单时保持为空 | 未匹配时保留提前加工待匹配去向；匹配后承接真实生产去向 |
| 采购 | 原采购或采购加工来源；按原实际分类保留，不能强制改成生产来源 | 原采购链的接收仓或已明确消费者 |
| 备货 | 原备货来源和库存归属 | 原中央仓或已明确分配对象 |
| 补料 | 原补料记录、需求方及指定接收位置 | 原补料消费任务或指定位置 |
| 设计改款 | 原改款任务、结果关联、收料团队和位置 | 原销售展示样衣用料的收料团队或中央工厂 |

展示来源与底层分类存在归并时，沿用原映射；例如采购可能归入采购备货底层分类。不能为了满足六类展示而新造业务身份。

提前加工后来匹配生产单时，补充实际关联，不复制判断或水洗单、不抹去原需求身份；匹配失败不改写已发生的水洗事实。

## R3 印花完成与触摸判断

### R3.1 判断前置

只有已实际完成的面料产出可进入判断。热转印类必须完成面料上的真实转印；图案文件完成、纸张打印完成、计划完成或打印标签都不能替代。

允许已经完成的批次先判断，不等待整张印花单全部批次或人工结单。原单取消、暂停或来源冲突时，遵循现有适用限制；不能以本功能绕过生产限制。

判断范围必须来自当前可识别的实物卷，显示对应面料真实图片、名称、短编号、规格、批次、卷码和原单位数量。缺少实物对应、图片或数量时提示核对已有资料，不用无关图片或计划数补齐。

判断与该实物的原印花要求版本、批次和卷版本关联。上游合法纠正影响该实物身份或数量时，先重新核对对应范围，不能把原判断套用到另一个实物或覆盖已发生的交接历史。

### R3.2 现场动作

现场人员从印花实际产出或其明确待办进入，系统带入当前批次可处理卷。需要缩小范围时按整卷选择，不要求重新填写面料身份或计划用量。

- 点击“不需要水洗”保存所选卷的触摸判断。
- 选择目标手感后点击“创建水洗加工单”，共同保存“需要水洗”的判断与水洗单。

不预选“需要”或“不需要”，不从技术包、名称、花型、印花方法、历史选择推断。不增加必填原因、触摸照片、主管审核、手工操作人或先选择染厂的建单条件。判断人员及登记时间由当前身份和操作记录带入。

系统记录人员声明的实际判断，不声称电子记录自动证明真实触摸。

## R4 手感与水洗建单

### R4.1 手感

只提供柔软手感、增厚蓬松棉手感、硬挺手感三个确定选项，一次选择一个，不默认选择。缺少手感时不能创建需要水洗的单据；“不需要水洗”不填写手感。

助剂、百分比和投料不出现在判断、建单、派厂、执行、完成或打印的必填项中，也不在后台另设同义字段或配方门禁。

### R4.2 建单结果

建单后展示水洗单号、目标手感、面料、批次、卷范围、数量单位和来源印花单。原来源与原最终去向自动承接，染厂可在派单时确定。用户只需在已带入的实物范围内选择手感并提交。

原最终去向尚未确定时保留待确定状态，不因此增加建单条件，也不虚造接收方；水洗交回前再按原来源核对实际接收对象。当前承接染厂与水洗后的最终去向分开表达。

同一次提交共同完成：判断、单据、卷占用、来源关联和操作记录。任何一项失败均未保存，不出现“判断需要但无单据”或“单据存在但未关联”。

同一次操作重试返回已保存结果；新操作重复选取已有有效单据占用的卷，显示对应单据并阻止重复建单。

## R5 染厂承接与执行

判断、派厂、加工、交出、下游接收和单据完成分别表达，不用一个总状态覆盖所有事实：

| 维度 | 业务表达 |
| --- | --- |
| 触摸判断 | 尚未判断、不需要水洗、需要水洗并已关联有效单据 |
| 承接 | 待派厂、待接单、已接单、已拒单 |
| 加工 | 未开始、加工中、部分完成、全部完成；异常单独标明 |
| 交出 | 未交出、部分交出、全部交出 |
| 下游接收 | 待接收、部分接收、全部接收；差异单独标明 |
| 单据 | 未完成、已人工完成、已作废；保留变更历史 |

状态依据相应记录推导；这些维度不意味着每个名称都增加一次按钮确认。

### R5.1 派厂与接单

计划或跟单从既有启用且具备相应能力的染厂中派单；不强制返回此前染色的同一家厂。没有有效染厂时保留水洗单待派厂，不能把建单显示成失败，也不能虚构工厂。

本期不新增定价或结算能力。沿用适用的既有派厂确认要求，不把报价或结算增加为现场建单条件，也不从手感或线下助剂推导系统费用。

染厂只能查看和处理本厂获派的单据；当前原型沿用既有工厂及人员上下文表达职责，不将页面判断描述为服务端鉴权。

接单、拒单及派厂纠正沿用现有适用方式。拒单说明原因，原实物和判断不删除；尚未发生交出或接收时可以重新派厂。已生效交接范围不直接改收货方。

### R5.2 接收 开工与加工完成

印花方按实际卷交出，染厂逐卷核对和登记实收。派单或上游交出不自动生成染厂实收。扫错卷、扫错单、重复接收和超过对应已发实物范围必须阻止。

染厂基于本厂已实际接收、可用的面料登记开工。不得凭计划数量或尚未接收数量登记加工投入。

水洗收货、厂内库存和实际领用保持水洗身份，不落入染色或水溶的默认分类；不使用旧流程中的“历史可用量”兜底虚增本次可用实收。

完成时记录本批实际产出卷和数量，手感要求从本单读取；不填写助剂、配比或投料。可按已完成整卷分批登记与交出，未完成部分保持待加工。

加工完成与人工结单、实际交出、下游接收分别表达，不能相互自动代填。零产出或去向不明不能假称全部完成，保留异常及负责人处理事实。

### R5.3 交回与最终去向

每张实际交出单只有一个明确接收方。水洗产出继续承接原印花来源的真实后续去向；不一律发往裁床或中央仓。

下游分别确认实收和差异。加工完成、打印单据或交出确认不自动制造下游入库或可用库存。

## R6 按卷分流与数量

### R6.1 分流

同一印花单可同时有无需水洗卷、不同手感待洗卷和未判断卷：

- 无需水洗卷按原去向流转。
- 需要水洗卷交给对应水洗单的承接染厂。
- 未判断卷不能向正常后续加工交出或被实际领用、开工。

不同去向分开交出，不通过修改整张印花单的接收方覆盖所有卷。已有效交出的范围冻结其接收方；后续新增卷根据自身判断确定去向，不追改原交接。内部存放、必要数量维护和不改变加工责任的移位不等于下游加工放行。

需要水洗的卷必须完成水洗，且后续责任方已经实际接收后，才作为该责任方的可加工实物。允许无关卷按自身条件继续，不等整单全部水洗。

### R6.2 数量计算

选择数量＝所选整卷已核实数量之和；卷数＝所选卷个数。重复卷不重复计数，不能选择未完成、已被其他有效操作占用或已不可追回的卷。

交接差异＝同一交接范围的实交数量－实收数量。加工数量变化＝同一已完成加工范围的实际投入数量－实际产出数量；与尚未加工的厂内余量分开表达。

继承来源精度保存，显示沿用现有单位格式且不能隐藏关键差异。合法换算只复用已明确的同维度换算；kg 与长度、卷数与长度不能凭空换算。

不将数量变化自动认定为损耗，不预设缩水率。正负差异均保留实测事实，影响责任或结算时按既有二次确认规则确认对象、数量和后果；不将差异强制改成零。

水洗前后保留同一 SKU 与来源卷追溯。需要新包装或新卷标识时，明确关联原卷，避免将重贴标签当成新增面料库存。

## R7 工艺路线与生产单拆解

### R7.1 技术包

新编制、编辑及后续用于创建新生产单的路线中，不允许静态水洗节点、候选水洗步骤、预设水洗手感或由 BOM 自动生成的水洗要求。

移除旧固定水洗后，后续节点连接原水洗的实际有效前序。例如旧演示的裁剪改为承接印花；同时处理前置关系、顺序、BOM 引用、说明、预览和测试。

水洗成为实际执行记录后，不反写技术包、不更改原技术包的工艺确认结果、不为水洗申请改款或新技术包版本。

### R7.2 初始拆解与实际追加

初始拆解不生成水洗加工单、占位单、待判断水洗任务或自动需求；拆解预览不能把水洗列为必需但尚未生成的路线产物。

现场建单关联实际生产过程，不重拆整单，不重置已有裁剪、车缝、印花等任务的编号、分配、进度或交接。

生产单详情和实际加工关系展示现场追加的水洗单及当前执行，不要求水洗具有技术包路线节点。无正式生产单的来源也可建单并保留原身份。

## R8 角色权限与纠错

| 职责 | 可执行动作 | 限制 |
| --- | --- | --- |
| 现场判断人员 | 对本人实际触摸的面料登记结果、按手感建单 | 不替他人补造触摸，不改历史操作人时间 |
| 原判断人员 | 尚未派厂且未发生实物交接时纠正本人判断或手感 | 共同更新判断、未执行单和卷占用；保留旧版本 |
| 计划或跟单 | 派厂、处理拒单、处理尚未生效交接前的纠错 | 已派厂的手感变更须先协调撤销原承接，不能单方覆盖 |
| 染厂人员 | 本厂接单、实收、开工、产出、交出 | 不修改原现场判断，不处理其他厂实物 |
| 实物接收责任方 | 接收本人责任范围、确认实收差异 | 不能自动接受上游全部交出数量 |
| 现场负责人或主管 | 处理已有实物交接后的纠错和异常 | 记录原因、相关单据与实际处理；不能回删已发生事实 |

取消、作废、改责任、差异确认和代确认按既有适用二次确认要求执行。一次完整表达对象、数量和后果的最终确认足够，不叠加同义弹窗。

已有交接后发现误判或错手感时，停止受影响卷的新流转，先核对实物责任；保留原判断、单据和交接，按实际纠正事件恢复后续资格。已进入后续加工的卷不能用撤销判断倒退历史。

水洗效果不达标时保留实物并登记异常，由负责人协调线下处理；本期不自动再建水洗单或重新触发初始拆解。

## R9 页面 移动端与打印

### R9.1 印花入口

在现有印花实际产出及适用移动执行中提供触摸判断，显示卷级结果和关联水洗单。尚无完成实物时解释前置，不展示可提交的假产出。

现场主操作围绕“不需要水洗”或“选择手感并建单”，不增加助剂说明卡片或配方填写步骤。局部弹窗和状态变化局部更新，输入不整页重绘。

### R9.2 染厂入口

水洗加工单归属染厂管理，与染色、水溶保持独立业务身份。管理列表按现有标准骨架，提供本任务必要的来源、面料、手感、承接厂、数量和状态信息；查询只增加真实需要的条件，不为模板新增批量或导出能力。

详情提供来源、判断结果、实物卷、执行和交接追溯。移动端以当前任务和实物为中心，扫码后给出明确结果，沿用既有无扫码设备兜底。

### R9.3 图片与单据

需要识别面料的页面与打印使用对应真实图片。屏幕缩略图可放大、关闭、Esc 退出，保持原始比例、小屏不溢出和失败状态；纸面核对对应关系、清晰度与版式。

水洗加工单及适用交接打印包含单号、来源、面料、批次或卷、数量单位、目标手感和实际责任方。不包含助剂配比；打印不产生加工、交出或接收事实。手感等执行要求合法更改后，提示相关旧单据需重印并保留版本。

## R10 保存与恢复

用户判断、单据、数量、关系、执行、交接和操作记录按记录保存到同一浏览器 IndexedDB。共同成功的结果在同库同事务完成，完成前不发布成功。

建单一次保存判断、主单、卷占用、来源关系和记录。交出一次保存实物分配、交出事实及下游待接收来源。接收一次保存实收、责任库存及必要回写。不能用顺序双写和内存回退冒充共同成功。

普通查看、刷新或首次进入不写种子、不自动迁移、不落整包副本。列表、详情、下游直达独立读取；失败不伪装空记录后覆盖。

保存失败保留可恢复输入，重试沿用稳定操作标识。多标签在事务内核对版本和卷占用。偏好存储失败回默认，不阻断已迁移业务。附件复用文件引用，必要用户文件保存原始 Blob，不复制 Base64。

非 PCS 的水洗资料复用轻量共用入口提供容量估算、附件统计、完整备份恢复及无引用清理，不在每张单重复建设。没有可复用入口时仅补本任务必要的 FCS 共用能力。备份包含本专项及必要 FCS 关联记录、覆盖或删除标记、附件实体和格式版本；恢复先核对结构、版本、引用及重复冲突，失败不损原数据。清理核验有效引用并处理对应实体。指定范围重置须明确对象、后果并另有实际操作授权，本方案不授权重置或清空。该入口不变相提供 PCS 业务维护或删除 PCS 资料。

## R11 存量切换

静态演示样本移除固定水洗链，并为正常和边界明确建立新演示场景。不得凭旧路线补造“已触摸”或用户判断人时间。

已发布历史技术包及生产单冻结快照保留原身份。新业务使用合规路线版本；旧生产单的未执行安排通过明确的执行调整记录处理，不覆盖冻结历史。历史已实际流转完成的面料不因缺少新判断记录而被追溯阻断。

尚未流转的存量卷在首次适用后续加工放行前实际触摸判断；已派厂或发生实物动作的旧水洗记录先核对并保留事实，不能自动删除、重建或重复占用。

受影响旧记录切换须先登记边界、停止对应旧写入、转换、读回核对，再清理有权且已验证的旧项；共用记录与附件保留。无需本次迁移的历史引用保持只读。PCS 页面不新增迁移、备份、恢复或清理入口。

## R12 时效 验收与交付

新增水洗展示实际加工和交接历时，不擅自套用辅助工艺 3 天或其他未确认时限。既有生产履约统计的起止及总体口径保持，直接参与的水洗来源和耗时按真实事件关联。

验收覆盖六类面料印花来源、三种手感、不需要、未完成、分批分卷、混合去向、提前加工匹配、纠错、存量和失败恢复，覆盖 Web、适用 PDA、图片和打印。非面料印花、原染色水溶及未受影响任务回归不退化。

管理端按 1366×768 和最低 1280×720，主管或员工 Web 按 1024×768，PDA 使用明确记录的实际小屏。主体不横向溢出，宽表仅内部滚动。

适用完整响应不超过 1000ms；每个有效性能家族至少 5 个原始样本，任一超时判失败。保存完成须包含持久回读，不用页面节点出现、HTTP 成功或构建代替。

V1.0 需求已进入本轮实施，具体实现及技术验证状态以原子矩阵和专项验收记录为准。技术验证与用户接受分别登记，原型操作不代表工厂现场已发生。本轮禁止提交、推送和部署。

## R13 业务场景

### R13.1 正常场景

某批面料真实印花完成，共 6 卷且实测数量已登记。现场触摸后选择其中 2 卷不需要水洗，保存判断；另外 4 卷选择柔软手感建 1 张水洗单。计划派给染厂。印花方分开交出两种去向，染厂只接收对应 4 卷，登记加工及产出，再交回原后续责任方。无需水洗的 2 卷可以独立继续。

### R13.2 边界场景

热转印单只完成纸张打印，不能判断。面料转印完成后，同批 3 卷分别需要柔软、硬挺和不需要水洗，分别形成两张单及一份无需判断。已在交出草稿中的卷先解除或更正冲突草稿再重新安排，不能同时发两处。保存中断不产生半张单；刷新后只读取成功事务结果。

### R13.3 提前加工与历史

生产需求提前印花时尚无生产单，现场仍可对完成面料判断、建单及实际水洗，原待匹配去向保留。后来正式匹配只补关联，不重复建单。历史已交付的面料没有本次判断记录时保持历史可读，不自动补判断或回滚库存。
