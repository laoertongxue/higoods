# 后道烫包工序唯一化实施计划

## 1. 目标与完成标准

将后道成衣处理收口为 `IRON_PACK / PROC_IRON_PACK / CRAFT_2000010 / 烫包 / needIronPack`，并对字典、任务、质检、合同、PDA、技术包、Mock、文档和测试做全链路收口。

## 2. 工作包

### WP-01：字典与共享事实源

- **业务目标**：建立唯一烫包工序。
- **文件／符号**：`process-craft-dict.ts`、`process-types.ts`、`post-stage-taxonomy.ts`、`merged-production-task.ts`。
- **修改**：删除旧定义、数值码、映射、停用行和兼容别名；保留唯一当前工序；独立烫包按整个生产任务分配并保留成衣 SKU 需求明细。
- **验证证据**：字典专项检查、后道路线检查。
- **完成条件**：后道三工序与烫包唯一工艺数量精确匹配，烫包分配粒度与需求明细口径一致。

### WP-02：质检、加工单与页面

- **业务目标**：质检及加工单只记录一个烫包事实。
- **文件／符号**：`post-finishing-domain.ts`、`qc-orders.ts`、`production/detail-domain.ts`。
- **修改**：以 `needIronPack` 取代双字段；质检选项收口为三项；装扣关联只锁定烫包。
- **验证证据**：质检数量桶专项检查、名后道页面 E2E。
- **完成条件**：页面、实体、Mock 和投影无双写。

### WP-03：任务、时效、合同和评估

- **业务目标**：合并任务与履约链路全部使用烫包。
- **文件／符号**：`sewing-delivery-sla.ts`、`production-contracts.ts`、`third-party-factory-comprehensive-assessment.ts`、`milestone-configs.ts`。
- **修改**：收口合并任务类型、时效类型、合同类型和里程碑工序码。
- **验证证据**：统一分配基础检查、生产确认单检查。
- **完成条件**：所有类型和用户可见名称均指向烫包。

### WP-04：技术包、PDA 与 Mock

- **业务目标**：上下游入口不再生成或识别旧后道工序。
- **文件／符号**：`tech-pack/context.ts`、`tech-pack/events.ts`、`pda-handover-events.ts`、`pda-mobile-mock.ts`、`production-material-prep.ts`、`production-orders.ts`。
- **修改**：BOM 使用工序、PDA 识别、待办、任务号、清单和死事件处理统一收口。
- **验证证据**：PDA 专项检查、技术包路由页面验收。
- **完成条件**：旧字段和旧 Mock ID 不再存在。

### WP-05：文案、文档与双重审计

- **业务目标**：清理所有库内残留，同时保护不同业务对象。
- **文件／符号**：`src/`、`scripts/`、`tests/`、`docs/`、`business-model.html`、全部文件名。
- **修改**：更新历史规格、测试断言和示例；保留包材、送货和染色内部封装语义。
- **验证证据**：第一遍正向追踪；第二遍反向全库审计；文件名审计。
- **完成条件**：两遍核查结果均无未解释残留。

## 3. 依赖顺序

`WP-01 → WP-02 → WP-03/WP-04 → WP-05`。共享事实源先收口，上下游消费者随后迁移，最后进行两次审计和命名页面验收。

## 4. 风险

- 把染色内部成卷封装节点误删，会中断染色交出。
- 把包材或出货信息误当后道工序，会破坏 PCS 物料档案和交接凭证。
- 只改显示名不改类型和字段，会继续产生双事实。

## 5. 待确认项

无。本次完全按用户确认的“后道新增烫包并彻底删除两项旧工序”执行。
