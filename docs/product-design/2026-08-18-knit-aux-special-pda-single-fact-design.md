# 毛织、辅助工艺、特种工艺 PDA 单一加工单事实总体设计

## 1. 背景与目标

毛织、辅助工艺、特种工艺在 PDA 曾同时存在“执行 / 交接”和“仓管待加工 / 待交出”两套操作入口，确认接收、加工填报、发起交出也没有按现场职责落在正确 Tab。结果是同一加工单可以从不同页面被推进，页面动作与 Web 加工单事实不一致。

本次把三类工艺统一收口为一套“加工单执行事实”：PDA 只按现场职责提供不同操作表面，所有保存继续写入已有加工单事实，不新建仓管旁路、第二套状态或第二套命令。

- `交接`：确认接收、发起交出。
- `执行`：加工填报、完成加工单；毛织加工单额外提供关联横机设备。
- `仓管`：只保留查库存、扫码查询、库存盘点，不推进三类加工单。

## 2. 范围与非范围

### 2.1 本次范围

- 毛织、辅助工艺、特种工艺 PDA 交接、执行、待办和旧仓管入口。
- 确认接收、发起交出、加工填报的生产单 / 加工单扫码优先入口。
- 一个生产单对应多张加工单时的候选选择，以及跨厂、无当前动作、已完成等阻断。
- 款式真实图片、识别结果、大图预览和加载失败反馈。
- 旧仓管专属菜单、页面分支、草稿状态、字段、事件处理器、写动作数据文件和旧专项脚本的完整删除。

### 2.2 非范围

- 不改变 Web 端加工单动作、状态、数量规则和领域命令。
- 不改变裁床、后道、中央成衣仓等其他 PDA 流程；既有中央成衣出库权限门禁继续保留。
- 不新增摄像头或厂商扫码 SDK；原型以扫码枪输入回车、手工输入点击识别模拟扫码。
- 不新增真实接口、离线队列、自动重试或上传基础设施。

## 3. 单一事实与 Tab 职责

| 工艺 | `交接 / 待接收` | `交接 / 待交出` | `执行` | `仓管` |
| --- | --- | --- | --- | --- |
| 毛织 | 确认接收 | 发起交出 | 加工填报、关联横机设备、完成加工单 | 只查库存、扫码查询、库存盘点 |
| 辅助工艺 | 确认接收 | 发起交出 | 加工填报、完成加工单 | 只查库存、扫码查询、库存盘点 |
| 特种工艺 | 确认接收 | 发起交出 | 加工填报、完成加工单 | 只查库存、扫码查询、库存盘点 |

动作白名单既控制页面显示，也控制事件执行。通过旧 URL、查询参数或 DOM 注入错误动作时仍必须阻断，不能只隐藏按钮。

PDA 与 Web 读取同一加工单事实：确认接收、加工填报、发起交出、毛织横机关联和完成加工单均复用已有领域写入口。PDA 页面不保存自己的加工进度投影，也不生成仓管专属加工事实。

## 4. 扫码识别规则

确认接收、发起交出、加工填报都优先扫描生产单或加工单：

1. 精确匹配加工单号 / 加工单 ID；任务号和来源任务号只作为兼容识别码。
2. 未命中加工单时再精确匹配生产单号 / 生产单 ID，不做模糊猜测。
3. 加工单唯一命中且属于当前工厂、当前 Tab 有可执行动作时，直接进入聚焦操作页。
4. 一个生产单命中多张加工单时，展示全部候选的加工单号、生产单号、款号、款式名称和真实款式图，由操作员选择。
5. 跨厂、已完成、尚未接收、没有可交数量或当前 Tab 无对应动作时阻断，说明原因且不写入事实。
6. 扫码枪回车与“识别加工单”按钮调用同一解析逻辑。

扫码负责识别加工单，保存仍受原领域的工厂归属、状态、数量、接收方和完成条件约束。

## 5. 页面与流程

### 5.1 确认接收

操作员进入 `交接 / 待接收`，扫描生产单或加工单。唯一命中后只展示确认接收动作及防错所需的加工单、生产单、款式图、款号、工序 / 加工对象；确认后写入原加工单接收事实。

### 5.2 加工填报

操作员进入 `执行`，扫描生产单或加工单。唯一命中后进入加工单执行页，只显示当前工艺允许的执行动作。毛织可加工填报、关联横机设备、完成加工单；辅助和特种工艺可加工填报、完成加工单。确认接收和发起交出不出现在执行页。

### 5.3 发起交出

操作员进入 `交接 / 待交出`，扫描生产单或加工单。唯一命中后只展示发起交出动作及可交数量、接收方和加工对象；没有已填报可交数量时阻断并提示先加工填报。

### 5.4 待办与旧链接

- 待确认接收、待交出进入 `交接` 对应子 Tab。
- 待加工填报、待完工进入 `执行`。
- 三类工艺访问旧待加工仓 URL 时跳到 `交接 / 待接收`；访问旧待交出仓 URL 时跳到 `交接 / 待交出`。
- 旧 URL 只承担兼容跳转，不再渲染旧表单或触发旧写动作。

## 6. 删除边界

删除必须覆盖下列全部层面，不能仅隐藏仓管首页卡片：

- 仓管首页三类工艺的待加工仓、待交出仓入口和数量提示。
- 两个旧仓管子页中的专属渲染分支、表单、草稿状态、DOM 标识、字段解析、确认弹窗和事件处理器。
- 特种 / 辅助工艺仓管专属写动作文件及其导入、调用和旧专项脚本。
- 毛织仓管中的纱线确认接收、纱线领用、纱线退回、库存调整、待交出库存调整 / 转移旁路。
- 与旧入口绑定的待办路由、测试名称、命令编号和操作者文案。

保留的只有旧 URL 到正确 `交接` 子 Tab 的无写入跳转，以及其他工厂仍在使用的通用仓管能力。

## 7. 正常与边界场景

### 正常场景

- 扫加工单号唯一命中，直接进入对应接收、执行或交出聚焦页。
- 扫生产单号命中多张加工单，操作员根据真实款式图和加工对象选择正确加工单。
- 毛织执行页关联横机后，同一加工单事实立即回显设备；辅助和特种工艺不显示横机动作。

### 边界场景

- 扫到其他工厂加工单：阻断，不产生任何记录。
- 在 `执行` 注入确认接收 / 发起交出动作，或在 `交接` 注入加工填报 / 完成动作：事件白名单阻断。
- 扫到尚未接收的加工单执行：提示先去 `交接 / 待接收`。
- 扫到没有可交数量的加工单：提示先加工填报。
- 图片加载失败：显示明确失败信息，仍保留加工单、生产单和款号供人工核对，不用无关占位图冒充。

## 8. 验收口径

1. 三类工艺只有一套加工单事实与写命令；仓管不能推进加工单。
2. `交接`只有确认接收、发起交出；`执行`只有加工填报、完成加工单及毛织专属关联横机设备。
3. 确认接收、发起交出、加工填报均能用生产单 / 加工单扫码枪回车识别。
4. 生产单多加工单不自动猜测；跨厂、状态不允许和错误 Tab 动作均阻断。
5. 待办和旧 URL 到达正确 Tab，旧仓管代码、数据、处理器和脚本无生产残留。
6. 识别结果的款式图与款号、加工单、生产单同块展示，支持大图、`Esc` 关闭和失败反馈。
7. 当前分支在 400×806、360×800 完成三类工艺命名路由和关键交互验收，无横向溢出和控制台错误。
8. 同一工作树的专项检查、构建、原型治理、局域网 HTTP 200 和任务收据形成最终证据；无法完成的项目必须据实标明原因。
