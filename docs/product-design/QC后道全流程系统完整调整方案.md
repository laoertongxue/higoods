## 0. 方案结论

本次不是在现有页面上补几个字段，而是要把后道全流程收口为一条由送货单驱动、逐环节交接、数量守恒、差异授权、全程可追溯的业务链。

最终业务链为：

```text
送货单
  → 工厂登记回货
  → 后道待加工仓生成待确认记录
  → PDA 或 Web 二次点数并确认回货
  → 按最终确认数量进入后道待加工仓可用库存并生成正式入库流水
  → 从后道待加工仓发起送检并形成送检出库流水
  → Web 质检员输入完整任务号领取并完成质检
  → 需要后道：生成后道任务 → PDA 后道加工 → 生成复检单
  → 不需要后道：直接生成复检单
  → PDA 复检数量和 SKU 条码
  → 一张复检单幂等生成一张后道出货单
  → 打印出货单条码并随货交接
  → 仓库 PDA 扫描出货单条码收货
  → 完成入库与全链操作追溯
```

端侧分工确定为：

| 环节 | 员工执行端 | 管理/追溯端 | 最终边界 |
|---|---|---|---|
| 工厂登记回货 | 后道工厂公共 PDA | Web 查看 | 保留现有锁定式公共 PDA 模式 |
| 回货二次点数 | PDA 或 Web，读取后道待加工仓同一待确认记录 | Web 待加工仓管理、筛选、送检 | 两端不能分别形成不同确认结果；确认后必须落库存和流水 |
| 质检 | 无 PDA 入口 | Web“质检任务”单一菜单，按角色展示任务输入区和主管列表 | 质检严格 Web-only；Web 主操作是输入任务号，不表述为扫描 |
| 后道加工 | PDA 扫描后道任务并执行 | Web 查看、打印、追溯 | 基于现有能力保留 PDA 执行 |
| 复检 | PDA 扫描复检单并执行 | Web 查看、追溯 | 文档明确要求 PDA |
| 出货单 | 无人工新建 | Web 自动生成、详情、打印 | 一张复检单只能对应一张出货单 |
| 仓库收货 | PDA 扫描出货单条码并收货 | Web 查看接收人与授权人 | 文档明确要求 PDA |
| 授权码 | 触发差异时扫码 | 指定授权人查看动态码、管理授权记录 | 30 秒刷新、单次使用 |

## 1. 目标、范围与非目标

### 1.1 目标

1. 统一所有环节的业务对象、数量来源、状态和责任人。
2. 把回货差异与回货后的差异分成两套明确授权规则。
3. 保证多次送货可以分别形成独立链路，但同一次送货不能拆成多张质检任务。
4. 质检任务只能由一个质检员领取，错误领取可以退回待质检。
5. 质检参考资料独立于技术包，由买手或 QC 上传并绑定到本次质检。
6. 质检瑕疵和后道瑕疵使用同一套记录、原因、证据和后续处理逻辑。
7. 复检同时完成数量清点和 SKU 条码核对，条码错误必须阻断出货。
8. 仓库使用后道出货单条码作为唯一现场收货入口。
9. 所有差异、授权、领取、退领、重贴码和收货动作均有操作日志，可按条件回溯。

### 1.2 范围

- 回货登记、回货确认和送检入口。
- 送货单号、质检任务号、后道任务号、复检单号和出货单号的生成及关联。
- 单一“质检任务”菜单中的 Web 任务号输入领取、执行区、主管管理列表和质检单打印。
- 质检参考资料上传、查看和历史绑定。
- PDA 后道加工、复检和仓库收货。
- 后道出货单列表、详情、整单打印、出货单条码和 SKU 重贴码。
- 动态授权码、差异记录和操作日志。
- 当前冲突入口、旧文案、旧校验和旧 Mock 的收口。

### 1.3 非目标

- 不把色差图、尺寸标准写入技术包，也不修改技术包结构来容纳这些资料。
- 不把本原型扩展为真实后端、数据库、生产鉴权或离线队列。
- 不新增人工创建后道出货单；出货单只能由复检完成触发。
- 不把后道加工数量做库存锁定；继续遵循“无需锁定库存”。
- 不允许为了保留旧页面而同时存在两套质检、授权、出货或仓库收货口径。

### 2.2 当前代码中必须删除或改写的旧口径

1. 当前 PDA 可以创建质检单、录入质检结果和完成质检；必须全部关闭。
2. 调整前质检单二维码会跳转 PDA 质检执行页；现已改为 Web 质检任务执行页。
3. 调整前 Web 质检页默认展示“待质检列表”，并支持从列表选择、按生产单创建；现普通质检员只输入完整任务号领取，不展示待质检池。
4. 当前质检单号是独立的 `QC-POST-2026-xxx`；必须改为“生产单号-本生产单送货序号”。
5. 当前质检可从多条待质检库存中自由选择数量；必须改为一张送货单确认后只生成一张不可拆分的质检任务。
6. 当前回货数量不一致即可进入“数量差异待处理”，且确认数量可以直接进入库存；必须增加 5%计算、二次点数和超阈值授权门禁。
7. 当前后道 PDA 完成时可直接使用计划数量，没有完整录入后道瑕疵；必须改为逐 SKU 录入实际结果。
8. 当前复检没有 SKU 条码核对，也没有数量守恒和授权；必须补齐。
9. 当前复检完成即生成出货单，没有条码错误阻断；必须增加“条码异常待重贴”门禁。
10. 当前仓库 PDA 不识别后道出货单号，而是走另一套交接编号；必须让出货单号成为现场唯一扫码入口。
11. 当前多处操作人使用“PDA 后道质检员”“PDA 复检员”“后道仓管员”等固定名称；必须改为真实当前账号。
12. 当前没有 30 秒刷新、单次使用的动态授权码，也没有统一授权记录；必须新增统一机制。
13. 当前用户可见文案混用“次品、不合格、返工、瑕疵接收”；必须按业务对象重新命名，不能简单全文替换导致“返厂”“返工”等动作含义丢失。

## 4. 业务对象与一单到底关系

### 4.1 核心对象

1. **送货单**：一次实际送货的业务身份。可以由不同业务入口触发生成，但必须由同一个编号服务生成。
2. **回货登记**：工厂对本次送货的逐 SKU 登记数量，所有登记明细必须大于 0。
3. **回货确认**：后道人员的二次点数结果，作为本次送检数量来源。
4. **质检任务**：一张送货单确认后唯一生成的一张质检任务。
5. **质检参考资料**：独立于技术包、绑定本次质检任务的色差参考图和尺寸判断标准。
6. **瑕疵记录**：质检和后道共用的质量事实，保留发现阶段。
7. **后道任务**：仅承载质检合格、需要继续后道加工的数量。
8. **复检单**：由“不需要后道”的质检结果或已完成后道任务唯一生成。
9. **后道出货单**：由复检完成幂等生成，每张复检单最多一张。
10. **仓库接收记录**：仓库扫描后道出货单后形成的逐 SKU 实收事实。
11. **差异授权记录**：记录触发规则、差异、授权人和使用结果，不保存可复用的明文授权码。
12. **操作日志**：记录领取、退领、点数、提交、授权、打印、重贴码、复扫和收货等动作。

### 4.2 唯一关系

```text
一个生产单
  └─ 可以有多张送货单
       └─ 每张送货单只能有一条回货确认
            └─ 每张送货单只能生成一张质检任务
                 ├─ 需要后道：一张后道任务 → 一张复检单
                 └─ 不需要后道：直接一张复检单
                      └─ 每张复检单只能生成一张后道出货单
                           └─ 一张后道出货单形成一组仓库接收明细
```

所有对象必须保存直接上游和生产单关系。列表可以按任一单号查询并回到完整链路，不能只靠文案拼接推断来源。

## 5. 单号生成方案

### 5.1 送货单号

- 车缝正常交出、车缝厂公共 PDA 自助回货、管理端补登记等触发入口均调用同一个送货单号生成服务。
- 生成服务记录“生成来源”，但不因来源不同使用不同编号事实。
- 同一次提交必须幂等：重复点击或重试返回原送货单号，不得新建第二张。
- 送货单号生成后不可人工修改。

### 5.2 质检任务号

- 格式：`生产单号-序号`，例如 `PO1234-1`、`PO1234-2`。
- 序号只在同一生产单内递增。
- 生成时检索该生产单已有质检任务的最大序号后加 1。
- 一张送货单只生成一个质检任务号，重复执行送检返回已有任务。
- 质检任务号不可人工修改。

### 5.3 后道任务号、复检单号和出货单号

- 需要后道时，质检完成唯一生成后道任务号；重复提交不得重复生成。
- 不需要后道时，质检完成唯一生成复检单号；需要后道时由后道完成唯一生成复检单号。
- 复检完成唯一生成后道出货单号；同一复检单重复提交只更新原出货单，不新建。
- 所有单号生成均保留来源对象 ID、来源单号和幂等键。

## 6. 数量口径和守恒公式

### 6.1 变量定义

| 符号 | 业务含义 |
|---|---|
| `F` | 工厂登记回货数量，必须 `F > 0` |
| `R` | 后道二次点数确认数量 |
| `Q` | 送检数量，等于确认入库数量 `R` |
| `QC_OK` | 质检合格数量 |
| `QC_DEFECT` | 质检瑕疵数量 |
| `QC_RETURN` | 质检返厂数量 |
| `POST_IN` | 进入后道数量，等于 `QC_OK` |
| `POST_OK` | 后道完成后的合格数量 |
| `POST_DEFECT` | 后道环节新增瑕疵数量 |
| `POST_RETURN` | 后道环节返厂数量 |
| `RC_IN` | 复检交接数量；有后道时为 `POST_OK`，无后道时为 `QC_OK` |
| `RC_OK` | 复检合格数量 |
| `RC_DEFECT` | 复检瑕疵数量 |
| `OUT_QTY` | 后道出货数量，等于 `RC_OK` |
| `WH_ACTUAL` | 仓库实际接收数量 |

所有数量先按 SKU 明细计算，再汇总整单。不同 SKU 的多货和少货不能互相抵消；任一 SKU 明细触发差异，即视为该业务对象存在差异。当前成衣数量单位统一为“件”，只允许非负整数；工厂回货登记还必须严格大于 0。

### 6.2 工厂回货差异

```text
差异数量 = R - F
差异率 = |R - F| ÷ F × 100%
```

- `F = 0`时不允许提交回货登记，因此系统不存在除以 0场景。
- 当前有效阈值为 5%，阈值作为系统配置项保存，但普通现场人员不可修改。
- 差异率 `≤ 5%`，允许确认入库，不需要授权。
- 差异率 `> 5%`，先提示二次点数；二次点数后仍超过 5%，必须授权。
- 正负差异均按绝对值判断，同时在页面明确显示“少 X 件”或“多 X 件”。

### 6.3 回货后的数量守恒

质检：

```text
QC_OK + QC_DEFECT + QC_RETURN = Q
```

后道：

```text
POST_OK + POST_DEFECT + POST_RETURN = POST_IN
```

全链复核：

```text
POST_OK + QC_DEFECT + POST_DEFECT + QC_RETURN + POST_RETURN = Q
```

无后道时不计算后道变量，直接使用：

```text
QC_OK + QC_DEFECT + QC_RETURN = Q
```

复检：

```text
RC_OK + RC_DEFECT = RC_IN
```

仓库接收：

```text
WH_ACTUAL = OUT_QTY
```

上述公式对每个 SKU 和整单汇总分别校验。回货后任一 SKU 或整单公式不成立，只要差异不为 0，就必须授权；没有百分比阈值，也不能用另一个 SKU 的多货抵消当前 SKU 的少货。

### 6.4 数量进入下一环节的规则

- 送检数量只取确认入库数量，不取工厂登记数、计划数或可用库存数。
- 质检瑕疵和质检返厂不进入后道。
- 后道任务数量只取质检合格数量，无需锁定库存。
- 后道瑕疵和后道返厂不进入复检。
- 复检交接数量取上一环节实际合格数量。
- 后道出货数量只取复检合格数量。
- 仓库按实际接收数量入库；有差异时必须先授权，再以实收数量形成事实。

## 7. 统一差异授权机制

### 7.1 触发矩阵

| 环节 | 触发条件 | 是否授权 |
|---|---|---|
| 回货二次点数 | 差异率 `≤ 5%` | 否 |
| 回货二次点数 | 差异率 `> 5%`，二次点数后仍超阈值 | 是 |
| 质检 | 三类结果合计不等于送检数量 | 是 |
| 后道 | 后道结果合计不等于进入后道数量，或全链复核不守恒 | 是 |
| 复检 | 合格加瑕疵不等于交接数量 | 是 |
| 仓库收货 | 实收不等于出货交接数量 | 是 |

### 7.2 动态授权码

1. 只有权限名单中的指定人员具有授权码。
2. 每名授权人的授权码每 30 秒自动刷新。
3. 每个授权码只能成功使用一次；同一时间窗内第一次提交成功后，再次使用必须提示“授权码已使用”。
4. 过期授权码提示“授权码已过期，请联系授权人获取最新授权码”。
5. 授权码必须通过扫码或精确输入校验，不支持模糊匹配。
6. 授权只对当前业务对象、当前环节、当前差异内容有效。
7. 授权后如果修改任何数量、SKU 或差异原因，原授权立即失效，需要重新授权。
8. 授权提交必须填写差异原因；系统自动记录应有数量、实际数量、差异数量、差异率（仅回货阶段）、操作人、授权人和时间。
9. 日志只保存授权成功事实和不可复用的凭证标识，不显示或保存可再次输入的明文授权码。

### 7.3 端侧交互

- 正常数量一致时不展示授权输入框。
- 触发差异后，页面先显示差异事实和二次点数/重新核对动作。
- 仍需提交时才出现“扫描授权码”主动作。
- 授权成功后明确显示授权人姓名和“本次授权已使用”。
- 授权失败不能保存业务结果，不能先写库存、再补授权。

## 8. 模块一：回货确认与送检

### 8.1 工厂登记回货

1. 后道管理员在公共 PDA 开启“车缝现场交货登记模式”。
2. 公共 PDA 锁定后只保留扫码登记、提交、最近记录和管理员退出。
3. 送货人员扫描纸质生产确认单或业务允许的送货来源单据。
4. 系统识别生产单、车缝任务、车缝工厂、款式图片、SPU、SKU、颜色、尺码、计划数量和默认暂存库位。
5. 送货人员逐 SKU 输入本次登记数量；每条提交数量必须大于 0。
6. 输入 0 时立即提示“回货登记数量必须大于 0”，不得静默忽略。
7. 填写送货人姓名、联系方式并上传现场凭证图片。
8. 提交时由统一送货单号服务生成或返回本次送货单号，同时形成车缝侧交出事实和后道待确认回货记录。
9. 待确认阶段不进入后道可用库存，不生成正式入库流水。

### 8.2 回货确认和二次点数

1. 后道确认人员从 PDA 或 Web 打开同一张待确认送货单。
2. 页面逐 SKU 展示工厂登记数量，并要求录入后道第一次实点数量。
3. 有差异时系统显示差异数量和差异率，并要求再次点数。
4. 第二次点数覆盖第一次临时点数，但两次点数过程写入操作日志。
5. 第二次点数差异率不超过 5%时可直接确认。
6. 第二次点数差异率超过 5%时必须扫描动态授权码。
7. 授权完成后，以最终确认数量进入后道待加工仓并生成正式入库流水。
8. 确认记录保存确认人员；差异授权时同时保存授权人员。

### 8.3 质检任务自动生成和送检

1. 回货确认后，系统为本送货单创建唯一质检任务草稿，任务号按“生产单号-序号”生成。
2. 同一生产单多次送货分别生成 `-1`、`-2`、`-3`等任务。
3. 同一送货单重复确认或重复点击送检，只返回原质检任务，不允许拆分或重复生成。
4. Web 回货页面出现“送检”入口；只有已确认回货可以送检。
5. 送检动作记录送检人员和送检时间，任务状态变为“待质检”。
6. 送检数量逐 SKU 取最终确认入库数。

### 8.4 送检单

送检单必须包含：

- 质检任务号及可扫描条形码。
- 送货单号、生产单号和本次送货序号。
- 送检时间、送检人员和确认入库人员。
- 存在超 5%差异时的授权人员。
- 产品真实图片、SPU、SKU、颜色、尺码。
- 每个 SKU 的送检数量及总数量，数量来源明确标注为“确认入库数”。

送检单条码必须打开 Web 质检工作台，不得再跳转 PDA 质检页面。

## 9. 模块二：Web 开始质检

### 9.1 终端和入口

- 删除后道质检在 PDA 的创建、执行、完成入口。
- 删除 PDA 执行列表中“待质检/质检中”的后道质检动作。
- 质检单打印二维码和条形码只能打开 Web 质检工作台。
- 主管管理页可以保留质检单列表用于查询、追溯和异常处理；普通质检员的执行工作台不得显示待质检任务池。

### 9.2 输入完整任务号领取

1. 质检工作台首屏只有扫描框、精确输入框和“打开质检任务”主动作。
2. 不支持模糊查询、部分单号或按生产单随意选择待质检 SKU。
3. 扫描/输入完整质检任务号后，系统校验任务存在、状态为待质检、当前用户具有质检角色。
4. 成功打开即原子领取，记录质检员、领取时间，状态变为“质检中”。
5. 同一质检任务同一时刻只能有一个质检员。
6. 其他质检员再次扫描时阻断并提示：“该质检任务已由 XX 质检员质检中，领取时间 YYYY-MM-DD HH:mm。”
7. 已完成任务只能只读查看，不允许再次领取或覆盖结果。

### 9.3 退领

1. 当前领取人可在未提交任何最终质检结果前点击“退领”。
2. 退领需二次确认并可填写原因。
3. 退领后清空当前占用人，状态回到“待质检”，其他质检员可以重新扫描领取。
4. 已完成任务不可退领；已有未提交草稿时，退领需明确提示草稿将被放弃。
5. 领取、冲突扫描和退领全部写入操作日志。

### 9.4 任务信息与质检参考资料

质检页面展示：

- 送货时间、送检时间、送货单号和质检任务号。
- 产品真实图片、SPU、SKU、颜色、尺码、每个 SKU 送检数量和总数量。
- 质检参考资料区：色差参考图、尺寸判断标准、上传人、资料来源、上传时间。

质检参考资料规则：

1. 资料不属于技术包，页面不得显示“来自技术包”或“技术包版本”。
2. 买手可以在回货确认后、送检前上传。
3. 买手通过飞书线下给到 QC 时，QC 可以代为上传，必须记录“代上传”和实际上传人。
4. 资料绑定本次质检任务；任务完成后历史查看仍显示当时绑定的资料。
5. 后续重新上传只形成新资料记录，不覆盖已完成质检的历史依据。
6. 未上传资料时显示“本次未上传质检参考资料”，不伪造默认色差图或尺寸标准；当前方案不把缺失资料设为质检硬阻断。

### 9.5 质检结果录入

1. 按 SKU 录入“合格数量、瑕疵数量、返厂数量”。
2. 所有用户可见的“次品”统一为“瑕疵”。
3. 瑕疵数量大于 0时，必须填写瑕疵原因；需要证据时上传对应图片。
4. 返厂数量大于 0时，必须填写返厂原因和接收责任方。
5. 系统自动计算三类合计和与送检数量的差异，员工不手算。
6. 合计等于送检数量时可正常完成。
7. 合计不等于送检数量时，无论差多少都必须扫描授权码后完成。
8. 授权完成后仍保存真实结果，不把差异强行补到某一分类。

### 9.6 后道判定和下游生成

- 勾选“需要后道加工”：完成质检后唯一生成后道任务号，数量为质检合格数。
- 勾选“不需要后道加工”：完成质检后唯一生成复检单号，状态为“待复检”。
- 同一质检任务只能选择一个分支，完成后不得通过重复提交生成另一条链。
- 主管纠错必须通过明确的业务更正流程，不允许直接编辑历史单号。

### 9.7 后道工序加工单

需要后道时，可以按后道任务号打印《后道工序加工单》，随质检合格实物交给加工组。打印内容至少包括：

- 后道任务号和条码。
- 关联送货单、质检任务和生产单。
- 产品真实图片、SPU、SKU、颜色、尺码。
- 逐 SKU 需加工数量，总数量等于质检合格数。
- 加工项目和交接时间。

## 10. 模块三：后道加工

### 10.1 PDA 进入与开始

1. 后道操作员在 PDA“执行”中扫描或精确输入后道任务号。
2. 不展示完整待后道任务池，不允许模糊匹配后直接代选第一张。
3. 页面展示真实产品图片、SPU、SKU、颜色、尺码、需加工数量和加工项目。
4. 操作员确认实物和任务一致后点击“开始后道”，状态变为“后道中”，记录真实操作人和开始时间。
5. 后道加工数量等于质检合格数量；质检瑕疵和质检返厂不进入后道。
6. 本环节不增加库存锁定。

### 10.2 后道瑕疵

1. 后道环节只新增本环节发现的瑕疵，不得修改质检阶段已经形成的瑕疵事实。
2. 无后道瑕疵时可以留空，系统按 0处理。
3. 同一任务在完成前可以追加后道瑕疵记录；已有记录不可无痕覆盖，修改必须留下前后值。
4. 后道瑕疵与质检瑕疵共用同一套字段、原因字典、图片证据、责任归属和后续处理逻辑。
5. 瑕疵记录必须额外保存发现阶段：`质检`或`后道`，保证合并处理时仍可追溯来源。
6. 所有页面统一显示“瑕疵”，不得显示“次品”。

### 10.3 完成与数量核对

1. 逐 SKU 录入后道合格、后道瑕疵和后道返厂数量。
2. 系统先校验本环节守恒，再校验包含质检结果在内的全链守恒。
3. 任一差异不为 0时弹窗展示差异并要求授权。
4. 完成后状态变为“后道完成”，自动且唯一生成复检单号，状态“待复检”。
5. 复检交接数量只取后道合格数量。

## 11. 模块四：PDA 复检与后道出货

### 11.1 复检领取

1. PDA“复检”入口首屏只提供扫码和精确输入。
2. 扫描复检单号后调出任务并记录复检员，状态从“待复检”变为“复检中”。
3. 为避免多人同时处理，同一复检单同一时刻只允许一个复检员；其他人扫描时显示当前复检员。
4. 错误领取可由当前复检员或主管释放，释放后回到“待复检”并记录日志。该项是对“任务领取”的必要并发防错设计。

### 11.2 复检范围

复检只做两件事：

1. 清点交接数量。
2. 核对每个 SKU 实物条码是否正确。

不在复检环节重复录入质检原因、后道加工项目或技术资料。

### 11.3 PDA 复检页面

页面展示：

- 复检单号、关联质检任务、后道任务和生产单。
- 产品真实图片、SPU、SKU、颜色、尺码。
- 每个 SKU 的交接数量。
- 每个 SKU 的条码扫描状态。

操作流程：

1. 逐 SKU 扫描实物条码，系统与当前有效 SKU 条码精确比对。
2. 条码正确显示绿色“条码正确”。
3. 条码错误立即阻断，显示应有 SKU、实际扫描条码和“重新贴码”动作。
4. 重新打印正确 SKU 贴标并贴码后，必须再次扫描；复扫正确才能继续。
5. 逐 SKU 录入复检合格数量和复检瑕疵数量。
6. 系统自动校验合计是否等于交接数量。
7. 数量不等时必须扫描授权码；条码错误不能通过授权绕过。
8. 所有 SKU 条码正确且数量规则通过后，状态变为“复检完成”。

### 11.4 条码异常状态

```text
复检中
  → 扫描错误条码
  → 条码异常待重贴
  → 打印并重新贴码
  → 复扫正确
  → 返回复检中
```

处于“条码异常待重贴”时：

- 不得进入可出货状态。
- 不得让仓库收货。
- 记录错误条码、应有 SKU、发现人、发现时间、重贴人、重贴时间和复扫结果。

### 11.5 后道出货单

1. 复检完成后自动生成后道出货单。
2. 一张复检单只能对应一张出货单；重复完成、重复点击或页面重试均更新原单。
3. 出货明细逐 SKU 数量等于复检合格数量。
4. 出货单保存送货单、质检任务、后道任务、复检单和生产单关系。
5. 条码异常未解除时，出货单不得进入“待仓库接收”的可执行状态。
6. 后道出货单页面展示列表、详情、整单打印和 SKU 重贴码入口。

### 11.6 两类条码必须明确区分

| 条码 | 内容 | 用途 | 扫描人 |
|---|---|---|---|
| 后道出货单条码 | 后道出货单号，如 `FCK...` | 打印在整张出货单上，仓库 PDA 扫描收货 | 仓库人员 |
| SKU 商品条码 | 当前有效 SKU 条码 | 贴在实物上，复检核对或错误后重贴 | 复检员 |

页面按钮必须分别命名为“打印出货单条码/打印整单”和“打印 SKU 贴标”，不能继续用一个模糊的“打印条码”。

## 12. 模块五：仓库 PDA 收货

### 12.1 扫码入口

1. 仓库人员进入 PDA“后道出货收货”。
2. 首屏只保留后道出货单条码扫描框和最近本人收货结果。
3. 扫描 `FCK...` 出货单条码后精确打开一张待仓库接收的出货单。
4. 不支持用复检单号、内部交接号或模糊关键字代替出货单号。
5. 当前内部 `HOH-POST-...` 等记录可以作为系统内部交接事实保留，但不得成为现场第二个扫码身份。

### 12.2 信息展示

扫描成功后显示：

- 后道出货单号、来源后道工厂、出货时间。
- 产品真实图片、SPU、SKU、颜色、尺码。
- 待接收总数量。
- 每个 SKU 对应的待发/待接收数量。
- 关联复检单、质检任务和生产单。

### 12.3 实收和授权

1. 仓库人员逐 SKU 录入实际接收数量，系统自动汇总总实收。
2. 每个 SKU 和整单均展示应收、实收、差异。
3. 全部一致时直接确认入库。
4. 任一 SKU 或总数存在差异时，无论差多少都必须扫描动态授权码。
5. 授权前不得写入已接收状态或库存。
6. 授权完成后按实际接收数量入库，并保存差异原因。
7. 重复扫描已接收出货单时只读展示原接收结果，不得再次入库。

### 12.4 Web 追溯

Web 后道出货单和仓库接收记录增加：

- 实际接收入库人员账号和姓名。
- 接收时间。
- 有差异时的授权人员账号和姓名。
- 应收、实收和差异数量。
- 差异原因。

列表支持按时间、环节、接收人、授权人、生产单、送货单、质检任务、复检单和出货单筛选。

## 13. 瑕疵统一处理方案

### 13.1 统一术语

- 用户可见名统一为“瑕疵”。
- “返厂”是货物去向，不改名为瑕疵。
- “返工”是处理动作，不与瑕疵数量混为同一字段。
- 历史数据中的“次品”读取时映射显示为“瑕疵”，新数据不再生成“次品”文案。

### 13.2 统一瑕疵记录

每条瑕疵记录至少包含：

- 来源质检任务/后道任务。
- 发现阶段：质检或后道。
- SPU、SKU、颜色、尺码。
- 瑕疵数量。
- 瑕疵原因。
- 图片或其他现场证据。
- 责任类型和责任方。
- 后续处理动作及状态。
- 记录人、记录时间和后续处理人。

质检与后道使用相同原因字典、相同图片要求和相同后续处理入口；列表允许合并查看，也必须能按发现阶段筛选。

## 14. 操作日志和差异追溯

### 14.1 必须记录的动作

- 送货单生成。
- 工厂登记回货。
- 第一次点数、第二次点数和最终确认。
- 送检、打印送检单。
- 质检领取、占用冲突、退领、完成。
- 质检参考资料上传、代上传和更新。
- 后道开始、瑕疵追加、数量提交、完成。
- 复检领取、条码扫描、条码错误、重贴码、复扫、完成。
- 出货单生成和打印。
- 仓库扫描、实收和确认。
- 每一次授权成功、失败、过期和已使用拒绝。

### 14.2 日志内容

每条日志至少保存：业务环节、业务对象、来源单号、操作动作、操作人、时间、操作前状态、操作后状态、数量前后值、差异原因、授权人（适用时）和结果。

### 14.3 查询页面

Web 新增“差异与授权记录”查询页面，支持：

- 时间范围。
- 环节。
- 作业人。
- 授权人。
- 生产单、送货单、质检任务、后道任务、复检单和出货单。
- 差异方向：多、少。
- 授权结果：成功、过期、已使用、无效。

“永久保存”在本方案中表达为操作日志长期留存且可回溯；原型只展示完整历史事实，不承诺真实生产存储年限。

## 15. 状态设计

### 15.1 回货与送检

```text
待登记
→ 待后道确认
→ 点数中
→（一致或差异≤5%）已确认待送检
→（差异>5%）待二次点数
→（仍>5%）差异待授权
→ 已确认待送检
→ 已送检
```

### 15.2 质检

```text
待质检
→ 质检中
→ 退领 → 待质检
→（数量不等）质检差异待授权
→ 质检完成
→ 待后道 或 待复检
```

### 15.3 后道

```text
待后道
→ 后道中
→（数量不等）后道差异待授权
→ 后道完成
→ 待复检
```

### 15.4 复检、出货和收货

```text
待复检
→ 复检中
→ 条码异常待重贴 → 复扫正确 → 复检中
→（数量不等）复检差异待授权
→ 复检完成
→ 待仓库接收
→ 收货中
→（数量不等）收货差异待授权
→ 已接收入库
```

## 18. 验收场景

### 18.1 正常场景

同一生产单第一次送货，工厂登记 100 件，后道确认 98 件，差异率 2%，无需授权；系统生成 `生产单号-1`质检任务。QC 在 Web 输入完整任务号领取，录入 95 合格、2 瑕疵、1 返厂，选择需要后道；后道 PDA 扫描任务，录入 94 合格、1 后道瑕疵；复检 PDA 扫描并完成 94 合格且全部条码正确；系统生成唯一出货单；仓库 PDA 扫出货条码并实收 94 件，流程完成。

### 18.2 回货超 5%差异

工厂登记 100 件，第一次点数 93 件，系统要求二次点数；第二次仍为 93 件，差异率 7%，未授权不能确认入库。扫描有效授权码后确认；重复使用同一授权码必须失败。日志能查到两次点数、操作人、授权人和差异原因。

### 18.3 同一生产单多次送货

同一生产单第二次和第三次送货分别生成 `生产单号-2`、`生产单号-3`。每张送货单各有且仅有一张质检任务；重复点击送检不产生 `-4`。

### 18.4 质检并发领取与退领

质检员 A 输入完整任务号后任务进入质检中；质检员 B 输入同一单号，系统提示“已由 A 质检中”。A 发现领取错误后退领，任务回到待质检；B 再次输入可以领取。日志完整保留领取、冲突和退领。

### 18.5 质检差异授权

送检 100 件，QC 录入 95 合格、3 瑕疵、1 返厂，合计 99；没有授权不能完成。授权后按真实 99 件结果完成，并记录少 1 件，不能自动把少量补进合格或瑕疵。

### 18.6 后道瑕疵同逻辑

后道发现 2 件瑕疵，使用与质检相同的原因、图片和处理字段记录；质检阶段原有瑕疵数量保持不变。全链页面能合并显示 2 个阶段，也能按发现阶段筛选。

### 18.7 SKU 条码错误

复检扫描到错误 SKU 条码，任务进入条码异常待重贴，不能完成可出货状态。打印正确 SKU 贴标、重新贴码并复扫正确后才允许继续。错误条码、重贴人和复扫记录可追溯。

### 18.8 一复检一出货

同一复检单重复提交完成，只更新原后道出货单的数量和时间，不生成第二张出货单。

### 18.9 仓库差异收货

出货单应收 94 件，仓库实收 93 件；未授权不能入库。扫描有效授权码后按 93 件入库，Web 可以按接收人和授权人查到该记录。

### 18.10 边界场景

- 工厂登记数量为 0：阻断。
- 回货差异率恰好 5%：允许，无需授权。
- 回货差异率 5.01%：二次点数后仍存在时授权。
- 回货后差异 1 件：仍需授权。
- 已使用授权码在 30 秒内再次提交：阻断。
- 授权后修改数量：原授权失效。
- 质检任务号输入部分字符：不返回候选。
- 已完成质检单再次输入：只读，不可覆盖。
- 条码错误但数量一致：仍阻断出货。
- 已收货出货单再次扫描：只读，不重复入库。

1. 原始需求中的每一条规范性要求和用户 19 项确认均在追踪矩阵中有唯一或明确复用的需求编号。

4. 回货 5%规则和回货后零阈值规则分别验证，不能混用。
5. 30 秒刷新、单次使用、过期、已使用和修改数量后失效均有专项证据。
6. 同一送货单只生成一张质检任务，同一复检单只生成一张出货单。

## 21. 实际实现与本地验证结论

> 2026-09-01 纠偏结论：用户在默认 Web 页面验收时指出的真实后道待加工仓、Web 回货确认与送检、单一质检菜单、Web 输入口径、日志主从展示、个人授权码入口和默认全流程 Mock 缺口均已补齐。最后一次实质修改后已重新执行两轮独立 3×5×5 跨端验收，以下结论及证据均指向纠偏后的当前版本。

截至 2026-09-01，本方案所述业务链已经在当前独立工作树完成原型实现，并达到“本地原型已验证”。该状态只说明当前代码、Mock 业务事实、Web/PDA 页面和打印预览通过了本地验证，不代表已提交 Git、已推送远端、已部署生产或已由用户最终接受。

实际实现已覆盖以下闭环：

1. 工厂公共 PDA 登记回货，逐 SKU 数量必须大于 0；送货单可由多个入口触发，但共用一个编号服务并保持幂等。
2. 回货确认按工厂登记数量计算逐 SKU 差异率；绝对值不超过 5%直接确认，超过 5%必须二次点数，仍超差后必须使用动态授权码。
3. 回货后的质检、后道、复检和仓库收货逐 SKU 比较，只要任一 SKU 有差异即授权，整单多货和少货不能相互抵消。
4. 质检仅在 Web“质检任务”页输入完整任务号领取；一单一人，占用冲突显示当前质检员，错误领取可退领；质检参考资料独立于技术包并按任务冻结。
5. 后道 PDA 只接收质检合格数量，质检瑕疵与后道新增瑕疵共用原因、证据、责任和后续处理结构，且保留发现环节。
6. 复检 PDA 只处理数量和 SKU 条码；条码错误即使数量一致也阻断出货，必须重新打印贴标、重新贴码并复扫正确后恢复。
7. 一张复检单幂等对应一张后道出货单；仓库 PDA 只接受 `FCK...`出货单号，差异授权后按实收数量确认，重复扫描只读且不重复入库。
8. 送检单、后道加工单、后道出货单和 SKU 重贴标签分别使用正确单号与目标端；全链动作、差异、授权和责任账号进入可筛选操作日志。
9. 旧车缝自助回货的直接确认入口已关闭，历史待处理记录统一引导到新回货确认页，不能绕过 5%复点与授权门禁。
10. 工厂登记即在后道待加工仓形成待确认记录；Web/PDA确认后形成唯一入库流水和逐 SKU 可用量；Web从库存发起送检后形成唯一出库流水并清零可用量。
11. Web 菜单只保留一个“质检任务”，上方是普通质检员完整任务号输入领取，下方是主管任务管理；差异日志按一次回货链展示列表和详情时间线。
12. “我的动态授权码”只向当前指定授权身份显示本人30秒动态码，非授权身份拒绝显示；日志页不展示当前可用码。
13. 全新浏览器默认加载3个生产单×每单5个SKU×每单5次回货的多状态Mock；双轮全链测试单独关闭默认数据并从空状态产生全部业务事实。

验证规模为两轮独立执行，每轮均包含 3 个生产单、每个生产单 5 个 SKU、每个生产单 5 次回货，共 15 条回货链和 75 条 SKU 回货明细。两类证据分别承担不同职责：领域规则套件逐条验证阈值、授权过期/复用、状态和幂等边界，每轮形成 15 条待加工仓记录、30 条出入库流水、336 条操作日志和 15 次授权消费；连续跨端 UI 套件从空状态开始，15 条链逐条操作公共 PDA、Web/PDA 回货确认、待加工仓入库/送检、Web 送检与打印、统一 Web 质检、Web 后道打印、后道 PDA、复检 PDA、Web 出货与打印、仓库 PDA 和日志链详情，全部业务写入由 Web/PDA 页面操作产生，每轮落地 271 条操作日志、5 次分别发生在 Web 回货确认、Web 质检、PDA 后道、PDA 复检和 PDA 仓库收货的授权消费、32 张页面截图及 1 份完整 Playwright trace。最终 9 个命名页面场景另覆盖默认 Mock、低分辨率、异常和打印回归，不代替全链 UI 验收。
