# 染色印花加工单响应性能整改

用户要求：染色、印花加工单页面任一点击或加载响应低于 200ms；继承此前提前建单迁移及印花列表按钮位置要求。

## 范围与验收

命名页面为 FCS `/fcs/process/dye-orders`、`/fcs/process/print-orders`，以及复用相关事实和列展示的 PFOS 染色、印花加工单列表。当前分支 `codex/move-early-process-orders-to-fcs`，基准 HEAD `c56c80fb`，工作树 `/Users/laoer/Documents/higoods`，Vite 4176；桌面 1366×768，补充 1280×720。

以事件发生至目标内容完成更新并经过绘制帧计时，不能用按钮变色替代业务完成。首次文档加载、模块加载和页内交互分别记录。正常场景包括首次点击、筛选、分页、列设置、详情、图片、提前建单；边界场景包括无结果、校验失败、重复建单、取消确认及刷新后持久化。业务数量、关系、图片和既有操作权限不变。

## 现场证据与实施计划

整改前染色页面就绪约 10 秒，首次打开提前建单约 14.7 秒；CPU 样本主要消耗在工厂接收事实的重复深拷贝。首次点击经整个 FCS 事件模块加载；每行染色列表又各自读取全部任务关系。

1. 当前页面直接处理事件 → `src/main.ts` → 在已有工序快捷分发旁增加两个准备页入口 → 首次点击真实测量 → 不再加载无关 FCS 事件模块。
2. 按加工单读取接收事实 → `factory-receiving.ts`、`factory-receiving-warehouse.ts`、`printing-task-domain.ts` → 先筛选当前单据再克隆，消除循环内全库深拷贝 → 数量、来源与修改隔离契约 → 同一事实、无长期缓存或双账。
3. 同次列表复用关系数据 → `process-order-task-links.ts`、`dye-work-order-online-view.ts` → 一次构建关系后批量映射 → 单条/批量结果一致、后续修改可见 → 保留上下游及来源。
4. 逐项运行命名页面，按实测继续处理超时路径；最后补齐审查记录与任务收据。
5. 首屏加载单列验收：分别测量 Vite 开发服务与同代码构建预览，记录模块装载、公共业务初始化和页面就绪。不得以站内切换或局部交互通过替代完整文档加载。后续需要进一步拆分共享数据初始化依赖；本次不把尚未达标的冷加载关闭。
