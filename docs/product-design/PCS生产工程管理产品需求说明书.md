# PCS 生产工程管理产品需求说明书

## 0. 文档信息

| 项目 | 内容 |
|---|---|
| 产品模块 | PCS 生产工程管理 |
| 文档用途 | 交付产品、研发与测试共同实施和验收 |
| 当前业务主线 | 设计改款 → 工程主单 → 正式技术包 |
| 统计边界 | 生产准备时效只读取工程主单 |
| 当前版本 | 2026-08-27 |

本文仅描述业务需求，不包含原型代码或技术实现。此前独立的“设计打样”“改款打样”和“工程变更”不再是当前产品能力。

## 1. 产品背景

业务在做大货之前，既可能基于旧款调整，也可能基于参考款形成新设计。两者实际都需要参照款、目标款、设计稿、颜色、物料、成本和多个专业团队协作，因此不应要求业务先判断“设计”还是“改款”。满足做大货条件后，才进入工程主单，形成正式生产所需资料和技术包。

## 2. 产品目标

1. 一张设计改款任务承接所有做大货前的款式开发。
2. 每一步按团队交接，页面明确当前团队、当前动作、前置条件和完成后去向。
3. 目标款颜色、BOM 与价格由买手一次准备并确认。
4. 专业团队在真实专业任务中执行并上传真实成果。
5. 工程主单复用前期成果，并成为正式技术包唯一来源。
6. 生产准备时效准确反映工程主单任务的开始、提交和完成。
7. 删除重复、难理解且与正式事实源冲突的旧能力。

## 3. 范围

### 3.1 包含

- 设计改款任务列表、新建、详情和四步协作。
- 设计稿真实上传和锁定前替换。
- B 款目标颜色与 A 款参考色。
- BOM 物料、标准单价、自定义费用、汇率和综合成本。
- 制版、花型、调色、销售展示样衣等专业任务。
- 工程主单任务方案、前期成果复用、产前版样衣和关闭。
- 技术包草稿、现行审核、正式发布和 FCS 读取。
- 项目关系、归档和关闭。
- 生产准备时效只读投影。

### 3.2 不包含

- 老任务迁移或兼容功能。
- 同一 SPU 在工程主单关闭后继续修改正式技术包。
- 独立工程变更业务。
- 技术包模板库或历史技术包导入。
- 新审批流和任务取消。
- 可自由调整任务依赖。

## 4. 角色

| 角色／团队 | 责任 |
|---|---|
| 跟单 | 建单、设计稿、工作安排、样衣要求、工程主单方案、整单确认、主单关闭 |
| 买手 | 目标颜色、参考色、BOM 与价格、花型和调色审核 |
| 版师／毛织团队 | 基码、齐码等纸样成果 |
| 花型团队 | 花型源文件和预览成果 |
| 染厂 | 实际调色成果 |
| 制作团队 | 销售展示样衣和产前版样衣 |
| 技术包审核角色 | 对完整技术包执行现行审核 |

页面优先显示团队，不预先指定具体个人。具体人员在实际操作时记录。

## 6. 设计改款任务

### 6.1 新建

#### 必填信息

- 参照款 A。
- 目标款 B。
- 设计改款要求。
- 真实设计稿图片。
- 跟单。

#### 规则

1. A、B 必须来自已存在的商品／款式档案。
2. A、B 不能是同一 SPU。
3. 设计稿只接受图片文件。
4. 设计稿由当前跟单选择真实本地文件上传。
5. 创建成功后进入“新款资料准备中”，不向用户显示模糊的“草稿”主状态。
6. 缺少任何必填项时不创建，并在原表单提示如何补齐。
7. 设计稿读取失败时保留 A、B 和要求，允许重新选择。
8. 任何测款结果或样衣返工不能自动替业务创建该任务。

### 6.2 设计稿

- 详情显示文件名、上传团队、上传人、上传时间和图片预览。
- 工作安排确认前，跟单可以替换。
- 替换后操作记录保留前后文件名、操作人和时间。
- 工作安排确认后设计稿锁定。
- 预览支持缩略图、大图、遮罩、关闭按钮和 Esc。
- 加载失败显示失败原因与重新选择，不用无关图片替代。

### 6.3 列表

#### 列表字段

- 任务号。
- 参照款 A → 目标款 B。
- 当前步骤。
- 当前需处理的团队。
- 专业任务完成数／总数。
- BOM 与价格状态。
- 跟单。
- 更新时间。
- 操作。

#### 筛选与列表规则

- 提供“当前需处理的团队”筛选。
- 不提供“设计／改款”类型筛选、标签或统计。
- 列设置放在数据列表表头最右侧。
- 列表分页并显示总数、当前范围、页码和每页条数。
- 款式图片、SPU 和名称同块展示。

## 7. 四步协作

### 7.1 步骤一：新款资料准备

**当前团队：买手。**

#### 目标颜色

- 买手可自定义 B 款颜色。
- B 款颜色数量可以少于、等于或多于 A 款。
- 每个 B 色可选择一个 A 色作为参考，允许多个 B 色参考同一个 A 色。
- 允许选择“无参考色”。

#### BOM 初始化

- 有参考色：复制 A 色最近一份已完成且已确认的物料方案作为 B 色草稿。
- 多份有效方案时，按完成确认时间优先、更新时间其次，取最近一份。
- 无参考色：建立空白方案。
- 复制只作为初始内容，不与 A 款后续变化联动。

#### 物料维护

买手可以：

- 新增物料；
- 删除复制来的物料；
- 替换物料；
- 修改单位用量、打样数量、损耗；
- 确认是否印花、是否染色、是否需要采购；
- 维护适用 SKU 和备注。

物料必须有有效标准单价；没有标准单价时不得加入，并提示先维护物料档案。已加入物料若标准单价失效，立即标记并阻止提交。

#### 费用维护

- 自定义费用作用于整个 SPU，不按颜色重复。
- 自定义费用以印尼盾维护，例如车位费。
- 物料标准单价使用人民币。
- 汇率由系统配置统一维护，页面只展示最新汇率。
- 同时展示物料成本人民币、自定义费用印尼盾、综合成本人民币和综合成本印尼盾。

#### 确认

- “确认 BOM 与价格”一次确认全部颜色物料和整款费用。
- 若任一颜色无完整物料决定、任一物料单价失效或费用未明确，阻止确认并逐项指出。
- 确认后进入“待跟单安排”。

### 7.2 步骤二：工作安排

**当前团队：跟单。**

跟单：

1. 查看系统建议的专业工作。
2. 勾选本次需要执行的条件工作。
3. 对销售展示样衣逐行下达“颜色、尺码、要求数量”。
4. 确认本次工作安排。

固定工作和前置依赖由系统带出；若选择后置任务，系统自动补齐必要前置。用户不能改变依赖。

确认后一次生成专业任务，进入“专业工作中”。

### 7.3 步骤三：专业工作

**当前团队：根据任务类型动态确定。**

列表显示：

- 当前团队；
- 当前动作；
- 需要先完成；
- 完成后去向；
- 状态；
- 进入任务。

“进入任务”打开真实任务详情，与左侧专业任务列表中的同一任务一致。

#### 制版任务

- 团队：版师或毛织团队。
- 成果：真实 PRJ 等纸样文件、版本和适用部位／尺码。
- 基码完成后才能开始依赖它的样衣或齐码任务。
- 齐码提交即完成，在技术包审核中统一审核。

#### 销售展示样衣任务

- 团队：制作团队。
- 输入：跟单下达的颜色、尺码、要求数量。
- 每条要求必须提交足量真实样衣图片。
- 提交完成即任务完成。

#### 花型任务

- 团队：花型团队。
- 成果：源文件和预览图。
- 买手审核整张任务。
- 未通过时逐项标记未通过成果和原因，已通过成果保持通过。

#### 调色任务

- 第一阶段读取 BOM 中“需要染色”的物料。
- 跟单维护潘通色号、颜色名称等调色要求。
- 染厂提交实际调色成果。
- 买手最终审核；未通过返回染厂重新调色。

### 7.4 步骤四：整单确认

**当前团队：跟单。**

仅在全部专业任务完成时开放。确认后：

- 父单状态为已完成；
- 所有资料和成果可回看；
- 工程主单可以发现并选择可复用成果；
- 设计改款本身仍不能生成正式技术包。

### 状态展示原则

- 用户看到业务步骤，不显示内部英文状态码。
- 状态推进成功后页面立即读取最新事实并切到最新步骤。
- 重复点击同一完成动作不重复生成任务、BOM 或日志。
- 前置未满足时按钮不可执行，并明确等待对象。

## 10. 工程主单

### 10.1 新建门禁

- 款式已建档。
- 存在满足做大货条件的业务事实。
- 同一 SPU 没有未关闭工程主单。
- 跟单明确建单原因。

### 10.2 第一步：任务方案确认

系统按专业任务类型列出：

- 固定必做任务；
- 根据生产准备类型建议的条件任务；
- 已确认设计改款成果。

对前期成果，跟单逐项选择“复用”“重新执行”或“不采用”。多个有效成果默认推荐最近确认的一份，但可改选其他历史有效版本。

### 10.3 工程任务

- 固定依赖不可调整。
- 工程主单的销售前成果不能替代产前成果。
- 产前版样衣也必须按颜色、尺码和要求数量下达。
- 工程任务开始、提交和完成时间同步到生产准备时效。
- 返工在原任务内新增轮次。

### 10.4 关闭

必须满足：

- 工程任务达到关闭要求；
- 技术包审核通过并发布生效；
- 系统关闭校验通过。

由跟单人工关闭。关闭后只读。本期不提供关闭后继续修订同一 SPU 的入口。

## 11. 技术包

### 11.1 创建

技术包草稿只能从工程主单的“技术包确认任务”创建。系统校验：

- 来源工程主单存在；
- 来源任务属于该主单；
- 来源任务类型正确；
- 技术包款式与主单款式一致。

任何设计改款、专业任务或独立新增入口都不能新建新业务技术包。

### 11.2 内容

技术包包含工程 BOM 与价格、纸样、花型、调色、样衣、工艺、尺码、设计、附件和质量资料。BOM 是技术包内容的一部分，不独立形成第二份正式版本。

### 11.3 审核与发布

- 继续使用当前技术包审核流程。
- 审核退回后修正原主单相关资料或任务。
- 审核通过并发布时冻结正式 BOM 与价格快照和其他技术资料。
- 已发布版本供 FCS 读取。
- 复用的设计改款成果只用于追溯，不成为技术包来源。

## 12. 生产准备时效

### 12.1 数据来源

仅来源于：

- 工程主单；
- 工程主单生成的专业任务；
- 工程主单技术包状态。

不读取设计改款任务，也不读取任何已删除对象。

### 12.2 页面行为

- 只读展示。
- 不提供创建、补录、开始、完成或改依赖。
- 可返回工程主单详情或相应工程任务详情。
- 一张主单只出现一条时效记录。

## 13. 项目、关系与归档

- 项目关系统一登记“设计改款任务”，不再登记旧改版任务。
- 归档统一收集设计稿、目标颜色、BOM、样衣和专业成果。
- 项目关闭不再要求旧改版记录。
- 正式技术包继续保留所复用设计改款成果的追溯标识。
- 旧任务、旧关系和旧归档不迁移、不兼容、不显示提示。

## 14. 删除要求

必须同时删除：

- 工程变更菜单、路由、页面、操作和存储；
- 工程变更创建专业任务、生成下一版技术包和作为 BOM 来源的逻辑；
- 独立“设计打样”“改款打样”菜单、路由、类型和统计；
- 旧改版任务类型、仓储、辅助资料和归档；
- 旧路由重定向；
- 旧 Mock、测试和现行文档中的现行业务描述。

历史文档可以保留原结论，但必须标注为历史且不能被当前交付检查读取。

## 15. 核心验收场景

### 15.1 正常场景

| 编号 | 场景 | 预期 |
|---|---|---|
| N-01 | A 两色、B 一色，有参考色 | B 建立一色，复制最近已确认 A 色物料方案 |
| N-02 | A 一色、B 三色，其中一色无参考 | 三个独立 BOM；无参考色为空白 |
| N-03 | 买手替换物料并新增车位费 | 物料和费用一次确认，综合成本双币种展示 |
| N-04 | 跟单下达两色三尺码不同数量 | 样衣任务生成六条要求，逐条校验交付数量 |
| N-05 | 花型三项成果一项不通过 | 两项保留通过，一项带原因返工 |
| N-06 | 设计改款完成后创建工程主单 | 主单可选复用／重做／不采用 |
| N-07 | 工程任务完成并发布技术包 | 正式快照生成，FCS 可读取 |
| N-08 | 工程任务推进 | 生产准备时效同步；设计改款推进不新增记录 |

### 15.2 阻断与边界场景

| 编号 | 场景 | 预期 |
|---|---|---|
| B-01 | A 或 B 未建档 | 阻止创建并指出缺失档案 |
| B-02 | A 与 B 相同 | 阻止创建 |
| B-03 | 设计稿为空、非图片或不是当前跟单上传 | 阻止创建 |
| B-04 | 工作安排确认后替换设计稿 | 阻止并说明已锁定 |
| B-05 | 物料无有效标准单价 | 不能加入 BOM |
| B-06 | 只确认物料、费用未决定 | 不能完成 BOM 与价格确认 |
| B-07 | 样衣要求缺颜色、尺码或数量 | 不能确认工作安排 |
| B-08 | 前置未完成却开始后置任务 | 阻止并显示等待任务 |
| B-09 | 设计改款直接新建技术包 | 阻止 |
| B-10 | 同一 SPU 已有未关闭主单 | 阻止重复建单 |
| B-11 | 已关闭主单尝试修改 | 阻止，只读 |
| B-12 | 访问旧双路由或已删除入口 | 无匹配页面，不重定向 |

## 17. 可用性与真实素材

- 本地按钮 200ms 内出现反馈。
- 上传立即显示读取中、成功或失败。
- 页面不因输入、筛选或弹窗整页闪烁。
- 款式、物料、设计稿和样衣均使用对象对应真实图片。
- 缩略图可打开大图，失败态可见。
- 管理列表按 1366×768 验收，最低 1280×720。
- 大量数据分页，不在启动时构造全量页面索引。

## 18. 交付标准

- 总体设计、实施计划、81 条矩阵、PRD 和测试方案一致。
- 81 条需求有当前版本实现、自动化和适用页面证据。
- 两轮核验均通过。
- 没有与新口径冲突的入口、文案、Mock 或检查。
- 任何被发现的遗漏修复后，两轮证据全部重新生成。
