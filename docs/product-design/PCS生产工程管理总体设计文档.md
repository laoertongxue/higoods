# PCS 生产工程管理总体设计文档

## 0. 文档信息

| 项目 | 内容 |
|---|---|
| 文档性质 | 当前生产工程管理权威总体设计 |
| 适用范围 | 设计改款、工程主单、BOM 与价格、专业任务、技术包、生产准备时效 |
| 不再适用 | 独立“设计打样”“改款打样”双流程；工程变更；旧改版任务第二事实源 |
| 当前版本 | 2026-08-27 |
| 业务确认 | 设计与改款合并；设计稿由跟单上传；不保留分类统计；生产准备时效只读工程主单 |

本文件取代此前把“设计打样”“改款打样”和“工程变更”作为现行业务能力的设计。历史文档仅用于追溯，不得作为当前研发或验收依据。

## 1. 背景与目标

### 1.1 业务背景

做大货之前，业务会基于一款已建档商品形成另一款已建档商品，并通过设计稿、目标颜色、用料、成本、纸样、花型、调色和销售展示样衣把新款做出来。此前原型把相同业务拆成“设计打样”和“改款打样”，又在工程主单关闭后建立一套“工程变更”执行线，造成对象重复、入口重复、任务来源难以理解、技术包来源不唯一。

### 1.2 目标

1. 统一为一张“设计改款任务”，不再要求业务判断属于设计还是改款。
2. 让买手、跟单和专业团队按照固定先后顺序协作，每一步明确当前团队、当前动作和完成后去向。
3. 让目标款形成自己的颜色、BOM 与价格、专业成果和销售展示样衣。
4. 让工程主单成为做大货前工程执行的唯一主线。
5. 让正式技术包只有工程主单一个生成来源。
6. 让生产准备时效只读取工程主单及其专业任务的真实时间。
7. 完整删除工程变更和旧改版任务第二事实源。

### 1.3 非目标

- 不处理旧任务迁移、兼容读取或历史数据提示。
- 不支持同一 SPU 的工程主单关闭后继续修改正式技术包。
- 不新增审批流、取消流程或可调依赖关系。
- 不把销售展示样衣等同于产前版样衣。
- 不实现真实后端、鉴权、离线队列或自动重试基础设施。

## 2. 业务对象与关系

| 对象 | 业务含义 | 必要来源 | 主要产出 |
|---|---|---|---|
| 参照款 A | 已建档、供新款参考的款式 | 商品／款式档案 | 参考颜色、最近已确认物料方案、历史专业成果 |
| 目标款 B | 本次要做成的已建档款式 | 商品／款式档案 | 目标颜色、BOM 与价格、专业成果 |

| BOM 与价格草稿 | B 款各颜色用料与整款费用 | 买手维护 | 已确认物料方案和综合成本 |

## 3. 角色与协作

| 团队 | 当前范围内的职责 |
|---|---|
| 跟单 | 创建任务；上传或在锁定前替换设计稿；确认工作安排；下达销售展示样衣颜色、尺码、数量；确认工程主单任务方案；整单确认；人工关闭工程主单 |
| 买手 | 维护目标颜色与参考色；维护并统一确认物料与整款费用；审核花型和调色成果 |
| 版师／毛织团队 | 制作并提交基码、齐码等纸样真实文件 |
| 花型团队 | 制作花型并提交源文件和预览图 |
| 染厂 | 根据已下达色号、颜色名称等要求提交调色成果 |
| 制作团队 | 按颜色、尺码和数量制作并提交销售展示样衣或产前版样衣 |
| 技术包审核角色 | 继续执行当前技术包审核流程，不在任务详情重复审核齐码纸样 |

系统先显示“当前需处理的团队”；具体操作人在该节点真正开始、提交、审核或确认时记录。列表只提供“当前需处理的团队”筛选，不制造每个团队专属状态。

## 4. 设计改款业务流程

~~~mermaid
flowchart LR
  C[跟单选择 A、B，填写要求并上传设计稿] --> B[买手定义 B 款颜色和参考色]
  B --> P[买手维护各色物料与整款费用]
  P --> BC[买手统一确认 BOM 与价格]
  BC --> M[跟单确认工作安排]
  M --> T[专业团队按固定依赖执行]
  T --> R{需买手审核的成果?}
  R -->|花型／调色| BR[买手整张任务审核，未通过项逐项说明]
  BR -->|退回| T
  R -->|其他任务| D[制作团队提交即完成]
  BR -->|通过| F[专业工作全部完成]
  D --> F
  F --> CFM[跟单整单确认]
  CFM --> DONE[设计改款完成，可供工程主单复用]
~~~

### 4.1 创建门禁

- A、B 都必须已建档。
- A 与 B 不能是同一个 SPU。
- 必须填写设计改款要求。
- 必须选择真实图片文件作为设计稿。
- 设计稿必须由当前跟单上传。
- 测款结论、样衣返工或其他业务事件不得静默自动创建设计改款任务。

### 4.2 第一步：新款资料准备

1. 买手可以新增、删除和调整 B 款颜色，数量不受 A 款限制。
2. 每个 B 款颜色可选择一个 A 款参考色，也可选择“无参考色”。
3. 有参考色时，系统取 A 款该颜色最近一份“已完成且已确认”的物料方案作为初始草稿。
4. 无参考色时，从空白 BOM 与价格草稿开始。
5. 买手可以新增、删除、替换初始物料，维护单位用量、打样数量、损耗、印花、染色、采购要求和适用 SKU。
6. 标准单价只从物料档案读取；无有效标准单价的物料不能加入。
7. 自定义费用统一作用于整个 SPU，以印尼盾维护。
8. 页面同时展示物料成本人民币、自定义费用印尼盾、系统最新汇率、综合成本人民币与印尼盾。
9. 物料和费用作为一份整款方案一次确认，不能出现“物料已确认但费用未决定”。
10. 买手完成后，任务进入“待跟单安排”。

### 4.3 第二步：工作安排

- 跟单从系统建议中选择本次需要的专业任务。
- 依赖关系由系统固定，选择后自动补齐前置任务，不允许人工调整。
- 销售展示样衣要求按“颜色 + 尺码 + 要求数量”逐行下达。
- 确认后一次生成真实专业任务，进入“专业工作中”。
- 确认后设计稿、颜色和 BOM 输入锁定；后续返工在相应任务轮次内完成。

### 4.4 第三步：专业工作

- 每张真实任务独立存在并进入对应专业任务列表。
- 父单“进入任务”和专业列表“查看详情”打开同一任务详情、同一任务 ID、同一状态事实。
- 任务开始、提交、审核、返工和完成均在规范任务详情页操作。
- 所有成果上传均读取真实本地文件；图片、PRJ、AI、PDF 等按任务要求校验。
- 花型和调色整张任务由买手审核；未通过时逐项标记未通过成果及原因。
- 基码、齐码和样衣等无额外任务内审核要求的工作，制作团队提交即完成；齐码成果进入技术包后随技术包审核。

### 4.5 第四步：整单确认

专业任务全部完成后，由跟单确认任务结果。完成后保留 A/B 款关系、设计稿版本、目标颜色与参考色、已确认 BOM 与价格、专业任务各轮成果、销售展示样衣要求与图片，以及操作人和时间。

## 5. 状态设计

### 5.1 设计改款父单状态

~~~mermaid
stateDiagram-v2
  [*] --> 新款资料准备中
  新款资料准备中 --> 待跟单安排: 买手统一确认 BOM 与价格
  待跟单安排 --> 专业工作中: 跟单确认工作安排
  专业工作中 --> 待整单确认: 全部专业任务完成
  待整单确认 --> 已完成: 跟单整单确认
~~~

页面以四个业务步骤展示，不把“草稿”作为用户创建成功后的主状态。存储层可保留内部状态，但用户看到的是当前业务步骤和当前需处理的团队。

### 5.2 专业任务状态

~~~mermaid
stateDiagram-v2
  [*] --> 待前置
  待前置 --> 待开始: 前置任务完成
  待开始 --> 进行中: 当前团队开始
  进行中 --> 待审核: 花型或调色提交
  待审核 --> 已完成: 买手全部通过
  待审核 --> 返工中: 存在未通过成果
  返工中 --> 待审核: 重新提交
  进行中 --> 已完成: 无任务内审核的成果提交
~~~

已开始任务不可取消；已提交成果不能删除历史轮次。未开始且业务上不再需要的条件任务使用通用“因需求变更结束”状态，页面文案为“因本次需求调整结束”。

## 6. 工程主单

### 6.1 创建与唯一性

- 仅为满足做大货条件的已建档 B 款创建。
- 同一 SPU 同时只允许一张未关闭工程主单。
- 新建后第一步必须由跟单确认工程任务方案。

### 6.2 复用设计改款成果

系统按专业任务类型展示已完成且整单确认的设计改款成果。跟单逐项选择：

- 复用：把选中成果作为工程主单输入，不重复生成该工作；
- 重新执行：创建工程专业任务；
- 不采用：不把该成果带入本主单。

销售展示样衣不能替代工程主单的产前版样衣。工程主单的产前版样衣仍按颜色、尺码、要求数量单独下达和交付。

### 6.3 主单内修改与关闭

- 主单关闭前，补任务、返工、BOM 修正和技术包退回都在原主单内完成。
- 技术包发布生效且关闭门禁通过后，由跟单人工关闭。
- 关闭后主单和正式技术包只读。
- 若关闭后需要形成不同款式结果，必须建立新目标 SPU，重新走设计改款与新工程主单；本期不提供同一 SPU 继续修订能力。

## 7. 技术包

1. 新业务技术包只能由工程主单中的“技术包确认任务”创建。
2. 设计改款、制版、花型、样衣或手工入口不得直接新建技术包。
3. 技术包草稿汇总工程 BOM、纸样、花型、调色、样衣、工艺、尺码、设计和附件。
4. 技术包继续使用现行审核流程。
5. 审核通过并发布时，形成正式 BOM 与价格快照以及完整技术资料版本。
6. 已发布版本继续供 FCS 生产单和生产技术包快照读取。
7. 技术包可以记录所复用的设计改款成果用于追溯，但这不改变工程主单是唯一生成来源。
8. 不设置技术包模板库，也不提供导入历史技术包功能。

## 8. 生产准备时效

- 数据只来自工程主单及其专业任务。
- 一张工程主单只形成一条时效记录。
- 任务开始、提交、完成时间由工程任务动作同步投影。
- 设计改款任务不进入时效。
- 页面只读，不允许创建、补录、开始、完成或改依赖。
- 时效页可以返回工程主单或相应工程专业任务。

## 9. 页面与信息架构

### 9.1 保留的生产工程入口

工程主单、设计改款任务、制版任务、花型任务、调色任务、辅料下单任务、技术包确认任务、销售展示样衣任务、产前版样衣任务。

### 9.2 设计改款列表

- 唯一路径：/pcs/engineering/design-revision。
- 展示任务号、A 款 → B 款、当前步骤、当前需处理的团队、专业任务进度、BOM 与价格、跟单、更新时间和操作。
- 只保留“当前需处理的团队”筛选。
- 列设置位于数据列表表头最右侧。
- 款式图片与款号／名称同块展示，支持大图、遮罩、关闭按钮和 Esc。
- 使用分页，不一次构造全量页面内容。

### 9.3 设计改款详情

- 顶部展示任务、A/B 款、设计稿和当前团队。
- 四步页签依次为“新款资料准备 → 工作安排 → 专业工作 → 整单确认”。
- 当前步骤可操作，后续步骤显示等待原因，已完成步骤可回看。
- 不展示内部英文状态码、旧对象名或系统实现术语。

## 10. 删除边界

当前版本不存在：

- 工程变更菜单、路由、页面、处理器、领域对象、工作区、存储键、Mock 和任务投影；
- 工程变更作为 BOM 所有者、技术包来源或专业任务来源；
- 旧改版任务仓储、辅助类型、项目关系和归档分组；
- 独立设计打样／改款打样菜单、路由、类型、筛选和统计；
- 旧路由重定向、兼容读取或数据迁移；
- 测款未通过或样衣返工自动创建旧改版任务。

“因需求变更结束”是通用任务结束原因，不代表已删除模块。

## 11. 权限与门禁

| 动作 | 允许团队 | 主要门禁 |
|---|---|---|
| 创建设计改款 | 跟单 | A/B 已建档且不同；有要求和真实设计稿 |
| 替换设计稿 | 跟单 | 工作安排尚未确认 |
| 维护颜色／BOM／费用 | 买手 | 当前处于新款资料准备 |
| 确认 BOM 与价格 | 买手 | 所有颜色物料完整；费用已明确 |
| 确认工作安排 | 跟单 | 买手资料准备完成；样衣要求完整 |
| 执行专业任务 | 当前专业团队 | 前置完成；真实文件满足任务要求 |
| 审核花型／调色 | 买手 | 每项成果均有通过／不通过决定 |
| 整单确认 | 跟单 | 全部专业任务完成 |
| 创建技术包草稿 | 跟单 | 来源为工程主单技术包确认任务 |
| 关闭工程主单 | 跟单 | 正式技术包已发布且关闭校验通过 |

## 12. Mock 与演示数据

演示数据至少覆盖：目标颜色少于、等于、多于 A；有参考色和无参考色；参照款有多份已确认物料方案并选最近版本；物料新增、删除、替换和自定义费用；纸样、花型、调色、销售展示样衣多专业任务；花型／调色通过和逐项退回；工程主单复用、重做、不采用；两张工程主单生成两份正式技术包；设计改款推进不产生生产准备时效记录。

所有款式、物料和成果使用与对象对应的真实图片或真实文件，不以色块、图标或占位图冒充。

## 13. 验收总则

1. 业务人员从一个入口完成设计改款，不再判断设计或改款。
2. 每张任务均能追溯 A、B、真实设计稿、颜色、BOM、费用、样衣要求和专业成果。
3. 每一步只由当前团队处理，完成后自动交给下一团队。
4. 专业任务从父单和专业列表进入同一详情。
5. 工程主单可复用设计改款成果，但仍独立产生工程任务和产前版样衣。
6. 技术包只有工程主单来源并继续正常审核、发布和被 FCS 读取。
7. 生产准备时效只读工程主单及其任务。
8. 被删除入口、对象、文件和旧文案没有可见或可执行残留。
9. 原子需求矩阵 81 条全部有实现与验证证据。
10. 两轮正反向核验均在最后一次实质修改后通过。
