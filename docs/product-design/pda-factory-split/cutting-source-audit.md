# C01 裁床中央 PDA 源码核查与实施边界

## 范围、继承和当前阶段

继承中央/三方 PDA 拆分目标：中央独立新写，V34只作交互基线，冲突时遵循当前业务；无接单、竞价、商业开工、入驻或身份提示。承接C05冻结，不改标其历史证据。当前HEAD fc3283f6286e943e66d2b0c7f91cab88571b85ae、codex/pda-factory-split。本节是实施前的源码与原Web只读基线核查，尚未新增裁床中央页面、命令或迁移；表中计划不能当作已实现。

当前只审查本地源与隔离浏览器，没有连接测试站数据库、没有更改用户浏览器。原Web两仓在1280×720可打开、页面错误0，但仅证明当前原型展示，不证明库存、收发或工厂现场接受。

## 已确认对象与业务差异

1. 待加工仓是面料与铺布用料：原Web明确三个动作“中转仓接收、加工接收、回收入仓”。中转仓接收为入，关联配料记录/单/行及实际位置；加工接收为出，关联铺布单、当前来源入仓事件及接收会话；回收为入，保留原铺布单和剩料、取消加工等原原因。三者的来源、数量意义和责任不同，不能合成通用上架/领用/退回。
2. 原Web的submitWaitProcessWarehouseAction要求数量大于0；入仓/回收重核真实WAIT_PROCESS库位，传warehouseLocations及storageFootprint。加工接收从当前物位匹配物料SKU和生产单，必须有sourceInboundEventIds，可能有唯一pickupSessionId。缺关联不能用物料总余额猜一次实际出库。
3. Web上述命令当前写yard，但库存汇总已有米；材料账也有各自unit。新端必须先追明事件、物理卷及汇总间已有换算，不把yard字符串、Yard、米或卷数混作同一数量。原Web按总量估算rollCount且rollNos为空，也不能据此生成虚构原卷条码。
4. 待交出仓以实际菲票、部位片和当前中转袋使用周期为核心。现有动作不止“裁片交出/袋交出”：还有菲票装袋、中转袋入仓、菲票编号、特殊工艺回仓、空袋回收/报废、按当前交接任务的拆袋重装。逐项来源见wait-handover-runtime与transfer-bag-operations；不能只迁移截图中可见的两个按钮。
5. 中转袋入仓：必须已装袋且当前PACKED，至少一个当前空闲WAIT_HANDOVER库位，提交前重核布局与选择，保存当前usageCycleId，不能重复入仓。整袋交出：必须INBOUND_STORED，袋内菲票没有已交事实，当前周期与完整袋内快照存在，每票都有当前车缝任务和接收工厂。保留原拆重装、混袋、回仓及分批事实，不新增“齐套才能交”的自设门禁。
6. submitWholeBagHandover的同一正式事件包含现有自动车缝接收事实；hydrateCuttingEventRecords按这些事实推导后续任务。此处与洗水独立下游点收不同，必须按裁床原契约确认真实业务责任，不能照搬洗水“全部等待对方点收”或反向把所有交出都自动实收。简易裁片交出的RECEIVED事实同样需专项核对。
7. 正式执行源通过任务/生产单/裁片单/铺布会话关联，getSourceExecutionsByTaskId对一个铺布会话只关联一个裁片单的情况投影执行行，明确不猜合床用料归属。新端不能从global首单、演示任务或URL前缀猜当前工厂及单据；商业接单/开工与实际开始铺布/裁剪应分别核查。
8. fabric-warehouse-model的buildRolls会由聚合数平均拆出估算卷数、长度和RB码。这是既有展示投影，不能作为新PDA实际扫码或收发的原卷事实源。现有真实卷/配料来源、材料账和位置占用须在接入前追到唯一来源。

## 现有保存边界及已见问题

已有higood-cutting-records-v1，records/commands/meta/files，共同提交带revision、稳定command id/intent、source guard和事务complete。runCuttingEventAction在原同步域准备变更，再共同保存裁后事件、相关菲票/放行及来源初始化，提交后回读；新端应沿用此基座，不另建裁床快照或业务localStorage。

当前MANAGED_CUTTING_EVENT_TYPES包括铺布/裁剪及裁后交出等，**不包括**中转仓接收、待加工仓加工接收和回收入仓。原Web三动作直接appendCuttingRuntimeEvent，不能直接宣称已经同库共同保存。接入须先确认它们当前旧账及直接读取入口，限定迁移到本动作必要事实；不能只在新端改成IndexedDB而让Web继续写另一事实源。

原两仓只读浏览器基线：wait-process首次读出现一笔higood:cutting-warehouse-layout:v3:FACTORY-ONBOARD-0035:WAIT_PROCESS:FIW-FACTORY-ONBOARD-0035-WAIT_PROCESS，4571字节；无IDB put。另有higood-tabs偏好。wait-handover该次只见tabs偏好。源码loadWarehouseLayoutSnapshot会在读时移除旧布局/历史key、重写有效v3、缺省时写初始布局；布局包括实际库区/货架/库位，并非普通筛选偏好。新端需要实际物位，因此该读取/编辑与旧配置保护属于直接边界：先列明旧配置版本与消费者、实现不写业务的普通读取、显式迁移/回读后退出旧写入。不得因当前页面可打开就默许清理用户旧布局。

基线证据：output/playwright/pda-factory-split/c01-cutting-original-web-read-baseline.js/.log，两仓截图同前缀；其passed只表示路由/标题可见且pageerror0，写入事实另列，**不表示STORE合规通过**。已确认库存既有未接收0量、已领用及非零面料；待交出中既有有片却可交0/缺分配的袋内票。源码校验正常PACKED→入仓、INBOUND_STORED且有完整分配→交出的条件和缺位置/重复/缺任务阻断；当前还没有新命令正常/失败回放，不能填为验证完成。
