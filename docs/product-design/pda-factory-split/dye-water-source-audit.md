# C03 前置水溶：同厂连续染色

本阶段承接完整拆分矩阵 C03.45～49。UI/交互继承已发布 V34；业务与当前 Web 冲突时沿当前业务代码。本阶段不替代 C06 独立水溶加工单，也不关闭全部染色材料、旧存储 owner 或完整 PDA 拆分。

## 源码核对与对象边界

| 对象 / 入口 | 当前代码事实 | 新中央 PDA 对应 |
|---|---|---|
| 染色单 `requiresWaterSoluble` | 与染色为同一单、同一厂；`WATER_SOLUBLE` 在六个染色/后处理节点之前；水溶后没有中间交出 | 同单加工区显示当前水溶动作，完成后返回原染色步骤；最终沿原逐卷、打印、扫码、运输交出 |
| `startDyeWaterSolubleNode` | 实收、适用色样、投入确认和排缸完成后才能开始；本批投入是累计实收减历史水溶投入；上批包装完成且有新增实收才可新批 | 直接带入实际投入及原单位，不手填水溶投入，不新增商业接单或开工入口 |
| `completeDyeWaterSolubleNode` | 填本批累计完成；前批产出加本批完成不能回退，且本批不能超过本批投入；累计与原水溶计划不等时必须填写说明；少于计划进入暂停 | 本批数、单位、条件出现的“本批说明 / Catatan lot ini”；使用原规则，不恢复通用数量不符/异常处理面板 |

| `canContinueDyeWaterSoluble` | 上批水溶和包装均结束且有新增实收；已水溶未染的余量仍可先染 | 原染色主动作保持可用，旁边“水溶新增来料”；同页切换，不制造第二单据或用新来料覆盖旧余量 |

相关 Web 为 `work-order-detail.ts` 的“染缸执行”视图及 `events.ts` 的水溶动作；底层事实仍在 `dyeing-task-domain.ts`。普通原型单的 Web 基本信息页没有水溶实际数量，跨端回读必须打开 `?tab=execution`，不能用错误视图的超时推断保存失败。

## 实现与责任

- `dye-water-model.ts` 读取同一原单、当前水溶节点和历史批次，给出阶段、实际投入、累计下限、单位和修订标识。保存使用既有 `runCentralDyeCommand`；原单/节点/共同账仍在原 PCS IndexedDB 的逐记录事务中保存，不新建业务 localStorage、后台服务或自动重试。
- `dye-water-view.ts` 提供中文/印尼语字段、三个下一步、局部数量校验、底部主按钮及历史；页面控制器在 `dye-page.ts`。草稿按实际账号/工厂/原单/批次/阶段隔离，返回和语言切换保留数值，清空与退出统一清理；没有空输入就不算草稿。
- 新 `executeCentralDyeWaterSoluble` 使用现有业务节点函数及真实活跃账号；不修改旧 PDA 的全局会话或角色适配。新中央页面不放岗位选择、管理员提示或权限卡片。
- 开始人和完成人分别保存。共享 `recordDyeWaterOperator` 兼容旧节点已有的 operator 信息，避免另一端完成时覆盖原开始人；旧 Web 水溶动作也使用这个具名记录入口。`resolveDyeWaterSolublePause` 在改状态前保存当前完成节点快照、数量及实际决定人，Web 与新 PDA 的决定各只记录一次。
- 已提交但回读失败时只显示一个“重新读取”主动作，锁定原输入及清空/切换动作，用原操作号取回结果；没有第二次业务提交。错误提示进入内容区可见范围；同一控制器的其他产出保存错误沿用该可见性处理。
