# C09 织带与花边当前源审查及实施边界

2026-10-22，codex/pda-factory-split，6f477 + 未提交任务差异。继承总需求/计划/矩阵；本文件为当前源核查及下一阶段实施前范围，不是已实现或最终验收。旧 V34 外观沿用，业务冲突遵守当前 Web。盘扣/花朵仅显示归类调整，原身份、来源票与单位不变。

## 织带

原事实源 `src/data/pms/tmf-material-purchases.ts`，原单投影 `tmf-work-order-view.ts`，原 Web `accessory/webbing/work-order-detail.ts`。旧 `pda-execution.ts` 的演示员工和页面体系不作为新中央页依赖。

- 投入逐原发料批次、SKU、需求与路线。辅料仓直接来料按米确认；染色/印花回料必须接原交出，不可另增本地实收。米料只有已实际接收且未消耗/未退余额可加工。
- 截断条数、实际截断长度 mm 均为正整数。消耗米数＝本次条/根数×实际截断毫米数÷1000，另计损耗米数，原批余额约束不变；不把毫米或重量当米。
- 无需打头须报实际成品 mm；需要打头时截断不允许填写预计成品长度冒充实际成品。尺寸超公差整批不良；不良/损耗/超需求保留原原因校验。
- 打头引用具体截断批次，分端要求与原辅材领用、实用/损耗，不能跨批借数。合格打头批次方可按本实际规格装包。
- 装包数量正整数，不超该截断/打头批次未装包合格数；原包/子包身份不能混用。交出整个有效包，目的仓必须是原来源辅料仓，已交/已回仓不可再交；发方不登记收方实收。
- 连续余料退回与辅材退回分别保留米、个/kg/g及原领用来源。半成品生产另有基础原料重量账，不混入截断米账。上述分支须逐一接入，不以一个通用数量框代表全部完成。

当前存储缺口已确认：原模块四个 singleton section 仍整包保存，普通同步 commit 会先更新内存、后台存盘且失败写 localStorage；染色/印花接续另有直接原域写。不能直接把旧同步方法接到新PDA并显示成功。实施先登记逐记录及同事务边界、停止相关旧写、显式旧源处理，再接新中央页和直接 Web/收方/打印读取。现有采购不相关动作不擅改业务功能；读写共同事实变更按直接消费者纳入。

## 花边

原事实源 `lace-factory-domain.ts` 与 `lace-factory-purchase-projection.ts`；原四动作可用性 `accessory/lace/work-order-action-policy.ts`，Web明细 `work-order-detail.ts`，独立收方 `wls-accessory-receipts.ts`。

- 从原采购需求/SKU/版本生成原花边单。接收是确认生产任务及默认投入完整，不是输入实物米数或虚构领料；缺投入 SKU、单位、用量时原规则阻断。
- 加工填报按原单单位（如米、Yard），正数、两位小数累计；不统一换成米。累计达到计划1.5倍沿用原二次确认，不能以旧“删除超计划解释”要求取消当前有效 Web 校验。
- 加工中且有实际产出可完工；已完工仍能交出剩余有效产出，与旧V34全部只读冲突时以当前Web为准。
- 交出不超累计加工减累计已交；送货单号、正整数包数和预计接收方为原必需项。固定目标仓取原单，不手选无关去向。预计接收方不是实际接收人，禁止发方代实收。
- 收方由中央辅料仓独立确认原交出；最终实收包括原单位、实际人/时间/库区；差异/多收主管及证据沿用原Web规则。PDA发方只读本笔/整单实收，不伪造收方。
- 默认投入、真实物料和款式图按原单只读展示；修改投入/撤销完工/取消恢复/采购变更是原Web管理动作，不为中央执行增加管理入口。

当前花边原域仅内存，含原单/填报/交出/收货/日志与原采购投影。实施需逐实体保存静态覆盖及新记录，原单+相关记录+操作号同事务；原Web、WLS、采购及打印直接冷读共同接管。不得只给中央新页建立第二套可写事实。原种子只读，正常读取不存整包。

## 顺序、负责文件与验收

先花边独立逐记录封装及原消费者（原纯域业务方法不改规则），再花边中央接收/执行/仓管；织带先完善原批次/包模型和存储边界再接页面，不能顺序双写染色/印花与织带冒充原子。新页面复用中央独立frame/session，不依赖旧PDA页面。所有成功等待事务complete，失败保留原输入；版本冲突重新读取；实际UID/工厂与姓名核对，换人清未保存表单。

完成条件：原正常/边界契约、故障/同单并发/不同单不串、Web和收方独立冷读、原图、320×480中印及硬键输入/返回/换人、适用家族五样本及源码资产绑定。当前仅源审查，不预填已验证。

### 存储边界现状

`tmf-material-purchases.ts` 原先按四个 singleton section 整包写入 PMS IndexedDB。本轮改为：新增 `pmsTmfRecords` 逐记录行（`recordKey = group/encodeURIComponent(key)`），保存本次动作改变的记录、删除标记和稳定操作号；四个旧 section 保留为**只读基线**，正常读取不迁移、不重写。保存事务同时：

- 读取旧 section 指纹，若旧版本页面在本标签页读取后改过快照，拒绝本次保存并提示刷新；
- 对已有覆盖行核对当前数据与读取时一致，新行核对未被其他页面创建，冲突即整笔拒绝；
- 同一操作号已有相同内容时直接返回，不重复执行业务变更；
- 等 PMS 事务 `complete` 后才发布内存状态；等待型接收在失败时保留原单与原输入。

旧 `localStorage` 迁移改为写逐记录行，失败保留旧键。新增 `pmsTmfRecords` 使 PMS 数据库版本从 3 升到 4，旧 4 个 store 与数据保留。

### C09.05～07 织带执行动作（2026-10-22，局部）

中央织带页新增执行动作；全部沿原 TMF 命令并等待逐记录事务完成：

- 截断：按已收投入填写本次条数、实际下料 mm、非打头实际成品 mm、不良、损耗、原因；原命令校验正整数、公差整批不良、损耗/超需求说明、原批余额；不出现打头规格的成品长度输入。

- 连续余料退回：按实际剩余连续料填米数和原因；生成退料单/回仓批次，原命令校验已截断/损耗不可退回且不超实收余额。
