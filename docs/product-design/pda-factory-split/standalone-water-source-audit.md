| 环节 | 现行规则 | 新 PDA 必须保留的区别 |
|---|---|---|
| 接收 | `receiveWaterSolubleInput` 旧函数始终拒绝，要求去染厂待接收核对原单/实收/库位；真实实收来自共同 receiving 账 | 接收 Tab 使用真实来源行与该工序必要入库物位；不再调用旧捷径，也不套辅助/特种自动隐藏库位的规则 |
| 实际投入 | `startWaterSoluble` 读取累计实收减原 inputQty；有新来料才记录实际用料；补做已有投入不重复扣用 | 带入待投入量与米；“投入本批来料”是实际执行动作，不增加商业接单/竞价/开工 |
| 完成 | `completeWaterSoluble` 填全单累计完成，不能少于已有完成，不能超过实际投入；0 或超计划必须说明 | 与 C03 的本批累计不同，字段明确累计；不把前置水溶“计划不相等都必填”复制到独立单 |
| 正数部分完成 | 0<完成<计划、无说明可以直接 WAIT_HANDOVER；有不足说明才 PRODUCTION_PAUSED | 必须既覆盖可直接分批交出，也覆盖真实暂停；不强制所有部分完成都暂停 |
| 暂停决定 | 补做保留 completedQty；按实际继续需正完成数；返工完成数归0并清 handoverQty/说明 | 使用原决定及后果，实际具名账号；不新增通用异常原因卡或岗位权限提示；旧关联交出/卷占用的边界必须先核对，不能靠清历史伪装可返工 |
| 维护卷 | 同原单自动编号/条码；卷长2位，最小0.01；已交/草稿占用不能改；改数量撤销打印；未交卷合计不超实际可交 | 保留原米数，不增加不适用的重量/缸号手填；真实卷和对应图必须能识别 |
| 标签 | 维护真实卷后才可标记打印；当前 Web 有真实 Code128 标签及对象图 | 新 PDA 沿同一真实条码和打印结果责任；预览、取消与已打印事实分开，不承诺物理打印验收 |
| 草稿合单 | 支持同厂多原单合入一个草稿，保留各行原单、SKU、单位和唯一接收方；占用和可用量分别校验 | 不用当前一单的下游概括全部行，扫码后不会把其他单的实物归到当前单 |
| 正式交出 | 每卷必须实际扫码；司机/车型/车牌必填；确认时再核原单状态、工厂、接收方、数量、未交/打印；生成正式交接记录 | 执行 Tab 同单完成卷维护与交出；具名创建、扫码、发出人分别保留；不冒用旧全局登录会话 |
| 对方实收 | 按原交接批次写独立累计实收；发方交出不等于收方接收 | 本批与整单分别查看数量和实际收方/时间；保留来源及交出单关联，不造代确认 |
| 完单 | 仅 WAIT_MANUAL_COMPLETION；不能有未收或未确认差异的批次，也不能有已完成但未交数量；当前允许已确认差异的批次完成 | 不照搬普通染色“每批必须绝对等量”的完单条件；必须先按实际代码确认剩余量与批次闭合，DONE 后只读 |

当前 Web 中的角色限制、宽表筛选、说明卡等展示不迁入新中央 UI。中央独立新页面使用真实活跃账号及工厂；原 Web/旧 PDA 的会话和角色接口保留原语义，不能通过假登录或改账号身份调用。
