## 当前 Web 事实源

## 回货确认首版（2026-10-23）

用户确认：现有后道工厂管理员承担后道主管动作；操作工只读。实现按实际登录账号 ID/姓名，不新增角色选择器，不伪造登录身份。

- `post-model.centralPostConfirmer`：仅本厂 ACTIVE 管理员可映射为「后道回货确认人员」；其他账号返回只读。
- 详情页对待后道确认/待二次点数显示逐 SKU 一次点数输入；首次差异率超过 5% 时原命令返回 `SECOND_COUNT_REQUIRED`，页面保留第一次值并显示第二次点数输入；最终确认仍调用原 `confirmPostFinishingFactoryReturn`，经 `runPostFinishingCommand` 同库保存。
- 差异超过容忍率且无动态授权码时，原命令把状态置为「差异待授权」并拒绝最终确认；PDA 只显示阻断提示，不提供假授权或代确认。
- 成功后会生成质检任务和待送检后道实收记录，详情页读取同一事实。

证据：

- `c10-post-confirm-contract`：ID-F002 管理员；正常100/100确认、刷新后保持已确认待送检、后道实收待送检、质检任务可见；一次点数90触发第二次点数，最终确认100；第二次仍90时状态差异待授权，仅阻断提示、无确认按钮。
- `c10-post-confirm-performance`：生产预览48340、5样本；确认保存最大93ms、刷新读取134ms，均≤1000ms。
- `c10-post-confirm-build2.log`：1667单元、Vite构建通过。

未完成：动态授权码核销、QC领取/结果/返工、后道加工/复核、出库与仓库实收写操作、两仓，以及操作工的岗位动作映射；不新增第二套后整保存。


## 差异动态授权（2026-10-23）

- 差异待授权详情增加动态授权码和差异原因输入；授权码必须由授权人提供，PDA 不生成、不展示授权码，也不保存授权人秘密。
- 最终确认把 `authorization: { scanValue, differenceReason }` 交给原 `confirmPostFinishingFactoryReturn`；原模块校验授权人、30秒时段、6位码、一次性使用和差异指纹，失败保持差异待授权并显示原错误。
- 授权确认仍走 `runPostFinishingCommand` 同库保存；成功后状态已确认待送检、后道实收待送检、QC任务生成。

- `c10-post-authorization-performance`：5样本，授权确认最大93ms。
- `c10-post-authorization-build.log`：1667单元、Vite构建通过。

未完成：QC领取/结果/返工、后道加工/复核、出库/仓库实收写操作、两仓；授权码的物理扫描设备和现场时限未验收。

## QC 全部合格完成（2026-10-23）

## QC 不良/返工/差异授权（2026-10-23）

- 质检结果按 SKU 填合格、不良、返工数量；不良必须从系统瑕疵原因中选择，返工必须选择原复检工厂并填原因。
- 合格+不良+返工等于应收时不需授权；不等时显示动态授权码和差异原因，原 `consumeRequiredAuthorization` 校验后完成。
- 完成后原命令生成不良记录/返工事实，并按后道项目生成后道任务或直达出库单。

## 后道加工 → 复检 → 出库 → 仓库实收（2026-10-23，正常全量路径）

- 后道任务按加工项顺序登记：当前页每次登记该加工项全部可用数量，原命令校验前序完成量和当前 SKU 可用量；全部加工项完成后可交复检。
- 交复检生成复检单；复检员按 SKU 扫描条码，全部正确后完成复检，生成出库单和待交出仓记录。
- 仓库收货人员对出库单执行实收，生成仓库实收记录；待交出仓记录转为已交出。
- 两仓：详情同时显示后道实收（待加工仓）和待交出仓记录；状态与数量来自原命令。

证据：

- `c10-post-full-chain-contract`：ID-F002 管理员；001-5 四个加工项登记→交复检→领取→5个SKU扫码→复检完成→出库单待仓库接收→仓库实收；刷新保持“已接收入库”及待交出仓“已交出”；截图 `c10-post-full-chain-320x480.png`。
- `c10-post-full-chain-performance`：加工登记278ms、交复检63ms、领取69ms、复检完成42ms、仓库实收96ms（各5样本）。
- `c10-post-full-chain-build.log`：1667单元、Vite构建通过。

## V34 后整在线设计复核（2026-10-23，T0）

参考：`https://higood.12lab.cn/newpda/index.html?screen=receive-list&v=34&op=后整` 与 `screen=sewing-return`。V34 后整包含：

- 接收列表：车缝送货到厂入口（公共机）、待后道确认回货。
- 车缝回货模式：送货人开启模式，扫 `PFRETURN` 来源码或按任务找；逐 M/L 码填本次送货数量（不超剩余）、送货人、联系方式、至少 1 张现场凭证；提交后待后道点收；可查看本机最近登记、废弃有误登记；退出模式保护未提交填写。
- 点收/差异：后道按原送货单逐码点收，数量一致直接确认；差异需授权。
- 后整加工：逐尺码填已处理，剩余自动计算；已处理+未处理=应处理，未处理须原因；质检与放行在管理端。
- 数量条码复核：逐 SKU 核对数量与包装条码；数量差异需授权，条码错换标重扫。

当前实现已有：待确认列表、逐 SKU 一次/二次点数、差异动态授权、QC 领取/结果/不良/返工/差异授权/完成、后道加工（按加工项全量）、交复检、复检条码扫描/完成、出库、仓库实收、两仓只读记录。

## V34 后整补齐（2026-10-23，本机技术核验）

上节 9 项按当前 Web 业务命令补齐，未新增角色选择器或假入口：

1. **车缝回货公共机模式**：新增 `/fcs/pda/central/post/sewing-return`，接收列表入口进入；开启模式、扫 `PFRETURN` 或按任务选来源、逐尺码显示剩余并登记数量、送货人/电话、至少 1 张现场凭证；提交原 `registerPostFinishingFactoryReturn`，送达后为“待后道确认”，本机最近登记刷新保持；管理员可按原 `discardPostFinishingFactoryReturn` 填原因废弃；未提交退出弹出放弃确认，结束登记回到入口。
2. **后道点收**：保留逐 SKU 一次/二次点数和差异授权；详情增加商品图、尺码、来源和登记/确认数量摘要，数量一致时直接确认。
3. **后整加工部分数量**：逐尺码填写已处理，页面同步计算剩余；未填满必须填写未处理原因，随 `appendPostFinishingProcessCompletion` 记录保存；不强制一次登记全部可用量。
4. **复检数量差异**：逐 SKU 填实际交出数量；与应收不一致时显示动态授权码和差异原因，原 `completePostFinishingRecheckOrderFullFlow` 消费授权后生成实际数量出库单和待交出仓入库。
5. **条码错误换标复扫**：错码→“错误待重贴”→重贴→“已重贴待复扫”→复扫正确，原命令记录条码事件并放行。
6. **两仓**：仓管页按 SKU 汇总待加工仓/待交出仓可用、入仓和已交出数量，并显示原库存移动记录；状态、库区在印尼语下显示本地化。原后道域没有手工移库/调整命令，本页不提供假移动按钮。
7. **照片**：送货登记现场凭证进入送货单证据；QC 不良可拍照，`defectImageUrl` 同时写入质检结果和不良记录。
8. **印尼语**：后整、复检、条码、两仓状态和车缝回货页均按语言切换，实测无中文状态残留。
9. **仓库实收差异**：逐 SKU 填实收；差异无授权阻断，有有效授权后保存实际 98/100 并回读“已接收入库”。
