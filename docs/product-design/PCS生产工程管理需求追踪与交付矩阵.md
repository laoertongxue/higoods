# PCS 生产工程管理需求追踪与交付矩阵

> 版本：V1.0
> 日期：2026-08-04
> 权威需求来源：`docs/product-design/PCS生产工程管理总体设计文档.md`
> 实施依据：`docs/product-design/PCS生产工程管理实施计划.md`
> 用途：把总体设计中的业务规则拆成可单独实现、验证和交付的原子需求，防止遗漏、合并理解或以构建通过代替业务完成。

## 1. 使用规则

1. 每个需求 ID 只表达一个可判定“通过／不通过”的业务结果。
2. “已验证”必须同时填写实际实现位置、自动检查证据、命名页面或业务场景证据、验证版本和验证人；缺一项不得标记完成。
3. 状态只允许：`待实施`、`实施中`、`已实现待验证`、`已验证`、`已阻塞`、`不适用`。
4. 原型中已有相似页面或 Mock，不代表本矩阵已经完成；实施前全部以 `待实施` 起步，逐条用当前版本证据收口。
5. 需求变化时先修改总体设计，再修改本矩阵及实施计划；不得只改代码或只改计划。
6. 每个实施任务或 PR 必须声明覆盖的需求 ID；审查时同时做“需求到实现”和“实现到需求”两次反向核对。
7. 本项目是前端原型。矩阵中的“服务、仓储、事件”等实现锚点，均指本地领域模型、Mock 事实源和页面行为，不表示真实后端能力。

## 2. 证据类型与工作包

### 2.1 证据类型

| 代码 | 证据 |
|---|---|
| C | 领域规则或状态推导专项检查 |
| U | 页面结构、字段、文案和交互专项检查 |
| B | 指定路由浏览器实测，含关键动作和结果 |
| I | 真实缩略图、失败态和高清大图弹窗实测 |
| P | 首屏、局部交互、懒加载和重复构造性能检查 |
| R | 菜单、路由、页面、处理器、Mock、测试和文案的删除检索 |
| X | 跨模块端到端场景验收 |
| G | 类型、构建、治理检查、CodeGraph 和任务收据 |
