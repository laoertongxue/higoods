# 生产准备历史工序彻底删除实施计划

## 1. 目标与完成标准

在 `codex/requirement-work-20260821` 分支彻底删除两项已取消准备工序，并证明现行准备工序、技术包、工厂档案和任务链路未被误删。

完成标准：`PREP-REMOVE-001` 至 `PREP-REMOVE-009` 均绑定实际实现位置与当前版本证据；正向追踪无遗漏，反向扫描无旧入口；最后一次实质修改后的专项检查、页面验收、构建、原型治理、CodeGraph 和任务收据全部重新执行。

## 2. 工作包

### WP-1：删除字典与承接能力

- 业务目标：当前字典和工厂档案不再认识两项旧工序。
- 文件／符号：工序工艺字典、工厂类型、工厂 Mock、内部仓和特殊工艺工厂选择。
- 修改：删除工序、工艺、历史映射、工厂类型、能力映射和专属 Mock；完整面料工艺回到现行特种工艺工厂规则。
- 验证证据：字典分类、工厂档案与菜单专项检查，页面抽查。
- 完成条件：所有现行查询与选项均无法返回旧定义。

### WP-2：删除 BOM 与技术包联动

- 业务目标：产品资料不再采集、保存或推导两项旧要求。
- 文件／符号：BOM 类型、仓库、表单、事件、技术包同步、版本快照和 PCS 工作台。
- 修改：删除需求字段、默认值、克隆映射、表格列、编辑控件、版本比较及自动准备工序同步。
- 验证证据：生产构建、BOM/技术包专项检查、命名页面抽查。
- 完成条件：新旧对象经过当前代码后均不会暴露或生成旧能力。

### WP-3：删除运行 Mock 与页面残留

- 业务目标：其他业务页面不再通过文案、预留项或 Mock 暗示旧能力仍存在。
- 文件／符号：裁片特殊工艺、菲票、生产准备时效、生产单快照、样衣成本及工程 Mock。
- 修改：删除预留项、说明、费用行和相关快照字段；保留相邻业务事实。
- 验证证据：直接专项检查和相关页面抽查。
- 完成条件：用户可见页面及 Mock 中不存在旧工序语义。

### WP-4：删除专属文件并收口契约

- 业务目标：测试和文档不再要求恢复已取消能力。
- 文件／符号：专属说明、检查脚本、浏览器用例，以及引用旧口径的其他检查和历史文档。
- 修改：删除专属文件；其余契约改为验证现行准备工序和“旧定义不存在”。
- 验证证据：全仓文件名、文字、代码标识和引用扫描。
- 完成条件：不存在专属文件和无说明残留。

### WP-5：双向追踪与运行验收

- 业务目标：证明删干净且未误伤相邻能力。
- 文件／符号：追踪矩阵、原型审查记录、命名页面与任务收据。
- 修改：补齐实际实现和证据；执行正向与反向追踪。
- 验证证据：专项检查、构建、治理、浏览器、CodeGraph 和收据。
- 完成条件：矩阵没有无说明的待实施、实施中、待验证或阻塞项。

## 3. 依赖顺序

`WP-1` 和 `WP-2` 先删除事实源；`WP-3` 清理读取者与 Mock；`WP-4` 删除旧契约；最后由 `WP-5` 统一验证。不能先删除测试后保留运行代码，也不能只隐藏页面。

## 4. 风险与控制

| 风险 | 控制 |
| --- | --- |
| 只删页面，技术包仍自动生成 | 直接删除字段、同步器和字典定义，并以数据契约验证 |
| 辅料或面料物性名称仍包含旧工序字样 | 辅料统一称“洗护唛”、面料物性统一称“面料缩率”，全仓按字面零残留复核 |
| 工厂类型删除后完整面料工艺无承接方 | 回归现行特种工艺工厂选择和专属工厂规则 |
| 历史测试继续要求旧能力 | 删除专属契约，其他检查改为禁止旧定义回归 |
| 删除字段破坏旧 Mock 克隆 | 用生产构建、专项契约和命名页面覆盖保存、读取与版本展示 |
