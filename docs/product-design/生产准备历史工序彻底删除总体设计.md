# 生产准备历史工序彻底删除总体设计

## 1. 背景与目标

当前原型仍保留两项已经取消的生产准备工序：它们虽然没有完整加工单与 PDA 闭环，但仍存在于工序工艺字典、BOM 需求字段、技术包自动生成、工厂类型、Mock、页面文案、检查脚本和历史文档中，容易让产品、研发和测试继续把它们当作待建设能力。

本次目标是从当前仓库彻底移除这两项工序及其兼容路径，使准备阶段只保留当前继续讨论和使用的工序；页面、数据模型和自动化检查不得再暴露、生成、传递或兼容这两项能力。

## 2. 范围与非范围

### 2.1 本次范围

- 删除两项工序在工序定义、工艺定义、准备阶段定义和历史兼容映射中的全部记录。
- 删除 BOM 中对应的两个需求字段、默认值、表格列、编辑控件、保存与版本快照字段。
- 删除技术包根据这两个字段自动生成、保留、移除或等待确认准备工序的逻辑。
- 删除专门承接这两项工序的工厂类型、能力映射、工厂 Mock 和工厂筛选分支。
- 删除裁片特殊工艺预留、菲票说明、生产准备时效、样衣成本和生产快照中的相关内容。
- 删除相关专项检查、浏览器用例、说明文档及其专属文件。
- 清理其他测试、历史设计和审查记录中的旧口径，避免当前仓库继续传播已取消能力。

### 2.2 保留边界

- 保留印花、染色、水溶及其他现有准备、生产和后道工序。
- 成衣护理标识辅料统一使用“洗护唛”名称，不保留包含旧工序名称的别名。
- 面料物性统一使用“面料缩率”名称，不保留包含旧工序名称的别名。
- 不改动已经提交的 Git 历史，只清理当前分支工作树中的现行文件。
- 本仓库为原型，不执行生产数据库迁移。

## 3. 目标业务结果

1. 工艺人员在 BOM、技术包和工序工艺字典中看不到这两项工序或需求字段。
2. 技术包同步 BOM 时不会生成、保留或等待确认这两项准备工序。
3. 工厂档案中不存在只为这两项工序设置的工厂类型或承接能力。
4. 任务、加工单、PDA、菲票、交出、产能和时效配置均不存在相关入口或兼容分支。
5. 当前仓库不存在以这两项工序为主题的源码、测试、检查或说明文件。

## 4. 场景校验

### 4.1 正常场景

技术包 BOM 只维护印花、染色和水溶等现行要求。保存后，准备阶段只按这些真实要求生成对应记录；工序工艺字典和工厂能力选项与其保持一致。

### 4.2 边界场景

旧版本对象或 Mock 中即使仍携带已取消字段，当前页面、同步逻辑和任务生成也不得重新暴露或生成对应工序；原型数据应在种子与克隆过程中完成清理，而不是继续保留兼容入口。

## 5. 验收口径

- `PREP-REMOVE-001`：工序、工艺、准备阶段和历史映射中不存在两项旧定义。
- `PREP-REMOVE-002`：BOM、技术包、PCS 及版本快照中不存在对应需求字段。
- `PREP-REMOVE-003`：不存在自动生成、同步、保留、移除或待确认旧准备工序的逻辑。
- `PREP-REMOVE-004`：页面不存在对应列、控件、卡片、提示和预留入口。
- `PREP-REMOVE-005`：工厂类型、工厂 Mock、能力映射和筛选分支不存在旧能力。
- `PREP-REMOVE-006`：任务、加工单、PDA、菲票、时效、成本与生产快照不存在旧口径。
- `PREP-REMOVE-007`：专属源码、测试、检查和说明文件已经删除。
- `PREP-REMOVE-008`：全仓反向扫描对旧中文名称、英文编码、字段名、文件名及隐式判断均为零命中，不设置非工序语义例外。
- `PREP-REMOVE-009`：现行准备工序及相邻页面、构建和治理检查通过。
