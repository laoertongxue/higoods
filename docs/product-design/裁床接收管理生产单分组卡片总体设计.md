# 裁床接收管理生产单分组卡片总体设计

## 1. 背景与目标

裁床接收管理的“已配齐待接收”“未配齐配料”“已接收”用于主管在 Web 端按生产单核对并完成接收。现有分组卡片虽然替代了扁平表格，但卡头留白大、重复状态与说明过多，物料明细仍保留与接收无关的列，核心动作又只能跳转 PDA。此次将三页统一收口为紧凑的生产单分组卡片，并补齐 Web 接收闭环。

完成后，用户应能在首屏快速确认“哪个生产单、什么款式、哪些物料、在哪里、应接收多少、已经接收多少、接收后还缺多少”，并在 Web 端选择裁床待加工仓库位后完成整个接收节点。

## 2. 范围

- 路由：`/fcs/craft/cutting/pickup-management/ready`、`/fcs/craft/cutting/pickup-management/incomplete`、`/fcs/craft/cutting/pickup-management/history`。
- 端类型：PFOS 管理端 / 主管端 Web；PDA 保持可用并复用同一接收确认规则。
- 角色：裁床主管、裁床仓管。
- 调整对象：三个页面下方结果区、共用生产单卡片、卡内物料表、Web 接收弹窗、接收记录、大图、底部分页及 Web/PDA 共用接收确认入口。

## 3. 明确保留

- 上方筛选区的字段、顺序、文案、交互和筛选规则不变。
- 上方统计卡的指标、文案、数量口径和排列不变。
- 菜单、三个命名路由和页面标题不变。
- 接收节点仍由既有业务事实形成；没有活动节点时不得接收。
- 每次确认仍接收当前节点全部物料，不增加勾选物料、改数量或部分接收。
- 节点版本、数量单位、多次补料、同 SKU 独立需求行、接收会话、接收明细、差异处理、待加工仓流水及幂等规则保持。
- PDA 接收入口继续可用，不因新增 Web 接收而移除。

## 4. 展示对象与分组

- 外层对象为生产单；同一页面中一个生产单只出现一张外层卡片。
- 正常配料单在前；当前可独立处理的多次补料按次数在卡内分段。已接收页仍按既有历史投影归入生产单接收段，但补料需求行的来源、次数、数量和节点身份不得合并。
- 同 SKU 的不同正常 / 补料需求行必须保留各自来源、数量和节点身份。
- 同一物料的多个当前位置保持一条物料行，在“位置 / 载体”中逐行列出库区、库位和数量。
- 三页共用同一个卡片、款式摘要、需求段和物料表骨架，仅摘要、状态和动作资格随页面事实变化。

## 5. 紧凑卡片骨架

### 5.1 卡头

- 单行优先展示生产单号、需求单号、售卖类型、必要状态和操作；配料单 / 补料单号只在下方需求段展示，避免卡头重复。
- 可接收节点显示主按钮“接收”和次操作“接收记录”；不可接收时仅显示紧凑的“暂不可接收”。
- 删除“生产单信息”、页面名称重复标签、“配料需求：”、待接收页空值的最近接收人 / 时间以及“一次接收本节点全部物料”等重复说明。
- 多个活动需求节点时，各节点操作以紧凑按钮组展示，不再套嵌独立操作小卡。

### 5.2 款式与接收摘要

- 款式缩略图、款号、款名和 SPU 同块展示，缩略图约 56～64px。
- 摘要只保留该页决策所需事实：可接收物料 / 数量、缺料数量 / 缺口，或接收次数 / 最近接收事实。
- 卡头与摘要区合计高度以不超过约 176px 为目标；1366×768 下从卡片顶部应能看到卡头、款式摘要、物料表头和首条物料。

### 5.3 物料明细

- 保留列：物料、需求来源、位置 / 载体、应配、当前配料、累计接收、本轮可接收、接收后仍缺；已接收页按事实显示剩余。
- 删除列：加工状态、加工可供、已到仓、超配异常。
- “位置 / 载体”目标宽度 180px，不再使用内嵌灰色小卡；多库位以紧凑文本逐行展示。
- 需求来源简写为“配料”或“补料第 N 次”；补料原因只在需求段标题展示一次。
- 物料缩略图约 48px，并与名称、SKU、颜色、规格、类型同列。
- 物料明细可以在卡内横向滚动，页面主体不得横向溢出。

## 6. 三页差异

### 6.1 已配齐待接收

- 突出直接配齐 / 由未配齐升级、可接收物料种数、按单位可接收数量和最近配齐时间。
- 有活动节点时允许 Web 接收；接收成功后该节点不再留在待接收结果中，并可在已接收页查到记录。

### 6.2 未配齐配料

- 突出当前位置数、可接收物料种数、仍缺物料种数及接收后缺口。
- 只要存在合法活动接收节点即可整节点接收；没有节点的补料段只显示“暂不可接收”。

### 6.3 已接收

- 突出接收路径、最终结果、接收次数、最近接收人和最近接收时间。
- 主操作为“接收记录”；若生产单又产生新的活动节点，可显示“接收”处理新节点。

## 7. Web 接收

### 7.1 打开接收

- 点击“接收”后重新读取活动节点，并核对节点 ID 与版本；节点已变化或消失时阻断并提示重新核对。
- 弹窗展示生产单、配料 / 补料单、节点版本、物料种数、按单位合计和当前节点全部物料；物料只读。
- 接收人默认为“裁床仓管”，可在 Web 弹窗内修改。
- 用户必须明确选择一个可用的裁床待加工仓及一个或多个空闲库位；存在多个仓时不得静默选择第一个。

### 7.2 确认接收

- 提交前再次校验节点版本、待处理差异、仓库范围、库位存在性、停用状态和实时占用状态。
- 一次确认形成一个接收会话，并为节点内每条物料形成接收明细和裁床待加工仓入库流水。
- Web 与 PDA 调用同一接收确认能力；仅事件来源和操作角色不同，数量、节点、库位、幂等和事务规则一致。
- 接收会话与仓库流水要么共同成功，要么共同回滚；重复点击或重试不得重复接收或重复入库。
- 成功后关闭弹窗、刷新三页共享事实缓存，并局部刷新当前页统计、卡片与分页，不整页闪烁。

### 7.3 差异与恢复

- Web 弹窗提供折叠的“上报接收差异”；用户选择物料、填写正数差异，并至少提供照片或说明。
- 差异提交后立即阻断该节点接收，保留到主管处理完成。
- 库位已占用 / 停用时保留仍有效的选择，并明确提示重新选择。
- 原子写入失败时弹窗和当前选择保持，允许直接重试。

## 8. 图片与交互

- 款式与每种物料使用现有真实对应图片；缺少素材时明确显示“图片未提供”，不得使用无关占位图。
- 缩略图显示加载中和加载失败状态。
- 款式和物料缩略图均可点击查看大图；大图支持关闭按钮、遮罩和 `Esc`，保持比例且不超出低分辨率视口。
- 筛选、排序、分页、列设置、接收弹窗、接收记录和大图均使用局部更新。

## 9. 分页与低分辨率

- 三页底部始终使用统一分页组件，按生产单卡片分页，支持每页 10 / 20 / 50 条、当前范围、总数、当前页、上一页和下一页。
- 列显示、顺序、冻结和每页条数继续按路由持久化；被删除的四个旧列键从旧偏好中自动清理。
- 按 1366×768 验收，最低 1280×720 可完成筛选、核对、Web 接收、差异上报、记录查看和大图操作。

## 10. 完成标准

- 三个命名路由共用紧凑生产单卡片，上方筛选和统计无变化。
- 一生产单一卡片，正常需求、多次补料、同 SKU 独立行、多库位和全部数量单位不丢失。
- 四个删除列在表头、行内容、列设置和旧偏好恢复后均不出现；“位置 / 载体”按 180px 紧凑展示。
- Web 可完成整节点接收，PDA 仍可接收，二者写入相同接收会话 / 明细 / 仓库事件事实。
- 节点失效、差异未处理、库位无效 / 占用、重复提交和写入失败均有可验证防错结果。
- 三页底部分页、大图交互、两种桌面分辨率和相关专项契约均在最终改动后通过。
