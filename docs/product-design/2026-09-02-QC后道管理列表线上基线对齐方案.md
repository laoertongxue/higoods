# QC 后道管理列表线上基线对齐方案

> 历史口径：其中“PDA优先、Web应急、可选后道/直达复检、复检Web只读”已被 `2026-09-03-QC后道领取Web执行与出货打印调整方案.md` 取代；本文件仅用于追溯线上列表基线。

> 日期：2026-09-02  
> 状态：本地原型已验证，最终证据以需求追踪矩阵与原型审查记录为准  
> 上位业务设计：`docs/product-design/QC后道全流程系统完整调整方案.md`  
> 本轮纠偏依据：用户提供的线上后道任务、质检单、后道单、复检单页面及 `codex://threads/01a0557f-f7ff-7c03-9054-9ee35c9f97a0`

## 1. 背景与目标

前一轮已经建立 QC 后道的 Mock 全流程、PDA 执行和 Web 兜底，但四张 Web 管理列表的结构与线上页面差异过大，导致线上已有的搜索条件、统计卡片、字段和打印入口被弱化。

本轮目标不是重做业务流程，而是在继续读取同一套 QC 后道事实和状态的前提下，让四张管理列表回到线上页面的基本信息架构，并补齐原型缺失的可操作入口。

## 2. 范围与非目标

### 2.1 本轮范围

- 后道生产任务：恢复线上统计、筛选、字段和操作区；“查看来源任务”按后道生产任务号精确定位到任务分配工作台；保留设置 SKU 重量、查看回货记录、查看质检单、打印质检单、打印质检详情单，不显示手工“生成质检单”。
- 质检单：将页面、菜单和用户可见文案从“质检任务”统一为“质检单”，恢复线上筛选、字段、查看与两类打印。
- 后道加工单：恢复线上筛选、字段、查看详情和打印加工单流转卡，同时保留 PDA 优先、Web 应急兜底。
- 复检单：恢复线上筛选、字段和查看详情，同时保留 PDA 复检入口及主管释放能力。
- 打印：以线上页面实际打开的版式为准，统一后道生产任务和质检单列表的质检单、质检详情单打印，并保留后道加工单流转卡。

### 2.2 非目标

- 不改变待加工仓送检、质检、可选后道、复检、待交出仓、出货的状态推进顺序。
- 不新增绕过待加工仓送检的手工创建质检单入口。
- 不实现真实后端、线上百万级数据、真实鉴权、打印机驱动或生产接口。
- 不修改此前确认的 PDA 后道数量、逐原因瑕疵调整和 Web 兜底规则。

## 3. 角色与端侧分工

| 角色 / 端 | 本轮页面任务 | 操作边界 |
| --- | --- | --- |
| 管理人员 Web | 搜索、统计、查看四类单据、打印、追溯 | 不在后道生产任务页直接制造质检单 |
| 质检员 Web | 输入完整质检单号领取并完成质检 | 一张质检单只由一名质检员操作 |
| 主管 Web | 查看全量单据，释放被占用的质检或复检单 | 释放必须继续写入既有操作事实 |
| 后道操作员 PDA | 执行后道完成数量及瑕疵调整 | PDA 为首选现场入口 |
| 管理人员 Web | PDA 故障时进入后道加工单详情应急处理 | 与 PDA 读写同一后道草稿和状态 |
| 复检员 PDA | 扫码领取、数量与条码复检 | Web 详情保持只读追溯 |

## 4. 业务对象与流程不变

四张列表只改变管理呈现，不改变对象关系：

`生产单 / 后道生产任务主线 → 每次回货送货单 → 回货最终确认并唯一生成“待送检”质检单 → 待加工仓确认送检出库并激活为“待质检” → 质检完成 → 按质检结论生成后道加工单或直达复检单 → 后道完成唯一生成复检单 → 待交出仓 → 出货单`

关键约束：

1. 每次回货是一条独立业务链，不把多次回货合并成一张质检单或后道加工单。
2. 后道生产任务页不提供“生成质检单”；每次回货对应的质检单在最终确认回货时自动形成，待加工仓送检只激活同一单，不增加第二个人工入口，也不绕过库存和状态门禁。
3. 四张列表、详情、PDA 和打印继续读取 `post-finishing-full-flow` 同一事实源。
4. 页面统计是现有 Mock 事实的聚合，不反向写业务状态。

## 5. 页面设计

### 5.1 后道生产任务

- 顶部统计：后道生产任务、计划数量、未质检数量、已入待加工仓、待交出数量。
- 搜索条件：关键词、出库状态、后道来源、分配状态、工厂、售卖类型。
- 列表字段：SPU、后道生产任务、生产单信息、计划数量、已入待加工仓、未质检、已质检、待交出、上游来源、分配状态、SKU 重量、操作。
- 操作：查看任务、设置 SKU 重量、查看质检单、打印质检单、打印质检详情单。
- “查看来源任务”进入任务分配工作台，并用当前行后道生产任务号作为精确查询条件；目标页只展示该任务及其 SPU、生产单、工厂和分配信息。
- SKU 重量按生产单逐 SKU 设置，显示真实图片、颜色、尺码和 `kg/件`；保存只影响演示重量，不改变数量流转。

### 5.2 质检单

- 用户可见名称统一为“质检单”。
- 顶部保留精确输入完整质检单号领取；明确质检单在回货最终确认时自动生成，只有待加工仓完成送检出库后才可领取。
- 搜索条件：关键词、当前状态、后道来源、工厂。
- 列表字段：质检单号、单号、来源工厂、质检台、SKU 明细、质检数量、合格数量、不合格数量、质检结果、状态、质检人、操作。
- 操作：完成质检、查看质检单、打印质检单、打印质检详情单、主管释放。

### 5.3 后道加工单

- 搜索条件：关键词、当前状态、后道项目、工厂。
- 列表字段：单据、工厂、SKU 明细、后道项目、总数量、后道不合格、后道状态、时间、操作。
- 操作：查看详情、PDA 执行（优先）、打印任务流转卡、查看全流程。
- 查看详情继续进入既有 Web 应急处理页；加工项目继续来自质检确认结果。

### 5.4 复检单

- 搜索条件：关键词、当前状态、后道加工单来源、工厂。
- 列表字段：复检单号、来源、关联质检单、关联后道加工单、生产单号、加工工厂、款式名称、SKU 明细、复检数量、合格数量、不合格数量、复检状态、复检时间、操作。
- 操作：查看复检详情；现场仍优先进入 PDA 复检，主管释放保留在适用记录上。
- Web 详情展示 SKU 数量、条码过程和关联单据，不替代 PDA 现场复检。

### 5.5 图片与宽表

- 所有出现款式或 SKU 的列表均使用既有 Mock 中与对象一一对应的正式图片。
- 图片与 SPU / SKU、颜色、尺码位于同一信息块，支持点击大图、加载中和失败态。
- 四页采用标准管理列表组件；宽表只在表格容器内横向滚动，页面主体不横向溢出。

### 5.6 首屏信息密度

- 四页不再重复显示“后道生产任务列表 / 质检单列表 / 后道加工单列表 / 复检单列表”二级标题栏；页面主标题仍保留。
- 不删除第 5.1～5.4 节确认的字段和操作，只压缩固定列宽并允许长编号、工厂、款式和时间在单元格内合理换行。
- 后道生产任务重点压缩 SPU、任务和操作列；质检单重点压缩质检单号、单号、SKU 和操作列；后道加工单重点压缩单据、工厂、SKU、后道项目和操作列；复检单重点压缩关联单号、款式、SKU 和操作列。
- 操作列固定为双列网格：后道生产任务和质检单最多 3 行，后道加工单最多 2 行，复检单最多 1 行；既有动作不得因压缩被隐藏。
- 1366×768、侧栏展开、表格位于最左端时，后道生产任务、质检单、后道加工单至少完整显示前 5 个数据列和固定操作列；复检单至少完整显示前 6 个数据列和固定操作列。
- 横向滚动继续作为查看后续列的兜底，但页面主体本身不得出现横向滚动。

## 6. 打印

- 质检单：采用线上主质检单版式，标题为“质检单（Pemeriksaan Kualitas）”，展示条码、SPU、款式评级、生产单、工厂、产品实图与吊牌价、买手、生产单类型、售卖类型，并继续展示面辅料实图 / 编码 / 单耗 / 准备栏及尺码表。
- 质检详情单：采用线上质检详情版式，标题为“质检详情单（Pemeriksaan Kualitas）”，展示条码、SPU、打印时间、生产单、工厂、买手、生产单类型、售卖类型，以及逐 SKU 的待加工数量、待质检数量、质检数量和日期签名栏。
- 后道生产任务和质检单列表的同类打印入口必须进入同一打印路由、读取同一业务链事实，不能出现两套版式。
- 后道加工单流转卡：展示质检单、生产单、加工项目、逐 SKU 数量和 PDA 执行二维码。
- 打印入口只读既有事实，不推进状态。

## 7. 正常与边界场景

### 7.1 正常场景

1. 管理人员在后道生产任务页搜索生产单，查看统计和流转进度；点击“查看来源任务”后，任务分配工作台按该后道生产任务号只展示目标任务；管理人员还可为某个 SKU 设置重量。
2. 待加工仓完成送检后，质检员在质检单页输入完整单号领取，完成质检；管理人员可查看或打印。
3. 需要后道的记录进入后道加工单，PDA 完成现场操作；设备故障时从 Web 详情接管。
4. 质检直达或后道完成后产生复检单，Web 查看单据关系，PDA 完成现场复检。

### 7.2 阻断与恢复场景

1. 未送检记录在后道生产任务页没有“生成质检单”操作；已最终确认回货的质检单显示“待送检”，未最终确认回货尚无质检单，待加工仓送检不得重复建单。
2. 不完整质检单号：不允许领取或代选。
3. 质检单已被他人领取：既有冲突门禁和主管释放继续生效。
4. PDA 不可用：后道加工单 Web 详情读取同一草稿，按既有接管规则继续。
5. 无后道项目：质检完成后按既有规则直接生成复检单，列表不得强制出现后道加工单。
6. 图片加载失败：显示明确失败态，不以无关占位图冒充款式。

## 8. 验收标准

- 四张页面分别通过线上字段、筛选、统计和操作入口专项契约。
- `质检任务`不再出现在本轮相关用户界面；内部类型名不作为页面文案。
- 后道生产任务不显示“生成质检单”，也不能从该列表触发送检领域动作。
- 后道生产任务“查看来源任务”必须携带当前任务号进入任务分配工作台，并精确展示对应任务。
- 设置 SKU 重量可实际保存并即时更新已设置数量。
- 质检单、质检详情单、后道加工单流转卡可由具体 Mock 单据打开；后道生产任务与质检单列表打开的两类质检打印版式一致，并与用户提供的线上打印字段、实图和表格结构一致。
- 四张命名页面在本地同一分支、同一工作树和 1366×768 浏览器中验收，无控制台错误。
- 四页重复列表标题栏已移除，首屏可见列数达到第 5.6 节下限，操作入口按双列网格展示且不超过 3 行。
- 构建、列表治理、原型治理、专项业务检查和 CodeGraph 同步通过；任务收据无法与用户既有工作区差异隔离时明确记录未运行，不以此冒充独立交付。

## 9. 假设与待现场确认

- 本轮按用户提供的 2026-09-02 线上页面作为视觉与字段基线。
- Mock 数量和账号只用于原型演示，不代表真实工厂当前数据。
- 真实打印机、真实扫码枪、现场 PDA、弱网和生产权限未由本地浏览器证据替代，部署后需另行验收。
