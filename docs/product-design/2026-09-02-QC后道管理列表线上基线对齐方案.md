# QC 后道管理列表线上基线对齐方案

> 日期：2026-09-02
> 状态：本地原型已验证，产品确认待完成；最终证据以需求追踪矩阵与原型审查记录为准
> 上位业务设计：`docs/product-design/QC后道全流程系统完整调整方案.md`
> 本轮纠偏依据：用户提供的线上后道任务、质检单、后道单、复检单页面及 `codex://threads/01a0557f-f7ff-7c03-9054-9ee35c9f97a0`

## 1. 背景与目标

前一轮已经建立 QC 后道的 Mock 全流程、PDA 执行和 Web 兜底，但四张 Web 管理列表的结构与线上页面差异过大，导致线上已有的搜索条件、统计卡片、字段和打印入口被弱化。

本轮目标不是重做业务流程，而是在继续读取同一套 QC 后道事实和状态的前提下，让四张管理列表回到线上页面的基本信息架构，并补齐原型缺失的可操作入口。

## 2. 范围与非目标

### 2.1 本轮范围

- 后道任务：恢复线上统计、筛选、字段和操作区，保留设置 SKU 重量、查看质检单、打印质检单、打印质检详情单。
- 质检单：将页面、菜单和用户可见文案从“质检任务”统一为“质检单”，恢复线上筛选、字段、查看与两类打印。
- 后道单：恢复线上筛选、字段、查看详情和打印任务流转卡，同时保留 PDA 优先、Web 应急兜底。
- 复检单：恢复线上筛选、字段和查看详情，同时保留 PDA 复检入口及主管释放能力。
- 打印：补齐质检单、质检详情单和后道任务流转卡的命名打印页面。
- 菜单：“我的动态授权码”继续保持原位置和路由，并显示可识别的钥匙图标。

### 2.2 非目标

- 不改变待加工仓送检、质检、可选后道、复检、待交出仓、出货的状态推进顺序。
- 不新增绕过待加工仓送检的手工创建质检单入口。
- 不实现真实后端、线上百万级数据、真实鉴权、打印机驱动或生产接口。
- 不修改此前确认的 PDA 后道数量、逐原因瑕疵调整和 Web 兜底规则。

## 3. 角色与端侧分工

| 角色 / 端 | 本轮页面任务 | 操作边界 |
| --- | --- | --- |
| 管理人员 Web | 搜索、统计、查看四类单据、打印、追溯 | 不在后道任务页直接制造质检单 |
| 质检员 Web | 输入完整质检单号领取并完成质检 | 一张质检单只由一名质检员操作 |
| 主管 Web | 查看全量单据，释放被占用的质检或复检单 | 释放必须继续写入既有操作事实 |
| 后道操作员 PDA | 执行后道完成数量及瑕疵调整 | PDA 为首选现场入口 |
| 管理人员 Web | PDA 故障时进入后道单详情应急处理 | 与 PDA 读写同一后道草稿和状态 |
| 复检员 PDA | 扫码领取、数量与条码复检 | Web 详情保持只读追溯 |

## 4. 业务对象与流程不变

四张列表只改变管理呈现，不改变对象关系：

`生产单 / 后道任务主线 → 每次回货送货单 → 待加工仓确认 → 送检并唯一生成质检单 → 质检完成 → 按质检结论生成后道单或直达复检单 → 后道完成唯一生成复检单 → 待交出仓 → 出货单`

关键约束：

1. 每次回货是一条独立业务链，不把多次回货合并成一张质检单或后道单。
2. “生成质检单”只把用户带回待加工仓的对应送检业务，不调用生成动作、不绕过库存和状态门禁。
3. 四张列表、详情、PDA 和打印继续读取 `post-finishing-full-flow` 同一事实源。
4. 页面统计是现有 Mock 事实的聚合，不反向写业务状态。

## 5. 页面设计

### 5.1 后道任务

- 顶部统计：后道任务、计划数量、未质检数量、已入待加工仓、待交出数量。
- 搜索条件：关键词、出库状态、后道来源、分配状态、工厂、售卖类型。
- 列表字段：SPU、后道任务、生产单信息、计划数量、已入待加工仓、未质检、已质检、待交出、上游来源、分配状态、SKU 重量、操作。
- 操作：查看任务、生成质检单、设置 SKU 重量、查看质检单、打印质检单、打印质检详情单。
- SKU 重量按生产单逐 SKU 设置，显示真实图片、颜色、尺码和 `kg/件`；保存只影响演示重量，不改变数量流转。

### 5.2 质检单

- 用户可见名称统一为“质检单”。
- 顶部保留精确输入完整质检单号领取；明确质检单由待加工仓送检自动生成。
- 搜索条件：关键词、当前状态、后道来源、工厂。
- 列表字段：质检单号、单号、来源工厂、质检台、SKU 明细、质检数量、合格数量、不合格数量、质检结果、状态、质检人、操作。
- 操作：完成质检、查看质检单、打印质检单、打印质检详情单、主管释放。

### 5.3 后道单

- 搜索条件：关键词、当前状态、后道项目、工厂。
- 列表字段：单据、工厂、SKU 明细、后道项目、总数量、后道不合格、后道状态、时间、操作。
- 操作：查看详情、PDA 执行（优先）、打印任务流转卡、查看全流程。
- 查看详情继续进入既有 Web 应急处理页；加工项目继续来自质检确认结果。

### 5.4 复检单

- 搜索条件：关键词、当前状态、后道单来源、工厂。
- 列表字段：复检单号、来源、关联质检单、关联后道单、生产单号、加工工厂、款式名称、SKU 明细、复检数量、合格数量、不合格数量、复检状态、复检时间、操作。
- 操作：查看复检详情；现场仍优先进入 PDA 复检，主管释放保留在适用记录上。
- Web 详情展示 SKU 数量、条码过程和关联单据，不替代 PDA 现场复检。

### 5.5 图片与宽表

- 所有出现款式或 SKU 的列表均使用既有 Mock 中与对象一一对应的正式图片。
- 图片与 SPU / SKU、颜色、尺码位于同一信息块，支持点击大图、加载中和失败态。
- 四页采用标准管理列表组件；宽表只在表格容器内横向滚动，页面主体不横向溢出。

### 5.6 首屏信息密度

- 四页不再重复显示“后道任务列表 / 质检单列表 / 后道单列表 / 复检单列表”二级标题栏；页面主标题仍保留。
- 不删除第 5.1～5.4 节确认的字段和操作，只压缩固定列宽并允许长编号、工厂、款式和时间在单元格内合理换行。
- 后道任务重点压缩 SPU、后道任务和操作列；质检单重点压缩质检单号、单号、SKU 和操作列；后道单重点压缩单据、工厂、SKU、后道项目和操作列；复检单重点压缩关联单号、款式、SKU 和操作列。
- 操作列固定为双列网格：后道任务和质检单最多 3 行，后道单最多 2 行，复检单最多 1 行；既有动作不得因压缩被隐藏。
- 1366×768、侧栏展开、表格位于最左端时，后道任务、质检单、后道单至少完整显示前 5 个数据列和固定操作列；复检单至少完整显示前 6 个数据列和固定操作列。
- 横向滚动继续作为查看后续列的兜底，但页面主体本身不得出现横向滚动。

### 5.7 动态授权码菜单图标

- “我的动态授权码”菜单显示与其功能匹配的钥匙图标，文字、菜单顺序和目标路由保持不变。
- 图标纳入现有侧栏按需图标包，不引入新的图标依赖或独立组件。

## 6. 打印

- 质检单：展示质检单号、送货单、生产单、送检信息、逐 SKU 数量与条码。
- 质检详情单：展示逐 SKU 应检、合格、瑕疵、返厂和原因。
- 后道任务流转卡：展示质检单、生产单、加工项目、逐 SKU 数量和 PDA 执行二维码。
- 打印入口只读既有事实，不推进状态。

## 7. 正常与边界场景

### 7.1 正常场景

1. 管理人员在后道任务页搜索生产单，查看统计和流转进度，并为某个 SKU 设置重量。
2. 待加工仓完成送检后，质检员在质检单页输入完整单号领取，完成质检；管理人员可查看或打印。
3. 需要后道的记录进入后道单，PDA 完成现场操作；设备故障时从 Web 详情接管。
4. 质检直达或后道完成后产生复检单，Web 查看单据关系，PDA 完成现场复检。

### 7.2 阻断与恢复场景

1. 未送检记录点击“生成质检单”：只进入待加工仓对应记录，不直接生成。
2. 不完整质检单号：不允许领取或代选。
3. 质检单已被他人领取：既有冲突门禁和主管释放继续生效。
4. PDA 不可用：后道单 Web 详情读取同一草稿，按既有接管规则继续。
5. 无后道项目：质检完成后按既有规则直接生成复检单，列表不得强制出现后道单。
6. 图片加载失败：显示明确失败态，不以无关占位图冒充款式。

## 8. 验收标准

- 四张页面分别通过线上字段、筛选、统计和操作入口专项契约。
- `质检任务`不再出现在本轮相关用户界面；内部类型名不作为页面文案。
- 后道任务“生成质检单”不能直接调用送检领域动作。
- 设置 SKU 重量可实际保存并即时更新已设置数量。
- 质检单、质检详情单、后道任务流转卡可由具体 Mock 单据打开。
- 四张命名页面在本地同一分支、同一工作树和 1366×768 浏览器中验收，无控制台错误。
- 四页重复列表标题栏已移除，首屏可见列数达到第 5.6 节下限，操作入口按双列网格展示且不超过 3 行。
- “我的动态授权码”左侧显示钥匙图标，菜单名称、顺序和路由不变。
- 构建、列表治理、原型治理、专项业务检查、CodeGraph 同步和任务收据通过。

## 9. 假设与待现场确认

- 本轮按用户提供的 2026-09-02 线上页面作为视觉与字段基线。
- Mock 数量和账号只用于原型演示，不代表真实工厂当前数据。
- 真实打印机、真实扫码枪、现场 PDA、弱网和生产权限未由本地浏览器证据替代，部署后需另行验收。
