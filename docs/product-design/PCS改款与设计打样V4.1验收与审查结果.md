## 1. 与原实现相比的实际变化

| 业务位置 | 原实现 | V4.1 实现 | 可观察结果 |
| --- | --- | --- | --- |
| 列表动作 | “列设置”和“新建”同时出现在页面标题区 | 新建保留页面右上；列设置只放在数据列表表头最右侧 | 页面只出现一个列设置 |
| 新建草稿 | 按目标款已有颜色立即生成 BOM | 只建立打样业务单，BOM 和专业任务均为 0 | 先由买手定义本次新款资料 |
| 目标颜色 | 固定使用目标款档案已有颜色 | 买手可新增、选用或移出本次颜色 | 颜色数可少、可多、可相同 |
| 颜色参考 | 每个 B 色机械选择 A 色 | 每个目标颜色可参考 A 色或无参考；允许一对多 | 参考关系与本次新款事实分开 |
| BOM 时点 | 颜色确认前已存在空壳 BOM | 确认 N 个目标颜色后建立 N 份 B 款 BOM 草稿 | 颜色和 BOM 一一对应 |
| BOM 来源 | 可能读取 B 款同色历史 | 只有明确 A 款参考色才读取合格 A 款 BOM；无参考时空白 | 来源可解释、可追溯 |
| BOM 修改 | 参考转换与最终 BOM 维护割裂 | 买手直接维护 B 款 BOM；A 款只读；明确重新生成才覆盖 | 不会静默丢失买手修改 |
| 详情结构 | 各团队内容从上到下平铺 | 四步导航：新款资料准备、工作安排、专业工作、整单确认 | 默认只展示当前团队的工作 |
| 团队交接 | DRAFT 无法区分买手／跟单 | 当前步骤和当前团队由完成事实推导，操作后自动推进 | 列表与详情一致显示轮到谁 |
| 退回 | 缺少买手和跟单之间的修订闭环 | 工作安排前，跟单可填写原因退回买手 | BOM 解锁，买手修改后再次交接 |
| 页面骨架 | 改款／设计可能形成独立布局 | 标准列表、详情头部、当前动作、内容卡片和操作记录与专业任务一致 | 页面习惯统一 |
| 上传 | 页面重组存在退回文件名模拟的风险 | 真实文件选择、读取、保存、失败阻断、预览和下载 | `.prj`、样衣图及附件可真实验收 |

### 3.3 目标颜色少于来源款（对应 19.3、ADJ-030、ADJ-031、ADJ-033）

1. 来源款存在多个可参考颜色。
2. 买手只建立一个目标颜色，并选择其中一个 A 款颜色为参考。
3. 系统只建立一个目标颜色和一份 B 款 BOM，不为未选择颜色建立空壳 BOM。

结果：领域契约在最后一次源代码修改后通过，证据编号 E-AUTO-06；当前实现结果符合预期。

### 3.4 目标颜色多于来源款及一对多（对应 19.4、ADJ-030～ADJ-034）

1. 买手建立三个目标颜色。
2. 两个目标颜色共同参考同一个 A 款颜色。
3. 第三个目标颜色选择“无参考颜色”。
4. 系统建立三份 B 款 BOM；前两份从同一合格 A 款 BOM 独立带入，第三份为空白。

结果：领域契约验证 `3 个目标颜色 = 3 份 BOM`，并验证一个 A 色可对应两个 B 色和无参考色。通过。

### 3.7 买手到跟单交接（对应 19.7、ADJ-036～ADJ-038）

真实浏览器步骤：

1. 买手完成一个目标颜色及其 BOM。
2. 点击“完成新款资料准备，交给跟单”。
3. 页面自动进入“第二步：工作安排”，当前团队切换为跟单。
4. 跟单填写原因退回买手，页面自动回到第一步，BOM 重新开放。
5. 买手完成修改后再次交给跟单。

结果：全流程通过；操作记录保留完成、退回、再次完成事实。

### 3.8 跟单到专业团队交接（对应 19.8、ADJ-036～ADJ-038）

1. 跟单看到系统建议和固定依赖。
2. 确认工作安排后一次生成基码纸样和销售展示样衣任务。
3. 页面自动进入“第三步：专业工作”。
4. 销售展示样衣等待基码纸样，不允许绕过。
5. 基码纸样完成后，销售展示样衣自动进入可开始。

结果：真实浏览器通过；专业任务页面与主任务共用同一任务事实。

### 3.9 专业团队到整单确认（对应 19.9、ADJ-037、ADJ-041）

1. 版师开始基码纸样任务。
2. 上传空 `.prj`，页面明确阻断。
3. 上传真实非空 `.prj`，填写版本、部位／尺码和说明后提交。
4. 下载链接保留原文件名。
5. 制作团队开始销售展示样衣任务，上传真实 JPEG，填写数量、颜色、尺码和纸样版本后提交。
6. 大图可打开，`Esc` 可关闭。
7. 所有专业任务完成后，主任务自动进入“第四步：整单确认”。
8. 跟单填写成果版本和整单说明，确认后状态为已完成。

结果：真实浏览器全流程通过。

## 5. 审查结果

### 5.1 正向追踪

ADJ-028～041 均已从专项设计章节映射到 WP10、实现位置、专项契约和适用页面场景，并在最后一次源代码修改后取得直接证据；正向追踪 14／14 通过。

### 5.2 反向追踪

| 反查项 | 结果 |
| --- | --- |
| 是否仍在创建草稿时提前建立 BOM | 否 |
| 是否仍把 B 款现有颜色固定为本次目标颜色 | 否 |
| 是否按名称或 B 款历史 BOM 隐式复制 | 否 |
| 有多份合格 A 款 BOM 时是否确定选择最近一份 | 是；按完成确认时间或更新时间倒序选择 |
| 是否允许工作安排后修改目标颜色 | 否 |
| 是否允许买手完成后绕过跟单继续改 BOM | 否 |
| 是否存在另一套团队专属状态 | 否；只保留统一状态和团队筛选 |
| 是否把个人当成未开始任务负责人 | 否；先显示团队，实际动作后记录个人 |
| 是否仍纵向平铺四个团队工作表单 | 否 |
| 是否只有文件名／地址模拟上传 | 否 |
| 是否把设计打样错误显示成 A→B | 否 |
| 是否让独立打样 BOM 提前成为正式版本 | 否；仍为草稿，正式版本由技术包审核形成 |

### 5.3 本轮查漏补缺发现

1. 浏览器验收最初发现：完成买手、工作安排或最后专业任务后，领域状态已改变，但页面仍停留在旧步骤。已统一在成功动作后重新选择当前业务步骤，并重放完整流程通过。
2. 浏览器验收脚本最初把清空本地数据注册成每次页面跳转执行，导致刚生成专业任务在全页导航时被测试误删。已修正测试隔离方式；生产数据保存／读取链路无需为测试问题增加兼容代码。
3. 设计打样首条 Mock 已完成，默认显示第四步。验收改为点击第一步回看，验证“四步骨架”和“已完成步骤可回看”，不再错误要求所有详情必须从第一步开始。
4. 最终代码审查发现：合格来源 BOM 列表虽然过滤了状态，但未明确按完成／更新时间倒序，不能保证取到“最近一份”。已补充排序并新增多版本回归，验证 B 款带入最新来源版本的物料用量。

### 5.4 当前风险和边界

- 本仓库是前端高保真原型，文件保存使用浏览器可持久化的原型事实，不代表已接入云存储或生产后端。
- 用户工作区存在与本 PCS 任务无关的 FCS 修改；最终验证和任务收据必须隔离或明确说明，不能吸收这些差异。
- 当前分支未提交、未推送，因此最终只能达到 `verified`，不能声明 `delivered`。
