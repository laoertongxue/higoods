# 七张新生产需求单全流程：只读覆盖审查

审查输入：`生产工艺路线与全阶段加工单增量迭代调整方案.md` §5～7、§12，与 `七张生产需求单全流程验收.md` 当前7CASE/16E2E计划。只审设计覆盖，不读取代码结构、不操作浏览器、不初始化数据、不修改workspace。

**结论：七张单的数量满足“至少五张”，但当前场景定义不足以覆盖所有规范性流程。** 本文“已明确”仅表示计划有对应，不表示已执行或通过。E2E-003/004/013/016等总括条目不能单独证明其下每条具体业务分支。每一新增路径必须记录新需求→新生产单→适用任务→真实交接→该单最终责任接收→人工完成；原专项仅作为补充依赖。

## 2. §5～7还有§12未穷尽的对象缺口

### 准备对象补充

- §5 PREP007独立水溶与PREP008染色内嵌水溶是两个载体场景：现七单都未明确。建议CASE01不同适用材料分支分别承接；内嵌只存在染色单内部要求，不再多生独立水溶，独立单必须真实分批交出/人工完成。
- PREP009合并染色编组：选上述同条件两张已经存在的染色单（可来自两新需求，满足真实合并条件）；实际编组执行、拆开追溯，各原单数量、来源、occurrence保留。反例不同单位/不可合并条件拒绝或按已有规则分开，不能把编组作为第三个需求。
- PREP012物料准备/领料：在CASE01上游已交出但尚未人工完成时，核对可领与加工完单不同；只有合法仓储可用量可领。备货未绑定生产单前仍保持备货来源，后续分配不重建历史。

## 3. 最小执行增补排序

1. 先把CASE01具体化为A/B路线、多occurrence、裁片分两批、仅车缝锁三项；CASE02具体化为反序准备（若资料支持）、部分SKU第6次回货、QC空项与部分返厂恢复；CASE03分空项批/手选两项批并绑定实际辅料调拨。
2. CASE04明确纱线（若需先染则染纱）与毛织成衣；CASE05明确两类片分别交出、先到先开工；CASE06/07各自合法KOL终点不借普通POST。
3. 单列新单相关备货/补料六来源和水溶独立/内嵌、共享产出两消费、合并染色执行编组；记录所属CASE、原源单与最终消费。
4. 用“每个§6对象→已确认技术包→新CASE”的表选择必要新增适用款；没有合法款承接的项保持未覆盖，不能以旧生成专项替代。
5. 把物料替换、差异授权、版本订正、草稿接管、错码恢复、SPU替换分别固定到某一批次，失败后必须继续完成本需求剩余量。
6. 历史名称/旧ID/旧store迁移和静态禁词作为H01～H03等伴随审查，不算新需求数，也不强行套进新需求业务。历史映射仍未建立时明确残余，不虚构正式目标。

## 4. 逐CASE真正终点

普通新需求的终点不是FCK生成：应同时满足适用任务人工完成、所有回货批次质量/返厂/未处理余量各有合法去向、所有应入仓出货由外部仓库责任确认唯一实收、生产单明确人工完成；不得不同SKU互相抵消。备货/补料/专项部件的终点是实际被目标任务消费并随所属新需求走到终点，不以部件交出本身计整单通过。KOL按原独立终点核对，不能为统一表格伪造普通QC/FCK。

边界动作终点统一为：拒绝有明确现场提示、前后数量/状态/原关系未被污染、正确恢复后原新单继续至上述终点。若原流程缺少恢复动作，是本轮真实缺口，不允许删掉剩余量或预置终态关闭。

本文没有判定任何CASE/E2E已验证；只形成规范性覆盖缺口与最小执行补充。
