# 后道交接 SKU 明细与已交出调整方案

## 1. 目标与边界

本次只收口后道工厂 PDA 的接收明细、交接状态和现场操作页返回入口，不改变 Web 后道出货单、成衣仓确认状态及回货数量规则。

- “接收”必须让现场人员知道本次在收哪个 SKU，不能只显示整体数量。
- “接收明细”必须展示每个 SKU 的款式图、SPU、SKU、颜色、尺码和本次数量，并保留应收、实收、差异和状态。
- 后道工厂“交接”只保留“待接收”和“已交出”；不再让后道工厂从“待交出”重复发起交出。
- “已交出”直接读取 Web “后道出货单”的同一组单据；生成出货单即表示后道已交出，出货单的“待确认／已确认”仍表示成衣仓是否确认。
- 后道加工和后道复检是从“执行”工作台进入的操作页，必须可明确返回该工作台。

## 2. 页面与交互

### 2.1 待接收详情

顶部继续展示生产单和整单应收／已收／待收。“当前等待你确认”区域在交付数量和时间下方显示当前 SKU 识别卡；数量确认、数量差异和驳回动作仍只针对当前 SKU。

历史区改为“接收明细（N 个 SKU）”。展开后每条是一个 SKU 明细，可查看对应款式大图，并继续展示该行的应收、实收、差异、确认时间和处理状态。

### 2.2 交接已交出

“已交出”卡片展示后道出货单号、生产单号、复检单号、SKU 种数、交出数量、成衣仓已确认数量、出货单状态、时间和操作人。展开后逐 SKU 显示款式图、SPU、SKU、颜色、尺码和交出数量。本页只读，不放“发起交出”。

### 2.3 后道加工与复检

两个页面标题栏左侧增加“返回”，返回后道工厂的“执行”工作台。无论尚未扫描还是已进入具体单据，返回入口都必须可见。

## 3. 正常与边界场景

- 正常接收：打开生产单待接收，能看到当前 SKU 和数量；展开接收明细可核对全部 SKU。
- 已交出：Web 已有后道出货单时，PDA 显示同一出货单号和同一组 SKU 数量。
- 成衣仓未确认：出货单仍出现在“已交出”，同时保留“待确认”状态和 0 件已确认数量，不将其误判为尚未交出。
- 旧地址：后道工厂访问 `tab=handout` 时不再展示“待交出”，回到“待接收”。
- 其他工厂：通用工厂仍保留原有“待接收／待交出”，本次不扩大改动范围。

## 4. 验收标准

1. 后道待接收当前区和历史区都有可识别的逐 SKU 明细。
2. 后道交接不存在“待交出”，存在“已交出”。
3. “已交出”的单号、状态、数量和 SKU 与 Web 后道出货单一致。
4. 后道加工和后道复检可返回“执行”工作台。
5. 390×844 和 480×800 视口无横向溢出，图片可打开大图，加载失败有明确提示。
6. 通用工厂原有交接页签和接收记录不受影响。
