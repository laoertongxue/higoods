## 1. 调整结论

本次不是在现有页面上增加几个 PPIC 筛选条件，而是要建立一个以“一家三方车缝工厂对应一张执行任务”为责任颗粒度、贯穿任务分配、物料交出、产前版样衣、批版建议、生产、回货、异常和退仓的车缝外发协同域。财务结算属于完整业务链的相邻专业域，但本轮暂不在PPIC侧建设菜单、页面或专属投影。

建议新增一级菜单 **“车缝外发协同”**。菜单服务的是车缝外发业务，不以组织名称“PPIC管理”命名；PPIC 是主要使用者，但裁床、批版人员、后道、仓库、财务和负责人也要在同一链路中提供或消费事实。

完整调整必须先完成以下底层收口，再建设工作台：

1. 纠正任务分类：业务只有独立车缝、车缝＋烫包、裁剪＋车缝＋烫包三类；“独立车缝单厂／多厂”只是分配结果。
2. 只有独立车缝可按完整 SKU 拆给多厂；两个组合任务必须整任务、单工厂。
3. 分配工厂时冻结任务 PPIC；工厂以后换 PPIC 不得自动改写未完任务，只有管理人员婕哥、凌云可以显式移交。
4. 对独立车缝、车缝＋烫包，把裁片放行从风险提示改为派单硬门禁，并禁止把放行调低到有效分配以下。
5. 同时建立“裁床欠工厂的裁片片数”和“工厂欠公司的成衣件数”两本账。
6. 以完整 BOM 必需部位计算严格齐套；建立 PPIC 人为排除部位记录，以有效齐套确定工厂回货责任，但不消灭欠片。
7. 保留三方工厂制作的“产前版样衣”实物对象，新建“批版建议”业务记录与页面；PCS 当前同名对象统一显示为“首单样衣”。
8. PPIC 只读取裁床补料事实，不创建、不推进补料单；工厂线下提出裁片退仓，当前任务PPIC核对后在系统建单，裁床待交出仓只接收、记录差异和入仓。
9. PPIC 回货只读取后道最终确认数量和时间，不允许手工补录；30%／70%／100%时效统一从这一事实计算。
10. 建立个人工作台，把 600 多家工厂转化为当前登录PPIC名下各类情况的汇总和专业入口；工作台不得出现车缝任务列表，具体任务统一进入“车缝任务”页。
11. 工作台区分普通PPIC与婕哥、凌云两名管理人员；“交出与欠片”及其他专业页按一眼可识别的当前情况分组。
12. 完整删除PPIC侧“对数与结算跟进”的菜单、路由、页面、专属数据和处理器，不影响相邻财务域已有能力。

## 5. 目标业务对象与关系

### 5.1 主链关系

```text
上游车缝来源任务
  ├─ 独立车缝：可按完整 SKU 拆分
  │    ├─ 执行任务 A = 工厂 A + 冻结 PPIC A
  │    └─ 执行任务 B = 工厂 B + 冻结 PPIC B
  ├─ 车缝＋烫包：整任务 → 一个执行任务 = 一家工厂 + 一个 PPIC
  └─ 裁剪＋车缝＋烫包：整任务 → 一个执行任务 = 一家工厂 + 一个 PPIC

每个执行任务
  → 物料前置事实
  → 产前版样衣送回与批版建议
  → 生产阶段与异常
  → 后道确认回货
  → 质量／仓储事实
  → 对数与结算
```

来源任务只负责聚合，执行任务才是 PPIC 责任、工厂责任、物料、首件、回货、异常和结算跟进的主对象。

### 5.2 核心对象

| 对象 | 唯一业务含义 | 关键身份 |
|---|---|---|
| 来源任务 | 上游形成的完整车缝责任范围 | `sourceTaskId`、生产单、任务类型 |
| 执行任务 | 一家工厂实际承接的一张任务 | `executionTaskId`、任务号、来源任务、工厂、SKU范围 |
| 有效分配 | 某次生效的工厂、数量、工价、业务分配时间 | `assignmentId`、执行任务、工厂、分配版本 |
| 任务 PPIC 责任 | 分配当时冻结的责任人及后续显式移交 | 执行任务、责任版本、原／新PPIC、有效时间 |
| 裁片放行版本 | 裁床对可供分配数量的承诺 | 来源任务／SKU／颜色尺码、版本、放行数量 |
| 裁片交出批次 | 实际交给具体执行任务工厂的裁片 | 执行任务、批次、颜色、尺码、部位、片数 |
| 裁片欠片账 | 公司／裁床尚欠工厂的具体裁片 | 执行任务、颜色、尺码、部位、欠片数 |
| 部位排除决定 | PPIC对有效齐套口径的版本化调整 | 执行任务、范围、部位、原因、证据、审核 |
| 回货责任账 | 工厂基于有效齐套应向公司交回的成衣 | 执行任务、责任版本、累计件数 |
| 面辅料交出 | 裁剪＋车缝＋烫包的面料与辅料应交／实交 | 执行任务、物料、单位、批次、差异 |
| 产前版样衣 | 三方工厂收到裁片／物料后制作并送回的一件大货产前版实物 | 执行任务、工厂、样衣标识、照片、送回时间、去向 |
| 批版建议 | 批版人员对照公司样衣、生产单图片、纸样和面辅料后上传的核对结论与四类结构化意见 | 执行任务、工厂、产前版样衣、批版人员、结论、批版面料、工艺意见、用料意见、其他意见、版本 |
| 后道确认回货 | 后道对工厂实际回货的最终确认事实 | 送货单、执行任务、分配、SKU、确认数量／时间 |
| 回货履约投影 | 根据分配、有效齐套和后道确认形成的节点状态 | 执行任务、30%／70%／100%节点 |
| 异常／跟进 | 当前问题、下一责任方、承诺与下次跟进 | 执行任务、异常类型、责任方、期限 |
| 结算跟进 | 是否具备结算条件及未决事项 | 执行任务、工价版本、合格量、调整、状态 |

### 5.3 不允许只用生产单或 SPU 聚合

同一生产单可以有多个来源任务；独立车缝来源任务还可以拆成多个工厂执行任务。所有可改变责任、数量、时效和结算的事实必须至少带 `executionTaskId` 和 `assignmentId`。生产单、PO、SPU 只能用于查询聚合，不能替代具体任务身份。

## 6. 三类任务的统一规则

| 项目 | 独立车缝 | 车缝＋烫包 | 裁剪＋车缝＋烫包 |
|---|---|---|---|
| 多厂 | 允许 | 不允许 | 不允许 |
| 最小分配颗粒度 | 完整 SKU，同一 SKU 不拆数量 | 整张任务 | 整张任务 |
| 一厂一任务 | 是 | 是 | 是 |
| 裁片放行门禁 | 有 | 有 | 无 |
| 裁片交出／欠片 | 有 | 有 | 无 |
| 面料／辅料交出 | 按现有上游责任，不在本域代替裁片账 | 按现有上游责任，不在本域代替裁片账 | 必须有，分别按自身单位记账 |
| 人为排除部位 | 适用 | 适用 | 不适用 |
| 产前版样衣 | 有 | 有 | 有 |
| 批版建议 | 有 | 有 | 有 |
| 30%／70%／100% | 第4／8／9自然日 | 第5／9／10自然日 | 第6／9／12自然日 |
| 回货来源 | 后道最终确认 | 后道最终确认 | 后道最终确认 |

## 7. 详细调整方案

### 7.1 任务分类、拆分和执行任务生成

1. `merged-production-task.ts`中两个组合任务的 `assignmentGranularity`改为整任务。
2. `allocateRuntimeSkuTaskScope`只允许独立车缝任务调用；对两个组合任务调用时直接阻断。
3. `dispatchRuntimeTaskByDetailGroups`在数据层再次校验：组合任务只能有一个工厂分组且必须覆盖完整任务范围，不能只依赖页面隐藏。
4. 独立车缝多厂拆分前校验每个 SKU 恰好属于一个工厂，同一 SKU 不得按数量分成两份。
5. 每个工厂分配成功后形成独立执行任务；来源任务汇总子任务状态、数量和工厂，不承载单一 PPIC。
6. 改派工厂应关闭旧有效分配、形成新分配版本。旧分配的交出、回货、异常和结算事实继续保留，不移动到新工厂。
7. 同步改写当前把“组合任务可按完整SKU拆分”当作正确行为的检查、Mock 和页面文案。

### 7.2 工厂 PPIC 主数据、任务冻结和责任移交

本方案中的“凌云”是PPIC团队负责人的人名，不是系统、算法或补料来源；当前具备团队管理权限的两个人是婕哥、凌云。

1. 正式三方车缝工厂保存时必须有且仅有一个有效 PPIC；入驻转正式前同样阻断缺失归属。
2. 当前默认补齐只解决原型空值，正式迁移必须导入真实 PPIC 名单与工厂映射，并输出缺失、重复、停用人员三类阻断清单。
3. 未分配任务没有任务 PPIC；它位于共享待分配池。
4. 分配工厂成功的同一事务内读取工厂当前有效 PPIC，并把 `ppicId/name`、来源工厂归属版本和冻结时间写入执行任务责任记录。工厂与 PPIC 关系是 1:N，但任务只冻结一个当前责任人。
5. 工厂主数据换 PPIC只影响后续新任务，不自动修改任何未完任务。
6. 新建“未完任务责任移交”。只有PPIC管理人员婕哥、凌云可发起；权限应绑定其有效账号／人员 ID，而不是用显示姓名字符串判断。移交时选择原 PPIC、目标 PPIC、具体未完执行任务、剩余事项和生效时间。
7. 移交不是改历史：原责任版本结束，新责任版本开始；交出、首件、回货、异常和跟进日志仍保留原操作人。
8. 完结任务原则上不可移交；如需纠错，走有理由、有审核的历史订正，不复用普通移交。

### 7.3 裁片放行与分配额度硬门禁

适用范围仅为独立车缝和车缝＋烫包。

1. 同时展示目标数量、当前齐套数量、当前有效放行数量，不互相覆盖。
2. 按任务范围、SKU、颜色、尺码建立有效放行与有效分配的同颗粒度对照。
3. `可分配余量 = 当前有效放行数量 - 当前有效分配数量`。
4. 没有有效放行、分配范围找不到对应放行、或任一明细分配超过余量时，整个分配失败，不生成半张任务。
5. 修改放行时先计算当前有效分配下限。新放行小于下限时整个保存失败，旧版本继续有效，并提示最低可保存数量及占用它的执行任务。
6. 放行高于当前齐套仍可按已有业务保留风险确认，但风险确认不能绕过目标上限和已分配下限。
7. 撤销尚未发生实物与回货事实的分配后，释放相应额度；已有实物事实的撤销必须先走业务收口，不得直接返还额度。
8. 裁剪＋车缝＋烫包不读取裁片放行，也不生成裁片分配额度。

### 7.4 裁片交出、欠片、严格齐套和有效齐套

1. 每次实交绑定具体执行任务、工厂、批次、颜色、尺码、部位、每件用量和片数。
2. 分配承诺按完整 BOM 必需部位展开，不能只遍历本次实际出现的部位。完全未交的必需部位数量按 0 参与严格齐套。
3. 对每个颜色尺码和部位计算：

```text
应交裁片数 = 执行任务该颜色尺码分配件数 × 每件该部位用量
累计有效实交 = 所有已确认交出批次之和 - 已确认退回／作废之和
欠片数 = max(应交裁片数 - 累计有效实交, 0)
多交数 = max(累计有效实交 - 应交裁片数, 0)
严格齐套件数 = min(每个必需部位的 floor(累计有效实交 ÷ 每件用量))
```

4. 不同部位的多与少不能抵消；不同颜色、尺码、任务和工厂也不能抵消。
5. 欠片账单位为片，保留结构性缺失、较大缺口和零散差异全部明细。
6. 回货责任账单位为件，只能从有效齐套形成；两本账分别展示，不把片直接换算为扣款件数。

### 7.5 人为排除部位

1. 人为排除面向“整个部位未及时裁出”或“较大比例短缺、主体可以先生产”等实际场景，不为零散少 1～2 片自动制造首页高优先级异常。
2. PPIC在执行任务下选择具体颜色、尺码、部位和适用批次，填写原因、生产影响、图片／沟通证据及预计补交时间。
3. 排除决定必须有版本、申请人、审核人、时间和有效状态。可取消排除，但不能删除历史。
4. `有效齐套件数`只在当前有效排除集合之外求最小值；`严格齐套件数`始终按全部必需部位计算。
5. 排除不改 BOM、不删除应交、不清零欠片、不表示质量合格，也不自动表示允许结算。
6. 每次已确认交出形成回货责任增量快照。后续补交只消减欠片；已有责任不能因重新计算重复增加，也不能被静默回写。需要纠错时使用授权调整记录。
7. 工作台根据业务影响分级：完整部位缺失、较大比例缺失、已排除、影响里程碑或超期时突出；微小差异留在明细，临近收口或实际影响生产时再升级。

### 7.6 裁剪＋车缝＋烫包的面辅料交出

1. 该类型由承接工厂负责裁剪，不生成裁片放行、裁片交出、欠片、严格齐套或部位排除。
2. 面料和辅料分别维护应交、实交、单位、批次、差异和接收确认，不允许把米、公斤、卷、个等单位混算。
3. 面辅料差异影响开工或时效归责时形成下一责任方，但不能借用“裁片欠片”的字段和文案。
4. 分配后即按整任务数量建立回货计划；公司面辅料交付延迟使用独立责任调整／暂停事实处理，不能伪造成裁片有效齐套不足。

### 7.7 产前版样衣、批版建议与 PCS 名称收口

需要区分四个对象／概念：

| 对象 | 正确名称 | 所属阶段 | 本次处理 |
|---|---|---|---|
| PCS 工程阶段当前 `PRE_PRODUCTION_SAMPLE` | 首单样衣 | 商品开发／工程准备 | 用户可见名称收口 |
| 工厂入驻审核样衣 | 工厂准入样衣 | 工厂准入 | 保持独立 |
| 三方车缝工厂执行任务的第一件大货产前版实物 | 产前版样衣 | 外发大货任务开始后 | 新建实物身份与交接记录 |
| 批版人员对产前版样衣和生产资料形成的意见 | 批版建议 | 外发大货任务开始后 | 新建业务节点、记录和页面 |

目标流程：

```text
待工厂制作产前版样衣
  → 产前版样衣待送回PPIC
  → PPIC已接收，待交批版人员
  → 批版人员核对中
  → 批版建议已上传（无问题／有问题＋四类结构化意见）
  → PPIC已查看并截图反馈外发工厂
  → 工厂按批版建议生产大货
```

批版人员至少对照：公司内部已制作／留存样衣、生产单图片、纸样、面料和辅料；存在工艺单、尺寸表等资料时，还要冻结本次实际引用的版本。

批版建议至少记录执行任务、SPU、PO、工厂、PPIC、产前版样衣标识与全部照片、样衣送达／转交时间、批版人员、批版日期、引用资料版本、结论、批版面料、工艺意见、用料意见、其他意见、线下批版单佐证照片和上传时间。结论只有“无问题”和“有问题”两个业务方向；选择“有问题”时四类意见至少填写一项。PPIC接收样衣照片必须支持多选、追加、预览、逐张删除及保存后全量回看。

“有问题”不是统一的“不通过”状态。按当前业务事实，批版人员上传四类结构化意见后，PPIC即可截图发给外发工厂，工厂据此生产大货。只有批版人员明确要求重新制作／再次批版时，才追加下一版；不再把“有问题就强制整改、重新送审、通过后才能生产”作为默认流程。

页面主标题、菜单和业务记录均使用“批版建议”，页面内部再展示关联的产前版样衣实物。截图卡片主体按线下登记台账展示PO、SPU、工厂、全部产前版样衣图片、结论、四类结构化意见、批版人员和日期；系统不代替即时通讯发送。

PCS收口优先更改用户可见名称和领域说明；内部 `PRE_PRODUCTION_SAMPLE`代码可先保留为兼容枚举，增加明确别名／迁移说明，避免一次性破坏依赖关系。最终是否改枚举代码需要通过影响分析后决定。

### 7.8 补料跟进

1. 补料单创建、修改、推进和放弃仍只在裁床模块发生。
2. 凌云可以与裁床沟通并形成 PPIC 跟进记录，但不能代替裁床发起补料操作。
3. PPIC侧建立只读关联：执行任务 → 缺片部位／数量 → 生产单 → 补料单 → 当前状态 → 可交工厂数量／时间。
4. PPIC可记录“已联系谁、承诺时间、下次跟进时间和结果”，这些是协同日志，不修改补料单业务状态。
5. 附件中的第一次、第二次、第三次跟进作为展示重点，不把日志限制为最多三次。
6. 找不到补料单时明确显示“当前无补料单”，而不是自动创建；需补料时引导穿透到裁床页面或联系裁床责任人。

### 7.9 裁片退仓

目标状态：

```text
工厂线下向任务PPIC提出退仓
  → PPIC核对任务、部位、数量并在系统建单
  → 待裁床待交出仓接收
      ├─ 实物差异 → 仓库记录异常 → 当前PPIC重新确认
      └─ 接收一致 → 已入退裁片库区
```

工厂不直接登录PPIC管理端发起。PPIC在线下收到需求后核查部位、尺码、数量、关联执行任务和退仓原因，建单即冻结待接收明细，不再增加“待PPIC审核”状态。仓库只识别PPIC创建的退仓对象、按建单结果接收并入仓；发现实物不一致时只能记录接收差异并交当前PPIC重新确认，不能自行重做业务审核或静默改数。

### 7.10 后道回货唯一事实源

1. 后道回货确认对象补齐 `executionTaskId`、`assignmentId`、`factoryId`、任务类型和 SKU 范围，不能仅靠生产单号或 `sewingTaskNo`模糊匹配。
2. 工厂登记数量是申报，后道最终确认数量和 `confirmedAt`才是 PPIC回货事实。
3. PPIC没有新增、修改或删除回货数量的入口。发现错误时由后道按其授权流程订正，PPIC投影自动更新并保留版本／日志。
4. 一张送货单只能归属一个有效分配；改派前后的回货分别进入旧、新分配，不能因同一生产单而合并。
5. 当前 `post-finishing-full-flow.ts`需先完成基线归属确认，再作为正式事实源；在此之前不允许新 PPIC 模块直接依赖未受控文件。

### 7.11 回货时效和责任归因

统一保留当前已经明确的规则：

| 任务类型 | 30% | 70% | 100% |
|---|---:|---:|---:|
| 独立车缝 | 第4自然日 | 第8自然日 | 第9自然日 |
| 车缝＋烫包 | 第5自然日 | 第9自然日 | 第10自然日 |
| 裁剪＋车缝＋烫包 | 第6自然日 | 第9自然日 | 第12自然日 |

- 业务分配日为第 1 自然日。
- 节点截止时间为对应自然日 23:59:59。
- 节点计划数量 `ceil(执行任务有效分配件数 × 节点比例)`。
- 累计实回只汇总截至节点时间的后道最终确认数量。

独立车缝和车缝＋烫包同时展示：

```text
计划节点目标 = ceil(分配件数 × 节点比例)
节点工厂可归责目标 = min(计划节点目标, 截至该节点截止时间已形成的累计回货责任件数)
裁床供片差额 = max(计划节点目标 - 工厂可归责目标, 0)
工厂节点待回 = max(工厂可归责目标 - 节点前后道确认累计回货, 0)
```

裁床供片差额进入跟进裁床，不自动记为工厂延期。节点截止以后才形成的有效齐套不能倒算成工厂在原节点已经逾期；该新增责任从什么时间开始计算新的工厂承诺，需通过补交时间、正式调整或产品确认的追赶规则处理。裁剪＋车缝＋烫包没有裁片齐套约束，默认全分配量归工厂履约；面辅料延迟等公司原因通过独立责任调整影响归责。

`sewing-delivery-sla.ts`与`production-return-fulfillment.ts`目前存在平行投影。建议保留一套执行任务级履约事实：以有效分配快照、任务类型时效表、后道确认回货和责任调整为输入；现有其他页面改为读取适配器，最终删除重复存储和手工回货 Mock。

### 7.12 生产、异常和跟进日志

生产进度至少支持初期、中期、末期三个业务阶段及更新时间，但阶段的精确字段、比例或触发条件需要产品补充。任何异常必须包含：执行任务、异常类型、影响 SKU／数量、当前责任方、下一动作、承诺时间、下次跟进时间、最近结果、操作人和证据。

异常健康度与下一责任方是两个维度：

| 维度 | 值 |
|---|---|
| 健康度 | 正常、需关注、异常、数据不完整 |
| 下一责任方 | PPIC、裁床、三方车缝工厂、批版人员、后道、仓库 |

没有异常记录不等于正常。关键来源事实缺失、无法匹配执行任务或没有更新时间时显示“数据不完整”，不能用绿色正常掩盖数据断链。

### 7.13 PPIC结算能力删除边界

1. 完整删除“对数与结算跟进”菜单、路由、页面、页面处理器、PPIC专属准备度投影、Mock和专项脚本。
2. 我的工作台、车缝任务操作列、全链详情和专业页面都不再出现PPIC结算入口或“已完成未结算”卡片。
3. 财务域已有工价、对账或结算能力不在本次删除范围，不得为删除PPIC页面而破坏全局财务模块。
4. 如未来重新纳入，必须先明确正式数据源、角色权限、数量口径和验收门禁，作为一项新需求实施，不能复活旧页面代码。

## 8. 一级菜单、页面与信息架构

### 8.1 一级菜单名称

首选：**车缝外发协同**。

备选：“车缝外发”。不建议“PPIC管理”，原因是它表达组织管理而不是业务链路，也会让裁床、后道、仓库和财务误以为这些事实与自己无关。

### 8.3 我的工作台

工作台的数据入口是“当前登录人负责范围内执行任务的汇总事实”，不是先列出600多家工厂，也不是复制一张车缝任务表。

首屏建议：

- 汇总入口：未交出、已交出且欠片、产前版样衣／批版建议未闭环、30%／70%／100%临期或未达成、尚未完成、异常／数据不完整。
- 下一责任方汇总：裁床、工厂、批版人员、后道、仓库。
- 每张汇总卡只显示数量、范围说明和进入专业页面的动作；不得渲染任务行、表格分页、任务操作列或伪装成任务列表的卡片队列。
- 普通PPIC的个人工作台直接绑定登录身份，不提供身份切换；婕哥、凌云进入团队工作台并可按成员筛选，不能借团队筛选伪装成普通PPIC执行动作。

### 8.4 执行任务详情

任务详情以时间线和数量卡片贯穿：来源与分配 → PPIC责任 → 物料 → 产前版样衣 → 批版建议 → 生产 → 回货 → 质量／仓储。每个阶段显示来源系统、最后更新时间和穿透链接。

### 8.5 查询入口简化

删除独立“综合查询”菜单、路由、页面和专用聚合数据，同时完整删除PPIC侧“对数与结算跟进”。附件中本轮仍保留的信息回到“我的工作台”“车缝任务”操作列、任务全链详情及补料、退仓、回货等专业页面查看，避免重复列表、重复口径和重复穿透入口。

车缝任务不再单列“专业来源”列；批版建议、补料跟进、回货跟进、裁片退仓等入口与“全链详情”统一放入操作列。

“交出与欠片”固定按未交出、已交出不欠片、已交出且欠片三个Tab展示；批版建议、补料跟进、回货跟进、裁片退仓也按待处理／异常／已完成等业务情况分组，不使用一张混杂列表要求PPIC自行理解。

车缝外发协同页面删除只用于解释系统设计的蓝色／紫色提示横幅，仅保留操作成功、失败、阻断、差异和恢复动作等当前业务反馈。

### 8.6 页面设计门禁

- 工作台和标准列表按管理端 1366×768、最低 1280×720 验收。
- 标准列表使用现有列表组件、分页、列显示／顺序／冻结和表格内横向滚动。
- 所有出现款式、SKU、面料或辅料的位置必须使用与对象对应的真实图片；缩略图与编号同块展示，可打开高清大图，并具备加载／失败状态。
- 批版建议页还必须展示本次全部产前版样衣照片和批版依据；截图卡片需要在一个清晰信息块内呈现结论与批版面料、工艺意见、用料意见、其他意见，不能要求PPIC拼接多页截图。
- 红色只用于阻断／错误，黄色用于需关注，绿色用于已完成／一致，数据不完整不能显示绿色。
- 本轮主操作在 Web 管理端；裁片交出、后道回货、仓库接收如继续由 PDA执行，必须读取同一执行任务和数量事实，扫码后展示图片、尺码、数量和差异。
- 当前需求没有新增 PPIC 打印单据；批版建议采用屏幕截图卡片，不把截图需求擅自扩张成打印模板或即时通讯集成。

|---|---|---|---|
| 分配／改派工厂 | 当前登录的有效PPIC／PPIC管理人员 | 执行动作并查看结果与责任 | 分配操作PPIC、任务责任PPIC、前后工厂、范围、工价、时间、原因 |
| 维护工厂当前 PPIC | 工厂主数据管理员／PPIC管理人员授权 | 普通PPIC只读 | 前后PPIC、操作人、时间 |

| 发布／修改裁片放行 | 裁床授权人 | 只读 | 三数量、分配下限、版本、原因 |

## 10. 数据迁移与兼容策略

### 10.1 开工前置

1. 先确认当前大量未提交改动及未跟踪后道全流程文件是否作为新实施基线。
2. 获取真实 PPIC 人员清单、工厂清单和唯一归属映射；先做只读校验报告，再允许迁移。
3. 为现有未完执行任务确定历史责任人。不能只按迁移当天工厂当前 PPIC 自动回填；无法确认的任务进入待人工认领／凌云确认清单。

### 10.2 任务与放行

1. 识别当前组合任务被拆给多厂的历史样例。历史只读保留，不自动合并；新分配立即执行新规则。
2. 为现有有效分配建立放行占用投影。发现已分配超过当前放行时，不调低分配、不静默补放行，生成迁移阻断清单，由裁床／计划确认后再启用新编辑门禁。
3. 已有裁片交出按执行任务重新关联。无法唯一匹配的记录标记数据不完整，不猜测工厂或任务。

### 10.3 PPIC、产前版样衣与批版建议

1. 工厂当前 PPIC 与任务责任快照分两张事实维护。
2. PCS用户可见文案先统一为“首单样衣”；保留旧枚举／历史编码兼容读取，禁止把历史 ID 重新用于新外发产前版样衣或批版建议。
3. 新外发产前版样衣和批版建议只从新执行任务生成；不把工厂准入样衣或 PCS样衣批量迁成产前版样衣，也不把历史泛化“首件确认”自动迁成批版建议。

### 10.4 回货与PPIC结算入口删除

1. 后道送货单必须能唯一回填执行任务／分配。不能唯一匹配的历史回货只保留原查询，不进入自动 SLA。
2. 新旧回货投影允许短期对读核对，但页面只能展示标明来源的一套正式结果；核对通过后删除 PDA 交接作为回货事实的旧入口。
3. PPIC侧旧结算菜单、路由、页面、专属投影、处理器、Mock与检查脚本全部删除；相邻财务域不迁移、不重写。

## 11. 验收场景

至少覆盖以下命名场景，且每个场景都从具体执行任务追溯上下游：

1. 独立车缝按完整 SKU 分两厂，生成两任务、两工厂、两 PPIC；同一 SKU 数量拆分被阻断。
2. 车缝＋烫包选择部分 SKU 或第二家工厂被阻断。
3. 裁剪＋车缝＋烫包整任务分一厂，只出现面辅料交出，不出现裁片欠片。
4. 独立车缝无有效放行派单失败；放行 1000、已分配 800 时改为 700 整次失败且旧值不变。
5. 完整部位未交时严格齐套为 0；PPIC排除后有效齐套形成责任，欠片仍保留。
6. 后续补交被排除部位只减欠片，不把工厂回货责任重复增加。
7. 某部位存在低于需求量一半的局部缺口时保留明细；未排除、未影响生产且未逾期时不进入高优先级首页。整个部位、缺口达到需求量一半、已排除、影响生产或逾期则必须升级。
8. 工厂 PPIC主数据变更后，新任务取新PPIC；旧未完任务仍属原PPIC。
9. 婕哥或凌云显式移交选定未完任务，未选任务不变，历史责任可追溯。
10. 工厂制作产前版样衣并送回，PPIC上传多张实物照片后交给批版人员；批版人员对照公司样衣、生产单图片、纸样和面辅料，上传“有问题＋四类结构化意见”；PPIC打开截图卡片反馈工厂。任务不被自动改成“批版不通过／必须重新送审”。
11. 凌云协调缺片，裁床创建补料单；PPIC只看到单号、状态、缺少部位和可交状态。
12. 工厂线下提出裁片退仓，PPIC核对后建单；仓库读取建单数量，不能修改，只能接收或记录差异。
13. 工厂申报300、后道确认298，PPIC只显示298，第30%节点仍差2件。
14. 裁床有效齐套不足导致计划差额时，工作台下一责任方为裁床，不将差额计入工厂延期。
15. 后道确认回货、质检合格、大货入仓三个状态分别展示，不能一键同步完成。
16. 普通PPIC工作台只显示本人情况汇总且不存在任务列表；婕哥、凌云可查看团队汇总并进入责任移交。
17. “交出与欠片”三个Tab均有真实场景；未交出在交出前不判欠片，已交出不欠片与已交出且欠片不会混放。
18. 批版、补料、回货和退仓页均按当前情况分组；关键来源无法匹配执行任务时显示数据不完整，不显示正常。
19. PPIC侧菜单、路由、渲染器、处理器、数据模块和脚本均不存在对数与结算跟进残留。

## 12. 分期建议

### P0：事实源和硬门禁

- 任务分类／分配颗粒度。
- 执行任务身份、有效分配和任务 PPIC冻结。
- 裁片放行占用与两项硬门禁。
- 必需部位、严格／有效齐套、欠片和回货责任。
- 后道确认回货唯一关联与统一 SLA 投影。

P0 未完成前不建议正式建设工作台，因为任务归属、应回量和延期会继续错误。

### P1：核心协同

- PPIC责任移交。
- 产前版样衣交接与批版建议。
- 补料只读跟进。
- 裁片退仓职责拆分。
- 工作台、任务详情、回货和欠片页面。

### P2：查询收口和管理

- 各业务主题在工作台、车缝任务详情和对应专业页面中的查询与穿透。
- 月度汇总、产量、工费、特殊工艺联查。
- PPIC侧结算旧入口与专属代码删除；相邻财务域保持不变。
- 历史迁移收口、重复事实源和旧入口删除。

## 13. 仍需产品确认的决策

以下决策不会改变前述任务类型、责任、放行和回货来源，但会影响后续详细实现：

1. 一级菜单最终定为“车缝外发协同”还是“车缝外发”。本方案推荐前者。
2. 真实 PPIC与正式工厂映射清单，以及历史未完任务责任人的确认方式。
3. 批版人员标记“有问题”时，哪些严重情形需要明确要求重新制作产前版样衣并再次批版；默认场景仍按四类结构化意见直接指导大货生产。
4. 部位排除的最终审核角色、允许范围，以及排除部位未补齐时是否允许入仓／结算。
5. 欠片进入“需关注／异常”的业务阈值；本方案只确定结构性缺失和生产影响优先，不擅自设百分比。
6. 面辅料交付延误的暂停、归责和恢复规则。
7. 节假日、正式延期、暂停、撤销和改派后的 SLA 继承规则，以及节点后补齐裁片形成的新责任从何时起算。
8. 生产初期／中期／末期的具体字段、比例和确认责任。
9. 少数／超数原因字典、责任确认、申诉和扣款审批。
10. 若未来重新纳入PPIC结算跟进，需另行确认可结算数量来源、权限和页面范围；本轮不保留旧实现。
11. 产前版样衣归还／保管是否为任务完结硬门禁，以及由谁确认最终去向。
12. PPIC月度汇总用于工作量、风险管理还是绩效；未确认前不做排名。

## 14. 完成定义

本方案后续只有同时满足以下条件，才能从“方案”进入“完整交付”：

1. 98条原子业务需求全部映射到工作包、实现位置和证据，没有无说明遗漏。
2. 用户已确认规则覆盖旧代码、旧Mock和旧检查，冲突入口已同步删除或失效。
3. Web、适用PDA、路由、真实图片、数量、权限和异常场景在同一分支、同一工作树验证。
4. 后道最终确认回货能够通过具体执行任务／分配驱动唯一 SLA 投影，PPIC侧无手填回货和结算投影。
5. 最后一次修改后重新运行专项检查、构建、治理、CodeGraph同步和任务收据。
6. 追踪矩阵不存在无说明的`待实施`、`实施中`、`已实现待验证`或`已阻塞`条目。
7. 本地 `verified`、远端 `delivered`和产品 `accepted`分别保留证据，不互相替代。
