## 0. 执行结论

本次采用增量迭代方式。现有技术包路线数据、生产单技术包快照、显式任务关系、印花加工单主体、染色/水溶/毛织/特殊工艺专项单据、后道全流程、Web/PDA/打印入口继续作为实施基础，不建立平行模块，也不建立替代所有专项单据的“万能加工单”。技术包路线页面收口为单一三阶段工作区，旧独立画布及相关依赖已删除。

本轮实施只收口以下八类缺口：

1. 非裁片、车缝加工单的投入必须来自中央仓调拨或直接上游交出，不能无来源登记投入；
2. 每张加工单独立表达接收、加工、交出三个状态维度；
3. 每张加工单只允许一个下游接收方，但同一接收方允许多批交出和多批接收；
4. 生产准备末道根据生产、采购备货、补料来源解析真实目标仓，不再写死“中转区域”；
5. 页面在既有结构内精简文案和列，主体不横向溢出，宽表只在表格容器内滚动；
6. 所有用户可见的款式、物料、花型、部位图都绑定真实对应图片；缩略图与对象编号同区展示，点击可查看大图；
7. BOM 绣花属于准备阶段；BOM 绑定的捆条和橡筋定长切割属于生产阶段，并把被绑定 BOM 行传给实际加工单。
8. 常规 BOM 按线上 18 列、款色分组和原维护动作增量收口，物料缩略图必须是真实对应图片并可点击大图；烫画 BOM 不改动。

技术包工艺路线按三阶段实施：准备阶段从 BOM 面辅料的水溶、染色、印花、绣花要求生成，每条 BOM 物料并行、物料内工艺串行；生产阶段先裁剪，再读取纸样包逐片工艺顺序形成并行裁片分支，同时把 BOM 绑定的捆条或橡筋定长切割作为面辅料加工分支，全部裁片和面辅料加工完成后汇入车缝；车缝回货后进入后道阶段。纸样包内显示“第 N 道”并提供上移/下移，路线页只能读取，不能另改裁片工艺顺序。

完成判断必须同时具备代码、专项自动化、命名页面、PDA、打印、图片、尺寸和追踪矩阵证据。登记表通过、构建通过或单张截图均不能单独作为完成证明。

## 3. 目标业务模型

### 3.1 路线层、任务层、执行层

| 层级 | 负责内容 | 不负责内容 |
|---|---|---|
| 技术包路线 | 工艺 occurrence、对象分支、输入/输出对象类型、直接前置关系 | 实际 SKU、批次、接收量、交出量和现场状态 |
| 生产任务 | 把冻结路线 occurrence 拆成可执行任务，确定需求来源、责任工厂和唯一下游 | 不复制专项单据的数量账和操作日志 |
| 专项加工单 | 记录本单投入、要求、产出、接收/加工/交出状态和分批事件 | 不反写技术包版本，不凭页面状态虚构上下游事实 |

路线可以分支。一条路线边表示“上游产出供给下游投入”。当同一 occurrence 的产出需要交给两个不同工厂或仓库时，生成阶段必须拆成两张执行加工单；不允许一张加工单在执行过程中出现两个接收方。

### 3.2 三个独立状态维度

建议跨域使用相同业务语义，各专项域保留自己的内部状态和命名映射，不建立统一持久化大模型。

#### 接收维度

| 业务状态 | 判定 |
|---|---|
| 待来源 | 尚无有效中央仓调拨或上游交出可供接收 |
| 待接收 | 已有可接收来源，累计有效实收为 0 |
| 部分接收 | 累计有效实收大于 0 且小于本单应收；没有未处理差异 |
| 已收齐 | 累计有效实收达到本单应收且差异为 0 |
| 差异待处理 | 本次或累计接收存在少收、多收或异议，尚未完成责任处理 |

#### 加工维度

| 业务状态 | 判定 |
|---|---|
| 未开始 | 没有有效开工记录 |
| 加工中 | 已有效开工，尚未人工完成 |
| 加工完成 | 有人工完成记录；数量达到计划值本身不能触发该状态 |
| 已取消 | 有有效取消记录，并保留原因和操作人 |

工厂分配、接单、排缸、上机等仍可作为专项前置事实或内部节点显示，但不能替代上述加工维度。

#### 交出维度

| 业务状态 | 判定 |
|---|---|
| 未到交出 | 累计有效完成数量为 0 |
| 待交出 | 已有可交出完成量，累计有效交出为 0 |
| 部分交出 | 累计有效交出大于 0 且小于累计有效完成量 |
| 全部交出 | 累计有效交出等于累计有效完成量，且没有未处理的交出更正 |

“交出待接收、部分接收、已接收”不得再作为本单交出状态。上游详情可显示“下游已收 320/500 米”，但该值实时读取唯一下游加工单的接收记录或目标仓的收货记录，不在上游复制第四套状态。

### 3.3 投入来源

非裁片、车缝加工单的来源采用二选一事实：

| 来源类型 | 适用条件 | 必须引用 |
|---|---|---|
| 中央仓调拨 | 路线首道加工单；或备货物料已由中央仓调入责任工厂待加工仓 | 原调拨单、调拨明细、来源仓、目标待加工仓、实收记录 |
| 上游交出 | 非首道加工单 | 直接上游加工单、原交出批次、对象分支、目标待加工仓 |

来源解析只能返回当前加工单真实可用的记录。用户不能自由录入来源单号，也不能选择非直接前置、其他生产单、其他对象分支或已收完的记录。

裁片和车缝继续使用其现有配料/裁片交接业务。两者也要保留原单据和数量事实，但不强迫套用上述“非裁片、车缝”来源选择器。

### 3.4 唯一接收方和目标仓

建议给每张执行加工单保存一个冻结的接收方快照：

- 接收方类型；
- 接收方业务 ID；
- 接收方名称；
- 接收工厂 ID/名称；
- 目标仓 ID/名称；
- 存在时的下游加工单 ID、明细 ID 和路线 occurrence ID；
- 解析依据和冻结时间；
- 首次有效交出事件 ID。

解析优先级固定为：

1. 非末道：直接下游加工单责任工厂的待加工仓；
2. 生产单来源的准备末道：该生产单与裁床配套的具体中转仓；
3. 采购备货来源的准备末道：中央仓；
4. 补料来源：补料单指定的消费任务和接收位置。

首次有效交出后接收方冻结。纠正接收方必须撤销或更正原交出事件并保留原因、操作人和时间，不能直接覆盖旧字段。

### 3.5 数量公式和同源原则

```text
本单可接收 = 来源方累计有效调拨/交出 - 本单累计有效接收
本单可交出 = 本单累计有效加工完成 - 本单累计有效交出
下游待接收 = 本单累计有效交出 - 唯一下游累计有效接收
```

所有数量带原单位，禁止跨单位直接相加。接收、完成、交出、更正、撤销都基于原事件汇总；页面状态不作为事实源。一次接收只能消费一条明确的原调拨或原交出记录；一次交出只指向已冻结的接收方。

## 4. 页面和交互实施规则

### 4.1 管理端列表

加工单列表保留管理端需要的完整模型，但默认列只放可比较、可决策的信息：

| 默认列 | 内容限制 |
|---|---|
| 加工单/款式 | 加工单号、任务号、真实款式缩略图、款号/款名；最多三行文字 |
| 需求来源 | 来源类型和来源单号；不展示解释性段落 |
| 加工投入 | 物料真实缩略图、物料名/编码、计划/实收/使用数量 |
| 加工要求 | 专项工艺的关键要求；长说明进入详情 |
| 加工产出 | 产出真实缩略图、名称/编码、已完成数量 |
| 接收状态 | 一个状态徽标和“已收/应收” |
| 加工状态 | 一个状态徽标和最近关键时间 |
| 交出状态 | 一个状态徽标和“已交/可交” |
| 唯一接收方 | 接收方名称、工厂/目标仓；不存在时明确“待生成” |
| 操作 | 详情和当前允许的主动作 |

列表的版本历史、兼容说明、算法依据、长备注和完整日志进入详情或抽屉。现有业务字段不得直接删除；非默认但仍需管理的字段进入列设置。

所有标准管理列表继续使用 `renderStandardListPage`、`renderStandardListTable` 和 `renderTablePagination`。关键身份列固定左侧，操作列固定右侧，宽表只在表格容器内部横向滚动。

### 4.2 加工单详情

详情页按下列顺序组织：

1. 页头：加工单号、款式/对象真实图片、名称、需求来源、责任工厂、唯一接收方；
2. 三状态摘要：接收、加工、交出三张等权卡片，不混入第四个状态；
3. 加工投入：来源单号、原单明细、开始接收时间、累计实收、换料/调整入口；
4. 加工要求：保留印花、染色、毛织和各专项单据自己的要求；
5. 加工产出：固定产出对象、真实图片、完成数量和人工完成记录；
6. 接收批次表：原来源单号、接收时间、数量、操作人、差异；
7. 交出批次表：本单号、交出时间、数量、接收方、下游实收摘要、更正状态；
8. 条码、打印、变更和操作日志等专项信息。

批次表一行只表达一个批次，不写长段解释。阻断原因显示在当前动作旁，例如：“未找到中央仓调拨单，暂不能接收。请联系计划员补齐调拨。”

### 4.3 PDA/员工执行端

PDA 只围绕当前任务、当前对象、当前动作、当前结果：

- 扫描或进入加工单后展示真实图片、编号、对象、可操作数量；
- 接收动作明确显示来源单和本次可接收量；
- 执行动作显示本单要求和本次完成量；
- 交出动作显示唯一接收方、目标仓和本次可交出量；
- 每屏一个明显主动作；阻断时给出恢复办法；
- 不显示“投影、兼容、写回、执行事实、schema、Mock”等技术词。

### 4.4 页面宽度硬门禁

1. 管理端以 1366×768 验收，并在 1280×720 最低尺寸复核；
2. 主管/员工 Web 在 1024×768 可完成主要动作；PDA 至少覆盖 360×800 和 390×844；
3. `document.documentElement.scrollWidth` 必须等于 `clientWidth`，页面主体不得产生横向滚动；
4. 宽表允许自身 `scrollWidth > clientWidth`，但滚动条必须留在表格容器内部；
5. 关键身份列和操作列在内部滚动时仍可见；抽屉、弹窗不超过视口，内容区纵向滚动；
6. 筛选区自动换行，按钮不被挤出首屏；列表摘要保持单行或有可控换行；
7. 不通过缩小到难以阅读的字号解决宽度问题，不把字段堆成不可扫描的长文本块；
8. 路线图在节点多时使用画布内部平移/缩放，不撑开页面主体。

### 4.5 真实图片硬门禁

每一个在本次调整页面中出现的款式、面料、纱线、辅料、裁片部位、成衣产出和花型，都必须建立对象到图片的一对一清单：

| 字段 | 要求 |
|---|---|
| 对象类型/ID | 能唯一回到款式、物料、纸样部位或花型 |
| 图片来源 | 优先技术包冻结快照和 PCS 图片视图；Mock 只能使用与对象真实对应的稳定本地素材 |
| 缩略图位置 | 与名称、编码放在同一表格单元格或信息块 |
| 大图入口 | 整块缩略图可点击，有明确 `aria-label` |
| 大图内容 | 使用原图或高清图，保持宽高比，不溢出视口 |
| 关闭方式 | 关闭按钮、点击遮罩、Esc 均有效，关闭后焦点合理返回 |
| 加载/失败 | 有可见加载和失败提示；失败时不显示破图 |
| 验收证据 | URL 200、`naturalWidth > 0`、对象对应截图、大图截图 |

严禁使用 `placeholder.svg`、纯色块、首字母、无关通用图片或同一张无关素材冒充多个不同对象。现有“缺少对应图片”“历史图片缺失”只可作为实施过程中的阻塞提示，不能出现在通过验收的样例里。若真实素材尚未取得，该对象和对应页面保持“已阻塞”，不能标记“已验证”。

打印纸面没有点击行为，点击大图标记为“不适用”；但屏幕打印预览中出现缩略图时仍需可查看大图。纸面验收改为对象对应、清晰度、比例和不裁切。

### 4.6 文案白名单和禁用词

#### 列表/摘要允许出现

- 单据号、任务号、生产单/备货/补料来源单号；
- 款式、物料、花型、规格、颜色、尺码、部位；
- 计划、已收、已用、已完成、已交、下游已收和差异数量；
- 接收状态、加工状态、交出状态；
- 责任工厂、唯一接收方、目标仓、关键时间；
- 当前可执行动作和一句可恢复的阻断原因。

#### 普通业务页面禁用

- Mock、兼容、投影、写回、旧域、schema、fallback、执行事实、数据源；
- “固定产出，不随投入换料改变”等实现解释；
- “历史损耗（兼容）”“历史提示”等没有直接操作价值的标签；

- 重复说明同一个状态的段落；
- “系统自动生成……”这类无法帮助当前操作的过程说明。

审计页和操作日志可以保留必要的来源、版本和技术追溯字段，但使用业务名称，并放在详情或展开区。

## 8. 页面、图片和打印验收方案

### 8.1 命名路由

至少验收以下当前真实入口及其动态详情页：

- 技术包：`/pcs/technical-data/tech-packs`、`/pcs/engineering/tech-pack/:id`、`/fcs/production/orders/:id/tech-pack`；
- 印花：`/fcs/craft/printing/work-orders`、待加工仓、待交出仓、统计、详情、打印；
- 染色：`/fcs/craft/dyeing/work-orders`、合并染色、独立水溶、待加工仓、待交出仓、报表、详情；
- 毛织：`/fcs/craft/wool/work-orders`、待加工仓、待交出仓、横机设备、详情、交出打印；
- 特殊工艺和花边：当前菜单中的每类加工单列表/详情/仓库；
- 后道：任务、辅料调拨、QC、加工单、复检、待加工仓、待交出仓、出货、日志、授权码、统计及打印；
- 仓储：`/wls/inbound`；
- PDA：`/fcs/pda/task-receive`、`/fcs/pda/exec`、`/fcs/pda/handover`、`/fcs/pda/warehouse` 及后道子入口。

### 8.2 每页必须记录的证据

每张页面证据必须带：

- 分支、Git SHA、工作树、服务端口；
- 路由、业务对象编号、角色、视口尺寸、时间；
- 需求编号和验收用例编号；
- 关键动作前后截图；
- 刷新或关闭重开后的持久结果；
- 控制台错误结果；
- 图片加载和大图结果；
- 适用时的打印预览/纸面结果。

### 8.3 宽度验收

每个受影响管理列表分别在 1366×768 和 1280×720 执行：

1. 页面主体无横向滚动；
2. 筛选、摘要、列表、分页和操作区均在主内容范围内；
3. 宽表只在内部滚动；
4. 固定列不遮挡内容，操作按钮可点击；
5. 列设置、排序、分页后宽度仍正确；
6. 打开详情、抽屉、大图后不改变底层页面宽度；
7. 关闭浮层后滚动位置保持。

工艺路线另验收准备、生产、后道顺序；生产阶段在 1280×720 仍能直接看见裁剪→裁片并行→车缝的箭头。准备阶段验收多 BOM、多工艺场景：每条 BOM 独占一行，前移/后移只影响当前行，统一确认并刷新后顺序保持；页面主体不横向溢出，单行较宽时只在该行内部滚动。

技术包常规 BOM 分别在 1366×768 和 1280×720 验收线上 18 列及顺序、款色合并行、颜色级和行级操作、绣花需求和绑定工艺。表头、物料编码、物料名称不允许被挤成竖排；页面主体宽度等于视口，BOM 宽表只在自身容器内横向滚动。添加物料弹窗分别切换面料和辅料，核对捆条/橡筋定长切割选项互斥，并取消弹窗确认没有生成空白 BOM 行。独立烫画 BOM 不操作、不改动。

PDA 在 360×800、390×844 验收无横向滚动、主按钮首屏可见、软键盘出现后可完成输入。

### 8.4 图片验收

对图片 manifest 的每个对象逐项执行：

1. 缩略图与名称/编码同一单元格或信息块；
2. 图与对象内容相符，不是占位图或无关复用；
3. 图片请求成功，加载后 `naturalWidth`、`naturalHeight` 大于 0；
4. 点击缩略图打开原图/高清大图；
5. 大图比例正确，在最低分辨率不溢出；
6. 关闭按钮、遮罩、Esc 全部可关闭；
7. 模拟错误 URL 时显示明确失败态，不出现浏览器破图；
8. 键盘焦点和 `aria-label` 可理解；
9. 列表、详情、PDA、屏幕打印预览读取同一对象图片；
10. 缺图对象在矩阵中标记“已阻塞”，不得通过。

常规 BOM 还必须逐行核对物料档案 ID、编码、名称和图片一致；本轮新增的“腰口定长橡筋”缩略图应显示实际松紧带图片，点击大图后在 1280×720 内保持比例，关闭按钮与 Esc 均有效。任一常规 BOM 物料缺少对应图片时，本轮不得通过。

### 8.5 文案验收

1. 对受影响代码精确扫描禁用词；
2. 人工逐页检查列表无段落式解释、标题无工厂串联长句；
3. 每个状态只出现一次，名称与三状态定义一致；
4. 阻断提示说明“哪里错、怎么改、找谁处理”；
5. 空状态只说明当前没有什么和下一步，不解释内部实现；
6. 日志/审计页的追溯字段不泄漏到普通列表。

### 8.6 打印验收

1. 印花信息单、印花确认单、卷条码、毛织交出、后道出货/吊牌等现有打印入口不丢失；
2. 打印数据与屏幕当前加工单、对象、数量、接收方一致；
3. 真实图片清晰、不拉伸、不裁掉关键部位；
4. 条码/二维码可扫描，编号与业务对象一致；
5. A4/标签纸分页无跨页切断；
6. 图片缺失或加载失败时阻断打印并指出缺失对象；
7. 纸面点击大图标记“不适用”，屏幕打印预览仍按图片规则验收。
