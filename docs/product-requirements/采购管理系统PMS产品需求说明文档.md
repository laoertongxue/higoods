## 1. 背景与目标

### 1.1 背景

现有 higoods 原型中的采购管理系统（PMS）只有“采购订单、供应商管理、合同管理”三个菜单项，其中仅采购订单（花边辅料）已实现。另有一个独立完成的采购管理原型（SRM），覆盖采购主数据、采购建议、商品采购、面辅料采购、供应商确认、头程物流、采购对账与请款等完整链路。

本次把 SRM 原型中**有菜单入口的全部业务页面**迁移进 higoods 的采购管理系统，使 PMS 成为与商品中心（PCS）、工厂生产协同（FCS）、仓储物流（WLS）并列的完整系统。

### 1.2 目标

1. 采购管理主流程在 PMS 内闭环：采购建议 → 商品采购单 → 面辅料需求分析 → 面辅料采购单 → 物流跟踪 → 供应商确认 → 头程物流 → 对账 → 请款。
2. 采购主数据在 PMS 内可见可用：贸易主体、商品供应商、供应商供货档案、头程物流商、面辅料、成衣、样衣、仓库、单位、BOM/样板。
3. 保留原材料链路的辅助模块：面辅料库存监控、中转仓数据总览与收货单。
4. 保留系统设置类页面：用户管理、角色权限、字典配置（按结果展示页处理）。
5. 页面视觉与交互统一为 higoods 现有企业后台标准，列表页遵循标准列表治理。

### 1.3 非目标

- 不实现真实后端、接口、鉴权、数据库或权限控制。
- 不把 SRM 中无菜单入口的孤立页面迁移进来。
- 不改变现有花边辅料采购订单页面及其与 FCS/WLS 的联动方式。
- 不引入 React 页面体系、状态库、图表框架或新的通用抽象层。
- 不把对账、请款做成真实财务结算，只做演示级状态与数量。

## 2. 角色与现场条件

| 角色 | 端 | 主要任务 | 典型页面 |
| --- | --- | --- | --- |
| 采购员 | 管理端（桌面） | 看建议、开采购单、下推面辅料、跟踪物流、做供应商确认 | 商品采购单、面辅料采购单、采购跟踪 |
| 采购主管 | 管理端（桌面） | 看统计与异常、处理阻断、确认差异 | 工作台、供应商确认、对账 |
| 财务 / 跟单 | 管理端（桌面） | 对账、请款、付款状态 | 面辅料采购对账、物流费用对账、请款单 |
| 商品 / 主数据维护 | 管理端（桌面） | 维护供应商、单位、BOM 等基础资料 | 供应商管理、单位管理、BOM/样板管理 |

现场条件：管理端标准列表按 1366×768 验收、最低 1280×720；供应商确认与标签打印涉及二维码打印预览；不要求 PDA 页面。

## 3. 业务对象与关系

| 对象 | 唯一标识 | 主要来源 | 下游 |
| --- | --- | --- | --- |
| 贸易主体 | 主体编码 | 基础资料维护 | 采购单、对账、请款 |
| 商品供应商 | 供应商编码 | 基础资料维护 / PCS 同步 | 采购单、供货档案、供应商确认 |
| 供货档案 | 供应商 + 物料 | 供应商管理 | 包装换算、采购单快照 |
| 面辅料 / 成衣 / 样衣 | 物料编码 / SKU | PCS 同步（原型内 Mock） | 采购建议、采购单、BOM |
| BOM / 样板 | SPU | 技术资料 | 面辅料需求计算 |
| 商品采购建议 | SPU + 履约缺口 | 系统计算 | 商品采购单 |
| KOL 采购需求 | 需求单号 | 运营提交 | 采购建议扣减、商品采购单 |
| 商品采购单 | 采购单号 | 采购员创建 | 面辅料需求分析 |
| 面辅料需求分析 | 分析单号 | 商品采购单生成 | 面辅料采购单 |
| 面辅料采购单 | 采购单号 | 需求下推 | 物流跟踪、供应商确认 |
| 物流记录 | 采购单号 + 批次 | 快递导入 / 手工 | 头程物流 |
| 头程物流批次 | 头程单号 | 物流跟踪加入 | 中转仓、物流费用对账 |
| 供应商确认单 | 确认单号 | 采购单生成 | 卷号标签、采购单回写 |
| 应付明细 / 对账单 / 请款单 | 单号 | 对账 | 付款记录 |

关系要点：商品采购单只有“做货”类且 BOM 已匹配的 SKU 才能生成面辅料需求；面辅料需求必须绑定供应商才能下推为采购单；物流记录可分批加入头程；对账只能对同一对象、同一币种的未对账明细生成。

## 4. 数据来源与上下游

- 面辅料、成衣、样衣、仓库、供应商基础信息在原型中由 PCS/WMS“同步”而来，PMS 内只读或只补充采购侧信息，不新增删除。
- 采购建议由“待发货 + KOL 申请 − 采购中 − 实时库存”计算，KOL 草稿与已驳回不计入。
- 面辅料需求由“SKU 数量 × 单件用量 × (1 + 损耗) − 库存 − 采购中”计算。
- 对账金额由采购货款 + 物流费 + 调整金额构成；差异 = 供应商账单 − 最终应付。
- 所有数据只用于原型演示，刷新后回到演示初始状态（不实现持久化台账）。

## 5. 当前与目标流程

### 5.1 采购建议到面辅料采购（主链路）

1. 采购员进入“商品采购建议”，系统按缺口公式给出建议数量，可按爆款/热销折扣调整。
2. 勾选 SKU 生成商品采购单，选择供应商、区域、仓库，保存后进入“商品采购单”。
3. 对做货类采购单执行“生成面辅料需求分析”，按 BOM 拆出物料需求。
4. 在“面辅料需求分析”中修改实际采购数量并批量下推，生成“面辅料采购单”。
5. 在“面辅料采购单”导入快递信息或手工维护物流，进入“面辅料采购跟踪”。
6. 在跟踪页把国内物流分批“加入头程”，生成头程物流批次。
7. 在“供应商确认单”维护卷号与包装、生成标签并打印二维码、供应商确认后回写采购单。

### 5.2 对账与请款

1. 采购跟踪与收货完成后，在“面辅料采购对账”确认预计/实际费用，勾选生成请款单。
2. 在“物流费用对账”确认物流费用，勾选生成物流请款单。
3. 请款单按状态推进：未请款 → 部分请款 → 已请款 → 已完成；付款状态：未付款 → 部分付款 → 已付款。

### 5.3 异常与边界

- 建议缺口小于等于 0 不生成采购单；非做货或 BOM 未匹配的 SKU 阻断并提示。
- KOL 单条入库超量需要二次确认，批量入库禁止超量，已驳回不可入库。
- 需求已下推、建议量为 0、缺供应商时阻断下推。
- 加入头程数量必须在 1 到待头程数量之间，卷数为非负整数，头程单号不可重复。
- 供应商已确认后核心字段只读，修改需解锁并标记“已变更”，需重新确认。
- 对账差异未确认前不能确认；付款金额不得超过未付金额。
- 请款已完成后不可编辑，只可查看。

## 6. 状态和时序

| 对象 | 状态序列 |
| --- | --- |
| KOL 采购需求 | 草稿 → 待入库 → 部分入库 → 全部入库；草稿可被驳回 |
| 商品采购单 | 草稿 → 待采购 → 待确认 → 已确认 → 已发货 → 已到货 → 已入库 → 已完成 → 已关闭 |
| 面辅料需求 | 未生成 → 已生成 → 部分下推 → 已下推 |
| 头程物流批次 | 待起运 → 已装柜 → 头程中 → 已到仓 → 已完成 |
| 供应商确认单 | 待确认 → 已编辑 → 已确认；标签：未生成 → 已生成 → 已打印 / 部分打印 → 已重打 |
| 物流 / 面辅料请款 | 未请款 → 部分请款 → 已请款 → 已完成（另有已作废） |
| 付款 | 未付款 → 部分付款 → 已付款 → 已完成 |

## 8. Web / PDA / 打印分工

- 本次全部为 Web 管理端页面，不做 PDA。
- 打印场景仅一处：供应商确认单的卷号标签二维码打印预览，需要在页面内可预览、可重新打印，不接真实打印机。
- 与 FCS/WLS 的跨端事实不新增：面辅料采购单与 FCS 花边采购订单保持独立单据来源，不做跨系统写入。

## 9. 真实图片要求

- 所有出现款式、SKU、面辅料的列表、卡片、详情、弹窗中，每条记录必须有与对象对应的真实图片。
- 缩略图与名称/编码在同一单元格或同一信息块；缩略图可点击查看大图，支持关闭、遮罩、Esc。
- 图片加载中与失败状态必须可见；缺图对象必须登记，相关页面不得按完成交付。

## 10. 异常防错与恢复

- 超量、重复提交、必填缺失、状态不允许、单号重复必须阻断，并提示如何修正。
- 危险动作（关闭采购单、确认差异、确认供应商、停用对象、推进结算）必须二次确认并保留操作事实。
- 弱网与上传失败在原型中以可见失败提示 + 重试动作表达，不实现真实离线队列。

## 11. 数量、单位与权限

- 所有数量带现场单位（米、公斤、个、箱、件、卷等），金额带币种（RMB/USD）。
- 应领/已领、应交/已交、差异由系统计算，直接表达“少/多多少”。
- 原型不实现登录与权限控制；角色身份以页面内职责文案体现，不出现无权限声明。

## 12. 验收标准

1. 30 个迁移页面 + 2 个中转子页全部可从 PMS 菜单进入，无占位页、无死链。
2. 采购主链路可从建议走到请款，各单据状态与数量正确联动。
3. 所有列表页通过标准列表治理检查，查询/重置/导出、统计、分页、列设置可用。
4. 所有款式/物料图片满足真实图片硬门禁；缺图对象集中在矩阵登记。
5. 每个页面加载与交互响应严格低于 200ms。
6. 每批交付附原型审查记录与任务收据。
