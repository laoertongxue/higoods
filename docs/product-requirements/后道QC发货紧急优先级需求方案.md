# 后道 QC 发货紧急优先级需求方案

版本：V2，2026-10-21。阶段：D01～D06 已由用户确认，进入实施；功能完成情况以逐项验收清单为准。

本方案将成衣出库订单的最迟发货需求，扣除成衣仓库存及后道已有合格数量后，按当前有效 SKU 匹配待质检 QC 单，在 QC 流转单上显示紧急星级和今日、明日需求参考数量，帮助现场安排先后顺序。

关联文档：[实施计划](../implementation-plans/2026-10-20-后道QC发货紧急优先级实施计划.md)、[逐项验收清单](../requirement-traceability/后道QC发货紧急优先级逐项验收清单.md)。

## 1 范围与继承关系

### 1.1 本期目标

一线目前需要逐单核对发货时间，并在包装袋上手写紧急标识。本期用既有 QC 单据传递紧急程度及具体 SKU 的待补需求，不改变衣服的实际作业流程。

适用范围包括有效待发需求、成衣仓库存抵扣、已质检至待仓确认之间的数量抵扣、跨环节去重、SKU 替换、QC 匹配、星级、单据展示及后道规则维护。

### 1.2 继承与非范围

继续继承[原 QC 后道方案](../product-design/QC后道全流程系统完整调整方案.md)及[后道逐项加工与多次复检出货方案](../product-design/2026-10-19-后道逐项加工与多次复检出货调整方案.md)中未被本方案明确调整的规则。既有领取、质检、加工项顺序、分批登记、复检条码、数量差异授权、交接及实收职责保持有效。

本期不建立订单向生产单、回货或 QC 的数量分配，不新增加工排程或交期预测，不通过统计动作变更订单、库存、质量结果或实物数量，不向其他业务页扩展紧急看板，不接入真实后端或自动写入线上业务数据。

2026-10-21 用户确认 D01～D06 推荐口径并授权按计划实施。此次授权不自动包含 Git 合并、推送或部署；需求确认不等于功能实现或现场接受。

## 3 时间与有效需求

### 3.1 唯一时间依据

每张成衣出库单的揽收时效是最迟发货时间，其商品明细继承本单时效。实际发货时间表示已经发生的发货事实，不能替代截止时间。

生产单原优先级、要求交付日期、采购时间、生产时间、回货时间和后道出货时间不参与星级判断。

全部原型出库样本及已保存记录必须有有效揽收时效。空值、无法识别的日期均不符合要求；不能默认成当前时间或其他业务时间。历史缺失应依据来源修正；修正前不能用零需求、正常等级或静态旧结果冒充计算成功。

### 3.2 有效待发数量

以订单商品的有效未发件数为准，不逐行累加商品块中重复显示的 SKU 待发参考数。

| 订单状态或事实 | 处理 |
| --- | --- |
| 待处理、待拣货、拣货完成、已打单且仍有未发数量 | 纳入需求 |
| 已取消 | 排除需求 |
| 已出库或已揽收 | 不再形成待质检环节的待补需求 |
| 若存在部分取消或部分发货事实 | 仅取有效剩余量；本期不因此新增这些业务动作 |
| 缺失或无效揽收时效 | 报告资料不符合要求，不静默纳入或丢弃 |

同 SKU 多订单按各自的有效数量归集，保留各自截止时间；同一订单明细重复读取只能统计一次。单位统一为非负整数件；负数、小数、身份重复或关系不完整应识别为异常，不靠截为零掩盖。

## 4 当前有效 SKU 匹配

### 4.1 匹配粒度

需求、库存、后道合格量与待质检 QC 使用同一商品身份口径。相同 SPU 下不同颜色、尺码不能互抵；名称相似、图片相似、编号前缀相同均不能代替 SKU 关系。不同任务中的记录身份用于去重与追溯，不应误认为不同商品。

### 4.2 SPU 替换

按每部分成衣实际有效的商品身份及替换生效事实处理。A SKU 已有效切换到 B SKU 的部分，只能抵扣 B 的需求，不能通过原生产需求或替换映射继续满足 A。同一部分不能同时以 A、B 各计一次。

尚未有效切换的部分按其实际身份处理；已禁止用于原 SKU 的部分不得继续抵扣原需求。仅存在替换申请不能推定全部实物已经切换。原生产需求、工厂及结算追溯继续保留，但不能决定替换后衣服的当前需求归属。

识别不了当前有效身份时，不能靠原 SKU 反向兜底出一份看似准确的紧急结果。

## 5 两类可抵扣供给

### 5.1 成衣仓库存

抵扣能够实际满足统计范围内订单的同 SKU 成衣库存。同一库存即使出现在不同订单、不同查询或库存汇总与库位明细中，也只使用一次。

按 D02，以当前有效 SKU＋实际履约仓独立计算，默认不跨仓抵扣。已保障本次统计内订单的库存必须与对应需求成套处理，不能既保留全部订单需求又剔除其保障库存，造成虚假缺口。不能用于本订单的冻结、质量异常或其他范围占用量，不得无依据重复使用。

仓库在途库存如与后道已有合格量指向同一批衣服，不能另加一份。其他普通在途、调拨申请及计划入库第一版不额外抵扣，实际入仓后才成为该仓现货；不能把总库存直接当成可抵扣量。

### 5.2 后道已有合格量

范围从 QC 已完成并形成正式合格结果开始，至后道出货单尚未由成衣仓确认接收结束，两端均包含。

| 所处环节 | 可抵扣口径 |
| --- | --- |
| 待送检、待质检、质检中 | 尚无正式完成的合格结果，不纳入后道合格供给 |
| QC 完成，尚未流入后续记录 | 实际确认合格且仍保留的数量 |
| 后道待加工、加工中、部分完成 | 当前仍在该环节的合格数量；不要求全部加工完成才抵扣 |
| 后道完成、尚未交复检 | 尚未转入复检的合格数量 |
| 已交复检、待复检、复检中 | 本次复检占用且仍在该环节的数量 |
| 复检完成、待交出 | 已复核且尚未入成衣仓的数量 |
| 后道出货单待成衣仓确认 | 对应尚未确认接收的合格数量 |
| 已确认并计入成衣仓库存 | 从后道供给退出，仅归入库存供给 |

无需后道加工、由 QC 直接生成成衣仓交接的合格数量，同样纳入未入仓范围，不因没有加工单或复检单而漏计。

QC 瑕疵、返厂及后续已确认的报损、短少、不可交量，不是可用合格供给。应检数、登记数、计划加工数和历史累计交出数不能直接替代现存量。

后道在制量依用户确认参与抵扣，但不证明它能够在截止前完成加工和交货。需求参考不是交期承诺。

## 6 各环节去重与数量守恒

### 6.1 唯一计数原则

沿同一次回货、同一 QC、相关加工、复检、出货和实收关系，识别同一批同 SKU 的数量。同一部分在一个统计时点只归属一个现存位置。不同真实批次可以相加；同一批的上下游单据不能相加。

四个加工项各完成 50 件仍是 50 件衣服，不能累加为 200 件；QC 合格累计数也不能再加到这些数量上。交复检的部分从未交复检量退出；复检、待交出仓及后道出货单指向同一部分时只计一次。每一张实际复检和出货子单均须覆盖，不能只取生产单或加工单的第一张或最后一张。

### 6.2 分批分布示例

| 同批合格 100 件的当前位置 | 数量 | 供给归属 |
| --- | --- | --- |
| 加工中 | 30 | 后道 |
| 复检中 | 20 | 后道 |
| 待成衣仓确认出货 | 40 | 后道 |
| 已确认计入成衣仓 | 10 | 库存 |
| 合计 | 100 | 后道 90 加库存 10 |

QC 合格累计 100 件不再作为额外供给相加。只改变内部位置、未改变数量和有效 SKU 时，供给总量与需求缺口不变。

### 6.3 入仓及差异

同一确认数量从后道供给退出、进入成衣仓库存一次；仓库库存已经包含该实收时，不能再叠加一遍收货记录。也不能先移除后道量，却漏掉库存，制造暂时虚假紧急。

交出 40 件、实收 38 件时，库存只增加确认的 38 件。差异 2 件按实际确认结果处理：确认为短少或损失则排除；确实仍留后道则须有事实支持；未知时不能默认可用。不得取上下游最大数量或伪造一条损耗事实强行对平。

本期沿用已有按出货子单确认实收的能力；不因统计方案自动新增单张出货单的部分收货操作。分批入仓可由不同实际出货子单体现；若后续确需新增单张部分收货，另行确认业务及原子保存范围。

## 7 抵扣与星级计算

### 7.1 按仓、按订单保障关系抵扣

同一当前有效 SKU、实际履约仓、统计时点内，设 B 为真实合格现货实存，L 为该现货的全部有效占用。必须先验证占用与实存、订单行、SKU、仓库一致且 L 不大于 B；不能用截为零隐藏异常。

```text
每订单剩余需求 dᵢ = 有效未发数量 Dᵢ − 对应有效现货保障 Cᵢ
公共现货 F = B − L
公共供给 T = F + 去重后、明确供应本仓的后道合格量 P
```

Cᵢ 只覆盖其原订单，最高为 Dᵢ；已保障的库存不再进入公共供给。范围外占用不抵扣本次订单；取消或需求减少后多出的占用，在真实释放前仍锁定，不自动抢给近期待发。预售需求不等于现货占用，只有真实锁定合格实物的部分才属于 L。

需求与库存保障必须成套处理：不能只从库存扣除占用却保留全量订单需求，也不能先减需求又将保障库存重复放入公共池。没有可追溯占用关联时显示需核对，不猜归属。

### 7.2 日期覆盖顺序与去向

1. 先处理已有专属保障，将剩余需求按最早揽收截止时点排列；相同截止时点保持稳定顺序。
2. 以 T 依次覆盖剩余需求，每份供给只用一次，不能分别对今日和明日各扣一次全量供给。
3. 全部源时间明确其原始时区，统一换算为 Asia/Jakarta；按雅加达自然日归集历史超期、今日、明日和远期，不随浏览器时区变化。
4. 历史超期先覆盖；今日内超时仍是今日子项，不能再相加。

无专属占用时，今日 100、明日 80，公共现货 40、后道 90，结果为今日 0、明日 50。

占用示例：今日 60（已保障 40）、明日 50，现货 100，其中本次占用 40、范围外占用 30，公共现货 30、后道 20，结果今日 0、明日 20。一旦 40 件占用实际属于明日单，相同汇总数会得到今日 10、明日 10，不能凭汇总猜测。

后道数量沿生产/后道任务的已确认供货去向继承，不以工厂名或责任岗位猜目标仓。已生成出货子单冻结各自目标仓；修改父级去向仅影响尚未形成出货的剩余量。待接收子单可单独维护目标仓并留人、时间、原因；已实收子单不能改仓。分配 A 仓 60、B 仓 40 的同批 100 件只能分别计入；缺失去向列需核对，不能全仓共用。QC 仍按有效 SKU＋待质检匹配共享参考，按仓分列，不新增订单到 QC 的分配。

### 7.3 初版星级

| 抵扣后剩余需求 | 初版结果 |
| --- | --- |
| 历史超期仍有缺口，或今日仍有需求 | 两星；超期与今日数量分别展示 |
| 今日无缺口，明日仍有需求 | 一星，明日需发 |
| 近两日均被覆盖或只有后天及以后需求 | 无紧急星级，正常处理 |

星级只按时间紧迫性判定，数量较大不提升至更早日期等级。历史超期仍有缺口时保持最高等级并明确标识；不增加第三种紧急档位。

## 8 待质检 QC 匹配与展示

### 8.1 QC 匹配

仅匹配状态为“待质检”、实际包含相同有效 SKU 的 QC 单，不自行扩展至待送检、质检中或已完成 QC。已完成 QC 是供给来源，待质检 QC 是参考结果的接收对象，两种职责不能混淆。

“实际包含”指本批应检数量大于 0；生产单或回货记录为保留结构而带出的零应检 SKU 行不参与本批匹配，也不进入生产主单的待质检 SKU 并集。

同 SKU 的净需求先计算一次，再展示给匹配 QC。多张 QC 可以显示相同参考数量，但不能相加为多份需求，不宣称各自承担全部缺口，不创建独占关系。

同款只有黑色 M 紧急时，只包含白色 L 的 QC 不继承该紧急需求。一张 QC 含多个 SKU 时取相关 SKU 的最高星级，明细按 SKU 分列；不得把整单应检量全部标为某一个紧急 SKU 的需求。

### 8.2 单据内容

仅在 QC 流转单展示紧急信息。包括待质检 QC 主单、随附 SKU 明细和对应预览，两套入口一致。生产单主单按其待质检 QC 的 SKU 并集统计一次；已完成 QC 重打不显示实时紧急区。现有打印入口继续使用；其他业务列表、加工单流转卡、出货单和 PDA 待办不额外铺设紧急模块。

单据区分“本批应检数量”与“库存及后道合格量抵扣后需求参考”。显示星级文字、今日与明日参考件数、必要的 SKU 颜色尺码明细及统计截至时间；明确“未分配到本批”。保留现有款式评级、图片、条码、数量、签字和单号语义，星级不替代款式评级。

黑白打印时星级与文字仍能识别；数量为零不显示虚假紧急；数据读取或关系校验失败时不能画成正常等级或沿用旧数冒充最新结果。

## 9 规则维护与结果更新

在后道管理范围内提供规则维护位置，现场不逐单手工打星。星级、日期范围与显示文案受 U01、U07 约束，不能把采购时间等作为备用依据。维护责任及变更方式按已确认 D06 执行。

订单取消、发货、时效或数量变化，库存变化，QC 合格确认，数量差异及有效 SKU 切换，规则变化和跨日，都可能影响结果。单纯内部流转不应改变供给总量。

统计读取不修改业务事实。新查看、重打读取最新事实；同次主单/明细使用同一来源版本和统计时点。纸单不自动更新，初版不保存紧急结果历史快照。维护入口位于后道 QC 管理，后道负责人维护今日/明日星数和提示文字，今日必须高于明日、超期跟随最高等级；采购日期、抵扣公式和两日范围不可自由修改。星数为1～5的整数且今日高于明日。保存成功后新查看生效，记录维护人、原因、版本和时间；取消不写，失败保留输入，并发冲突不覆盖。PPIC 负责去向和仓库对应，成衣仓负责人负责库存、占用和实收，不新增假角色门槛。
