# HiGood 项目文档索引

## 1. 使用原则

项目文档按“现行规则、实施计划、交付证据、历史版本”区分。查业务事实时先使用现行产品需求和总体设计，再查实施计划、需求追踪矩阵和当前版本代码；原型审查记录只证明当时执行过的验收，不自动成为现行业务规则。

Git 历史已经保存被删除的旧版本。已被新文档替代、不会被现行代码或检查读取的历史计划，不继续放在默认工作树中。

## 2. 现行文档入口

| 文档类别 | 目录 | 用途 | 清理规则 |
|---|---|---|---|
| 项目治理 | `AGENTS.md` | 技术边界、执行和验证规则 | 必须保留 |
| 产品需求 | `docs/product-requirements/` | 业务对象、角色、状态和验收口径 | 必须保留；变更时保留修订记录 |
| 总体设计 | `docs/product-design/` | 现行专项业务设计和完整调整方案 | 新文档应声明替代关系；失效版本从默认工作树移除 |
| 实施计划 | `docs/implementation-plans/` | 当前或近期跨模块实施步骤 | 完成且已被新计划替代时可从默认工作树移除 |
| 需求追踪 | `docs/requirement-traceability/` | 原子需求与证据映射 | 必须保留 |
| 原型审查记录 | `docs/prototype-review-records/` | 当时版本的页面和治理证据 | 保留，不作为现行业务事实源 |
| 验证证据 | `docs/verification-evidence/` 及明确命名的证据文件 | 无法由测试重建的正式证据 | 确认不可重建后保留 |

## 3. 已退出的历史体系

- `docs/superpowers/`：项目已禁用该工作流；其中仍有效的规则已迁移到现行产品需求、总体设计或实施计划，旧文件只保留在 Git 历史。
- `.trae/` 中的 Superpowers 技能副本：不属于产品源码或现行项目治理，删除；CodeGraph 相关配置单独保留。
- 独立 Excel 核查输出和 agentmemory 运行状态不进入源码仓；需要长期保存的表格应进入正式文档系统或发布附件。

## 4. 文档新增要求

新增总体设计或实施计划时必须写明：

1. 适用业务范围和非范围。
2. 替代或继承的旧文档。
3. 对应需求追踪矩阵。
4. 当前状态：现行、已完成待归档、已替代。
5. 最终代码版本和验证证据。
