## 3. 自查结论

| 检查项 | 结论 | 说明 |
| --- | --- | --- |
| 角色匹配 | 通过 | 页面服务管理端和主管端，允许较高事实密度，同时保持接收、加工、交出、设备和完成责任可追溯 |
| 任务清晰度 | 通过 | 固定七个业务页签；概览先回答计划、当前状态、累计事实、下游去向和当前横机 |
| 信息架构与导航 | 通过 | 删除旧工序步骤、菲票、价格和旧异常证据页签；列表可返回，事实按业务对象分区 |
| 页面模式 | 通过 | 管理详情使用页签、宽表、弹窗和分页；不是一线 PDA 执行页 |
| 信息负荷 | 通过 | 概览仅展示计划和事实汇总；明细按页签及分页延后展开，不一次渲染全部记录 |
| 文案 | 通过 | 统一使用“确认接收、加工填报、发起交出、横机关联、完成加工单”；错误保留领域给出的具体原因和修改动作 |
| 数量与状态 | 通过 | 逐 SKU 展示计划、150% 剩余容量、累计加工、累计交出、默认库位库存和可交出余额，所有数量带单位 |
| 扫码与识别 | 不适用 | 本页是 Web 管理端 / 主管端事实详情，不新增扫码动作 |
| 防错 | 通过 | 已完成加工单隐藏所有修改数量入口；下游已确认的交出记录隐藏修改入口；保存仍由统一领域命令校验并原子同步库存 |
| UI 样式 | 通过 | 使用现有详情区块、徽章、表格和分页组件；危险或可变操作只在弹窗中进行 |
| 组件交互 | 通过 | 页签、分页、记录详情和修改弹窗只替换详情局部区域；输入不触发整页重绘；没有新增 document 级监听 |
| 协作关系 | 通过 | 详情展示结构化接收对象、交出方事实、下游实际确认、差异、仓库流水及横机关联历史 |
| 异常与追溯 | 通过 | 凭证、备注、差异说明、操作人、时间、原始仓库流水、调整流水和完整数量修改历史均可见 |
| 现场设备可用性 | 通过 | 宽表只在表格容器内滚动；弹窗限制高度并保持关闭及保存按钮可达 |

## 5. 主要问题与处理

| 问题 | 标签 | 影响角色 | 处理方式 | 是否仍有风险 |
| --- | --- | --- | --- | --- |
| 旧详情按横机成片、缝盘熨烫包装、菲票和价格组织 | `状态抽象` | 毛织主管 | 重写为七个事实页签，删除本详情内旧节点与相关死代码 | 否 |
| 单一领料和汇总数量无法解释款色能否开工 | `算不准` | 毛织主管、跟单 | 逐加工后 SKU 展示全部必需纱线及每种纱线的有效接收记录；纱线数量不换算开工件数 | 否 |
| 记录只有汇总，凭证、差异和修改过程不可见 | `追溯不足` | 毛织仓管、主管 | 记录详情直接展示凭证、备注、差异说明、操作者、业务时间、仓库流水和分页修改历史 | 否 |
| 完成后下游回写可能被误认为完成时已知事实 | `协作断裂` | 生产跟单 | 完成确认时四块冻结快照与完成时间后的下游确认分栏展示 | 否 |
| 页签和分页可能触发整页重绘并丢失阅读位置 | `组件误用` | 所有页面使用者 | 使用详情根节点内的局部 surface 更新；三类记录维护独立页码，弹窗和错误区独立刷新 | 否 |
| 修改数量可能绕过领域库存与交出边界 | `算不准` | 毛织主管、仓管 | 页面仅调用 `changeWoolFactQty`；加工和交出先显示当前记录最大可改数量，领域命令再次校验 | 否 |

## 6. 最终结论

结论：通过。

说明：

- 详情已按冻结加工单、有效业务记录和领域派生查询表达，不回查可能漂移的款式或工厂元数据。
- 页面没有建立第二套业务状态或完成快照；完成前后的事实边界来自领域完成记录和当前下游确认记录。
- 接收、加工、交出三个记录页签各自维护页码并只渲染当前页，其他事实列表及修改历史也保留分页口径。
