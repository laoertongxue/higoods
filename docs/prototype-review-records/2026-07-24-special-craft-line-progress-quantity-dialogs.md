| 检查项 | 结论 | 说明 |
| --- | --- | --- |
| 角色匹配 | 通过 | Web 和 PDA 均围绕工艺工厂现场操作员当前任务展示数量。 |
| 任务清晰度 | 通过 | 本次数量默认由系统计算，减少人工判断。 |
| 信息架构与导航 | 通过 | 不改变列表、详情和 PDA 入口。 |
| 页面模式 | 通过 | 维持原弹窗和 PDA 卡片模式，仅补行级数量列。 |
| 信息负荷 | 有条件通过 | 弹窗新增必要防错数量列，属于完成操作所需信息。 |
| 文案 | 通过 | 使用累计实收、累计完工、累计交出、本次完工、本次交出等中文业务文案。 |
| 数量与状态 | 通过 | 本次数量上限由累计数量自动计算，避免员工心算。 |
| 扫码与识别 | 通过 | 裁片仍按菲票号识别，成衣按 SKU 识别。 |
| 防错 | 通过 | Web/PDA 写回层按行级剩余量和整单剩余量双重拦截超量。 |
| UI 样式 | 通过 | 保持现有表格和 PDA 卡片样式。 |
| 组件交互 | 通过 | 弹窗局部交互不触发整页重绘。 |
| 协作关系 | 通过 | Web 与 PDA 共用加工单行级进度，数量口径一致。 |
| 异常与追溯 | 通过 | 保留统一操作记录和仓交出联动。 |
| 现场设备可用性 | 有条件通过 | PDA 增加行级摘要，但仍为短字段、可折叠区域内展示。 |

## 4. 问题标签

- `算不准`
- `点错风险`
- `协作断裂`

## 5. 主要问题与处理

| 问题 | 标签 | 影响角色 | 处理方式 | 是否仍有风险 |
| --- | --- | --- | --- | --- |
| 加工填报只按整单已接收校验，未扣除已完工数量。 | `算不准` | Web / PDA 操作员 | 增加行级累计进度和剩余量计算，本次完工不得超过累计实收未完工。 | 无 |
| 发起交出需要看到累计实收、累计完工、累计交出，否则容易超交。 | `点错风险` | Web / PDA 操作员 | 弹窗和 PDA 详情展示行级累计数量，并默认本次交出为累计完工未交出。 | 无 |
| Web 与 PDA 数量口径可能不一致。 | `协作断裂` | 工艺工厂主管、操作员 | Web/PDA 共用 `lineProgress` 行级进度。 | 无 |
