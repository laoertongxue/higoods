## 5. 主要问题与处理

| 问题 | 标签 | 影响角色 | 处理方式 | 是否仍有风险 |
| --- | --- | --- | --- | --- |
| 设备档案手工保存“生产中”会形成无加工单的伪状态 | `状态抽象` | 设备主管、毛织主管 | 档案状态限定为 `IDLE / REPAIR / DISABLED`，查询存在当前关联时才派生 `PRODUCING` | 否 |
| 多选保存只追加会遗留已取消设备 | `协作断裂` | 毛织主管 | 所选集合视为保存后的整组最终真相，统一计算新增、保持、移除和跨单转移 | 否 |
| 维修或停用设备仍可能被选中生产 | `选不对` | 毛织主管 | 保存前阻断维修和停用设备；存储校验也拒绝不可用设备存在当前关联 | 否 |
| 生产中设备直接登记维修或停用会静默中断加工 | `点错风险` | 设备主管、毛织主管 | 强制填写原因并确认影响，一次提交只解除目标设备的当前关联、更新该设备档案、写该设备关系日志和设备操作日志；同单其他设备完全不变 | 否 |
| 维修与停用之间直接切换或重复保存同状态会模糊设备恢复事实 | `状态抽象` | 设备主管 | 空闲只允许进入维修或停用；维修、停用只能恢复为空闲；同状态保存明确拒绝 | 否 |
| 设备恢复后自动续接旧加工单会绕过重新确认 | `点错风险` | 设备主管、毛织主管 | 维修或停用恢复只改为空闲，不恢复旧关系 | 否 |
| 完成加工单和设备关系模块各自实现释放可能行为漂移 | `协作断裂` | 毛织主管、设备主管 | 完成命令复用草稿级批量释放辅助函数，保留任务 5 的稳定日志 ID、动作和原子性 | 否 |
| 持久化失败可能只改设备或只删关系 | `协作断裂` | 设备主管、毛织主管 | 设备状态、当前关联、关系日志和设备操作日志由同一次 `commitWoolStore` 提交；失败全部回滚 | 否 |
| 当前关联缺少关联时间或关联人会形成无法追责的伪事实 | `追溯不足` | 毛织主管、设备主管 | 存储校验强制设备 ID、加工单 ID、关联时间和关联人均为非空文本 | 否 |
| 整组关系未变化仍持久化会刷新事实或在存储异常时误报失败 | `协作断裂` | 毛织主管 | 进入事务前比较目标集合与跨单来源；完全相同时直接返回副本，不调用 `setItem`、不更新时间和日志 | 否 |
| 整组保存返回内部存储对象会允许调用方改写已提交事实 | `追溯不足` | 毛织主管、设备主管 | 无变化、新增、移除和跨单转移均只返回目标加工单按设备 ID 排序的关联副本；修改返回数组或对象不影响存储 | 否 |

## 6. 最终结论

结论：通过

说明：

- 横机当前关系唯一落到具体 `woolOrderId`，生产单仅作为后续页面检索维度。
- 加工单关联入口复用既有加工填报门禁；加工单已有关系时即使达到填报上限，仍可进入并解除。
- 设备档案不存在“生产中”持久值，也不存在“已排产”领域值；生产中由当前关系实时派生。
- 单设备维修或停用只解除目标设备；同加工单其他设备继续关联并保持 `PRODUCING`，其档案时间和历史日志不变。完成加工单仍使用独立批量释放路径解除该单全部设备。
- 设备可用性按“空闲 → 维修/停用 → 空闲”维护，不允许维修与停用互切或重复保存同状态。
- 当前关联必须包含有效设备、加工单、关联时间和关联人；无变化整组保存为真正零写入操作。
- 整组保存的四条路径统一返回目标加工单的稳定排序关联副本，不暴露内部存储引用。
- 本次未修改页面、UI、组件或路由，不存在列表页模板和交互性能例外。
