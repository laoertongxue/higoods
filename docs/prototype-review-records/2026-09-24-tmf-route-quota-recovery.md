# TMF 路由入口容量异常恢复审查

## 1. 基本信息

| 项目 | 内容 |
| --- | --- |
| 记录日期 | 2026-09-24 |
| 相关需求 / 任务 | 修复织带厂演示数据因浏览器存储配额写入失败而导致任一织带厂页面降级的问题 |
| 记录模式 | 完整产品审查 |
| 涉及系统 | FCS / PMS |
| 涉及页面路径 | `/fcs/craft/accessory/webbing/purchase-demands`、`/fcs/craft/accessory/webbing/semi-finished-orders`、`/fcs/craft/accessory/webbing/work-orders`、`/fcs/craft/accessory/webbing/pending-receipts`、`/fcs/craft/accessory/webbing/handover-records`、`/fcs/craft/accessory/webbing/pda` |
| 端类型 | 管理端 / 主管端 / PDA |
| 主要角色与任务 | 采购员、织带厂主管、仓管和生产领料人在本地演示数据不完整时仍可进入对应页面查看已保存记录 |

## 2. 影响判定

- 用户可见影响：有
- 判定依据：织带厂各页面进入前会自动补齐串联 Mock；写入配额失败原先会从路由准备函数冒泡，整个页面显示通用加载失败。现在只对已知“未保存、数量未改变”的容量错误降级为醒目提示并继续渲染页面；其他初始化异常仍按原错误路径处理。
- 本修复不清理、不覆盖、不压缩用户业务事实，也不宣称容量不足时新数据已保存。
- 基线：`AGENTS.md` 第 4、5、7 节。

## 3. 自查结论

| 检查项 | 结论 | 说明 |

| 文案、状态、数量与单位 | 通过 | 未改变采购、加工、数量和状态事实；写入失败继续保持“未保存、数量未改变”。 |

- 性能：本次浏览器流程中的页面导航及菜单切换均在 Playwright 默认断言窗口内完成；本记录不将该结果作为完整 `<500ms` 性能基准，页面全交互性能仍由独立性能门禁覆盖。
- `npm run build`：通过；渐进类型检查范围 0 错误，仓库仍有 6 个既有范围外 TypeScript 错误，450 项单元测试通过，Vite 生产构建通过。
- `npm run check:prototype-design-governance`：通过；当前提交的受管页面 / 数据 / 路由文件无其他治理范围变更。
- `git diff --cached --check`：通过。

## 6. 与前次存储修复证据的关系

前次记录 `2026-09-24-tmf-semi-finished-storage-recovery.md` 验证的是缩短历史操作签名后，一种合成 250,000 字符单键场景可成功保存；它没有证明任意用户现存浏览器存储都可用，也没有覆盖整套演示数据补齐遇到配额异常时的路由行为。本次报告的线上错误说明该旧证据范围不足。本次将目标改为确保存储配额错误不再阻断页面，并在真实浏览器注入写入失败进行验证；它不声称已释放用户存储空间或保证满额情况下的写入成功。
