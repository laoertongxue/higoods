## 3. 当前实施范围

### 3.1 任务 1：待交出仓五入口

已实现：

- 裁床待交出仓根页统一展示「菲票装袋」「中转袋入仓」「中转袋交出」「特殊工艺回仓」「菲票打编号」五个现场动作入口。
- 五个入口直接进入对应操作页，不在根页继续展示候选列表或说明性流程卡。
- 旧 `action` 地址自动进入新的对应操作页，避免旧入口形成死路。
- 「中转袋交出」使用独立入口名称和路由语义，并可返回五入口根页。
- 根路由识别旧 `action` 后立即跳转；已删除跳转之后不可达的旧候选、暂存袋、投影构建和子页渲染链，不改变五入口、旧地址兼容或现场操作结果。

### 3.2 任务 2：菲票装袋与中转袋入仓

已实现：

- 「菲票装袋」固定为「1 扫中转袋、2 扫菲票、3 确认装袋」。
- 菲票扫码识别成功后立即加入当前袋，可连续扫描，不再要求第二次点击「加入菲票」。
- Enter 扫描立即校验；无 Enter 的扫码枪输入停顿约 150 ms 后统一校验，输入过程中不重复构造候选数据。
- 扫码等待按任务、执行单和模式状态键分轮次管理；确认装袋前同步完成待处理扫描，成功清空或离开当前模式/路由时取消等待，旧轮次回调不得写回新一轮。
- 未知、未打印、作废或跨生产单菲票在扫描完成时立即局部提示，清空扫码框便于重扫，并保留袋码和已扫菲票。
- 同一袋首张菲票确定生产单，后续不同生产单菲票禁止加入，符合一个唛架和中转袋链路只属于一个生产单的业务规则。
- 页面仅保留袋码、已扫菲票数量、裁片数量和简短菲票编号，删除生产单、铺布单、面料、状态、记录、候选列表和说明卡。
- 装袋成功明确提示「装袋成功」，并在同一路由清空袋码、菲票、数量和上次扫码结果，立即进入新一轮。
- 「中转袋入仓」固定为「1 扫中转袋、2 扫库区库位、3 确认入仓」，不扫描或展示菲票。
- 入仓成功明确提示「入仓成功」，并清空袋码、库位进入新一轮。
- 装袋或入仓失败时保留本轮已扫数据，便于现场修正后重试。
- 页面本地 Mock 台账明确记录袋、菲票和库位状态：只有空袋可装袋、待装袋菲票可加入、已装袋待入仓袋可进入启用的裁床库位。
- 不存在袋、非空袋、同轮或跨轮重复菲票、已作废 / 已装袋菲票、空袋 / 已入仓 / 已交出 / 已作废袋、无效 / 停用 / 非裁床库位均被自动检查覆盖并阻断；成功后同步更新袋、菲票和库位归属，失败不修改台账。
- 当前为快速原型，仅使用页面本地 Mock 状态，不写事件账、不做跨模块一致性或真实持久化。

### 3.3 任务 3：中转袋整袋交出

已实现：

- 新 `transfer-bag-handover` 模式与旧交出装袋确认、特殊工艺回仓、默认通用交出分支隔离，不复用拆袋装袋页面。
- 历史深链 `action=handover-bagging-confirm` 在页面入口统一规范化为 `transfer-bag-handover`；实际渲染整袋交出页，旧逐菲票确认命令在该模式下不可执行，不再形成可达旧写入口。
- 页面固定为「1 扫中转袋、2 扫车缝任务、3 确认交出」，只保留一个主要按钮「确认交出」。
- 最小交出单位固定为整个中转袋，不扫描或选择菲票，不输入数量，不展示来源袋、目标袋或部分交出结构。
- 车缝任务扫码后自动带出车缝任务号、生产单号和接收工厂；工厂只读，不提供手选入口。
- 袋内菲票数量由袋码 Mock 数据只读带出，仅用于整袋识别，不允许选择袋内部分内容。
- 确认前允许改扫同一生产单且可接收的车缝任务，并覆盖任务号、生产单号和接收工厂草稿；跨生产单或不可接收任务仍被阻断并保留原有效草稿。
- 确认前手动清空车缝任务输入会清除任务号、生产单号、接收工厂和旧扫码反馈，但保留已识别袋及袋内菲票数量；随后必须重新扫描任务才能确认。
- 确认前手动清空中转袋输入会重置整轮，同时清除袋、车缝任务及其派生信息；随后必须从中转袋重新开始。
- 只有确认成功后才把最终任务写入袋台账的 `boundSewingTaskNo` 并形成真实绑定；已确认绑定阻断换绑，袋状态更新为「已交出」后同时阻断重复扫描和重复确认。
- 本页 Mock 袋记录生产单和「待交出 / 已交出 / 已作废」状态，车缝任务记录生产单、接收工厂和是否可接收；扫码与确认都会阻断袋非待交出、任务不可接收及生产单不一致。
- 确认成功后先把当前页袋状态改为「已交出」并记录唯一车缝任务，再清空页面进入新一轮；再次扫描或用旧状态重复确认同袋都会即时阻断。
- Enter 立即完成扫描；无 Enter 输入停顿约 150 ms 后完成。确认前同步冲刷最新等待扫描，旧轮次回调不能在确认或成功重置后写回。
- 全局键盘事件已精确接入袋码和车缝任务扫码框，Enter 会把原始事件传给交出 handler；不匹配特殊工艺或默认交出字段。
- 路由离开清理已下沉到 `appStore.navigate` 和 `syncFromBrowser` 统一边界；菲票装袋 / 入仓与中转袋交出分别派发对应 leave 事件，main 导航、PDA 顶部待办、退出登录和浏览器前进后退均经过此边界，同 URL 不派发，且 main 不再重复派发。
- 交出成功明确提示「交出成功」，清空袋码、任务码和派生信息，并留在同一路由开始新一轮；失败即时提示并保留有效扫码数据。
- 页面不展示生产现场全链路、铺布、面料、当前情况、最近记录或说明流程卡，返回路径固定为五入口根页。
- 当前为快速原型，仅使用当前页本地 Mock 状态，不写事件账、不做跨模块一致性、真实持久化或 API。

### 3.4 任务 4：Web 三操作与整体终验

已实现：

- Web 既有待交出仓菜单路由直接进入独立非列表执行页，页面仅保留「菲票装袋」「中转袋入仓」「中转袋交出」三个聚焦操作；历史仓库列表页恢复到基线，不再承接这些操作。
- Web 端统一使用编号输入和按钮确认，不使用「扫码」措辞，也不依赖摄像头、二维码组件或扫码设备。
- 「菲票装袋」只输入中转袋编号和菲票编号；菲票可逐张加入紧凑明细，不展示待入仓候选大列表、生产 / 铺布 / 面料或流程说明。
- 「中转袋入仓」只输入中转袋编号和库区库位，不包含菲票字段、菲票列表或菲票关系改写。
- 「中转袋交出」只输入中转袋编号和车缝任务号；生产单号与接收工厂由任务只读带出，不提供工厂选择、菲票、数量、部分交出或拆袋入口。
- Web 本地 Mock 覆盖同生产单、待交出、任务可接收、跨生产单、不可接收任务、已交出袋和重复交出门禁；与 PDA 一样按整袋确认，但不为快速原型引入跨端共享状态、事件账、API 或真实持久化。
- 菲票候选 Mock 与既有袋内菲票使用互不重复的编号；装袋时除菲票状态外还检查所有袋的实际归属，即使状态数据脏污也会阻断跨袋重复装入。
- 三个动作成功分别显示「装袋成功」「入仓成功」「交出成功」，局部清空本轮输入并停留在当前操作开始新一轮；失败只更新操作区反馈并保留有效输入。
- 高频输入框不绑定逐字符整页重绘；切换操作、加入菲票、查询任务与确认动作均只更新独立页工作区，不改写应用根节点、不丢失页面滚动位置。
- `check:web-cutting-transfer-bag-actions` 同时执行命令处理器、候选状态更新、跨袋重复归属防错、成功清空 / 失败保留，并校验路由与全局事件处理器真实接线、历史仓库页基线哈希；已纳入 `check:cutting:all`。
- 原第一次审查曾把尚未执行的真实浏览器复验写成「已通过」，该结论失真，现已撤回并纠正。当前只确认任务 1 至任务 4 的自动检查、真实路由集成和构建证据；1366×768、1280×720 及 PDA 小屏的第二轮真实浏览器对抗式操作仍属于任务 5。

## 5. 性能与可恢复性自查

- 高频扫码输入标记 `data-skip-page-rerender="true"`，避免每次输入触发整页重绘。
- 输入字符阶段仅更新本地值并重置 150 ms debounce，不构造菲票候选投影；Enter 到达时取消等待并立即校验。
- 确认装袋先同步冲刷当前状态键的待处理扫描，再按最新状态确认；成功重置、模式切换和路由离开均取消 timer，轮次令牌阻断迟到回调。
- 菲票命中后只清空扫码输入并刷新已扫结果区域，不重新扫描整页图标。
- 「确认装袋」「确认入仓」只在提交结果变化时刷新当前路由页面，以便立即呈现新一轮。
- 中转袋交出复用状态键、轮次令牌和确认前 `flush` 模式；成功后取消等待并重置当前轮，扫描完成仅局部更新识别结果。
- 聚焦检查执行统一路由离开 helper，并通过 PDA 顶部待办间接调用真实 `appStore.navigate`、浏览器同步调用 `syncFromBrowser`，实际捕获 `higood:pda-cutting-inbound-leave` 与 `higood:pda-cutting-handover-leave` 各一次；同 URL 不重复派发。全局 Enter 也通过可执行 helper 验证两个交出扫码框会派发、非 Enter 与特殊工艺字段不派发。
- 聚焦检查以真实历史深链渲染整袋交出工作区，并执行旧确认命令回归，确认旧逐菲票事件写入口不可达。
- 快速检查 `check:pda-cutting-wait-handover-entry-routing` 只验证 `routes-pda` 根路由 / 动态路由注册、五入口固定深链、不可达旧链清理和五个 legacy 解析目标，不执行页面渲染；冷启动约 0.58 秒，保留在 `check:cutting:all`。
- 真实集成检查 `check:pda-cutting-wait-handover-route-integration` 在同步 `window.location` 和 PDA 登录态后，逐条通过 `resolvePage` 验证根页、五个新深链、五个 legacy 跳转及跳转目标可渲染；legacy 跳转使用有界条件等待，同时确认浏览器与应用路由到达目标。
- 真实集成检查冷启动约 19–20 秒（本轮独立实测 20.05 秒，此前实测 18.55 秒），未加入日常 `check:cutting:all`；已进入 `check:cutting:release` 发布就绪序列并固定先于 `check:cutting:all` 执行。
- 本轮 `check:cutting:release` 实测为真实路由集成先通过，随后 `check:cutting:all` 在既有 `src/pages/process-factory/cutting/production-order-overview-view.ts: min-w >= 1600px` 门禁失败。本记录不宣称 `check:cutting:all` 全绿，且本轮未修改或掩盖该既有基线。
- 失败结果通过本地状态保留袋码、菲票、数量、库位或已识别车缝任务及派生信息，不要求重新进入页面。
- 聚焦检查覆盖自动加入、连续扫码、整袋交出精确字段与唯一按钮、任务派生工厂、同袋单任务、成功清空、失败保留和 timer/确认竞态。
- 整袋交出聚焦检查还覆盖袋状态异常、任务不可接收、袋与任务跨生产单、成功后本地状态更新及同袋重复扫描 / 重复确认。
- Web 聚焦检查覆盖三模式字段与按钮、装袋逐票紧凑明细、成功清空、失败保留、入仓无菲票、交出无工厂 / 数量 / 菲票输入、任务派生、重复交出和高频输入不整页重绘。
- Web 三操作交互仅修改独立页工作区内的输入、紧凑明细、只读派生结果和反馈节点，不触发应用根节点整页重绘，滚动位置不丢失。
- 自动检查已约束局部更新路径，但尚未在真实浏览器测量「点击确认」到结果 DOM 更新的耗时；装袋、入仓、交出各至少一次 `< 200 ms` 的 Performance API 证据属于任务 5，当前交互性能结论为待复验。
- 三条 PDA 回归、Web 回归、真实路由集成、列表页治理、全量原型治理与 `npm run build` 已通过；任务 5 真实浏览器复验尚未执行。
