## 2. 影响判定

- 用户可见影响：有
- 判定依据：仓管扫码查询页由“输入即模糊筛选并默认展示全量库存”改为单输入框精确查询；统一接受物料码、生产单、中转袋、菲票码、库位码、加工单号；手动输入点击“查询”后执行，扫码枪回车自动执行并清空输入框继续聚焦；结果区只在执行查询后出现，并补充物料真实图片、失败态和大图入口。仓管首页同步把“载具码”改为“中转袋”。
- 当前治理基线：`AGENTS.md` 第 4 节员工执行端设计、第 5 节 UI / 真实图片门禁和第 7 节验证原则。

## 4. 问题标签

- `字段过载`
- `缺扫码识别`
- `视觉干扰`

## 5. 主要问题与处理

| 问题 | 标签 | 影响角色 | 处理方式 | 是否仍有风险 |
| --- | --- | --- | --- | --- |
| 旧输入事件逐字触发模糊筛选，手输和扫码没有动作边界 | `缺扫码识别` | 工厂仓管 | 拆分输入值与已提交查询；手输只在点击“查询”后提交，扫码回车自动提交 | 否 |
| 旧查询缺少生产单、加工单等业务主标识，且“载具码”不是现场对象名称 | `字段过载` | 工厂仓管 | 六类编码建立同一精确索引，统一改称“中转袋” | 否 |
| 初始页直接铺满库存和说明文案，核心动作不突出 | `视觉干扰` | 工厂仓管 | 初始页只显示输入框和查询按钮，执行后才展示紧凑结果 | 否 |
| 扫码提交与最后一个输入事件存在异步竞争，可能保留旧码 | `点错风险` | 连续扫码的工厂仓管 | 输入事件不再写回查询草稿；回车提交后清空输入框并保持聚焦 | 否 |
