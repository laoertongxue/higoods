## 2. 影响判定

- 用户可见影响：有
- 判定依据：菜单名称和图标、后道页面对象名称、复检完成按钮、后道出货单列表／详情／Mock／路由／打印入口、条码与吊牌的纸张尺寸和内容结构均发生变化；新生成出货单还需要在新标签页打印，因此增加了该对象的最小跨页持久化。

当前审查依据 `AGENTS.md` 第 4、5、7 节；线上页面与用户提供的打印截图优先于旧原型文案和旧测试。

## 3. 自查结论

| 检查项 | 结论 | 说明 |
| --- | --- | --- |
| 角色、任务与页面模式 | 通过 | 后道出货单是管理端标准列表；只能由复检完成生成，不开放现场新建。 |
| 文案、状态、数量与单位 | 通过 | 后道任务、后道单、后道两仓命名已收口；出库数量逐 SKU 等于复检合格数量，单位为件。 |
| 扫码、真实图片与对象识别 | 通过 | 出货明细仍按真实图片／款式／SKU／颜色／尺码同块展示并保留失败态；吊牌顶部按线上事实使用纯色圆点，不把它误作商品图片。打印使用真实 Code 128。 |
| 防错、危险确认与主管兜底 | 通过 | 未完成复检不能生成；同一复检单幂等一张出货单；重复完成不会重复建单。 |
| 交接、跨端事实与异常追溯 | 通过 | 出库仓、接收仓、来源动作、生产单、后道任务、质检／后道单和复检单均可追溯；未扩展用户排除的异常平台。 |
| 低分辨率、PDA、弱网与上传恢复 | 通过 | 管理列表在 1280×720 无页面级横向溢出；本次没有新增 PDA 动作、上传或真实弱网机制。 |
| 命名路由、交互、图片大图与打印 | 通过 | 新菜单带 `Truck` 图标；复检按钮走统一事件入口；条码 40×30、吊牌 40×100，整单 A4；全流程截图已留存。 |

## 5. 主要问题与处理

| 问题 | 标签 | 影响角色 | 处理方式 | 是否仍有风险 |
| --- | --- | --- | --- | --- |
| 旧复检按钮的内联事件进入实际 DOM 后为空，页面无法完成复检 | 点错风险 | 复检员 | 改为 `data-post-finishing-action="complete-recheck"`，由统一后道事件入口读取逐 SKU 结果并完成复检 | 否 |
| 新生成的出货单只在当前页内存中，新标签页打印无法读取 | 协作断裂 | 后道仓管 | 仅对后道出货单增加 `localStorage` 最小持久化，保留同一复检单幂等键 | 否 |
| 初版把线上条码纸张误判为 60×40 | 视觉干扰 | 换码人员 | 按用户线上截图白底 4:3 比例收口为 40×30，并重新截图验收 | 否 |
| 初版把吊牌顶部纯色圆点误作商品图片 | 视觉干扰 | 换码人员 | 删除吊牌图片读取、`<img>` 和失败态，改为固定深灰纯色圆点并增加 DOM 负向契约 | 否 |

结论：通过。
