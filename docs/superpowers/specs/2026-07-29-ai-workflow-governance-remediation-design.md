# AI 编码工作流治理整改设计

## 1. 目标

按 2026-06-29 至 2026-07-29 Better Harness 冻结审计的 7 项 Finding，建立最小、可执行、可验证的闭环：

1. 原型审查记录必须与本次受管文件或路由明确绑定。
2. 变更文件必须能确定性路由到最小检查集合。
3. 最终改动、相关检查、CodeGraph 状态和交付阶段必须进入同一份机器可读收据。
4. Superpowers 仅保留最小执行轨迹，不引入新的代理平台。
5. Better Harness 的经验候选必须来自独立、可比较的任务上下文，不能用重复摘要次数替代。

## 2. 范围与边界

项目侧只修改治理文档、治理脚本、工作流脚本、测试和 `package.json`。不修改页面、业务 Mock 数据、路由或交互，因此本次整改本身不需要新增原型审查记录。

Better Harness 侧只修改 Codex Session Evidence 的经验候选选择及对应测试。不得读取或写入 Memory 正文，不改变报告评分，不创建新的 Skill、Rule 或 Hook。

不引入数据库、服务端、状态管理框架或第二套测试框架。

## 3. 方案选择

采用“一套共享工作流内核 + 薄 CLI”方案：

- `scripts/workflow-governance/` 保存纯函数和稳定数据契约。
- 现有原型治理脚本调用共享内核完成记录绑定。
- 受影响检查路由和任务收据复用同一份变更路径分类结果。
- CodeGraph、验证和交付状态都写入同一份任务收据。
- Superpowers 阶段轨迹作为任务收据的可选输入；只有任务明确要求相应阶段时才校验。

未采用的方案：

- 不把逻辑全部堆进 `check-prototype-design-governance.ts`，避免后续收据脚本复制路径解析。
- 不创建独立 Web 服务或中央数据库，避免把原型仓库改造成工程平台。

## 4. 数据契约

### 4.1 原型审查记录

审查记录新增机器可读章节：

```markdown
## 7. 变更覆盖与验证

### 受管文件

- `src/pages/example.ts`

### 页面路由

- `/example`

### 验证命令

- `npm run check:example`：通过

### 例外

- 无
```

至少一项受管文件必须覆盖本次变更。记录还必须保留规范引用、自查结论、最终结论、验证命令和例外说明。

### 4.2 受影响检查路由

路由结果包含：

- `changedPaths`
- `fastChecks`
- `governanceChecks`
- `fullChecks`
- `unknownPaths`
- `escalationReasons`

页面、数据、路由、处理器、列表公共组件和治理脚本分别有确定性规则；未知路径升级到安全完整检查，不静默跳过。

### 4.3 任务完成收据

收据包含：

- 最终版本：Git HEAD、工作区差异指纹、变更文件。
- 验证：实际命令、退出码、开始与结束时间、覆盖说明。
- CodeGraph：同步前状态、同步退出结果、同步后状态、待同步文件。
- Superpowers：触发原因、调用、阶段产物、执行、审查和最终验证。
- 交付：`implemented`、`verified`、`delivered`、`accepted` 四级状态。

最后一次实质改动后，差异指纹变化会使旧收据失效。没有远端 provider 回执不能进入 `delivered`；没有明确接受引用不能进入 `accepted`。

## 5. 错误处理

- 审查记录缺失、无关或缺字段时输出具体文件和失败原因。
- 检查路由遇到未知路径时升级，不报“无检查”。
- 任一验证命令失败时仍写诊断收据，但状态不得超过 `implemented`。
- CodeGraph 同步失败、状态不可解析或存在待同步文件时不得进入 `verified`。
- 交付版本与验证版本不一致时拒绝升级状态。
- Superpowers 轨迹只在任务声明需要时强制；请求中出现技能名称不构成执行证据。

## 6. 测试策略

所有行为按 TDD 实现：

- 纯函数测试覆盖原型记录的成功与三个负例。
- 路由测试覆盖补料页面、裁片数据、主处理器、列表组件和未知路径。
- 收据测试覆盖验证后改动失效、CodeGraph 不健康阻断、无 provider 回执阻断交付。
- 阶段轨迹测试覆盖完整两阶段审查和“只出现技能名称”的负例。
- Better Harness 测试使用两个独立上下文和重复摘要噪音，确认只生成可比较候选。

最终运行项目专项测试、治理检查、构建、Better Harness 相关测试、CodeGraph 同步与状态检查。
