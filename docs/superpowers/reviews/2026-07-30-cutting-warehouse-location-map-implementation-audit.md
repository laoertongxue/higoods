# 裁床待加工仓与待交出仓库位图逐项实施审计

## 1. 审计范围与结论口径

本审计逐项对照：

- `docs/superpowers/specs/2026-07-30-cutting-warehouse-location-map-design.md`
- `docs/superpowers/plans/2026-07-30-cutting-warehouse-location-map-implementation-plan.md`
- 当前分支实际源码、专项检查、直接回归、Playwright 生产构建验收、治理检查和任务收据

状态定义：

- `已实现`：代码与专项证据存在。
- `已验证`：最后一次实质修改后，对应自动检查或浏览器验收通过。
- `不适用`：计划中的条件性文件无需修改，且真实写入路径已由其他文件统一承接。
- `待最终门禁`：实现与直接证据已通过，但仍需最后一次完整总跑、CodeGraph 同步或任务收据。

本轮审计不接受“文件存在”“构建通过”作为全部完成证据。每个业务条款必须同时指出实现位置和验证方式。

## 11. 本轮查漏补缺记录

本轮逐项审查实际发现并修正了以下遗漏，证明此前“全部完成”结论不成立：

1. Web 待交出仓顶部“中转袋入仓”被旧文本处理器抢占，新单选库位图未命中真实按钮。
2. 新处理器只读取 `data-wait-handover-action`，未承接顶部的 `data-wait-handover-web-action`。
3. 浏览器验收使用不存在的 `TASK-MAP`，没有命中真实 PDA 中转袋入仓任务。
4. PDA 连续多选验收以按钮序号代替物理连续关系，可能选到只有一个空闲格的货架。
5. 测试初始化在刷新时再次清空布局，形成虚假的持久化失败。
6. 特殊工艺旧检查仍要求“发料”旧契约，与当前“交出/回仓”页面不一致。
7. 特殊工艺部分交出和同袋部分回仓的占用数量折叠不完整。
8. 旧审查记录仍把“库区”描述为“库位组”，与确认设计冲突。
9. 仓库级门禁发现生产总览重复声明 2280px 最小宽度，页面宽度治理无法闭环。
10. PO14671 冻结 BOM 缺少面料样布图，导致裁片身份不完整。
11. 菲票循环场景全部带特殊工艺，普通菲票场景被覆盖。
12. 首次交出记录缺少 0 数量的“之前已交”快照。
13. 特殊工艺补充任务可能从没有适用成衣 BOM 的生产单生成，来源追溯不完整。
14. 生产总览与特殊工艺生成专项仍保留旧表头、旧分组和已删除子加工单契约。
15. 标准列表真实 Chromium 检查只放宽了服务启动等待，页面刷新仍使用 30 秒默认导航超时，导致冷启动抖动时收据不稳定。

上述问题均已增加专项或浏览器回归，避免再次出现“代码存在但真实入口未命中”的假完成。
