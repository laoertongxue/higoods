# 辅料仓分阶段验收方案（计划，不是测试结果）

> V1.0，2026-10-19；依据[调整方案](../product-design/2026-10-19-辅料仓业务调整方案.md)、[实施计划](../implementation-plans/2026-10-19-accessory-warehouse-flow.md)和[原子矩阵](../requirement-traceability/2026-10-19-accessory-warehouse-matrix.md)。
> 本文件保留验收设计；实际执行和结果见逐项验收结果（历史验收产物已清理），不将计划预期当作通过证据。D1/D3/D4随用户按方案执行授权采用方案建议；D2/D5/D6保留核验。实施期用户补充U9：演示款式图允许错配，但每款必须有图；不再以演示款名精确对应阻断，仍检查加载及适用交互。

## A. 验收层次与环境

1. 主数据/数量/分类/状态/幂等契约：复用 node:test 与项目 TypeScript 工具，优先最小失败场景，不建立新测试基础设施。
2. 原子保存与迁移：真实 IndexedDB 的隔离浏览器上下文，验证 transaction complete、刷新、关闭重开、下游直达、失败不半套。
3. 页面：实际导航、输入、查询、确认、扫码/打印等真实事件；检查可见结果与输入恢复。静态源码/DOM计数不能替代可见结果。
4. 产品与对抗审查：主代理逐条追踪且审完整diff；独立审查一名检查业务断点、数据来源、绕过入口和失败恢复，不重复无限文件探索。若用户另要求两轮再分别记录。
5. 性能：固定生产预览资产，在规定页面和动作完成时计时；每个适用家族至少5有效样本，任一>1000ms失败。

每次记录：源码HEAD/未提交diff哈希、工作树、构建命令及产物哈希、服务端口、浏览器版本、视口、Asia/Jakarta业务时区、实际测试日期、必要网络和图片来源、数据量、缓存条件、动作起点和可见结果终点。开发服务仅诊断，不能当生产预览或正式部署证据。

设备范围：管理列表1366×768及最低1280×720；仓管/员工主要动作1024×768；既有PDA领料与后道接收的受影响入口按实际目标小屏（未提供设备前使用390×844浏览器模拟并明确非实体设备）；不据模拟宣称扫码枪/打印机实测。阶段一不因WLS图标覆盖而跑所有WLS业务。

## H. 页面布局与性能

### H1 页面覆盖

- 第一阶段：基础仓库、库区库位、GTP配料、面料看板新菜单入口、WLS侧栏全部图标；改动公共基础页面时覆盖其共享路由别名的真实渲染分支，不机械重跑同组件所有重复地址。
- 第二阶段：GTP调拨、两仓待收/接收、有效分配后目的方更新；两仓各功能均核验。
- 第三阶段：两仓领料、两仓后道调拨、车缝任务、既有领料扫码、后道Web/PDA接收及受影响材料库存视图。
- 第四阶段：现有裁剪改派确认入口、相关列表/旧单、在途和已入库接收链。

### H2 性能家族草案

下表是采样设计，实际等价性在实现后核对；角色、成功/失败、保存/取消、冷/热不能随意合并。每个新增动作都须归属明确家族，不能只测列表加载。

| 家族 | 覆盖及代表选择 | 起点→完成 |
| --- | --- | --- |
| PF01 | 基础仓库/库位查询及明细，按实际规模最重者；三仓成员仍各做功能核验 | 实际查询/打开→结果及图标绘制可交互 |
| PF02 | GTP配料初次访问、刷新、站内切换分别采样；记录/备注/完成/适用导出打印各列动作家族 | 导航或真实事件→内容/必要图片就绪；保存还需持久可读 |
| PF03 | 完成配齐自动调拨、目的方待定补齐、整单出库分别测 | 确认或分配事件→对应单据/数量可见且持久可读 |
| PF04 | 两仓一次收货上架；错误位置/事务失败恢复单列 | 确认→单据、库存、库位共同完成；失败→错误及输入可操作 |
| PF05 | 有效任务领料加载、确认实交、旧版本阻断、打印 | 事件→当前清单/交接事实/图片或打印结果就绪 |
| PF06 | 后道调拨及Web/PDA接收；不同端实现不强合并 | 事件→同源接收状态及材料库存可读 |
| PF07 | 未出改厂、在途安排、原仓收后调拨、已入库改厂分别测 | 最终确认→全部必要记录持久及页面就绪 |
| PF08 | WLS侧栏展开/收起/选中，按最重分组含子菜单 | 点击→最终图标和菜单项绘制完毕 |

每个适用家族至少5个有效样本，含首次与边界；冷启动、刷新、站内切换按适用场景分开。保留原始值、最大值、环境、脚本、起终点和失败。任一有效样本>1000ms即失败；不能用平均、最快、Loading、占位、HTTP200、函数返回或减小数据量替代。计时不含用户阅读/填写等待。图标只变配置的无关业务动作不纳入性能重测；若公共渲染实现改变则按影响扩大。

证据采集先最小预检路由/账号/来源/选择器/图片，预检与正式冷态分开；脚本错误暂停修正，不盲跑批次。记录同机负载，不擅自关闭用户进程，保留慢样本。
