# 裁片放行管理优化 产品需求说明

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 文档日期 | 2026-07-25 |
| 涉及系统 | FCS（工厂生产协同系统）、PFOS（工艺工厂运营系统） |
| 主要角色 | 裁床主管、PPIC（生产计划与库存控制）、裁床交出人员、车缝厂 |

## 2. 需求背景

裁片放行管理的核心目的是：**裁床告知 PPIC，当前生产单可以拿去安排车缝的总量是多少件。**

此前页面以"系统计算的当前齐套数量"作为放行判断的唯一依据，导致：
- 裁床主管无法基于现场经验主动确认可放行数量。
- 即使某些裁片已经存在只是未点收入仓，系统也不允许放行。
- PPIC 看不到裁床的协作承诺，只能看系统齐套数字。
- 目标数量（用于补料/补裁计算）和可做放行数量被混为一谈。

本次优化将两个概念清晰拆分，并建立完整的裁决-派工-交出责任链路。

## 3. 涉及菜单页面与优化内容

### 3.1 裁片放行管理列表页

**菜单位置**：`裁床厂管理 → 裁片放行管理`

**优化内容**：

| 优化项 | 说明 |
| --- | --- |
| 新增"放行状态"列 | 展示每个生产单的放行结论。6 种状态：待维护目标、待裁床确认、按齐套放行、风险放行、暂不放行、确认后需复核 |
| 新增"可做放行数量"列 | 展示裁床主管确认的当前可安排车缝的总件数，PPIC 以此为准 |
| 新增"风险放行数量"列 | 当可做放行数量超过系统齐套数量时，差额部分在此展示 |
| 新增"放行状态"筛选项 | 可按放行状态过滤列表 |
| 列表统计区新增 | 增加"可放行"和"风险放行"的生产单数量统计 |

**业务逻辑**：
- 放行状态由系统根据裁床主管的确认动作自动判定。
- 没有放行确认记录时，状态为"待维护目标"（无目标数量）或"待裁床确认"（有目标但未确认放行）。
- 可做放行数量必须在 0 到目标数量之间，不允许超过目标数量。

### 3.2 裁片放行矩阵详情页

**菜单位置**：`裁片放行管理列表 → 点击"查看矩阵"`

**优化内容**：

| 优化项 | 说明 |
| --- | --- |
| 新增"确认放行"操作区域 | 裁床主管可逐颜色逐尺码确认可做放行数量，汇总后告知 PPIC |
| 新增"风险原因"填写入口 | 当可做放行数量超过系统齐套数量时，必须填写风险原因。当前版本不结构化，主管以自由文本描述 |
| 新增"放行距目标缺口"展示 | 裁床主管可以看到距离自己设定的目标还差多少 |
| 新增"放行确认版本日志"面板 | 每次确认放行生成一条不可变历史记录，含：版本号、确认时间、确认人、可做数量变化、风险数量变化 |
| 新增"查看补料依据"入口 | 链接到补料管理页面，携带当前生产单的目标缺口数据 |
| 颜色尺码汇总新增 | 每条颜色尺码行展示该颜色尺码的裁床确认可做放行数量 |

**业务逻辑**：
- 裁床主管必须先维护好颜色尺码的目标数量，才能确认可做放行数量。
- 目标数量用于计算补料/补裁的缺口：系统根据"目标数量 × 单件用料量 − 已裁裁片数量"反算出还需要补多少物料或裁片。
- 可做放行数量按颜色尺码分别填入，页面自动汇总。
- 当裁床确认可做数量 > 系统齐套数量时，超出部分称为"风险放行"，必须填写原因。
- 确认放行生成版本日志，旧版本保留但不再对 PPIC 生效。
- 确认放行后，如果裁片事实（铺布、裁片单冻结/恢复等）发生变化，放行状态自动标记为"确认后需复核"，不自动作废。

**交互流程**：
1. 裁床主管点击"选择目标"，逐颜色尺码填入计划要裁到的数量 → 点击"保存目标"。
2. 裁床主管点击"确认放行"，页面展示各颜色尺码的当前齐套数量和可做数量输入框。
3. 裁床主管逐颜色尺码调整可做数量（默认值取目标数量和齐套数量的较小值）。
4. 如果可做总数超过齐套总数，页面显示风险原因输入框（必填）。
5. 点击"确认放行"，生成版本记录，PPIC 页面同步更新。

### 3.3 PPIC 车缝分配工作台

**菜单位置**：`生产协同 → 车缝分配工作台`

**优化内容**：

| 优化项 | 说明 |
| --- | --- |
| 裁床判断区域重构 | 首行最大字体展示"当前可派车缝：N 件"，其次展示系统齐套、风险放行、裁床目标、距目标还差、风险原因 |
| 任务列表可分配判定 | 改为以裁床确认可做放行数量为可派上限 |
| 详情抽屉裁床判断卡片 | 展示放行状态和可派总量 |
| 派工弹窗裁床判断参考 | 展示放行状态和可派总量 |
| 新增"超可派派工确认"弹窗 | 当 PPIC 派工数量超过裁床确认可做放行数量时，弹出二次确认提示："当前派工数量超过裁床确认可做放行数量，可能导致车缝缺裁片开工，请确认是否继续。"不阻断操作，原因非必填 |

**业务逻辑**：
- PPIC 查看可派总量的优先级：当前可派车缝 > 系统齐套 > 风险放行 > 裁床目标。
- PPIC 可以超过裁床确认可做放行数量派工，但必须看到风险提示并二次确认。
- PPIC 不负责维护目标数量或可做放行数量，这些由裁床主管负责。

**交互流程**：
1. PPIC 进入车缝分配工作台，每个车缝任务显示裁床放行摘要。
2. PPIC 选择任务、填入派工数量。
3. 如果派工数量 > 裁床确认可做放行数量，弹窗提示超可派风险，PPIC 确认后继续。
4. PPIC 的历史派工记录保留当时引用的放行确认版本，后续可追溯。

### 3.4 车缝配料管理页

**菜单位置**：`生产协同 → 配料管理 → 车缝配料`

**优化内容**：

| 优化项 | 说明 |
| --- | --- |
| 裁片放行约束卡片 | 判断结果改为展示放行状态，可做数量改为展示 PPIC 可派总量 |

### 3.5 裁片交出管理页

**菜单位置**：`裁床厂管理 → 交出管理`

**优化内容**：

| 优化项 | 说明 |
| --- | --- |
| 裁片放行依据卡片新增 | 在原有"最低应回数量（交接时实际齐套）"下方，新增"按已交出中转袋菲票累计最低应回" |

**业务逻辑**：
- 车缝厂最终需要回货的数量，不取决于裁片放行数量，也不取决于 PPIC 派工数量，而是取决于**实际交给该车缝厂的中转袋里所有菲票对应的裁片部位数量**。
- 每个中转袋有唯一袋码，每个菲票唯一且对应一个裁片部位和数量。
- 最低应回按照"车缝厂 + 生产单"累计已交出的所有中转袋菲票计算：同颜色同尺码的所有部位裁片数量按 BOM 单件用量折算后，取最小值即为该颜色尺码的最低应回件数。

### 3.6 生产日报

**菜单位置**：`裁床厂管理 → 生产日报`

**优化内容**：

| 优化项 | 说明 |
| --- | --- |
| "当前可放行数量"指标口径更新 | 从原来的目标数量口径切换为裁床确认可做放行数量口径 |
| 裁片放行明细行 | 摘要和状态改为展示放行状态和裁床确认可做数量 |

## 4. 关键业务规则

| 规则 | 说明 |
| --- | --- |
| 可做放行数量 ≤ 目标数量 | 硬约束，不可超目标。超过目标的部分进入多裁/余片处理 |
| 可做放行数量 > 系统齐套数量 | 允许，属于"风险放行"，裁床主管必须填写风险原因 |
| 风险原因格式 | 暂不结构化，自由文本 |
| 目标数量维护人 | 裁床主管 |
| 放行确认版本化 | 每次确认生成版本记录，历史版本保留，PPIC 默认读取最新有效版本 |
| PPIC 超可派派工 | 不强制限制，但二次提示确认 |
| 放行确认粒度 | 生产单汇总由颜色尺码明细加总，不允许只填总数 |
| 车缝最低应回计算范围 | 车缝厂 + 生产单累计 |
| 车缝最低应回计算依据 | 实际已交出的中转袋内唯一菲票，不依赖车缝厂 PDA 收货确认 |
| 裁片事实变化处理 | 铺布完成、裁片单冻结/恢复/冲销后，如果已有放行版本，自动标记为"确认后需复核" |
| 目标数量变更处理 | 目标数量变更后，如果已有放行版本，自动标记为"确认后需复核" |

## 5. 完整业务链路

```
裁片事实 / 目标数量
  → 系统计算当前齐套数量、目标缺口、补料依据
  → 裁床主管确认可做放行数量
  → 生成裁床放行确认版本
  → PPIC 按最新有效放行版本判断生产单可派总量
  → PPIC 安排车缝任务
  → 裁床按中转袋交出裁片
  → 系统按车缝厂 + 生产单累计已交出中转袋菲票
  → 计算车缝最低应回数量
```

**三段责任边界**：

| 阶段 | 责任方 | 关键结论 |
| --- | --- | --- |
| 裁片放行判断 | 裁床主管 | PPIC 当前可派多少 |
| PPIC 派工决策 | PPIC | 具体派给哪个车缝厂、派多少 |
| 车缝最低应回 | 裁床交出 + 系统 | 按已交出实物至少该回多少 |
