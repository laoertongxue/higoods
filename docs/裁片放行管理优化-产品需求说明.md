# 裁片放行管理优化 产品需求说明

## 一、文档目的

本文档用于说明裁片放行管理的业务目标、角色分工、业务规则、页面需求和验收口径，供研发、测试、产品和业务人员共同理解需求。

本文档只描述业务要求，不限定研发实现方案。

## 二、业务背景

裁片放行管理的核心目标是：裁床明确告诉 PPIC，某个生产单当前可以用于安排车缝的数量是多少。

在现有业务中，系统通常以“当前系统齐套数量”判断是否可以安排车缝。但现场存在以下情况：

- 部分裁片已经在现场完成，只是系统尚未完成入仓或点收。
- 裁床主管掌握现场真实进度，但系统齐套数量不能完整表达现场判断。
- PPIC 需要一个明确、可追溯的裁床承诺数量，用于判断当前能派多少车缝。
- 目标数量、系统齐套数量、裁床确认可放行数量、车缝最低应回数量经常被混用，导致责任边界不清。

本次优化需要把这些数量口径拆清楚，并形成从裁床判断、PPIC 派工到裁片交出的完整业务链路。

## 三、业务目标

本次需求需要达成以下目标：

1. 裁床主管可以按生产单、颜色、尺码确认当前可放行给 PPIC 安排车缝的数量。
2. PPIC 在安排车缝时，可以优先看到裁床确认的当前可派数量，而不是只看系统齐套数量。
3. 当裁床确认的可放行数量超过系统齐套数量时，系统允许风险放行，但必须记录风险原因。
4. 裁床放行确认需要版本化，便于追溯 PPIC 当时依据的是哪一次裁床确认结果。
5. PPIC 可以超过裁床确认数量派工，但必须二次确认风险。
6. 车缝最低应回数量必须按实际已交出的中转袋和菲票计算，不以裁床放行数量或 PPIC 派工数量为准。
7. 同一生产单必须能够贯穿“裁床放行、PPIC 派工、裁片交出、最低应回”全链路。

## 四、核心业务概念

| 概念 | 业务含义 |
| --- | --- |
| 目标数量 | 裁床主管按生产单、颜色、尺码确认希望裁到的数量，用于补料、补裁和缺口判断。 |
| 系统齐套数量 | 系统根据当前已入仓、已确认有效的裁片数量，按部位齐套规则计算出的可成衣数量。 |
| 可做放行数量 | 裁床主管确认当前可以让 PPIC 拿去安排车缝的数量。 |
| 风险放行数量 | 可做放行数量超过系统齐套数量的部分。 |
| 放行确认版本 | 裁床主管每次确认可做放行数量后形成的业务记录，历史记录保留。 |
| PPIC 当前可派数量 | PPIC 当前安排车缝时应优先参考的裁床确认可做放行数量。 |
| 中转袋 | 裁片交出时用于装载裁片的实物袋，每个中转袋有唯一袋号。 |
| 菲票 | 裁片交出和追溯的最小业务凭证，记录生产单、颜色、尺码、部位和数量。 |
| 最低应回数量 | 根据已交给某车缝厂的中转袋内菲票，计算该车缝厂至少应回成衣的数量。 |

## 五、角色与职责

| 角色 | 主要职责 |
| --- | --- |
| 裁床主管 | 维护目标数量，确认可做放行数量，填写风险放行原因，复核裁片事实变化后的放行结果。 |
| PPIC | 查看裁床放行结果，安排车缝任务，在超出可派数量时确认派工风险。 |
| 裁片交出人员 | 按生产单、中转袋和菲票交出裁片，保证交出实物与记录一致。 |
| 车缝厂 | 接收裁片并按已收到的裁片组织生产，后续回货数量与已交出实物形成对应关系。 |
| 系统 | 计算系统齐套数量、目标缺口、风险放行数量和最低应回数量，并保留关键业务记录。 |

## 六、业务范围

本次需求包含以下业务范围：

- 裁片放行列表查看。
- 裁片放行矩阵查看。
- 目标数量维护。
- 裁床确认可做放行数量。
- 风险放行原因记录。
- 放行确认版本记录。
- PPIC 查看裁床可派数量。
- PPIC 超可派派工风险确认。
- 车缝配料场景读取裁片放行约束。
- 裁片交出场景读取放行依据和最低应回数量。
- 生产日报读取裁片放行确认口径。

本次需求不包含以下范围：

- 不新增真实后端审批流。
- 不要求自动替 PPIC 做派工决策。
- 不要求裁床放行自动生成车缝任务。
- 不要求车缝最低应回等同于最终结算数量。
- 不要求风险原因结构化为固定枚举。

## 七、页面业务需求

### 1. 裁片放行列表

裁片放行列表用于让裁床主管和管理人员快速查看每个生产单当前是否可以放行，以及可放行数量是多少。

列表需要展示以下业务信息：

| 信息 | 说明 |
| --- | --- |
| 生产单 | 当前裁片放行判断对应的生产单。 |
| 放行状态 | 展示当前生产单的放行结论。 |
| 目标数量 | 裁床主管维护的生产单目标数量汇总。 |
| 系统齐套数量 | 系统根据当前裁片事实计算出的齐套数量。 |
| 可做放行数量 | 裁床主管确认后，PPIC 当前可参考的可派数量。 |
| 风险放行数量 | 可做放行数量超过系统齐套数量的部分。 |
| 复核提示 | 如果目标或裁片事实在确认后发生变化，需要提示复核。 |

列表需要支持按放行状态筛选。

列表需要展示放行相关统计，包括可放行生产单数量、风险放行生产单数量、待确认生产单数量和需复核生产单数量。

### 2. 裁片放行矩阵

裁片放行矩阵用于让裁床主管按颜色和尺码查看目标数量、系统齐套数量、当前缺口和可做放行数量。

矩阵需要展示以下业务信息：

| 信息 | 说明 |
| --- | --- |
| 颜色 | 当前生产单下的成衣颜色。 |
| 尺码 | 当前生产单下的成衣尺码。 |
| 目标数量 | 裁床主管计划裁到的数量。 |
| 系统齐套数量 | 系统按裁片事实计算出的齐套数量。 |
| 可做放行数量 | 裁床主管确认可交给 PPIC 安排车缝的数量。 |
| 目标缺口 | 目标数量减去当前可支持数量后的缺口。 |
| 风险数量 | 可做放行数量超过系统齐套数量的部分。 |

裁床主管需要先维护目标数量，才能确认可做放行数量。

裁床主管确认可做放行数量时，必须按颜色和尺码填写，不允许只填写生产单总数。

系统需要自动汇总各颜色尺码的可做放行数量，形成生产单级别的 PPIC 当前可派数量。

### 3. 目标数量维护

目标数量由裁床主管维护。

目标数量用于以下业务场景：

- 判断裁床当前放行数量是否超过计划目标。
- 计算颜色尺码维度的目标缺口。
- 支撑补料、补裁和后续异常追踪。

目标数量的业务规则如下：

| 规则 | 说明 |
| --- | --- |
| 按颜色尺码维护 | 每个颜色尺码都需要有独立目标数量。 |
| 汇总只读 | 生产单总目标数量由颜色尺码明细自动汇总。 |
| 可调整 | 目标变化后，需要保留当前业务结果，并提示已有放行确认需要复核。 |
| 不等于放行数量 | 目标数量是计划口径，可做放行数量是当前协作承诺口径。 |

### 4. 裁床确认放行

裁床主管确认放行时，需要填写每个颜色尺码当前可做放行数量。

确认放行的业务规则如下：

| 规则 | 说明 |
| --- | --- |
| 不得超过目标数量 | 每个颜色尺码的可做放行数量不能超过该颜色尺码目标数量。 |
| 可以低于系统齐套数量 | 裁床主管可以保守放行，少于系统齐套数量。 |
| 可以超过系统齐套数量 | 允许风险放行，但必须填写风险原因。 |
| 风险原因按整单填写 | 当前版本不要求按颜色尺码分别填写风险原因。 |
| 确认后形成版本 | 每次确认后形成一条放行确认版本，历史保留。 |

确认放行后，系统需要输出以下结果：

- 放行状态。
- PPIC 当前可派数量。
- 风险放行数量。
- 风险原因。
- 确认人。
- 确认时间。
- 放行确认版本号。

### 5. 放行状态

系统需要支持以下放行状态：

| 状态 | 业务含义 |
| --- | --- |
| 待维护目标 | 当前生产单尚未维护目标数量，不能确认放行。 |
| 待裁床确认 | 当前生产单已有目标数量，但裁床尚未确认可做放行数量。 |
| 按齐套放行 | 裁床确认的可做放行数量不超过系统齐套数量。 |
| 风险放行 | 裁床确认的可做放行数量超过系统齐套数量，且已填写风险原因。 |
| 暂不放行 | 裁床主管确认当前不允许 PPIC 安排车缝。 |
| 确认后需复核 | 已有放行确认后，目标数量或裁片事实发生变化，需要裁床主管重新确认。 |

### 6. 放行确认版本

每次裁床主管确认放行，都需要形成一条放行确认版本。

版本记录需要包含以下业务信息：

| 信息 | 说明 |
| --- | --- |
| 版本号 | 同一生产单下按确认顺序递增。 |
| 生产单 | 当前确认对应的生产单。 |
| 颜色尺码明细 | 每个颜色尺码的目标数量、系统齐套数量和可做放行数量。 |
| 可派总量 | 所有颜色尺码可做放行数量汇总。 |
| 风险数量 | 所有颜色尺码风险数量汇总。 |
| 风险原因 | 风险放行时由裁床主管填写。 |
| 确认人 | 执行确认动作的裁床主管。 |
| 确认时间 | 放行确认完成时间。 |

PPIC 默认读取最新有效放行确认版本。

历史版本不能删除，便于后续追溯 PPIC 当时依据的裁床判断。

### 7. PPIC 车缝分配

PPIC 在安排车缝任务时，需要看到裁床放行摘要。

裁床放行摘要需要突出以下信息：

- 当前可派车缝数量。
- 放行状态。
- 系统齐套数量。
- 风险放行数量。
- 裁床目标数量。
- 距目标缺口。
- 风险原因。
- 裁床确认人和确认时间。

PPIC 派工规则如下：

| 规则 | 说明 |
| --- | --- |
| 优先参考裁床可派数量 | PPIC 安排车缝时，以裁床确认的当前可派数量为第一参考。 |
| 不强制阻断超可派 | PPIC 可以超过裁床当前可派数量派工。 |
| 超可派必须二次确认 | 如果派工数量超过裁床当前可派数量，系统必须提示风险，并要求 PPIC 确认后继续。 |
| 超可派原因非必填 | PPIC 确认风险即可继续，当前版本不要求填写原因。 |
| 保留当时版本 | 派工记录需要保留当时引用的裁床放行确认版本信息。 |

超可派提示文案业务含义为：当前派工数量超过裁床确认可做放行数量，可能导致车缝缺裁片开工，请确认是否继续。

### 8. 车缝配料

车缝配料场景需要读取裁床放行结果，用于提醒配料人员当前生产单是否存在裁片放行约束。

车缝配料页面需要展示以下业务信息：

- 放行状态。
- PPIC 当前可派数量。
- 系统齐套数量。
- 风险放行数量。
- 风险原因。

车缝配料不负责维护目标数量，也不负责修改裁床放行数量。

### 9. 裁片交出

裁片交出场景需要展示裁床放行依据，同时独立计算车缝最低应回数量。

裁片交出的业务规则如下：

| 规则 | 说明 |
| --- | --- |
| 按中转袋交出 | 裁片交出时必须能识别中转袋。 |
| 按菲票追溯 | 每张菲票记录生产单、颜色、尺码、部位和数量。 |
| 按车缝厂和生产单累计 | 最低应回按同一车缝厂、同一生产单下已交出的中转袋菲票累计。 |
| 不依赖 PDA 收货 | 最低应回以已交出实物记录为准，不等待车缝厂 PDA 收货确认。 |
| 不等于放行数量 | 最低应回不是裁床可派数量，也不是 PPIC 派工数量。 |

最低应回的业务计算口径如下：

1. 找到某车缝厂下某生产单已经交出的所有中转袋。
2. 汇总这些中转袋内所有有效菲票。
3. 按颜色、尺码、部位累计裁片数量。
4. 根据每件成衣所需部位数量进行折算。
5. 同一颜色尺码下，取所有必要部位中可组成成衣数量的最小值。
6. 将所有颜色尺码的结果汇总，得到该生产单对该车缝厂的最低应回数量。

### 10. 生产日报

生产日报需要读取裁床放行确认结果。

日报中的裁片放行指标需要使用“裁床确认可做放行数量”口径，不再使用目标数量或系统齐套数量替代。

日报需要展示以下业务信息：

- 当前可放行数量。
- 放行状态。
- 风险放行数量。
- 需复核提示。
- 裁床确认时间。

## 八、完整业务流程

完整业务流程如下：

1. 系统根据裁片事实计算当前系统齐套数量。
2. 裁床主管维护生产单下各颜色尺码的目标数量。
3. 系统根据目标数量和裁片事实计算目标缺口。
4. 裁床主管按颜色尺码确认当前可做放行数量。
5. 如果可做放行数量超过系统齐套数量，裁床主管填写风险原因。
6. 系统生成放行确认版本。
7. PPIC 在车缝分配时读取最新有效放行确认版本。
8. PPIC 按裁床当前可派数量安排车缝。
9. 如果 PPIC 派工数量超过裁床当前可派数量，系统提示风险，PPIC 确认后继续。
10. 裁床按中转袋和菲票向车缝厂交出裁片。
11. 系统按车缝厂和生产单累计已交出的中转袋菲票。
12. 系统计算该车缝厂对该生产单的最低应回数量。
13. 生产日报读取裁床放行确认结果，用于展示当前可放行情况。

## 九、数量口径说明

| 数量 | 维护或计算方 | 使用场景 | 是否可人工调整 |
| --- | --- | --- | --- |
| 目标数量 | 裁床主管维护 | 补料、补裁、目标缺口、放行上限 | 可以调整 |
| 系统齐套数量 | 系统计算 | 判断是否按齐套放行 | 不可人工调整 |
| 可做放行数量 | 裁床主管确认 | PPIC 当前可派参考 | 可以确认或调整 |
| 风险放行数量 | 系统计算 | 风险提示和追溯 | 不可直接调整 |
| PPIC 派工数量 | PPIC 决策 | 车缝任务安排 | 可以超过可派数量，但需确认风险 |
| 最低应回数量 | 系统计算 | 车缝回货最低责任数量 | 不可人工调整 |

## 十、异常与复核规则

### 1. 目标数量变化

如果生产单已有放行确认版本，裁床主管再次调整目标数量，系统需要提示该生产单“确认后需复核”。

目标数量变化不自动作废历史放行版本，但 PPIC 需要看到复核提示。

### 2. 裁片事实变化

如果生产单已有放行确认版本，后续发生裁片事实变化，系统需要提示该生产单“确认后需复核”。

裁片事实变化包括但不限于：

- 新增裁片入仓。
- 铺布完成数量变化。
- 裁片单冻结。
- 裁片单恢复。
- 裁片冲销。
- 菲票数量变化。

### 3. 风险放行

当可做放行数量超过系统齐套数量时，系统需要识别为风险放行。

风险放行必须记录风险原因。

风险原因由裁床主管自由填写，当前版本不做固定选项限制。

### 4. 暂不放行

裁床主管可以将可做放行数量确认为零。

当可做放行数量为零时，系统需要明确提示 PPIC 当前不建议派工。

PPIC 如仍需派工，必须进行超可派风险确认。

## 十一、同一生产单贯穿要求

同一生产单必须能够在以下业务场景中保持一致：

- 裁片放行列表。
- 裁片放行矩阵。
- 放行确认版本。
- PPIC 车缝分配工作台。
- PPIC 派工记录。
- 裁片交出单。
- 中转袋。
- 菲票。
- 车缝最低应回计算。
- 生产日报。

研发和测试需要重点验证：同一个生产单在裁片放行、PPIC 派工和裁片交出最低应回中不能出现不同业务单号。

## 十二、验收标准

### 1. 裁片放行验收

- 没有目标数量时，生产单状态为待维护目标。
- 有目标数量但没有确认放行时，生产单状态为待裁床确认。
- 可做放行数量不超过系统齐套数量时，生产单状态为按齐套放行。
- 可做放行数量超过系统齐套数量时，生产单状态为风险放行，并且必须有风险原因。
- 可做放行数量为零时，生产单状态可以表达暂不放行。
- 已确认放行后目标或裁片事实变化时，生产单状态需要提示确认后需复核。

### 2. PPIC 验收

- PPIC 可以看到裁床确认的当前可派车缝数量。
- PPIC 可以看到放行状态、风险数量和风险原因。
- PPIC 派工数量超过当前可派数量时，必须出现风险确认。
- PPIC 确认风险后，可以继续完成派工。
- PPIC 派工记录需要保留当时引用的裁床放行版本。

### 3. 交出最低应回验收

- 系统可以按车缝厂和生产单累计已交出的中转袋。
- 系统可以按中转袋内菲票累计颜色、尺码、部位数量。
- 系统可以按部位用量折算最低应回数量。
- 最低应回数量不受裁床放行数量和 PPIC 派工数量直接影响。
- 同一生产单必须能从裁床放行贯穿到 PPIC 派工，再贯穿到交出最低应回。

### 4. 日报验收

- 生产日报中的当前可放行数量使用裁床确认可做放行数量。
- 生产日报需要展示放行状态和风险放行数量。
- 对确认后需复核的生产单，生产日报需要能体现复核风险。

## 十三、示例业务场景

### 场景一：按齐套放行

某生产单目标数量为 1,000 件，系统齐套数量为 800 件。裁床主管确认当前可做放行数量为 800 件。

系统结果：该生产单为按齐套放行，PPIC 当前可派 800 件，无风险放行数量。

### 场景二：风险放行

某生产单目标数量为 1,000 件，系统齐套数量为 900 件。裁床主管确认当前可做放行数量为 950 件，并填写原因为部分裁片已完成但尚未入仓。

系统结果：该生产单为风险放行，PPIC 当前可派 950 件，风险放行数量为 50 件。

### 场景三：PPIC 超可派派工

某生产单裁床确认当前可派 950 件。PPIC 因排产需要安排 1,000 件车缝。

系统结果：系统提示超可派风险，PPIC 确认后可以继续派工，派工记录保留当时裁床确认版本。

### 场景四：最低应回独立计算

某生产单已向同一车缝厂交出若干中转袋。中转袋内菲票显示，某颜色尺码前片、后片和袖片各可组成 200 件，但领片只能组成 180 件。

系统结果：该颜色尺码最低应回为 180 件，因为最低应回取必要部位中可组成成衣数量的最小值。

## 十四、业务边界说明

- 裁片放行解决的是 PPIC 当前可以参考多少数量安排车缝。
- PPIC 派工解决的是将多少数量派给哪个车缝厂。
- 裁片交出解决的是实际交给车缝厂哪些裁片实物。
- 最低应回解决的是基于已交出实物，车缝厂至少应回多少成衣。
- 以上四类数量有关联，但不能互相替代。
