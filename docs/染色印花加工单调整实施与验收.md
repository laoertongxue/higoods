## 2. 总体设计

### 2.1 身份与上下游

需求来源说明加工单由哪张生产、备货或补料需求产生；上游说明实际供料工厂或仓库及供料单据。下道工序与实际接收单位、仓库分别表达。所有关联依赖已有业务标识，不按名称相似猜测。一个加工单保持明确指定接收对象，历史交接不能因展示更新而改写。

### 2.2 统一列表

七个业务列：加工单／商品、加工投入／上游、加工要求、处理进度、加工产出／下游、工厂／交期、操作。选择框合入第一列。投入端只放计划投入、已收、已用；产出端只放完成、已交、下游已收及有余额时的待收。不保留独立重复数量或来源列。

顶部只保留页面标题、批量动作、常用筛选、更多筛选、单行摘要和表格工具栏。常用筛选是综合查询、三个独立状态及加工厂。其他查询条件折叠。所有功能保留可到达入口，不能通过隐藏功能简化页面。

### 2.3 数量与状态

已收、已用、完成、交出、下游接收、确认损耗各由其对应记录支持。已收不得冒充已用；已收减产出不得冒充损耗；未知显示待补录；不同单位不混加、不相减。下游待收需区分在途、已处理差异和退回。接收、加工、交出独立判断；本批完成不冒充整单完成；下游接收不覆盖本单交出事实。

### 2.4 工艺、详情及保留能力

染色突出工艺、真实目标颜色／色号和色样，详情保留成分、参数、批次质量与数量依据。印花突出工艺、单双面和正反面花型，详情保留花型版本、打印转印、设备、换料、卷记录。技术包编号不得冒充色号、花型号或商品 SPU。缺失素材明确提示，不伪造图片。两页详情按基本信息、上游投入、加工要求、加工记录、产出下游、日志单据组织，记录按需展开。

保留原有编辑、换料、日志、合并染色关联、流程卡、印花信息单／确认单、产出卷条码和导出。不新增无业务依据的代确认按钮，不放开已完成记录编辑约束。

### 2.5 设备与交互

1366×768 及 1280×720 桌面验收；核心对象、要求和状态默认可见。宽表仅容器内滚动；固定身份和操作，路由各自保存列偏好。图片与对象同块且可放大、失败可见。分页、局部更新、滚动保持；有意义的颜色及链接反馈。PDA、弱网上传和实际打印设备不在本次新增能力范围，既有浏览器打印输出仍需检查。

## 4. 证据与交付

原子需求及逐项状态见同目录 `染色印花加工单逐项验收.csv`。每行关联用户方案节号、工作包、实现位置、技术与页面证据、版本及确认人。

矩阵已回填当前证据；“已验证”仅用于当前改动之后实际验证成功的项。缺图、缺实际记录或未完成场景保持明确状态，不能用构建或页面截图替代业务证据。

最终结果：89项中84项已验证、5项因正式素材或历史原始资料缺失已阻塞。15项类型/构建/专项检查中14项通过，1项图片完整性检查失败；16组浏览器检查通过。详情见《染色印花加工单验收结果清单.md》。未完成产品接受，不宣称完整交付。

### 4.1 收尾修正

- 无明确下道关系不得由接收仓推导入库；下道、接收单位、仓库分开。
- 实际投入按精确SKU关联图片，无资料显示缺失，不借计划图。
- 接收、加工、交出独立；多批染色累计且保留历史完成事实。
- 已处理差异与作废交出排除待收，在途不冒充接收差异。
- 零量草稿卷、未完成卷以及超过产出总量的卷阻断打印。
- 两页列设置勾选与表格同步。
- 最终采用代码文件SHA-256指纹绑定本次版本；未运行可能吸收既有无关差异的全量工作流收据。

最终交互性能：首次真实查询点击至双帧绘制，染色47.3ms、印花47.4ms，均低于200ms；原始结果见 `output/playwright/process-order-review/interaction-timing.json`。本页数据快照在路由重入或保存后失效；`src/main.ts`仅为两个命名列表直接分发已有处理器，避免首次操作加载整个FCS事件包。
